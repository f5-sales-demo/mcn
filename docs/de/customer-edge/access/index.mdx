Es gibt vier Zugangswege, und welcher anwendbar ist, wird durch den Zustand des Knotens,
den Verbindungsursprung und das Ziel bestimmt — nicht durch eine Präferenz.

| Weg | Knoten `ONLINE` erforderlich | Netzwerkerreichbarkeit erforderlich | Einschränkungen | Abdeckung |
| --- | --- | --- | --- | --- |
| [Debug-API](./debug-api/) | **ja** | ja | ca. 25–30 Minuten Anlaufzeit bei einer neuen Site | 34 Befehle |
| [Websitekonsole](./site-console/) | nein | über Azure Bastion, kein Jump-Host erforderlich | Bastion muss Standard-SKU mit Tunneling sein | F5's Knoten-Fehlerbehebungs-UI |
| [SSH](./ssh/) | nein | von innerhalb des VNet, nur zur internen Adresse | Schlüssel muss ab dem ersten Start vorhanden sein | Die vollständige On-Box-Site-CLI |
| [Serielle Konsole](./serial-console/) | nein | nein | eine Sitzung pro VM; 2.048-Zeichen-Einfügegrenze | Die vollständige On-Box-Site-CLI |

Die serielle Konsole ist das letzte Mittel und der einzige Weg, der einen Knoten ohne
funktionierenden Netzwerkpfad übersteht.

Die [Websitekonsole](./site-console/) ist in der Regel der erste Anlaufpunkt. Sie stellt
die geringsten Anforderungen — kein zu verteilender SSH-Schlüssel, kein Jump-Host, keine
öffentliche IP am Knoten und kein VM-Austausch — da der Zugang zu einer Azure RBAC-
Entscheidung wird statt zu einem Problem der Anmeldeinformationsverteilung. Sie bietet
F5's eigene Fehlerbehebungs-UI statt einer Befehlsoberfläche; greifen Sie daher darüber
hinaus, wenn Sie bestimmte Befehle ausführen oder Skripte erstellen möchten.

SSH ist die Wahl, wenn die Debug-API nicht ausreicht, da das Gerät wesentlich mehr Befehle
bietet als die 34, die diese API bereitstellt. Es hat zwei Kosten. Der Schlüssel wird von
cloud-init geschrieben und muss daher beim **ersten Start** vorhanden sein, was bedeutet,
dass seine Aktivierung auf laufenden Knoten diese ersetzt — was derzeit die Registrierung
blockiert ([Issue 674](https://github.com/f5-sales-demo/mcn/issues/674)). Und `sshd`
antwortet nur auf der internen Adresse des Knotens, sodass ein Host innerhalb des VNet
benötigt wird; das Prüfen der bekannten Knotenadresse meldet stets geschlossen.

## Warum die Aufteilung keine Präferenz ist

Die Debug-API wird von der F5 Distributed Cloud-Steuerungsebene bereitgestellt, die über
den Tunnel weiterleitet, den `vpm` während der Registrierung aufbaut. Keine Registrierung
bedeutet kein Tunnel, was bedeutet, dass die API nichts weiterleiten kann.

Der Fehler tritt auf eine wenig hilfreiche statt auf eine offensichtliche Weise auf,
sodass ein Knoten, der nie gestartet ist, wie ein API-Problem aussieht.

Die serielle Konsole geht den umgekehrten Weg — über die Azure-Plattform zum emulierten
seriellen Port des Knotens. Es spielt keine Rolle, ob der Knoten registriert ist,
Netzwerkerreichbarkeit hat oder eine funktionierende Datenebene besitzt. Diese
Unabhängigkeit ist der eigentliche Zweck, und deshalb muss die Boot-Diagnose auf den
CE-VMs aktiviert bleiben.

<Aside type="note" title="Wann welcher Weg">
Wenn Sie eine Automatisierung schreiben oder Nachweise sammeln, die Sie später erneut
ausführen möchten, verwenden Sie die Debug-API. Wenn die Registrierung das Problem ist,
ist die serielle Konsole kein Fallback — sie ist die einzige Option.
</Aside>

## Anmeldeinformationen

Jeder Weg verwendet unterschiedliche Anmeldeinformationen, und keine davon gehört in eine
Befehlszeile.

- **Debug-API** — ein F5 Distributed Cloud-API-Token als `XCSH_API_TOKEN`, mit der
  Mandanten-URL als `XCSH_API_URL`. Die `xcsh`-Kontextdatei unter
  `~/.config/xcsh/contexts/<tenant>.json` enthält beides, was
  `scripts/capture-sitecli.sh` liest, wenn die Umgebung sie nicht bereitstellt.
- **SSH** — die private Hälfte des Schlüsselpaars, dessen öffentliche Hälfte das
  Deployment beim ersten Start in `/var/home/admin/.ssh/authorized_keys` geschrieben hat,
  plus ein Host innerhalb des VNet, um die interne Adresse zu erreichen. Verbinden als
  `admin`, nicht als `azureuser`.
- **Serielle Konsole** — Ihre interaktive Azure-Anmeldung. Es gibt keinen
  Dienstprinzipal dafür: Der F5-Corporate-Entra-Mandant erlaubt keine Bereitstellung
  eines solchen, weshalb kein Teil davon in CI ausgeführt wird.

<Aside type="danger" title="Übergeben Sie ein Token niemals als Argument">
Ein Token in einer Befehlszeile landet im Shell-Verlauf und in der Prozessliste, wo
jeder andere Benutzer auf dem Rechner es lesen kann. `capture-sitecli.sh` lehnt
`--token` aus diesem Grund grundsätzlich ab und übergibt den Header stattdessen über
stdin an `curl`.
</Aside>
