## `diagnosis`

<Aside type="caution" title="GLOBAL-Scope — ein anderer Transportweg">
Wie bei `health` ein `GET` auf den `global`-Pfad und nicht über `exec-user` erreichbar.

```bash
curl -sS -H "Authorization: APIToken $XCSH_API_TOKEN" \
  "$XCSH_API_URL/api/operate/namespaces/system/sites/<site>/vpm/debug/global/diagnosis"
```

</Aside>

```json file=../../../../_data/sitecli-diagnosis.txt
```

Die Ergebnisse werden pro Knoten ausgegeben, an einem Standort mit mehreren Knoten erhalten Sie also jeweils einen Block.
`gateway_connectivity` und `dns_connectivity` enthalten jeweils eine Ping-Zusammenfassung — `dest_ip`, `sent`,
`received`, `lost` sowie Laufzeiten.

<Aside type="danger" title="Beide Ping-Prüfungen melden 100 % Verlust auf einem völlig gesunden Knoten">
In dieser Topologie melden **beide**, `gateway_connectivity` (an `10.0.1.1`) und `dns_connectivity` (an
`168.63.129.16`), `sent: 5, received: 0, lost: 100`, während der Standort `ONLINE` ist,
Datenverkehr weiterleitet und `registration_status: OK` lautet — beim Schreiben dieses Textes erneut überprüft. Zwei
`lost: 100`-Blöcke in einer Antwort sind das alarmierendste Erscheinungsbild auf dieser Seite und
gleichzeitig der Normalzustand.

`dns_connectivity` ist von beiden das irreführendere Feld, denn DNS funktioniert nachweislich: Das
`dns_query_result` derselben Antwort enthält zehn erfolgreiche Abfragen mit `NOERROR` gegen genau
diesen Resolver. Die Prüfung misst die ICMP-Erreichbarkeit, die von den Azure-Plattformadressen
nicht beantwortet wird; sie misst nicht DNS.

Betrachten Sie beide Felder nur dann als Signal, wenn Sie bereits andere Hinweise auf ein Problem haben oder
wenn sich der Wert ändert.
</Aside>

Die Felder, die zuerst gelesen werden sollten, finden sich an anderer Stelle in der Antwort: `registration_status`,
`curl_response` (ein Eintrag pro F5-Endpunkt, den der Knoten benötigt, jeweils `OK` oder nicht),
`dns_query_result` und `ntp_sync_status`.

`resolv_conf` zeigt den Resolver, den der Knoten tatsächlich verwenden wird — es lohnt sich, diesen mit
Ihren Erwartungen zu vergleichen, bevor Sie Zeit in [`dig`](../../network/dig/) investieren.
