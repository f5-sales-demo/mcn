Diese geben die Sicht des Kernels wieder. Die Argo-Datenebene führt ihre eigene, sichtbar über
[`vif`](../dataplane-forwarding/), und beide können voneinander abweichen.

## `ip`

Erwartet einen `ip`-Unterbefehl. `addr` ist der gebräuchliche; `route`, `link` und `neigh` funktionieren
ebenfalls.

```bash
{"command":["ip","addr"]}
```

```text file=../../../../_data/sitecli-ip.txt
```

Die CE besitzt konstruktionsbedingt drei Azure-NICs — Management/SLO, extern, intern/SLI —, aber das
Gastsystem stellt sie nicht in der Weise dar, die diese Reihenfolge nahelegt, und genau hier kostet
ein falsches Lesen der Ausgabe Zeit.

| Im Gastsystem | Trägt |
| --- | --- |
| `a-i-eth0` | **überhaupt keine Adresse** — dies ist die umbenannte physische eth0, und die Argo-Datenebene besitzt sie |
| `vhost0` | die Management-/SLO-Adresse, jene, von der BGP peert und die das Site-Objekt meldet |
| `eth1` und `eth2` | die externen und internen/SLI-Adressen — aber **nicht in fester Reihenfolge** |

<Aside type="danger" title="Welche von eth1 und eth2 die interne Schnittstelle ist, unterscheidet sich zwischen den Knoten">
Live von den drei CEs dieser einen Bereitstellung ausgelesen: auf `f5-xc-ce-vm-01` und
`f5-xc-ce-vm-03` liegt die interne/SLI-Adresse auf `eth2`, auf `f5-xc-ce-vm-02` auf
`eth1`. Nichts in der Konfiguration bestimmt dies.

Leiten Sie daher niemals ein Subnetz aus einem Schnittstellennamen ab und übertragen Sie niemals eine Zuordnung von einem Knoten
auf einen anderen. Gleichen Sie stattdessen über die Adresse ab — das Subnetz, zu dem eine CE-Adresse gehört, ist stabil, auch
wenn die Schnittstelle, die sie trägt, es nicht ist.
</Aside>

Dass `a-i-eth0` keine Adresse trägt, ist auch der gesamte Grund dafür, dass `sshd` unter der
Management-Adresse nicht erreichbar ist: Dort gibt es keinen Listener, keinen blockierten Port. Siehe
[SSH](../../../access/ssh/).

## `ip-link-show`

Nur Sicherungsschicht: Status, MTU, Queueing-Discipline, MAC.

```bash
{"command":["ip-link-show"]}
```

```text file=../../../../_data/sitecli-ip-link-show.txt
```

Schneller als `ip addr`, wenn die Frage lautet „Ist der Link aktiv und wie groß ist seine MTU“.
MTU-Abweichungen sind eine wiederkehrende Ursache für Tunnel, die zwar aufgebaut werden, aber keinen Datenverkehr durchlassen.

## `ip-link-set` <Badge text="Exec-Stufe — verändernd" variant="danger" />

Setzt eine Schnittstelle oder Gruppe auf up oder down.

```
ip-link-set (<device>||<group>) (up||down)
```

<Aside type="danger" title="Hier nicht ausgeführt und nicht auf dem üblichen Weg erreichbar">
Dies ist der einzige Befehl der `Exec`-Stufe in diesem Build. Er geht an den `exec`-Endpunkt
statt an `exec-user`, und er verändert den Knoten: `eth0` auf einer entfernten CE herunterzufahren
entfernt den Pfad, über den Sie sie verwalten, einschließlich der Debug-API selbst.

Auf dieser Seite gibt es bewusst keine aufgezeichnete Ausgabe. Das Aufzeichnungsgerüst verweigert
die gesamte `Exec`-Stufe und liest die Stufe aus dem Live-Katalog statt aus einer
fest kodierten Liste, sodass dies auch dann gilt, wenn ein künftiger Build weitere Befehle dorthin hochstuft.
</Aside>
