Der CE führt FRR für BGP aus. In dieser Topologie peert er mit den beiden Azure Route Server-
Instanzen, kündigt die VIP an und lernt das VNet-Präfix.

## `show-ip-bgp-summary`

Beginnen Sie hier. Eine Bildschirmausgabe zeigt, ob das Peering aktiv ist und wie lange es
stabil war.

```bash
{"command":["show-ip-bgp-summary"]}
```

```text file=../../../../_data/sitecli-show-ip-bgp-summary.txt
```

Lesen Sie zuerst `State/PfxRcd`. Eine Zahl ist die Anzahl der empfangenen Präfixe und bedeutet, dass die
Sitzung aufgebaut ist; alles andere — `Active`, `Connect`, `Idle` — ist eine Sitzung,
die nicht aktiv ist. `Up/Down` zeigt, wie lange der aktuelle Zustand angedauert hat; eine Sitzung,
die sich ständig zurücksetzt, zeigt daher einen auffällig kleinen Wert.

<Aside type="caution" title="Die vrf-ID hier ist nicht die, die rt erwartet">
Diese Ausgabe meldet `vrf-id 3`. Das ist FRRs Nummerierung. Die Argo-Datenebene verwendet eine
separate Tabellen-ID, und wenn FRRs Nummer an
[`rt --dump`](../dataplane-forwarding/) übergeben wird, wird `No such file or directory` zurückgegeben, was
wie ein defekter Knoten aussieht und nicht wie ein falsches Argument.
</Aside>

## `show-ip-bgp`

Die vollständige Tabelle mit sichtbarer Best-Path-Auswahl.

```bash
{"command":["show-ip-bgp"]}
```

```text file=../../../../_data/sitecli-show-ip-bgp.txt
```

`*` ist eine gültige Route, `>` der ausgewählte beste Pfad, `=` ein Multipath-Mitglied. Zwei
Einträge für ein Präfix, beide mit `*=` markiert, bedeuten, dass ECMP aktiv ist, was der
beabsichtigte Zustand in dieser Topologie ist.

## `show-ip-bgp-neighbors`

Details pro Nachbar: ausgehandelte Fähigkeiten, Timer, Nachrichtenzähler und der
Grund für den letzten Reset.

```bash
{"command":["show-ip-bgp-neighbors"]}
```

Verwenden Sie diesen Befehl, wenn die Zusammenfassung eine flappende Sitzung zeigt und Sie wissen möchten, warum.
`Last reset` und sein Grund sind die relevanten Zeilen.

<Aside type="note" title="Noch keine erfasste Ausgabe auf dieser Seite">
Diese Erfassung kann erst übertragen werden, wenn `f5-sales-demo/docs-control#795` eingebunden ist. FRR
schreibt ein Wort in seiner Graceful-Restart-Zeile falsch, und `codespell` lehnt die Datei ab.

Die erfasste Ausgabe zu korrigieren würde bedeuten, dass diese Dokumentation eine Ausgabe beschreibt, die nie
aufgetreten ist. Daher wird das Problem stattdessen im Upstream behoben. Führen Sie den Befehl in der Zwischenzeit
gegen Ihren eigenen Knoten aus.
</Aside>

## `show-ip-bgp-neighbors-advertised-route`

Was dieser Knoten seinen Peers mitteilt, im Gegensatz zu dem, was er kennt.

```bash
{"command":["show-ip-bgp-neighbors-advertised-route"]}
```

```text file=../../../../_data/sitecli-show-ip-bgp-neighbors-advertised-route.txt
```

Dies ist der Befehl für den Fall, dass „die VIP vom VNet aus nicht erreichbar ist". Wenn die VIP
hier fehlt, liegt das Problem auf diesem Knoten, und kein Blick auf den Peer wird helfen.
