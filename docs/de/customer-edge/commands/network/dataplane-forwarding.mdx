Argo hält den Weiterleitungszustand getrennt vom Linux-Kernel. Wenn
[`ip`](../ip/) und diese Befehle sich widersprechen, dann sind es diese Befehle, die den Datenverkehr bewegen.

## `rt`

Die vRouter-Routentabelle, pro VRF.

```bash
{"command":["rt","--dump","2"]}
```

```text file=../../../../_data/sitecli-rt.txt
```

<Aside type="danger" title="Die VRF-ID ist nicht die, die BGP meldet">
`show-ip-bgp-summary` gibt `vrf-id 3` aus. Das ist die Nummerierung von FRR und sie liegt in einem
anderen Namensraum als die Tabellen-ID des vRouters. Wird sie hier übergeben, schlägt es auf eine Weise fehl, die
sich wie ein defekter Knoten liest:

```
vRouter(Response):  [No such file or directory (2)]
```

Dieselbe Antwort kommt bei `--dump 0` zurück. In dieser Topologie ist **VRF 2** die
befüllte inet4-Tabelle, während VRF 1 zwei Routen enthält. Wenn Sie die ID nicht kennen,
tasten Sie sich von 1 aufwärts vor, anstatt der BGP-Ausgabe zu vertrauen.
</Aside>

## `nh`

Die Next-Hop-Tabelle. Jede Route verweist auf eine Next-Hop-ID, und diese löst sie auf.

```bash
{"command":["nh","--list"]}
```

```text file=../../../../_data/sitecli-nh.txt
```

Jeder Eintrag trägt einen `Type` und das VRF, zu dem er gehört. Auf diesen Knoten treten acht Typen auf, in
diesen Verhältnissen — bei Zählung identisch über alle drei CEs:

```text
Tunnel 558   Encap 27   NAT 22   Vrf 16   Receive 14   Composite 4   Drop 2   Resolve 2
```

Eine Route, die zu einem `Drop`-Next-Hop auflöst, ist ein Blackhole, und diese Kombination ist immer dann
eine Prüfung wert, wenn ein Präfix in `rt` vorhanden ist, der Datenverkehr aber dennoch verschwindet.

<Aside type="caution" title="Die obige Aufzeichnung ist gekürzt und enthält daher nicht jeden Typ">
Es sind die ersten 60 von 3.849 Zeilen. `Tunnel`, der mit großem Abstand häufigste Typ, erscheint in
diesen 60 Zeilen überhaupt nicht — lesen Sie die Aufzeichnung also nicht als vollständige Typ-Inventur und schließen Sie
nicht daraus, dass ein Typ auf einem Knoten fehlt, weil er in einer gekürzten Aufzeichnung fehlt. Die obigen Zählungen
stammen aus der ungekürzten Antwort.
</Aside>

## `vif`

Die Tabelle der virtuellen Schnittstellen: woran sich die Datenebene bindet, sowie
Zähler pro Schnittstelle.

```bash
{"command":["vif","--list"]}
```

```text file=../../../../_data/sitecli-vif.txt
```

Die Flag-Legende am Anfang ist es wert, einmal gelesen zu werden — `Vp` kennzeichnet die physische
vhost-Schnittstelle, `Dpdk` eine DPDK-verwaltete. Verwenden Sie dies, um zu bestätigen, dass die Datenebene die
erwartete Schnittstelle übernommen hat, und um RX- und TX-Zähler zu sehen, die Linux nicht anzeigt,
weil der Datenverkehr den Kernel nie erreicht.
