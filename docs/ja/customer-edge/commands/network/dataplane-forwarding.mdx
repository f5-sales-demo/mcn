Argoは転送状態をLinuxカーネルとは別に管理しています。[`ip`](../ip/)コマンドとこれらのコマンドの結果が異なる場合、実際にトラフィックを転送しているのはこれらのコマンドが示す内容です。

## `rt`

VRFごとのvRouterルートテーブルです。

```bash
{"command":["rt","--dump","2"]}
```

```text file=../../../../_data/sitecli-rt.txt
```

<Aside type="danger" title="VRF idはBGPが報告するものとは異なります">
`show-ip-bgp-summary`は`vrf-id 3`を出力しますが、これはFRRの採番であり、vRouterのテーブルidとは異なる名前空間です。ここにそのidを渡すと、ノードが壊れているかのように見えるエラーが発生します：

```
vRouter(Response):  [No such file or directory (2)]
```

`--dump 0`を指定した場合も同じ結果が返されます。このトポロジーでは、**VRF 2**がinetv4テーブルとして使用されており、VRF 1には2つのルートが存在します。idが不明な場合は、BGPの出力を信用せず、1から順に上方向に探索してください。
</Aside>

## `nh`

ネクストホップテーブルです。すべてのルートはネクストホップidを参照しており、このコマンドでそれを解決できます。

```bash
{"command":["nh","--list"]}
```

```text file=../../../../_data/sitecli-nh.txt
```

各エントリには`Type`と所属するVRFが含まれています。これらのノードでは8種類のタイプが存在し、3つのCE全体で集計すると以下の割合になります：

```text
Tunnel 558   Encap 27   NAT 22   Vrf 16   Receive 14   Composite 4   Drop 2   Resolve 2
```

`Drop`ネクストホップに解決されるルートはブラックホールを意味します。`rt`にプレフィックスが存在するにもかかわらずトラフィックが消えてしまう場合は、この組み合わせを確認する価値があります。

<Aside type="caution" title="上記のキャプチャは抜粋であるため、すべてのタイプが含まれているわけではありません">
これは3,849行のうち最初の60行です。最も多いタイプである`Tunnel`は、その60行にまったく含まれていません。そのため、このキャプチャをタイプの完全な一覧として解釈しないでください。また、抜粋されたキャプチャにタイプが含まれていないからといって、そのノードにそのタイプが存在しないと結論付けないでください。上記の集計は抜粋されていないレスポンスから取得したものです。
</Aside>

## `vif`

仮想インターフェーステーブルです。データプレーンがバインドするインターフェースと、インターフェースごとのカウンターを確認できます。

```bash
{"command":["vif","--list"]}
```

```text file=../../../../_data/sitecli-vif.txt
```

先頭のフラグの凡例は一度確認しておく価値があります。`Vp`はvhostの物理インターフェースを、`Dpdk`はDPDK管理のインターフェースを示します。このコマンドを使用して、データプレーンが期待通りのインターフェースを取得していることを確認したり、トラフィックがカーネルに到達しないためLinuxには表示されないRXおよびTXカウンターを確認したりできます。

## `mpls`

```bash
execcli mpls --help
```

ArgoのMPLSテーブルです。**ボックス上でのみ**使用可能です。`mpls`はデバッグAPIには含まれていないため、`rt`、`nh`、`vif`とは異なり、[`execcli`](../../on-box/)を通じて[SSH](../../../access/ssh/)または[シリアルコンソール](../../../access/serial-console/)が必要です。

ここにはキャプチャされた出力はありません。このデプロイメントではCEがBGPとECMPを使用してIPv4を転送しており、MPLSラベルを使用していないため、キャプチャしても空のテーブルが表示されるだけで有益な情報は得られません。コマンドの存在と`--help`引数の形式はアプライアンス自身の補完メニューから確認されており、実際にデータが入力された出力は再現していません。
