## `dig`

```bash
{"command":["dig","volterra.azurecr.io"]}
```

```text file=../../../../_data/sitecli-dig.txt
```

まずヘッダーの `status:` を確認してください — `ANSWER` 数がゼロでない `NOERROR` は、
正常に名前解決が完了したことを意味します。

下部の `SERVER:` は応答したリゾルバーを示しており、確認する価値がある部分です。Azureノードでは、通常はプラットフォームリゾルバーの `168.63.129.16` が表示されますが、それ以外の値が表示された場合、ノードは意図しないリゾルバーを使用していることになります。

登録の失敗は多くの場合DNSに起因します。ノードが `register.ves.volterra.io` やコンテナレジストリを解決できない場合、その先のすべての処理が機能しなくなります。これはその問題を素早く証明するための最短の方法です。

このコマンドは通常の `dig` 引数を受け付けており、特定のサーバーに問い合わせるための `@resolver` も使用できます。あるリゾルバーは応答するが別のリゾルバーは応答しないことを示す際に有用です。

:::note
`dig` は旧バージョンの公開サイトCLIリファレンスには一切記載されていません。ドキュメントを参照するのではなく、ノード自身のコマンドカタログに問い合わせることで発見されました。これが、本サイトに掲載されているすべてのコマンドが文書の転写ではなく発見によるものである理由です。
:::
