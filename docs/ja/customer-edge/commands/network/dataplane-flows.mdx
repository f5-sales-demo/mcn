Argo はすべての接続を追跡します。完全なダンプは原理的に無制限で、実際に扱いにくいため、
テーブルに何が含まれているかよりも、どのようにクエリするかのほうが重要です。

<Aside type="caution" title="629,760 はテーブルの容量であり、フロー数ではありません">
ヘッダー行 `Flow table(size 161218560, entries 629760)` は、データプレーンが割り当てたスロット数を
報告するもので、負荷に関係なくここではどのノードでも同じ値です。稼働中のフロー数はその行には
含まれていません。数行下の `Entries: Created … Added … Deleted …` は累積カウンターであり、
実際に格納されているフローは凡例の後に出力されるレコードです。本稿の執筆中に実行した際は、
542 行のレスポンス中に 73 件ありました。
</Aside>

## `flow-l-match`

ほとんどの場合、こちらを使いたいはずです。アドレス、またはアドレスとポートを指定します。

```bash
{"command":["flow-l-match","100.127.192.10:53"]}
```

```text file=../../../../_data/sitecli-flow-l-match.txt
```

各フローのアクションが要点です。`F` は転送、`D` はドロップ、`N` は NAT です。アクション `D` の
フローが存在するということは、データプレーンが意図的に判断を下したということであり、
接続性ではなくポリシーに目を向けるべきだということを示しています。

## `flow-l`

完全なダンプです。

```bash
{"command":["flow-l"]}
```

```text file=../../../../_data/sitecli-flow-l.txt
```

<Aside type="caution" title="切り詰め済み、かつサイズは変動します">
上記のキャプチャは 1,186 行のレスポンスから最初の 60 行に切り詰めたものです。本稿の執筆中に
実行した際は 542 行が返されました。レスポンスの長さは稼働中のフロー数に追随するため、
いずれの数値もコマンド固有の性質ではありません。テーブル全体を調査する本当の必要がない限り、
`flow-l-match` を使用してください。
</Aside>
