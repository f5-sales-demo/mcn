## `chronyc-sources`

```bash
{"command":["chronyc-sources"]}
```

```text file=../../../../_data/sitecli-chronyc-sources.txt
```

`MS` 列は 1 文字ではなく **2** 文字です。1 文字目はモードで、サーバーの場合は `^` です。
そして **2 文字目**が状態を表します。`*` は現在選択されているソース、`+` は許容可能な
代替、`-` は選択アルゴリズムによって除外されたもの、`?` は到達不能なものです。
つまり `^*` は選択されているサーバー、`^?` は到達不能なサーバーです。1 文字目だけを
読んでも何もわかりません。ここではすべての行が `^` だからです。

`*` がちょうど 1 つあるのが正常な状態であり、他のソースが `?` を示していてもそれは成り立ちます。

`Reach` は直近 8 回のポーリングを表す 8 進のレジスタであり、`377` は 8 回すべてが成功したことを意味します。
これより小さい値は、直近 8 回のうち少なくとも 1 回が失敗したことを意味します。ただしこれには、
最近になって応答し始めたばかりでレジスタがまだ埋まりきっていないソースも含まれます。
本稿の執筆中に実行した結果では、1 つのソースが選択済み(`^*`)であり、ログインバナーが
`NTP: Synced` と報告しているノード上で、`377` と並んで `3` や `37` が表示されていました。
`377` 未満の値をすべて障害と見なすのではなく、ソースが最後に応答してからの経過時間を示す
`LastRx` と合わせて `Reach` を読んでください。

認証や TLS が目に見える理由なく失敗している場合、早い段階で確認する価値があります。
クロックが十分に大きくずれたノードは有効な証明書を拒否し、自身のトークンも拒否されますが、
その結果として出るエラーが時刻について言及することはほとんどありません。
