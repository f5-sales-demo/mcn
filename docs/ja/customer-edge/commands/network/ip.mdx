これらはカーネルのビューを報告します。Argoデータプレーンは独自のビューを保持しており、
[`vif`](../dataplane-forwarding/) から確認できます。両者は一致しない場合があります。

## `ip`

`ip` サブコマンドを受け取ります。`addr` が一般的なものですが、`route`、`link`、`neigh` も
使用できます。

```bash
{"command":["ip","addr"]}
```

```text file=../../../../_data/sitecli-ip.txt
```

CEは設計上3つのNICを持ち、順序が重要です。`eth0` は管理およびSLOインターフェースで、サイトのBGPローカルアドレスを担い、その後に外部および内部が続きます。出力の `a-i-eth0` に注目してください — データプレーンが物理インターフェースを引き継ぎ、独自のインターフェースを提示しています。

## `ip-link-show`

リンク層のみ：状態、MTU、キューイングディシプリン、MAC。

```bash
{"command":["ip-link-show"]}
```

```text file=../../../../_data/sitecli-ip-link-show.txt
```

「リンクが起動しているか、MTUはいくらか」という問いに対しては `ip addr` より高速です。
MTUの不一致は、確立はするがトラフィックを通過させないトンネルの繰り返し発生する原因です。

## `ip-link-set` <Badge text="Exec ティア — 変更を伴う" variant="danger" />

インターフェースまたはグループをアップまたはダウンにします。

```
ip-link-set (<device>||<group>) (up||down)
```

<Aside type="danger" title="ここでは実行されず、通常の方法ではアクセスできません">
これはこのビルドで唯一の `Exec` ティアコマンドです。`exec-user` ではなく `exec` エンドポイントに送信され、ノードを変更します。リモートCEで `eth0` をダウンさせると、デバッグAPI自体を含め、管理に使用しているパスが削除されます。

このページには意図的にキャプチャされた出力がありません。キャプチャハーネスは `Exec` ティア全体を拒否し、ハードコードされたリストではなくライブカタログからティアを読み取るため、将来のビルドが他のコマンドをそのティアに昇格させた場合でも、この動作は維持されます。
</Aside>
