2 つのコマンドがあり、その違いこそがすべての価値です。

## `curl-host`

ホストネットワーク名前空間で実行されます — データプレーンが関与する前の、ノード自身の接続性です。

```bash
{"command":["curl-host","-v","cloud.f5.com"]}
```

```text file=../../../../_data/sitecli-curl-host.txt
```

## `curl-vega`

ホストではなく Vega (コントロールプレーン) のコンテキストで実行されます。観測可能な違い、そしてここで確認できる唯一の違いは、継承される環境です。`curl-vega` はプライベートレンジ、`int.ves.io`、`int.volterra.us`、およびサイト自身の `.tenant.local` ドメインを含む `NO_PROXY` リストを報告しますが、`curl-host` は何も報告しません。それが DNS パスについて何を意味するかは測定されていません。

```bash
{"command":["curl-vega","-v","cloud.f5.com"]}
```

```text file=../../../../_data/sitecli-curl-vega.txt
```

<Aside type="tip" title="この 2 つの組み合わせは二分探索です">
両方を実行してください。`curl-host` が成功して `curl-vega` が失敗する場合、ノードには接続性があり、コントロールプレーンのコンテキストにある何か — プロキシ設定またはリゾルバ — に問題があります。両方とも失敗する場合、問題はノードより上流にあります。ルーティング、ファイアウォール、またはエグレスパスです。`curl-host` のみが失敗する場合は、何か異常な状況を発見したことになるため、まずホストのルーティングテーブルを確認してください。

正常なノードでは両方が成功し、同じアドレスに到達するため、両方が問題なく通ることはどちらのコンテキストが使われているかについて何も証明しません — 情報を持つのは*相違*の方です。
</Aside>

どちらも通常の `curl` 引数を個別の配列要素として受け付けます。接続と TLS ハンドシェイクの行に失敗が現れることが多いため、`-v` は付けておく価値があります。
