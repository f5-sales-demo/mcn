このデプロイメントの 1 台の CE から 2026-07-28 に取得しました。これらはオンボックスコマンドであるため、デバッグ API ではなく Site CLI を経由して取得しています。`sitecli/exec-catalog.json` が対象範囲を、`sitecli/capture-manifest.json` がどのノードかを記録しています。

Envoy は Customer Edge 上でアプリケーショントラフィックを終端およびプロキシします。次の 4 つのコマンドはその管理インターフェースに問い合わせるもので、いずれも
[デバッグ API](../../../access/debug-api/) には含まれていません。

<Aside type="note" title="いずれもcurlの進捗メーターから始まります">
これらは Envoy の管理エンドポイントに対する `curl` ラッパーであり、`-s` を付けずに呼び出されるため、以下の各キャプチャの最初の 2〜3 行は curl が stderr に書き出す転送進捗です:

```text
  % Total    % Received % Xferd  Average Speed   Time    Time     Time  Current
                                 Dload  Upload   Total   Spent    Left  Speed
  0     0    0     0 …
```

これは Envoy の出力ではなく、エラーでもありません。また有用でもあります: `% Received` のバイト数から Envoy が何かを返したかどうかが分かり、「listener が設定されていない」のか「管理インターフェースが応答しなかった」のかを区別できます。
</Aside>

## `envoy-listeners`

Envoy にインストールされているすべての listener を `name:address:port` 形式で表示します。

```bash
execcli envoy-listeners
```

```text file=../../../../_data/sitecli-envoy-listeners.txt
```

**確認すべきポイント。** このデプロイメントでは、listener は `10.250.0.10:80` を持っています — これは CE が BGP に広告する VIP です。この 1 行が 3 つのレイヤーを結び付けています: [`show-ip-bgp-summary`](../../network/bgp/) がプレフィックスの広告を示しているのに、この listener が存在しない場合、そのルートはサービスを提供しないノードへトラフィックを引き寄せていることになります。これは ECMP セットにおいて最悪の障害モードであり、トラフィックがブラックホールへロードシェアされてしまいます。

末尾の `[fe80:…]:80` は、listener がバインドされているインターフェースのリンクローカルアドレスです。

**分からないこと。** アップストリームの健全性については何も分かりません — その背後にあるものが到達可能かどうかに関係なく listener は存在します。それには `envoy-clusters` を使用してください。

## `envoy-clusters`

すべての cluster と、その優先度ごとの接続数およびリクエスト数の上限を表示します。

```bash
execcli envoy-clusters
```

```text file=../../../../_data/sitecli-envoy-clusters.txt
```

**確認すべきポイント。** 各行は `cluster::scope::key::value` の形式です。`observability_name` エントリが各 cluster を識別し、`default_priority::max_connections`、`max_pending_requests`、`max_requests` の 3 つがリクエスト上限の表示箇所です — `max_pending_requests` に張り付いている cluster は、アップストリームではなく設定によってスロットリングされています。

## `envoy-config-dump`

Envoy の完全な設定を JSON で表示します。サイズは大きく、アイドル状態のデモノードでも 126 KB あります。

```bash
execcli envoy-config-dump
```

```text file=../../../../_data/sitecli-envoy-config-dump.txt
```

**確認すべきポイント。** トップレベルの `configs` 配列には、設定タイプごとに 1 つのオブジェクトが含まれます — bootstrap、clusters、listeners、routes、secrets です。listener や cluster が存在するのに想定外の挙動をする場合にこれを参照してください。読み通すのではなく検索して使うものです。

## `envoy-hc-config-dump`

ヘルスチェック設定に特化した出力です。

```bash
execcli envoy-hc-config-dump
```

```text file=../../../../_data/sitecli-envoy-hc-config-dump.txt
```

**確認すべきポイント。** このデプロイメントでは **1 バイト** のみを返します — curl のメーターに `100 1` として表示されます — つまりヘルスチェック設定がインストールされていないことを意味します。これはヘルスチェック対象のオリジンプールを持たない CE として想定される状態であり、認識しておく価値があります: ここでの空の結果はクエリの失敗ではありません。
