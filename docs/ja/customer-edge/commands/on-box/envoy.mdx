このデプロイメントの CE の 1 台から 2026-07-28 に取得したものです。これらはオンボックスコマンドであるため、デバッグ API ではなく Site CLI を経由して実行されます。`sitecli/exec-catalog.json` にはサーフェスが記録され、`sitecli/capture-manifest.json` にはどのノードかが記録されます。

Envoy は Customer Edge 上でアプリケーショントラフィックを終端してプロキシします。以下の 4 つのコマンドはその管理インターフェースを照会するものであり、いずれも
[デバッグ API](../../../access/debug-api/) には含まれていません。

<Aside type="note" title="これらはすべて curl の進捗メーターから始まります">
これらは Envoy の管理エンドポイントへの `curl` ラッパーであり、`-s` オプションなしで呼び出されます。そのため、以下に示す各キャプチャの最初の 2〜3 行は、curl の転送進捗が stderr に書き出されたものです。

```text
  % Total    % Received % Xferd  Average Speed   Time    Time     Time  Current
                                 Dload  Upload   Total   Spent    Left  Speed
  0     0    0     0 …
```

これは Envoy の出力ではなく、エラーでもありません。また有用な情報でもあります。`% Received` のバイト数を見ることで、Envoy が何かを返したかどうかがわかり、「リスナーが設定されていない」のか「管理インターフェースが応答しなかった」のかを区別できます。
</Aside>

## `envoy-listeners`

Envoy にインストールされているすべてのリスナーを `name:address:port` 形式で表示します。

```bash
execcli envoy-listeners
```

```text file=../../../../_data/sitecli-envoy-listeners.txt
```

**確認すべき点。** このデプロイメントでは、リスナーに `10.250.0.10:80` — CE が BGP にアドバタイズする VIP — が含まれています。この 1 行が 3 つのレイヤーを結びつけます。[`show-ip-bgp-summary`](../../network/bgp/) でプレフィックスがアドバタイズされているにもかかわらずこのリスナーが存在しない場合、そのルートはトラフィックを処理しないノードに引き寄せられていることになります。これは ECMP セットにおいて最も深刻な障害モードであり、トラフィックがブラックホールに向けてロードシェアリングされます。

末尾の `[fe80:…]:80` は、リスナーがバインドされているインターフェースのリンクローカルアドレスです。

**わからないこと。** アップストリームの健全性については何もわかりません — リスナーは、その背後にあるものが到達可能かどうかに関わらず存在します。その確認には `envoy-clusters` を使用してください。

## `envoy-clusters`

すべてのクラスターを、優先度ごとの接続数およびリクエスト数の上限とともに表示します。

```bash
execcli envoy-clusters
```

```text file=../../../../_data/sitecli-envoy-clusters.txt
```

**確認すべき点。** 各行は `cluster::scope::key::value` の形式です。`observability_name` エントリが各クラスターを識別し、`default_priority::max_connections`、`max_pending_requests`、`max_requests` の 3 つがリクエスト上限の表示箇所です。クラスターが `max_pending_requests` に張り付いている場合、アップストリームではなく設定によってスロットリングされています。

## `envoy-config-dump`

Envoy の完全な設定を JSON 形式で表示します。アイドル状態のデモノードで 126 KB と大容量です。

```bash
execcli envoy-config-dump
```

```text file=../../../../_data/sitecli-envoy-config-dump.txt
```

**確認すべき点。** トップレベルの `configs` 配列には、設定タイプごとに 1 つのオブジェクト — ブートストラップ、クラスター、リスナー、ルート、シークレット — が含まれています。リスナーやクラスターは存在するが予期しない動作をしている場合にこのコマンドを使用し、全体を読むのではなく検索して活用してください。

## `envoy-hc-config-dump`

ヘルスチェック設定のみを表示します。

```bash
execcli envoy-hc-config-dump
```

```text file=../../../../_data/sitecli-envoy-hc-config-dump.txt
```

**確認すべき点。** このデプロイメントでは **1 バイト** のみが返されます — `curl` メーターでは `100 1` と表示されます — つまり、ヘルスチェック設定がインストールされていないことを意味します。これはヘルスチェック対象のオリジンプールを持たない CE における期待された状態であり、認識しておく価値があります。ここで空の結果が返ることは、クエリが失敗したことではありません。
