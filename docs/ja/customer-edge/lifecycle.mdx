Terraform の 2 つの変数が Customer Edge のソフトウェアを設定します。オペレーティングシステム用の `ce_os_version` と、F5 Distributed Cloud ビルド用の `ce_sw_version` です。どちらも直感的な読み方とは逆の動作をするため、誤って使用するとフリートの再構築というコストが発生します。

## バージョンフィールドの動作 — 2 つのフェーズ

フェーズを分けて理解することが本質です。混同すると、動作が自己矛盾しているように読めます。

**最初の起動時、ノードは必ずアップグレードされます。** `terraform/modules/ce-node` は `version = "latest"` でマーケットプレイスイメージをデプロイしますが、そのイメージにはテナントが実行しているものより**古い**ビルドが含まれています。そのため、フィールドを設定してもしなくてもアップグレードが発生します。`ce_sw_version` が選択するのは**目的地**のみです — 空のままにするとサーバーが選択するのであり、何も起きないわけではありません。`ce_os_version` も同様です。

**その後は、自動でアップグレードされることはありません。** F5 Distributed Cloud は新しいビルドを通知して待機します。フィールドが空の場合は「最新を追跡する」という意味にはなりません — ノードは最初に到達したバージョンに留まります。

どちらのフェーズもサイトオブジェクトで確認できます。`2026-07-28 観測時`、このフリートは：

```text
volterra_software_status.available_version   crt-20260201-0179
operating_system_status.available_version    9.2026.14
```

一方、ノードは `crt-20250613-3382` と OS `9.2024.6` を実行しています。新しいビルドが提供されているにもかかわらず適用されていない状態 — これは停滞したアップグレードではなく、定常状態です。

## バージョン変更には再構築が必要であり、Terraform は自動で行いません

`ce_os_version` と `ce_sw_version` はどちらも**作成時のみ**設定可能であり、失敗時の挙動は単なる apply の拒否より深刻です。順を追って説明します。

1. 値を変更して apply を実行します。Terraform はインプレース更新を提案します。
2. API がそれを**拒否**します — `[BAD_REQUEST] Invalid request parameters`。
3. その拒否されたリクエストがサーバー上のフィールドをクリアし、プロバイダーの読み取りではそれが報告されません。Terraform の状態が実際のオブジェクトと乖離します。
4. 以降のすべての plan が**同じ失敗する変更**を無限に提案し続けます。

つまり、Terraform はサイトの置き換えにフォールバックしません。スタックしたまま、サイトと CE 仮想マシンを意図的に置き換えるまでその状態が続きます。フリートを別バージョンに移行することは、apply で適用する編集ではなく、**計画的な再構築**です。

<Aside type="danger" title="CE を置き換える場合のすべての影響が生じます">
新しい SSH ホストキー、再割り当てされる内部アドレス、新規登録、そしてノード上にのみ存在していたものの消失が発生します。新しい VM で cloud-init が再実行されるため、その方法で設定された SSH アクセスは引き継がれます — ただし cloud-init は**最初の起動時のみ**実行されるため、古いノードに手動で追加したものはすべて消えます。

スケジュールを組む前に、ホストキーとアドレスへの影響について [SSH](./access/ssh/) を参照してください。
</Aside>

<Aside type="note" title="報告済み — 本ページでは再現していません">
この拒否と状態の乖離は、本リポジトリの `terraform/modules/xc-site` コメントに記録されています — ピン留めとピン留め解除の両方向で、3 つすべてのサイトで検証済みです — また、プロバイダーの Issue `xcsh#1387` にも記録されています。このページでは再テストを行っていません。テストを実行すると、デプロイメントがすべての plan で失敗する変更を提案し続ける状態になるためです。
</Aside>

## このドキュメントが説明するビルド

このサイトのコマンドリファレンスは、このフリートが実行している **`crt-20250613-3382`** を説明しています。新しいビルドでのみ確認されたコマンドは、`sitecli/command-classification.json` の `not_on_this_build` にその名称で記録されており、実行可能なものとしてはドキュメント化されていません。[オンボックスコマンド](./commands/on-box/) を参照してください。

<Aside type="caution" title="新しいコマンドに到達するために再構築を計画しないでください">
新しいビルドが提供されていますが、このトポロジーにクリーンにインストールできるかどうかは未確定です — シングルノードの Azure Secure Mesh v2 サイトで失敗したという報告と、Customer Edge がそれを実行しているという反対の観測結果があります。テナントに残っているものからどちらも確認することはできません。

バージョン変更はフリートの再構築を意味するため、この不確実性が判断の根拠となります。それらのコマンドへの到達は、予定されたアップグレードではなく、未実証として扱ってください。エビデンスと検証のための実験は `sitecli/README.md` に記録されています。
</Aside>
