すべての Customer Edge は F5 のサイトコンソールを `https://<sli-ip>:65500` で提供しています。この
デプロイメントでは、通常これが最初に試すべき経路です。

要求されるものが最も少ない方法です。配布する SSH キーも、維持するジャンプホストも、ノード上の
パブリック IP も、有効化のための VM 置き換えも不要です。誰が接続できるかは **Azure RBAC の
判断** になります。さらに、サイトが登録済みである必要もありません。このページは 3 つのサイトすべてが
`site_state: FAILED` を報告している状態で最初に取得され、同じノードが `ONLINE` になった後に
変更なしで再検証されました。

問題は、サイトコンソールがノードの内部 (SLI) アドレスでのみ応答し、それは VNet 内部からのみ
到達可能だという点です。Azure Bastion は、ネットワーク上に他の何も配置することなく
そのギャップを埋めます。

<Aside type="note" title="ここで検証されていること、されていないこと">
このページのすべてのコマンドとすべての出力は、このデプロイメントの `f5-xc-ce-vm-01` に対して
実行され、失敗も含めて逐語的に再現されています。

**認証は検証済みです**: アプライアンスの `admin` 認証情報はトンネル経由で `200` を返します。
*検証されていない* のはコンソールそのものです。以下のいずれも、内部に入った後に何が見えるか、
何ができるかについては説明していません。

**Azure RBAC は検証されていません。** すべての実行はサブスクリプション所有者として行われたため、
ステップ 2 の Reader 要件はここで計測されたものではなく、Microsoft の文書化された要件です。
</Aside>

<Aside type="caution" title="Bastion はオプトインであり、デフォルトではデプロイされません">
`enable_bastion` のデフォルトは `false` であるため、デフォルトの `terraform apply` では Bastion
ホストは存在せず、`terraform output -raw bastion_name` は `null` になります。
`terraform/terraform.tfvars` で `enable_bastion = true` を設定してください。このデプロイメントでは `true` です。

オプトインである理由はリスクではなくコストです。Standard SKU のホストは、プロビジョニングされた
時点から誰かがトンネルを開くかどうかに関わらず時間単位の固定料金が課されます。`eastus` では
含まれる 2 つのスケールユニットで 1 時間あたり 0.29 米ドル (小売価格、2026-07)、月あたり約 212 米ドルです。
デモがコンソールアクセスを必要としないときは、再度オフにしてください。
</Aside>

## 開始する前に

<Steps>

1. Azure にサインインし、Bastion 拡張機能を追加します。トンネリングはネイティブクライアントの
   機能であり、拡張機能はデフォルトではインストールされていません。

   ```bash
   az login
   az extension add --name bastion
   ```

2. CE 仮想マシン、そのネットワークインターフェイス、および Bastion ホストに対して **Reader** を
   保持してください。これは Microsoft の文書化された要件であり、**ここでは検証されていません**。
   このデプロイメントでのすべての実行はサブスクリプション所有者として行われたため、それより
   低い権限のロールが十分であるか不十分であるかは示されていません。

3. Bastion がデプロイされ、機能を備えていることを確認します。Basic SKU はトンネリングも
   IP ベースの接続もサポートしないため、ここでの `Standard` と `True` はいずれも重要です。

   ```bash
   az network bastion list -g rg-mcn-ce-ha-rmordasiewicz \
     --query "[].{name:name, sku:sku.name, tunneling:enableTunneling}" -o table
   ```

   ```text
   Name               Sku       Tunneling
   -----------------  --------  -----------
   ce-ha-lab-bastion  Standard  True
   ```

</Steps>

## トンネルを開く

値は入力するのではなく `terraform output` から取得してください。リソース ID は手作業で
組み立てるようなものではありません。

<Steps>

1. Bastion ホストの名前、リソースグループ、対象 CE の VM リソース ID を読み取ります。

   ```bash
   cd terraform
   BASTION=$(terraform output -raw bastion_name)
   RG=$(terraform output -raw resource_group_name)
   VM_ID=$(terraform output -json ce_vm_ids | jq -r '.eastus01')
   ```

   ```text
   ce-ha-lab-bastion
   rg-mcn-ce-ha-rmordasiewicz
   /subscriptions/…/providers/Microsoft.Compute/virtualMachines/f5-xc-ce-vm-01
   ```

   <Aside type="caution" title="マップのキーはサイト名であり、VM 名ではありません">
   `ce_vm_ids` のキーは `eastus01`、`eastus02`、`eastus03` であり、**VM 名ではありません**。
   `jq -r '."f5-xc-ce-vm-01"'` のようなフィルターは `null` を返し、その結果トンネルは空の
   リソース ID で失敗します。不明な場合は一覧表示してください。

   ```bash
   terraform output -json ce_vm_ids | jq -r 'keys | join(", ")'
   ```

   ```text
   eastus01, eastus02, eastus03
   ```

   </Aside>

2. トンネルを開始します。停止するまでポートを開いたままにするため、バックグラウンドで実行するか、
   2 つ目のターミナルを使用してください。

   ```bash
   az network bastion tunnel \
     --name "$BASTION" \
     --resource-group "$RG" \
     --target-resource-id "$VM_ID" \
     --resource-port 65500 \
     --port 65500 &
   ```

   ```text
   WARNING: Opening tunnel on port: 65500
   WARNING: Tunnel is ready, connect on port 65500
   WARNING: Ctrl + C to close
   ```

   3 行すべてに `WARNING:` が前置されています。これは Azure CLI が進行状況を stderr に
   書き出しているだけで、問題ではありません。接続する前に `Tunnel is ready` を待ってください。

3. リスナーがローカルのループバック上にあることを確認します。

   ```bash
   lsof -nP -iTCP:65500 -sTCP:LISTEN
   ```

   ```text
   COMMAND   PID  USER  FD  TYPE  DEVICE  SIZE/OFF  NODE  NAME
   Python  41648  you   7u  IPv4  …            0t0   TCP  127.0.0.1:65500 (LISTEN)
   ```

4. コンソールを開きます。トンネルによりローカル扱いになるため、アドレスはノードのアドレスではなく
   `localhost` です。

   ```bash
   open https://localhost:65500/          # macOS
   xdg-open https://localhost:65500/      # Linux
   ```

5. 終了したらトンネルを停止してください。`Ctrl-C`、またはバックグラウンド実行した場合は `kill %1` です。
   開いたままにしておくと、ローカルポート 65500 と Bastion セッションが保持されます。

</Steps>

## 表示される内容

**ログインページではなく、認証情報のダイアログです。** コンソールは HTTP Basic 認証を使用するため、
ブラウザが独自のユーザー名とパスワードのプロンプトを表示します。見るべきフォームはありません。

```bash
curl -skI https://localhost:65500/
```

```text
HTTP/1.1 401 Unauthorized
WWW-Authenticate: Basic realm="Volterra Site Console"
Content-Type: text/html; charset=utf-8
Content-Length: 0
```

そのレルムを伴う `401` は、コンソールが正しく動作していることを示します。認証されていない
リクエストが受け取るべき結果です。そして同じ URL に `admin` 認証情報を指定すると `200` が
返り、これがブラウザを開く前に認証情報を確認する方法です。

```bash
curl -sk -u admin -o /dev/null -w '%{http_code}\n' https://localhost:65500/
```

```text
Enter host password for user 'admin':
200
```

コロンなしの `-u admin` は、`curl` にコマンドラインからパスワードを取得させるのではなく
プロンプトを表示させます。コマンドラインではシェル履歴やプロセス一覧に残ってしまいます。

**証明書の警告が、同時に 3 つの理由で表示されます。** 証明書を直接確認します。

```bash
openssl s_client -connect localhost:65500 -servername localhost </dev/null 2>/dev/null \
  | openssl x509 -noout -subject -issuer -dates
```

```text
subject=C=US, ST=California, L=Santa Clara, O=Volterra, OU=Volterra Edge Services, CN=site-local.volterra.io
issuer=C=US, ST=California, L=Santa Clara, O=Volterra, OU=Volterra Edge Services, CN=site-local.volterra.io
notBefore=Oct 25 04:51:31 2024 GMT
notAfter=Oct 25 04:51:31 2025 GMT
```

サブジェクトと発行者が同一であるため、自己署名証明書です。名前は `site-local.volterra.io` ですが
接続先は `localhost` なので一致しません。さらに、このデプロイメントが実行しているビルドでは
**証明書は 2025 年 10 月 25 日に期限切れになっています**。アプライアンスがそれを同梱しており、
このリポジトリ内には更新するものはありません。

無遠慮なブラウザ警告を予期し、毎回表示されることも予期してください。上記のサブジェクト行が
有用な部分です。ローカルポート 65500 で待ち受けている別のものではなく、アプライアンスに到達した
ことを確認する手段になります。

## admin 認証情報

`admin` としてサインインします。**このドキュメントはパスワードを公開しておらず、公開すべきでもありません。**

<Aside type="danger" title="このデプロイメントでは、そのパスワードは今も F5 の工場出荷時デフォルトです">
これは疑いではなく計測された事実です。工場出荷時デフォルトの認証情報は現時点で 3 つの CE すべてで
認証に成功し、`200` を返します。F5 はそのデフォルトを公開し、変更することを要求していますが、
変更されていません。

実際上の帰結として、このデプロイメントでは「Bastion に Reader を保持している」ことは、F5 の
公開ドキュメントに載っている値を知っている人にとって、アプライアンスコンソールへの完全な
アクセスと同等です。これを変更し、変更することを後からのハードニングではなくノードの
デプロイの一部として扱ってください。
</Aside>

ここで公開しないことが見た目以上に重要な理由が 2 つあります。

- このドキュメントは公開されています。フリート現行のコンソールパスワードを掲載すれば、
  「Bastion に Reader を保持している」ことが、このページを読む誰にとってもアプライアンスへの
  完全なアクセスに変わってしまいます。
- ドキュメントに公開されたパスワードは、誰かがローテーションした瞬間に誤りとなり、しかも最も
  誤解を招く形で誤りになります。読者は、ページが古いのではなく自分のアクセスが壊れていると
  結論づけてしまいます。

ローテーション後は、チームが運用上のシークレットを保管している場所から取得してください。

<Aside type="caution" title="Terraform からのパスワード設定は検証されていません">
サイトオブジェクトの `admin_user_credentials.admin_password` は、これを宣言的に設定する方法の
ように見えます。しかし、このビルドでサイトコンソールに反映されることは**確認されていません**ので、
そうであると想定しないでください。

[SSH のページ](../ssh/)をどちらの証拠としても読まないでください。`admin_password` が
「何も変わらなかった」というその知見は SSH 認証に対して計測されたものであり、`vpm` は `admin`
ユーザーについては SSH 認証を完全にスキップします。これはコンソールについて何も述べていません。
</Aside>

## トンネルがリソース ID を対象としなければならない理由

`--target-resource-id` は必須です。代わりにノードのアドレスを指定すると拒否されます。どの
アドレスを使っても同様なので、ここでは意図的に実際のアドレスを掲載していません。

```bash
az network bastion tunnel --name "$BASTION" -g "$RG" \
  --target-ip-address <any-sli-address> --resource-port 65500 --port 65501
```

```text
ERROR: Custom ports are not allowed. Allowed ports for Tunnel with IP connect is 22, 3389.
```

理由は IP ベースの接続が無効になっているからでは**ありません**。この Bastion では
`ip_connect_enabled` は `true` です。Microsoft はその設定に関わらず、IP ベースの
ネイティブクライアント接続でのカスタムポートをサポートしておらず
([Azure ドキュメント](https://learn.microsoft.com/azure/bastion/connect-ip-address))、65500 は
カスタムポートです。ここで Bastion の構成を調べても何も得られません。リソース ID を使用してください。

## うまくいかない場合

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| `ERROR: Custom ports are not allowed. Allowed ports for Tunnel with IP connect is 22, 3389.` | `--target-ip-address` を使用した | `--target-resource-id` を使用する |
| `ERROR: Defined port is currently unavailable` | 別のトンネルがそのローカルポートを既に保持している | 他のトンネルを停止する、または別の `--port` を指定する。`--resource-port` は 65500 のまま |
| `terraform output -raw bastion_name` が `null` または空 | Bastion がデプロイされていない | `enable_bastion = true` を設定して apply する |
| トンネルは開始するがリソース ID が空 | `jq` フィルターがサイトキーではなく VM 名を使用した | `eastus01`/`02`/`03` をキーにする |
| `401 Unauthorized`、レルム `Volterra Site Console` | 障害ではない。認証されていないリクエスト | `admin` 認証情報を指定する |
| ブラウザが証明書を拒否する | 自己署名、名前の不一致、2025 年 10 月以降期限切れ | 想定どおり。サブジェクトが `CN=site-local.volterra.io` であることを確認して続行する |

<Aside type="note" title="認可の失敗は再現されていません">
RBAC の不足はこれが失敗するもう一つの明白な要因ですが、再現するには共有デプロイメントから
ロール割り当てを削除する必要があるため、逐語的なエラーとともにここには記載していません。
トンネルが開始時に認可エラーで失敗する場合は、VM、その NIC、Bastion ホストの 3 つすべてで
Reader を確認してください。
</Aside>
