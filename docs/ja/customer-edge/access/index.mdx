使用可能なルートは4つあり、どのルートを適用するかは、好みではなく、ノードの状態、接続元、およびアクセスする必要があるものによって決まります。

| ルート | ノードが `ONLINE` である必要 | ネットワーク到達性が必要 | 制限事項 | 対象範囲 |
| --- | --- | --- | --- | --- |
| [デバッグ API](./debug-api/) | **はい** | あり | 新しいサイトでは約25〜30分のウォームアップが必要 | 34コマンド |
| [サイトコンソール](./site-console/) | いいえ | Azure Bastion 経由（ジャンプホスト不要） | Bastion はトンネリング対応の Standard SKU が必要 | F5 のノードトラブルシューティング UI |
| [SSH](./ssh/) | いいえ | VNet 内部から内部アドレスへのみ | キーは初回起動時に存在している必要あり | オンボックスサイト CLI の全機能 |
| [シリアルコンソール](./serial-console/) | いいえ | なし | VM あたり1セッション、貼り付けは2,048文字まで | オンボックスサイト CLI の全機能 |

シリアルコンソールは最終手段であり、ネットワークパスが機能していないノードでも使用できる唯一のルートです。

[サイトコンソール](./site-console/)は、通常最初に試すべきルートです。配布すべき SSH キーも、ジャンプホストも、ノード上のパブリック IP も、VM の交換も必要ありません。アクセスが資格情報の配布問題ではなく、Azure RBAC の決定となるため、最も手間がかかりません。特定のコマンドを実行したり、スクリプトを実行したりする必要がある場合は、コマンドサーフェスではなく F5 独自のトラブルシューティング UI が提供されるため、その場合はこのルートを超えて別のルートを利用してください。

SSH は、デバッグ API では不十分な場合に選択するルートです。アプライアンスは、API が公開している34コマンドよりも大幅に多くのコマンドを提供しているためです。ただし、2つのコストがあります。キーは cloud-init によって書き込まれるため、**初回起動時**に存在している必要があります。つまり、稼働中のノードでこれを有効にするとノードが交換されますが、これにより現在登録がウェッジ状態になります（[issue 674](https://github.com/f5-sales-demo/mcn/issues/674)）。また、`sshd` はノードの内部アドレスでのみ応答するため、VNet 内のホストが必要です。ノードとして把握しているアドレスを調べても、常にクローズと報告されます。

## 分割がユーザーの好みではない理由

デバッグ API は F5 Distributed Cloud コントロールプレーンによって提供され、登録時に `vpm` が確立するトンネルを経由してノードにリレーされます。登録がなければトンネルもなく、API がリレーする先もありません。

この場合、明確なエラーではなく、役に立たない方法で失敗するため、起動しなかったノードが API の問題のように見えてしまいます。

シリアルコンソールはまったく逆の方向を取ります。Azure プラットフォームを経由してノードのエミュレートされたシリアルポートに接続します。ノードが登録済みかどうか、ネットワーク到達性があるかどうか、データプレーンが機能しているかどうかを気にしません。この独立性こそが重要であり、CE VM でブートダイアグノスティクスを有効にしておく必要がある理由です。

<Aside type="note" title="選択すべきルート">
自動化を記述する場合、または後で再実行したい証拠を収集する場合は、デバッグ API を使用してください。登録が壊れている場合、シリアルコンソールはフォールバックではなく、唯一の選択肢です。
</Aside>

## 認証情報

各ルートはそれぞれ異なる認証情報を使用し、いずれもコマンドラインに記述すべきではありません。

- **デバッグ API** — `XCSH_API_TOKEN` として F5 Distributed Cloud API トークン、`XCSH_API_URL` としてテナント URL を使用します。`~/.config/xcsh/contexts/<tenant>.json` にある `xcsh` コンテキストファイルに両方が保存されており、環境変数で指定されていない場合は `scripts/capture-sitecli.sh` がここから読み取ります。
- **SSH** — デプロイメントが初回起動時に `/var/home/admin/.ssh/authorized_keys` に書き込んだ公開鍵に対応する秘密鍵と、内部アドレスに到達するための VNet 内のホストが必要です。`azureuser` ではなく `admin` として接続してください。
- **シリアルコンソール** — インタラクティブな Azure ログインを使用します。サービスプリンシパルはありません。F5 の企業 Entra テナントではサービスプリンシパルのプロビジョニングが許可されていないため、この処理は CI では実行されません。

<Aside type="danger" title="トークンを引数として渡さないでください">
コマンドラインにトークンを記述すると、シェル履歴やプロセスリストに残り、そのマシン上の他のすべてのユーザーに読み取られる可能性があります。`capture-sitecli.sh` はその理由から `--token` を完全に拒否し、代わりに `curl` に stdin 経由でヘッダーを提供します。
</Aside>
