Customer Edge（CE）是本仓库部署到 Azure 的 F5 Distributed Cloud 节点——`terraform/modules/ce-node`，基于
`volterraedgeservices/volterra-node` 市场镜像构建。

它运行数据平面（Argo）、控制平面（Vega）、Envoy 代理、Kubernetes
堆栈，以及 `vpm`——负责注册节点并管理其上所有其他组件的代理程序。

当 CE 出现异常时，Site CLI 是诊断工具。首要决策是确定适用哪种访问路径，选错路径会以一种看似节点故障的方式浪费大量时间。

## 两种访问路径，且不可互换

<CardGrid>
  <LinkCard
    title="Debug API"
    description="适用于状态为 <code>ONLINE</code> 的节点。可脚本化、只读，涵盖 34 条命令。"
    href="./access/debug-api/"
  />
  <LinkCard
    title="串行控制台"
    description="适用于从未完成注册的节点。当 API 无法响应时，这是唯一的访问途径。"
    href="./access/serial-console/"
  />
</CardGrid>

Debug API **通过 F5 Distributed Cloud 控制平面**访问节点。
这正是区分两种路径的根本原因：API 只有在节点完成注册并报告 `ONLINE` 状态后才能响应。

注册失败的节点——cloud-init 配置错误、令牌过期、无法路由到
`register.ves.volterra.io`——恰恰是需要诊断的场景，也恰恰是 API 无法提供服务的场景。

此外，节点在出厂配置中拒绝 SSH 连接。端口 22 在 CE 本身上已关闭，而非由网络安全组拦截：

```console
$ ssh -o ConnectTimeout=10 admin@<ce-public-ip>
ssh: connect to host <ce-public-ip> port 22: Connection refused
```

已从 VNet 内部通过同一子网上的跳板机进行验证，因此开放安全组规则并不会改变此行为。

因此：如果站点处于 `ONLINE` 状态，请使用 Debug API；如果不是，串行控制台是唯一的访问方式。

<Aside type="caution" title="请先检查站点状态">
一次请求即可告知您适用哪条路径：

```bash
curl -sS -H "Authorization: APIToken $XCSH_API_TOKEN" \
  "$XCSH_API_URL/api/config/namespaces/system/sites/<site>" \
  | jq -r '.spec.site_state'
```

`ONLINE` 表示 Debug API 可用。其他任何状态——或站点不存在——则意味着需要使用串行控制台。
</Aside>

## 安全规则

以下规则适用于下方每个页面上的所有命令。

- **除非确定安全，否则保持只读。** 命令集分为两个权限层级，`Exec` 层级的命令要么会改变节点状态，要么读取状态标记。本文档中的所有页面均不执行 `Exec` 命令，抓包工具集也不例外。
- **切勿仅凭名称判断命令是否安全。** `ip-link-set` 看起来像查询命令，实际上会使网络接口下线；`systemctl-restart-crio` 会在实时数据平面运行期间重启容器运行时。
- **优先使用能回答问题的最小范围命令。** `health` 和 `diagnosis` 以低开销对节点进行汇总；`flow-l` 则会转储包含 629,760 条目的流表。
- **CE 承载实时流量。** 这些是共享的演示环境。请假设有人正在从您调试的站点进行演示。

## 本文档的内容范围

本文档涵盖该租户所运行软件版本中，可通过 Debug API 访问的所有命令，每条命令的输出均来自实际节点的抓取，而非转录自其他来源。

[命令参考](./commands/)列出了所有命令及其类别、权限层级和传输方式；[工作流](./workflows/)将这些命令串联成在实际出现问题时所使用的操作序列。

Site CLI 中仅可在节点本机操作的部分——`configure`、`configure-network`、
`factory-reset`、`upgrade` 以及大约六十余条 `ExecCLI` 命令——不在本文档覆盖范围内。

这些命令只能在串行控制台会话中访问，因此无法通过程序化方式进行验证，而未经验证的命令语法正是本文档致力于避免重蹈的缺陷。
