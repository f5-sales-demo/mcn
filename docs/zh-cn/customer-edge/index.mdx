Customer Edge（CE）是本仓库向 Azure 预配的 F5 Distributed Cloud 节点 —— 位于
`terraform/modules/ce-node`，基于
`volterraedgeservices/volterra-node` 市场镜像构建。

它运行数据平面（Argo）、控制平面（Vega）、一个 Envoy 代理、一套 Kubernetes
栈，以及 `vpm` —— 负责注册节点并管理节点上其他一切的代理。

当 CE 出现异常时，Site CLI 就是诊断工具。第一个决策是确定适用哪条访问路径，
选错会浪费时间，而且表现出来就像节点坏了一样。

## 两条访问路径，且不可互换

调试 API **通过 F5 Distributed Cloud 控制平面**访问节点。
这正是区分二者的全部原因：只有当节点已完成注册并报告 `ONLINE` 时，API 才能响应。

注册失败的节点 —— cloud-init 有误、令牌过期、无法路由到
`register.ves.volterra.io` —— 恰恰是你最需要诊断的情况，
也恰恰是 API 无法提供服务的情况。

SSH 不是第三种选择。`sshd` 在节点上运行并在其内部（SLI）地址上响应，
但 `admin` 账户无法通过认证：`vpm` 会跳过该用户，因此你在站点对象上配置的
`ssh_key` 永远不会被应用。没有任何安全组规则能改变这一点。证据见
[SSH](./access/ssh/) 页面 —— 该页面之所以存在，是因为其中的每一种症状
看起来都像是防火墙或凭据故障。

所以：如果站点是 `ONLINE`，使用调试 API。如果不是，串行控制台是唯一的入口。

<Aside type="caution" title="先检查站点状态">
一个请求就能告诉你该走哪条路径：

```bash
curl -sS -H "Authorization: APIToken $XCSH_API_TOKEN" \
  "$XCSH_API_URL/api/config/namespaces/system/sites/<site>" \
  | jq -r '.spec.site_state'
```

`ONLINE` 表示调试 API 可用。其他任何状态 —— 或者站点根本不存在 ——
都意味着要用串行控制台。
</Aside>

## 安全规则

以下规则适用于下文各页面中的每一条命令。

- **除非你完全确定，否则只做只读操作。** 命令面被划分为两个权限层级，
  而 `Exec` 层级要么会修改节点，要么会读取某个状态标记。这些页面上不运行
  任何 `Exec` 命令，采集工具链也不会。
- **切勿仅凭命令名称就假定它是安全的。** `ip-link-set` 读起来像是查询，
  实际上会关闭某个接口。`systemctl-restart-crio` 会在数据平面处于运行状态时
  重启容器运行时。
- **优先选择能回答问题的最小范围命令。** `health` 和
  `diagnosis` 能以很低的代价概览节点状态；而 `flow-l` 会导出一张
  629,760 条目的流表。
- **CE 承载实时流量。** 这些是共享的演示环境。请假定有人正在使用
  你正在调试的站点进行演示。

## 本文档涵盖的内容

本租户所运行软件版本上，通过调试 API 可访问的每一条命令，
每条命令的输出均从实际运行的节点上采集，而非从其他来源转录。

[命令参考](./commands/)列出了全部命令及其类别、权限层级和传输方式；
[工作流](./workflows/)则将它们串联成出现问题时你实际会用到的操作序列。

Site CLI 中仅限本机使用的部分 —— `configure`、`configure-network`、
`factory-reset`、`upgrade` 以及大约六十条其他 `ExecCLI` 命令 —— 未在此涵盖。

它们只能通过串行控制台会话访问，因此无法以编程方式验证其任何信息，
而未经验证的命令语法正是本文档意在避免重复出现的缺陷。
