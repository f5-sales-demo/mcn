客户边缘节点（Customer Edge，CE）是本仓库向 Azure 预配的 F5 Distributed Cloud 节点 ——
`terraform/modules/ce-node`，基于 `volterraedgeservices/volterra-node` 市场镜像构建。

它运行数据平面（Argo）、控制平面（Vega）、一个 Envoy 代理、一套 Kubernetes
栈，以及 `vpm` —— 负责注册节点并管理节点上其他一切内容的代理。

当 CE 出现异常时，Site CLI 就是诊断工具。首先要判断适用哪条访问路径，
一旦判断错误就会浪费时间，而且表现得就像节点已经损坏一样。

## 两条访问路径，且不可互换

  <LinkCard
    title="Serial console"

  />
</CardGrid>

调试 API **通过 F5 Distributed Cloud 控制平面**访问节点。
这正是这一区分之所以重要的原因：只有在节点完成注册并报告 `ONLINE` 之后，API 才能作出响应。

注册失败的节点 —— 错误的 cloud-init、过期的令牌、无法路由到
`register.ves.volterra.io` —— 恰恰是最需要诊断的情况，
也恰恰是 API 无法提供服务的情况。

[SSH](./access/ssh/) 是第三种选择，也是唯一能够触及设备完整命令面的方式 —— 调试 API 暴露 34 条命令，
而节点本身提供的远不止于此。有两点限制。`sshd` 仅在节点的内部（SLI）地址上响应，
因此需要一台位于 VNet 内部的主机；而密钥是由 cloud-init 在首次启动时写入的，
因为站点对象上的 `ssh_key` 字段是无效的 —— `vpm` 会跳过 `admin` 用户，
从不应用该字段。因此，要在运行中的节点上启用它就意味着替换这些节点。

所以：如果站点处于 `ONLINE` 且 34 条命令已经够用，就使用调试 API。如果你需要其余的命令面
并且能够访问 VNet，就使用 SSH。如果问题出在注册环节，串行控制台就是唯一的入口。

<Aside type="caution" title="首先检查站点状态">
一个请求即可告诉你应该走哪条路径：

```bash
curl -sS -H "Authorization: APIToken $XCSH_API_TOKEN" \
  "$XCSH_API_URL/api/config/namespaces/system/sites/<site>" \
  | jq -r '.spec.site_state'
```

`ONLINE` 意味着调试 API 可用。其他任何状态 —— 或者站点根本不存在 ——
都意味着需要使用串行控制台。
</Aside>

## 安全规则

以下规则适用于下方各页面中的每一条命令。

- **除非你确有把握，否则只做只读操作。** 命令面被划分为两个权限层级，
  而 `Exec` 层级要么会改动节点，要么会读取状态标记。本文档各页面不会运行任何
  `Exec` 命令，采集工具也不会。
- **切勿凭命令名称假定其安全。** `ip-link-set` 读起来像是一条查询命令，
  实际上会关闭某个接口。`systemctl-restart-crio` 会在数据平面处于运行状态时
  重启容器运行时。
- **优先选择能回答问题的最小范围命令。** `health` 和 `diagnosis`
  能以很低的开销概括节点状态；而 `flow-l` 会导出一张包含 629,760 条目的流表。
- **CE 承载着实时流量。** 这些是共享的演示环境。请假定有人正在使用
  你正在调试的站点做演示。

## 本文档涵盖的内容

本租户所运行的软件版本上，可通过调试 API 访问的每一条命令，
其输出均从实际运行的节点上采集，而非从别处转录而来。

[命令参考](./commands/)列出了所有命令及其类别、权限层级和传输方式；
[工作流](./workflows/)将它们串联成你在出现问题时实际使用的操作序列。

Site CLI 中仅限本机使用的部分 —— `configure`、`configure-network`、
`factory-reset`、`upgrade` 以及大约六十条其他 `ExecCLI` 命令 —— 未被涵盖，
因为它们的输出没有像下方每个页面那样从实际运行的节点上采集过。

不过，它们已不再遥不可及。`scripts/sitecli_ssh_harvest.py` 通过 [SSH](./access/ssh/) 驱动
设备自身的补全菜单，并记录设备为每条命令给出的描述，从而使这一命令面可以被实际测量而非
凭空猜测。它的执行默认拒绝 —— 它会枚举全部内容，但只运行白名单中的命令 ——
因为未经验证的命令语法以及未经验证的命令*效果*，正是本文档存在的意义所在：避免重蹈覆辙。
