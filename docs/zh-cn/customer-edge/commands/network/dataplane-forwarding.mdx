Argo 将转发状态与 Linux 内核分开维护。当
[`ip`](../ip/) 命令与以下命令的结果不一致时，以下命令所呈现的内容才是实际流量转发的依据。

## `rt`

vRouter 路由表，按 VRF 划分。

```bash
{"command":["rt","--dump","2"]}
```

```text file=../../../../_data/sitecli-rt.txt
```

<Aside type="danger" title="VRF id 并非 BGP 报告的那个">
`show-ip-bgp-summary` 打印的是 `vrf-id 3`，这是 FRR 的编号，与 vRouter 表 id 属于不同的命名空间。将其传入此处会导致失败，表现为节点异常：

```
vRouter(Response):  [No such file or directory (2)]
```

`--dump 0` 也会返回相同的错误。在此拓扑中，**VRF 2** 是已填充的 inet4 表，VRF 1 持有两条路由。如果不确定 id，请从 1 开始逐步向上探测，而不要轻信 BGP 的输出结果。
</Aside>

## `nh`

下一跳表。每条路由都指向一个下一跳 id，该表用于对其进行解析。

```bash
{"command":["nh","--list"]}
```

```text file=../../../../_data/sitecli-nh.txt
```

每个条目包含一个 `Type` 字段——`Drop`、`Encap`、`Tunnel`、`Composite`——以及该条目所属的 VRF。解析到 `Drop` 下一跳的路由即为黑洞路由。当某个前缀存在于 `rt` 中但流量仍然消失时，应重点排查这种组合。

## `vif`

虚拟接口表：数据平面绑定的接口及各接口的计数器。

```bash
{"command":["vif","--list"]}
```

```text file=../../../../_data/sitecli-vif.txt
```

顶部的标志说明值得仔细阅读——`Vp` 标记 vhost 物理接口，`Dpdk` 标记由 DPDK 管理的接口。使用此命令可确认数据平面已接管预期的接口，并查看 Linux 不会显示的 RX 和 TX 计数器（因为相关流量从未到达内核）。
