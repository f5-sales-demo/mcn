两条命令，而它们之间的区别就是全部价值所在。

## `curl-host`

在主机网络命名空间中运行 —— 即节点自身的连通性，尚未涉及数据平面。

```bash
{"command":["curl-host","-v","cloud.f5.com"]}
```

```text file=../../../../_data/sitecli-curl-host.txt
```

## `curl-vega`

在 Vega（控制平面）上下文中运行，而非主机上下文。可观察到的差异，也是此处唯一确定的差异，是它所继承的环境：`curl-vega` 报告的 `NO_PROXY` 列表涵盖了各私有地址段、`int.ves.io`、`int.volterra.us` 以及站点自身的 `.tenant.local` 域，而 `curl-host` 则不报告任何内容。这对 DNS 路径意味着什么，并未经过实测。

```bash
{"command":["curl-vega","-v","cloud.f5.com"]}
```

```text file=../../../../_data/sitecli-curl-vega.txt
```

<Aside type="tip" title="这一对命令构成一次二分定位">
两者都运行。如果 `curl-host` 成功而 `curl-vega` 失败，说明节点具备连通性，而控制平面上下文中的某些东西不具备 —— 可能是其代理设置或其解析器。如果两者都失败，问题出在节点上游：路由、防火墙或出口路径。如果只有 `curl-host` 失败，你遇到了不寻常的情况，应先检查主机路由表。

在健康的节点上两者都会成功并到达同一地址，因此一对干净的结果无法证明当前正在使用哪个上下文 —— 承载信息的是二者之间的*差异*。
</Aside>

两者都接受作为独立数组元素传入的常规 `curl` 参数。值得保留 `-v`，因为连接与 TLS 握手相关的输出行通常正是故障显现之处。
