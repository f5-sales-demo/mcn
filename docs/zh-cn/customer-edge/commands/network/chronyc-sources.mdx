```

```

`MS` 列是**两个**字符，而不是一个。第一个字符表示模式 —— `^` 代表服务器 ——
**第二个**字符表示状态：`*` 表示当前选中的源，`+` 表示可接受的备选源，
`-` 表示被选择算法排除的源，`?` 表示不可达的源。
因此 `^*` 是被选中的服务器，`^?` 是不可达的服务器；只读第一个字符什么也说明不了，
因为这里每一行的第一个字符都是 `^`。

恰好有一个 `*` 就是健康状态，即使其他源显示为 `?` 也依然成立。

`Reach` 是最近八次轮询的八进制寄存器值，因此 `377` 表示八次全部成功。
低于该值意味着最近八次中至少有一次未成功 —— 但这也包括刚开始响应不久的源，
其寄存器仍在填充过程中。撰写本文时的一次实测显示，在某个节点上出现了 `3` 和 `37`，
同时还有一个 `377`，该节点已选中一个源（`^*`），且其登录横幅报告 `NTP: Synced`。
请将 `Reach` 与 `LastRx`（显示该源上次响应距今多久）结合起来看，
而不要把任何低于 `377` 的值都视为故障。

当认证或 TLS 无缘无故失败时，值得尽早检查这一项：时钟漂移过大的节点
会拒绝有效证书，其令牌也会被拒绝，而由此产生的错误信息很少会提及时间问题。
