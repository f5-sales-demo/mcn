Argo 会跟踪每一条连接。查询该表的方式比表中包含的内容更重要，
因为完整转储在原理上是无界的，在实践中也很不方便。

<Aside type="caution" title="629,760 是该表的容量，而不是流的数量">
标题行 `Flow table(size 161218560, entries 629760)` 报告的是数据平面分配的槽位数量，
无论负载如何，此处每个节点上的该值都是相同的。实时流数量并不在该行中。
其下几行的 `Entries: Created … Added … Deleted …` 是生命周期计数器，而实际已填充的流是
图例之后打印的那些记录 —— 在撰写本文时执行的一次运行中共有 73 条，响应总计 542 行。
</Aside>

## `flow-l-match`

几乎总是你想要使用的命令。接受一个地址，或者一个地址加端口。

```bash
{"command":["flow-l-match","100.127.192.10:53"]}
```

```text file=../../../../_data/sitecli-flow-l-match.txt
```

每条流上的动作才是重点：`F` 转发，`D` 丢弃，`N` NAT。若某条流存在且动作为 `D`，
说明数据平面做出了有意的决策，这会将你的排查方向引向策略而非连通性。

```bash
{"command":["flow-l"]}
```

上面的采集内容是从一份 1,186 行的响应中截取的前 60 行。撰写本文时的一次运行返回了 542 行 ——
响应长度取决于有多少条流处于活跃状态，因此这两个数字都不是该命令的固有属性。除非你确实需要
查看整张表，否则请使用 `flow-l-match`。
</Aside>
