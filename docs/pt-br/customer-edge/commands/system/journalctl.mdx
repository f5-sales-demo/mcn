## `journalctl`

```bash
{"command":["journalctl","-u","vpm","-n","200"]}
```

Argumentos padrão do `journalctl`, cada um como um elemento separado do array. `-u vpm` é o que
você mais precisará: `vpm` é o agente que registra o nó e gerencia
tudo mais nele, portanto seu journal é onde as falhas de registro aparecem com
timestamps e entre reinicializações.

Variantes úteis:

| Argumentos | Respostas |
| --- | --- |
| `-u vpm -n 200` | O que o vpm esteve fazendo recentemente |
| `-u vpm --since "10 min ago"` | O que aconteceu enquanto eu reproduzia o problema |
| `-p err -n 100` | Erros de todas as unidades |
| `-u kubelet -n 200` | Por que a stack do Kubernetes está com problemas |

Prefira este em vez de [`docker-logs vpm`](../docker/) quando precisar de timestamps, quiser
abranger uma reinicialização ou quiser correlacionar o vpm com outra unidade.
