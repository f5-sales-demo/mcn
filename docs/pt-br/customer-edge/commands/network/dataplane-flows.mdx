O Argo rastreia cada conexão. A forma como você consulta a tabela importa mais do que o seu conteúdo,
porque o dump completo é ilimitado em princípio e incômodo na prática.

<Aside type="caution" title="629.760 é a capacidade da tabela, não o número de fluxos">
A linha de cabeçalho `Flow table(size 161218560, entries 629760)` informa quantos slots o plano
de dados alocou, e ela é a mesma em todos os nós aqui, independentemente da carga. A contagem
de fluxos ativos não está nessa linha. `Entries: Created … Added … Deleted …`, algumas linhas
abaixo, são contadores acumulados de todo o ciclo de vida, e os fluxos realmente preenchidos são
os registros exibidos após a legenda — 73 deles em uma execução feita durante a redação deste
texto, em uma resposta de 542 linhas.
</Aside>

## `flow-l-match`

Quase sempre é o que você quer. Aceita um endereço, ou um endereço e uma porta.

```bash
{"command":["flow-l-match","100.127.192.10:53"]}
```

```text file=../../../../_data/sitecli-flow-l-match.txt
```

A ação em cada fluxo é o ponto central: `F` forward, `D` drop, `N` NAT. Um fluxo presente
com a ação `D` significa que o plano de dados tomou uma decisão deliberada, o que direciona
você para a política em vez da conectividade.

## `flow-l`

O dump completo.

```bash
{"command":["flow-l"]}
```

```text file=../../../../_data/sitecli-flow-l.txt
```

<Aside type="caution" title="Reduzido, e o tamanho varia">
A captura acima foi reduzida às suas primeiras 60 linhas de uma resposta de 1.186 linhas. Uma
execução feita durante a redação deste texto retornou 542 linhas — o comprimento da resposta
acompanha quantos fluxos estão ativos, portanto nenhum desses números é uma propriedade do
comando. Use `flow-l-match` a menos que você realmente precise examinar a tabela inteira.
</Aside>
