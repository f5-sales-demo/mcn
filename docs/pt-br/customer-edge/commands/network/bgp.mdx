O CE executa o FRR para BGP. Nesta topologia, ele realiza peering com as duas instâncias
do Azure Route Server, anuncia o VIP e aprende o prefixo da VNet.

## `show-ip-bgp-summary`

Comece aqui. Uma tela informa se o peering está ativo e há quanto tempo está
estável.

```bash
{"command":["show-ip-bgp-summary"]}
```

```text file=../../../../_data/sitecli-show-ip-bgp-summary.txt
```

Leia `State/PfxRcd` primeiro. Um número indica a contagem de prefixos recebidos e significa que a
sessão está estabelecida; qualquer outro valor — `Active`, `Connect`, `Idle` — indica uma sessão
que não está ativa. `Up/Down` mostra há quanto tempo o estado atual persiste, portanto uma sessão
que continua reiniciando apresentará um valor suspeitosamente pequeno.

<Aside type="caution" title="O vrf id aqui não é o que o rt espera">
Esta saída reporta `vrf-id 3`. Essa é a numeração do FRR. O plano de dados do Argo utiliza um
id de tabela separado, e passar o número do FRR para
[`rt --dump`](../dataplane-forwarding/) retorna `No such file or directory`, o que
parece um nó com problema em vez de um argumento incorreto.
</Aside>

## `show-ip-bgp`

A tabela completa, com a seleção do melhor caminho visível.

```bash
{"command":["show-ip-bgp"]}
```

```text file=../../../../_data/sitecli-show-ip-bgp.txt
```

`*` é uma rota válida, `>` o melhor caminho selecionado, `=` um membro de multipaths. Duas
entradas para um mesmo prefixo, ambas marcadas com `*=`, significam que o ECMP está em efeito,
que é o estado esperado nesta topologia.

## `show-ip-bgp-neighbors`

Detalhes por vizinho: capacidades negociadas, temporizadores, contadores de mensagens e o
motivo do último reset.

```bash
{"command":["show-ip-bgp-neighbors"]}
```

Utilize este comando quando o resumo indicar que uma sessão está oscilando e você precisar saber o motivo.
`Last reset` e seu respectivo motivo são as linhas úteis.

## `show-ip-bgp-neighbors-advertised-route`

O que este nó está informando aos seus pares, em oposição ao que ele conhece.

```bash
{"command":["show-ip-bgp-neighbors-advertised-route"]}
```

```text file=../../../../_data/sitecli-show-ip-bgp-neighbors-advertised-route.txt
```

Este é o comando para o cenário "o VIP não está acessível pela VNet". Se o VIP estiver
ausente aqui, o problema está neste nó e nenhuma análise do peer irá ajudar.
