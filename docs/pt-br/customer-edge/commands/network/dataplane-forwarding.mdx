O Argo mantém o estado de encaminhamento separado do kernel Linux. Quando
[`ip`](../ip/) e estes comandos discordam, são estes comandos que movem o tráfego.

## `rt`

A tabela de rotas do vRouter, por VRF.

```bash
{"command":["rt","--dump","2"]}
```

```text file=../../../../_data/sitecli-rt.txt
```

<Aside type="danger" title="O ID de VRF não é o que o BGP reporta">
`show-ip-bgp-summary` exibe `vrf-id 3`. Essa é a numeração do FRR e pertence a um
namespace diferente do ID de tabela do vRouter. Passá-lo aqui falha de uma forma que
parece um nó com problema:

```
vRouter(Response):  [No such file or directory (2)]
```

A mesma resposta é retornada para `--dump 0`. Nesta topologia, a **VRF 2** é a
tabela inet4 populada, com a VRF 1 contendo duas rotas. Se você não souber o ID,
sonde a partir de 1 incrementando gradualmente, em vez de confiar na saída do BGP.
</Aside>

## `nh`

A tabela de próximos saltos. Cada rota aponta para um ID de próximo salto, e esta tabela os resolve.

```bash
{"command":["nh","--list"]}
```

```text file=../../../../_data/sitecli-nh.txt
```

Cada entrada possui um `Type` e a VRF à qual pertence. Oito tipos ocorrem nesses nós, nas
seguintes proporções — idênticas nos três CEs quando contados:

```text
Tunnel 558   Encap 27   NAT 22   Vrf 16   Receive 14   Composite 4   Drop 2   Resolve 2
```

Uma rota que resolve para um próximo salto `Drop` é uma rota blackhole, e essa combinação vale
ser verificada sempre que um prefixo estiver presente em `rt`, mas o tráfego ainda desaparecer.

<Aside type="caution" title="A captura acima está truncada e não contém todos os tipos">
São as primeiras 60 linhas de 3.849. `Tunnel`, o tipo mais comum por ampla margem, não
aparece nessas 60 linhas — portanto, não interprete a captura como o inventário completo de tipos,
e não conclua que um tipo está ausente de um nó porque está ausente de uma captura truncada. As
contagens acima foram obtidas a partir da resposta completa.
</Aside>

## `vif`

A tabela de interfaces virtuais: ao que o plano de dados se vincula e os
contadores por interface.

```bash
{"command":["vif","--list"]}
```

```text file=../../../../_data/sitecli-vif.txt
```

A legenda de flags no topo vale ser lida uma vez — `Vp` marca a interface física do vhost,
`Dpdk` uma gerenciada pelo DPDK. Use isso para confirmar que o plano de dados assumiu
a interface esperada e para visualizar os contadores de RX e TX que o Linux não exibe
porque o tráfego nunca chega ao kernel.

## `mpls`

```bash
execcli mpls --help
```

A tabela MPLS do Argo. Acessível **somente a partir do equipamento** — `mpls` não está na API de
depuração, portanto, ao contrário de `rt`, `nh` e `vif` acima, requer [SSH](../../../access/ssh/) ou o
[console serial](../../../access/serial-console/), por meio do
[`execcli`](../../on-box/).

Não há saída capturada aqui. Nesta implantação, o CE encaminha IPv4 com BGP e ECMP e não
utiliza rótulos MPLS, portanto uma captura mostraria uma tabela vazia e não ensinaria nada. Sua
existência e a forma do argumento `--help` são verificadas a partir do menu de conclusão do próprio
appliance; a saída populada não é reproduzida.
