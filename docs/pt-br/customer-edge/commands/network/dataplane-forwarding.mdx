O Argo mantém o estado de encaminhamento separado do kernel Linux. Quando
[`ip`](../ip/) e estes comandos discordam, são estes comandos que movem o tráfego.

## `rt`

A tabela de rotas do vRouter, por VRF.

```bash
{"command":["rt","--dump","2"]}
```

```text file=../../../../_data/sitecli-rt.txt
```

<Aside type="danger" title="O id da VRF não é aquele que o BGP informa">
`show-ip-bgp-summary` exibe `vrf-id 3`. Essa é a numeração do FRR e trata-se de um
namespace diferente do id da tabela do vRouter. Passá-lo aqui falha de um modo que
parece indicar um nó defeituoso:

```
vRouter(Response):  [No such file or directory (2)]
```

A mesma resposta é retornada para `--dump 0`. Nesta topologia, a **VRF 2** é a
tabela inet4 populada, com a VRF 1 contendo duas rotas. Se você não souber o id,
faça a sondagem crescente a partir de 1 em vez de confiar na saída do BGP.
</Aside>

## `nh`

A tabela de próximos saltos. Toda rota aponta para um id de próximo salto, e isto os resolve.

```bash
{"command":["nh","--list"]}
```

```text file=../../../../_data/sitecli-nh.txt
```

Cada entrada carrega um `Type` e a VRF à qual pertence. Oito tipos ocorrem nesses nós, nestas
proporções — idênticas nos três CEs quando contabilizadas:

```text
Tunnel 558   Encap 27   NAT 22   Vrf 16   Receive 14   Composite 4   Drop 2   Resolve 2
```

Uma rota que resolve para um próximo salto `Drop` é um blackhole, e vale verificar essa
combinação sempre que um prefixo estiver presente em `rt` mas o tráfego ainda desaparecer.

<Aside type="caution" title="A captura acima está reduzida, portanto não contém todos os tipos">
São as primeiras 60 linhas de 3.849. `Tunnel`, o tipo mais comum por ampla margem, não
aparece nessas 60 linhas — então não interprete a captura como o inventário completo de tipos, e não
conclua que um tipo está ausente em um nó apenas porque ele está ausente de uma captura reduzida. As contagens
acima vieram da resposta não reduzida.
</Aside>

## `vif`

A tabela de interfaces virtuais: aquilo a que o plano de dados se vincula, e os
contadores por interface.

```bash
{"command":["vif","--list"]}
```

```text file=../../../../_data/sitecli-vif.txt
```

Vale a pena ler uma vez a legenda de flags no topo — `Vp` marca a interface física
vhost, `Dpdk` uma gerenciada por DPDK. Use isto para confirmar que o plano de dados assumiu
a interface que você espera, e para ver os contadores RX e TX que o Linux não mostra
porque o tráfego nunca chega ao kernel.
