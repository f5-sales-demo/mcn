## Disponibile solo nelle versioni più recenti

Un build corrente (`crt-20260201-0179`) espone **43** comandi — un sovrainsieme stretto,
senza rimozioni e senza metadati modificati. I nove che questo tenant non possiede:

| Comando | Categoria | Tier |
| --- | --- | --- |
| `collect-database-stats` | Sistema | `ExecUser` |
| `iptables-lv` | Rete | `ExecUser` |
| `marker-exists-NetworkManager` | Sistema | `Exec` |
| `marker-exists-crio` | Sistema | `Exec` |
| `marker-exists-kubelet` | Sistema | `Exec` |
| `systemctl-restart-NetworkManager` | Sistema | `Exec` |
| `systemctl-restart-crio` | Sistema | `Exec` |
| `systemctl-restart-kubelet` | Sistema | `Exec` |
| `systemctl-start-crio-prune` | Sistema | `Exec` |

Sono elencati solo per nome e tier, dalla scoperta del catalogo su un nodo con quel
build. Non è disponibile output acquisito per essi, poiché questo tenant non può eseguirli.
Si noti che quattro dei nove riavviano servizi su un piano dati attivo.

<Aside type="note" title="Rilevamento delle variazioni della superficie">
Poiché la superficie cresce con il build software, il catalogo registra il build da cui
proviene, e `scripts/capture-sitecli.sh --check` segnala una variazione del build
separatamente dai comandi aggiunti o rimossi. Quando questi nodi vengono aggiornati, è
questa verifica che notifica l'arrivo di questi nove comandi.
</Aside>
