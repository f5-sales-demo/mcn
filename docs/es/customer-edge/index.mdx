Un Customer Edge (CE) es el nodo de F5 Distributed Cloud que este repositorio aprovisiona en
Azure — `terraform/modules/ce-node`, construido a partir de la
imagen del marketplace `volterraedgeservices/volterra-node`.

Ejecuta el plano de datos (Argo), el plano de control (Vega), un proxy Envoy, una pila
de Kubernetes y `vpm`, el agente que registra el nodo y gestiona todo lo demás en él.

Cuando un CE falla, la CLI del sitio es el instrumento. La primera decisión es cuál
ruta de acceso aplica, y equivocarse desperdicia tiempo de una manera que parece un
nodo defectuoso.

## Dos rutas de acceso que no son intercambiables

  />
  <LinkCard

La API de depuración alcanza el nodo **a través del plano de control de F5 Distributed Cloud**.
Esa es la razón fundamental por la que la división importa: la API solo puede responder una vez
que el nodo se ha registrado y reporta `ONLINE`.

Un nodo que no logró registrarse — cloud-init defectuoso, token expirado, sin ruta hacia
`register.ves.volterra.io` — es exactamente el caso en que se necesitan diagnósticos, y
exactamente el caso que la API no puede atender.

[SSH](./access/ssh/) es la tercera opción, y la única que alcanza la superficie de comandos
completa del dispositivo — la API de depuración expone 34 comandos y el nodo en sí ofrece
muchos más. Dos cosas la restringen. `sshd` responde únicamente en la dirección interna (SLI)
del nodo, por lo que requiere un host dentro de la VNet; y la clave es escrita por cloud-init
en el primer arranque, porque el campo `ssh_key` en el objeto del sitio es inerte — `vpm`
omite el usuario `admin` y nunca la aplica. Por lo tanto, habilitarla en nodos en ejecución
implica reemplazarlos.

En resumen: si el sitio está `ONLINE` y 34 comandos son suficientes, use la API de depuración.
Si necesita el resto de la superficie y puede alcanzar la VNet, use SSH. Si el registro es lo
que está fallando, la consola serial es la única forma de acceder.

<Aside type="caution" title="Verifique el estado del sitio primero">
Una solicitud le indica en qué ruta se encuentra:

```bash
curl -sS -H "Authorization: APIToken $XCSH_API_TOKEN" \
  "$XCSH_API_URL/api/config/namespaces/system/sites/<site>" \
  | jq -r '.spec.site_state'
```

`ONLINE` significa que la API de depuración funcionará. Cualquier otro valor — o un sitio que no
existe — significa consola serial.
</Aside>

## Reglas de seguridad

Estas aplican para cada comando en cada página a continuación.

- **Solo lectura a menos que esté seguro.** La superficie de comandos está dividida en dos
  niveles de privilegio, y el nivel `Exec` ya sea muta el nodo o lee un marcador de estado.
  Ninguna página de este sitio ejecuta un comando `Exec`, y tampoco lo hace el arnés de captura.
- **Nunca asuma que un comando es seguro por su nombre.** `ip-link-set` parece una
  consulta y deja una interfaz inactiva. `systemctl-restart-crio` reinicia el
  tiempo de ejecución de contenedores bajo un plano de datos activo.
- **Prefiera el comando más específico que responda la pregunta.** `health` y
  `diagnosis` resumen el nodo de forma económica; `flow-l` vuelca una tabla de flujos
  con 629.760 entradas.
- **Un CE atiende tráfico en producción.** Estos son entornos de demostración compartidos.
  Asuma que alguien está presentando desde el sitio que está depurando.

## Qué está documentado aquí

Cada comando accesible a través de la API de depuración en la versión de software que ejecuta
este tenant, cada uno con salida capturada desde un nodo activo en lugar de transcrita de otra fuente.

La [referencia de comandos](./commands/) los lista todos con su categoría, nivel de privilegio
y transporte; los [flujos de trabajo](./workflows/) los encadenan en las secuencias que
realmente se usan cuando algo falla.

Las partes exclusivas del nodo de la CLI del sitio — `configure`, `configure-network`,
`factory-reset`, `upgrade` y aproximadamente sesenta comandos `ExecCLI` adicionales — no están
cubiertas.

Solo son accesibles desde una sesión de consola serial, por lo que nada de ellos puede verificarse
mediante programación, y la sintaxis de comandos no verificada es el defecto que esta
documentación existe para evitar repetir.
