Argo mantiene el estado de reenvío separado del kernel de Linux. Cuando
[`ip`](../ip/) y estos comandos discrepan, estos comandos son los que mueven el tráfico.

## `rt`

La tabla de rutas del vRouter, por VRF.

```bash
{"command":["rt","--dump","2"]}
```

```text file=../../../../_data/sitecli-rt.txt
```

<Aside type="danger" title="El id de VRF no es el que informa BGP">
`show-ip-bgp-summary` imprime `vrf-id 3`. Esa es la numeración de FRR y es un
espacio de nombres distinto del id de tabla del vRouter. Pasarlo aquí falla de una manera que
se interpreta como un nodo averiado:

```
vRouter(Response):  [No such file or directory (2)]
```

La misma respuesta se obtiene con `--dump 0`. En esta topología, **VRF 2** es la
tabla inet4 poblada, mientras que VRF 1 contiene dos rutas. Si no conoce el id,
sondee de forma ascendente desde 1 en lugar de confiar en la salida de BGP.
</Aside>

## `nh`

La tabla de siguientes saltos. Cada ruta apunta a un id de siguiente salto, y esto los resuelve.

```bash
{"command":["nh","--list"]}
```

```text file=../../../../_data/sitecli-nh.txt
```

Cada entrada lleva un `Type` y la VRF a la que pertenece. En estos nodos aparecen ocho tipos, en
estas proporciones — idénticas en los tres CE al contarlas:

```text
Tunnel 558   Encap 27   NAT 22   Vrf 16   Receive 14   Composite 4   Drop 2   Resolve 2
```

Una ruta que se resuelve a un siguiente salto `Drop` es un agujero negro, y esa combinación merece revisarse
siempre que un prefijo esté presente en `rt` y aun así el tráfico desaparezca.

<Aside type="caution" title="La captura anterior está recortada, por lo que no contiene todos los tipos">
Son las primeras 60 líneas de 3.849. `Tunnel`, el tipo más común con gran diferencia, no
aparece en absoluto en esas 60 — así que no interprete la captura como el inventario completo de tipos, ni
concluya que un tipo está ausente de un nodo porque esté ausente de una captura recortada. Los recuentos
anteriores proceden de la respuesta sin recortar.
</Aside>

## `vif`

La tabla de interfaces virtuales: a qué se enlaza el plano de datos, y los
contadores por interfaz.

```bash
{"command":["vif","--list"]}
```

```text file=../../../../_data/sitecli-vif.txt
```

Merece la pena leer una vez la leyenda de flags de la parte superior — `Vp` marca la interfaz
física vhost, `Dpdk` una gestionada por DPDK. Utilícelo para confirmar que el plano de datos ha reclamado
la interfaz que espera, y para ver los contadores de RX y TX que Linux no muestra
porque el tráfico nunca llega al kernel.
