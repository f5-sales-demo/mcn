Argo mantiene el estado de reenvío separado del kernel de Linux. Cuando
[`ip`](../ip/) y estos comandos no coinciden, son estos comandos los que mueven el tráfico.

## `rt`

La tabla de rutas del vRouter, por VRF.

```bash
{"command":["rt","--dump","2"]}
```

```text file=../../../../_data/sitecli-rt.txt
```

<Aside type="danger" title="El ID de VRF no es el que reporta BGP">
`show-ip-bgp-summary` muestra `vrf-id 3`. Ese es el número de FRR y pertenece a un
espacio de nombres diferente al ID de tabla del vRouter. Pasarlo aquí falla de una manera que
se interpreta como un nodo defectuoso:

```
vRouter(Response):  [No such file or directory (2)]
```

La misma respuesta se obtiene para `--dump 0`. En esta topología **VRF 2** es la
tabla inet4 poblada, con VRF 1 conteniendo dos rutas. Si no conoce el ID,
explore hacia arriba desde 1 en lugar de confiar en la salida de BGP.
</Aside>

## `nh`

La tabla de siguientes saltos. Cada ruta apunta a un ID de siguiente salto, y esto los resuelve.

```bash
{"command":["nh","--list"]}
```

```text file=../../../../_data/sitecli-nh.txt
```

Cada entrada contiene un `Type` y el VRF al que pertenece. Ocho tipos aparecen en estos nodos, en
estas proporciones — idénticas en los tres CEs cuando se cuentan:

```text
Tunnel 558   Encap 27   NAT 22   Vrf 16   Receive 14   Composite 4   Drop 2   Resolve 2
```

Una ruta que resuelve a un siguiente salto `Drop` es un blackhole, y esa combinación vale la pena verificar
siempre que un prefijo esté presente en `rt` pero el tráfico siga desapareciendo.

<Aside type="caution" title="La captura anterior está recortada, por lo que no contiene todos los tipos">
Son las primeras 60 líneas de 3.849. `Tunnel`, el tipo más común con amplia diferencia, no
aparece en esas 60 líneas — por lo tanto, no interprete la captura como el inventario completo de tipos, y no
concluya que un tipo está ausente de un nodo porque no aparece en una captura recortada. Los recuentos
anteriores provienen de la respuesta sin recortar.
</Aside>

## `vif`

La tabla de interfaces virtuales: a qué se vincula el plano de datos, y contadores
por interfaz.

```bash
{"command":["vif","--list"]}
```

```text file=../../../../_data/sitecli-vif.txt
```

La leyenda de indicadores en la parte superior vale la pena leerla una vez — `Vp` marca la interfaz
física del vhost, `Dpdk` una gestionada por DPDK. Úsela para confirmar que el plano de datos ha reclamado
la interfaz que espera, y para ver los contadores RX y TX que Linux no muestra
porque el tráfico nunca llega al kernel.

## `mpls`

```bash
execcli mpls --help
```

La tabla MPLS de Argo. Accesible **solo desde el equipo** — `mpls` no está en la API de depuración, por lo que
a diferencia de `rt`, `nh` y `vif` anteriores, requiere [SSH](../../../access/ssh/) o la
[consola serie](../../../access/serial-console/), a través de
[`execcli`](../../on-box/).

No hay salida capturada aquí. En este despliegue el CE reenvía IPv4 con BGP y ECMP y no
utiliza etiquetas MPLS, por lo que una captura mostraría una tabla vacía y no enseñaría nada. Su existencia
y la forma de su argumento `--help` se verifican desde el menú de autocompletado propio del appliance; su
salida con datos reales no se reproduce.
