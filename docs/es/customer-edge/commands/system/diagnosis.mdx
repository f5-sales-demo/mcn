## `diagnosis`

<Aside type="caution" title="Ámbito GLOBAL — un transporte diferente">
Como `health`, un `GET` a la ruta `global` y no accesible a través de `exec-user`.

```bash
curl -sS -H "Authorization: APIToken $XCSH_API_TOKEN" \
  "$XCSH_API_URL/api/operate/namespaces/system/sites/<site>/vpm/debug/global/diagnosis"
```

</Aside>

```json file=../../../../_data/sitecli-diagnosis.txt
```

El nodo sondea su propia puerta de enlace e informa el resultado por nodo, por lo que en un sitio
con varios nodos se obtiene un bloque por cada uno. `gateway_connectivity` contiene un resumen de
ping — `sent`, `received`, `lost` y tiempos de ida y vuelta.

<Aside type="note" title="Una pérdida del 100% hacia la puerta de enlace no es necesariamente un fallo">
En esta topología la puerta de enlace no responde a ICMP, por lo que `lost: 100` es el estado
estable mientras el sitio está `ONLINE` y reenviando tráfico. Trate este campo como una señal únicamente
cuando ya tenga otras evidencias de un problema, o cuando cambie.
</Aside>

`resolv_conf` es el campo más consistentemente útil: muestra el resolvedor que el nodo
utilizará realmente, lo cual vale la pena comparar con lo que se espera antes de invertir
tiempo en [`dig`](../../network/dig/).
