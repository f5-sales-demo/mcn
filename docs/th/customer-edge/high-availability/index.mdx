ความพร้อมใช้งานสูง (high availability) ของ F5 Distributed Cloud Customer Edge (CE) สามารถมีอยู่ได้ในสองระดับที่แตกต่างกัน เลือกเลเยอร์ก่อนที่คุณจะเลือกโปรโตคอลการกำหนดเส้นทาง: ไซต์ CE อิสระหลายไซต์จะให้ความพร้อมใช้งานในระดับการกำหนดเส้นทาง (routing-level) ในขณะที่โหนดของไซต์ CE ไซต์เดียวจะให้การรวมกลุ่มในระดับไซต์ (site-level clustering)

| การออกแบบ | หน่วยความล้มเหลว | การกระจายทราฟฟิก | ใช้เมื่อใด |
| --- | --- | --- | --- |
| ไซต์ CE อิสระที่ถูกเลือกโดย Virtual Site | หนึ่งไซต์ CE | เราเตอร์ต้นทางติดตั้งเส้นทาง Border Gateway Protocol (BGP) ที่มีต้นทุนเท่ากันไปยังไซต์ต่าง ๆ | เครือข่ายรองรับ BGP และ Equal-Cost Multi-Path (ECMP) และแอปพลิเคชันไม่ต้องการที่อยู่ IP เสมือนจริงในท้องถิ่นที่ใช้ร่วมกัน (VIP) ที่ใช้งานโดยโหนด CE |
| ไซต์ CE แบบหลายโหนดหนึ่งไซต์ | หนึ่งโหนดภายในไซต์ | คลัสเตอร์เป็นเจ้าของพฤติกรรมการส่งต่อในระดับท้องถิ่นของไซต์; Virtual Router Redundancy Protocol (VRRP) สามารถให้เน็กซ์ฮ็อป (next hop) ในระดับท้องถิ่นได้ในกรณีที่รองรับ | เครือข่ายที่เชื่อมต่อต้องการเกตเวย์ที่มีความซ้ำซ้อนในระดับท้องถิ่นหรือพฤติกรรมการปรับสมดุลโหลดในระดับท้องถิ่นที่ไซต์อิสระไม่ได้ใช้ร่วมกัน |

การออกแบบเหล่านี้แก้ปัญหาที่แตกต่างกัน Virtual Site จะจัดกลุ่มไซต์สำหรับการเลือกนโยบายและบริการ แต่ไม่ได้เปลี่ยนให้กลายเป็นคลัสเตอร์เดียว ส่วนคลัสเตอร์จะจัดกลุ่มโหนดเข้าเป็นไซต์เดียว แต่ไม่ได้ทำให้เราเตอร์ต้นทางกระจายทราฟฟิกไปยังไซต์ที่แยกจากกัน

## ควรเลือกใช้ HA ในระดับการกำหนดเส้นทางเมื่อเครือข่ายสามารถถอนเส้นทางที่ล้มเหลวออกได้

ด้วย HA ในระดับการกำหนดเส้นทาง แต่ละไซต์ CE จะโฆษณาพรีฟิกซ์บริการเดียวกัน เราเตอร์ต้นทางจะติดตั้งเส้นทางที่มีต้นทุนเท่ากันและกระจายโฟลว์ใหม่ไปยังไซต์ต่างๆ เมื่อเส้นทางของไซต์ใดไซต์หนึ่งถูกถอนออก เราเตอร์จะหยุดเลือกเส้นทางนั้นหลังจากโปรโตคอลการกำหนดเส้นทางลู่เข้าหากัน (converge) แล้ว

รูปแบบนี้สามารถขยายได้โดยการเพิ่มไซต์ แต่ทราฟฟิกขาออกที่มีประสิทธิภาพจะถูกจำกัดโดยเราเตอร์ต้นทาง หากเราเตอร์รองรับเน็กซ์ฮ็อปที่มีต้นทุนเท่ากันน้อยกว่าจำนวนไซต์ CE ที่สมบูรณ์ เส้นทางที่โฆษณาบางเส้นทางก็จะไม่นำส่งทราฟฟิก ตรวจสอบขีดจำกัดและพฤติกรรม ECMP ของเราเตอร์ก่อนที่จะเลือกจำนวนไซต์ เนื่องจากไม่มีจำนวน CE สากลที่นำไปใช้ได้กับทุกที่

## ใช้การทำคลัสเตอร์เมื่อเครือข่ายในระดับท้องถิ่นต้องการ

VRRP จะเลือกเราเตอร์ที่ใช้งานอยู่จากเราเตอร์หลายตัวที่ใช้ที่อยู่เสมือนร่วมกัน ไซต์ CE แบบโหนดเดียวไม่มีโหนดที่สองให้เลือก ดังนั้นจึงไม่สามารถให้ความซ้ำซ้อนของ VRRP ได้ ในกรณีที่ประเภทไซต์และสภาพแวดล้อมของ F5 Distributed Cloud รองรับ VRRP ให้สร้างไซต์แบบหลายโหนดที่จำเป็น แทนที่จะอธิบายโหนดเดียวว่าเป็นคลัสเตอร์

<Aside type="caution" title="ความพร้อมใช้งานสูงคือการตัดสินใจ ณ เวลาที่สร้างไซต์">
สำหรับ Secure Mesh Site v2 การเปิดใช้งาน **High Availability** จะเปลี่ยนไซต์จากโหนดเดียวเป็นรูปแบบหลายโหนดที่จำเป็น การตั้งค่านี้ไม่สามารถเปลี่ยนแปลงได้หลังจากที่ไซต์ถูกสร้างและปรับใช้แล้ว ยืนยันจำนวนโหนดและข้อจำกัดของแพลตฟอร์มในปัจจุบันใน [Create Secure Mesh Site v2](https://docs.cloud.f5.com/docs-v2/multi-cloud-network-connect/how-to/site-management/create-secure-mesh-site-v2) ก่อนที่จะสร้างไซต์
</Aside>

## อย่าผสมผสานชื่อของการออกแบบทั้งสองแบบ

ใช้ **ไซต์แบบโหนดเดียว** สำหรับ CE หนึ่งรายการที่ได้รับการจัดการอย่างอิสระ และ **คลัสเตอร์แบบหลายโหนด** สำหรับไซต์หนึ่งไซต์ที่โหนดมีส่วนร่วมใน HA ระดับไซต์ การเรียกชุดไซต์แบบโหนดเดียวที่ทำงานแยกกันว่าเป็นคลัสเตอร์ จะเป็นการบดบังขอบเขตความล้มเหลวและการกำหนดเส้นทางที่สำคัญ
