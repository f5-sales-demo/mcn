มีสองเส้นทางที่ใช้งานได้ และการตัดสินว่าเส้นทางใดจะถูกนำมาใช้นั้นขึ้นอยู่กับสถานะของโหนด ไม่ใช่ความชอบส่วนบุคคล

| เส้นทาง | ต้องการโหนด `ONLINE` | ต้องการการเข้าถึงผ่านเครือข่าย | ข้อจำกัด | ครอบคลุม |
| --- | --- | --- | --- | --- |
| [Debug API](./debug-api/) | **ใช่** | ใช่ | ประมาณ 25–30 นาทีสำหรับการวอร์มอัพบนไซต์ใหม่ | 34 คำสั่ง |
| [Serial console](./serial-console/) | ไม่ | ไม่ | หนึ่งเซสชันต่อหนึ่ง VM; จำกัดการวางข้อความที่ 2,048 อักขระ | Site CLI แบบเต็มบนเครื่อง |

Serial console คือทางเลือกสุดท้าย และเป็นเส้นทางเดียวที่ยังใช้ได้กับโหนดที่ไม่มีเส้นทางเครือข่ายใช้งานได้

[**SSH ไม่ใช่เส้นทางที่สาม**](./ssh/) บัญชี `admin` ไม่สามารถยืนยันตัวตนได้บนบิลด์ที่เทนแนนต์นี้ใช้งานอยู่ `vpm` ไม่เคยนำคีย์ไปใช้ และไม่มีการตั้งค่าไซต์ใดที่เปลี่ยนแปลงสิ่งนี้ได้ หน้านี้มีอยู่เพื่อบันทึกหลักฐาน เพราะรูปแบบความล้มเหลวทุกอย่างที่นั่นดูเหมือนปัญหาไฟร์วอลล์หรือปัญหาข้อมูลรับรอง

## เหตุใดการแบ่งนี้จึงไม่ใช่เรื่องความชอบ

Debug API ให้บริการโดย control plane ของ F5 Distributed Cloud ซึ่งส่งต่อไปยังโหนดผ่านอุโมงค์ที่ `vpm` สร้างขึ้นระหว่างการลงทะเบียน หากไม่มีการลงทะเบียนก็ไม่มีอุโมงค์ ซึ่งหมายความว่า API ไม่มีอะไรให้ส่งต่อ

มันล้มเหลวในลักษณะที่ไม่เป็นประโยชน์แทนที่จะชัดเจน ดังนั้นโหนดที่ไม่เคยขึ้นมาเลยจึงดูเหมือนเป็นปัญหาของ API

Serial console ทำงานในทางตรงกันข้ามโดยสิ้นเชิง — ผ่านแพลตฟอร์ม Azure ไปยังพอร์ตอนุกรมจำลองของโหนด มันไม่สนใจว่าโหนดได้ลงทะเบียนแล้วหรือไม่ มีการเข้าถึงผ่านเครือข่ายหรือไม่ หรือมี data plane ที่ทำงานได้หรือไม่ ความเป็นอิสระนั้นคือประเด็นสำคัญทั้งหมด และนั่นคือเหตุผลที่ boot diagnostics ต้องเปิดใช้งานไว้บน CE VM

<Aside type="note" title="ควรเลือกใช้อะไร">
หากคุณกำลังเขียนระบบอัตโนมัติ หรือรวบรวมหลักฐานที่คุณต้องการรันซ้ำในภายหลัง ให้ใช้ debug API หากการลงทะเบียนคือสิ่งที่เสียหาย serial console ไม่ใช่ทางเลือกสำรอง — แต่เป็นตัวเลือกเดียวที่มี
</Aside>

## ข้อมูลรับรอง

ทั้งสองเส้นทางใช้ข้อมูลรับรองที่แตกต่างกัน และไม่มีอันใดที่ควรอยู่บนบรรทัดคำสั่ง

- **Debug API** — โทเค็น API ของ F5 Distributed Cloud ในรูปแบบ `XCSH_API_TOKEN` พร้อมกับ
  URL ของเทนแนนต์ในรูปแบบ `XCSH_API_URL` ไฟล์บริบทของ `xcsh` ที่
  `~/.config/xcsh/contexts/<tenant>.json` เก็บทั้งสองอย่างไว้ ซึ่งเป็นสิ่งที่
  `scripts/capture-sitecli.sh` อ่านเมื่อสภาพแวดล้อมไม่ได้จัดหาให้
- **Serial console** — การเข้าสู่ระบบ Azure แบบโต้ตอบของคุณ ไม่มี service principal
  สำหรับสิ่งนี้: เทนแนนต์ Entra ขององค์กร F5 ไม่อนุญาตให้จัดเตรียมขึ้นมา ซึ่ง
  ก็เป็นเหตุผลว่าทำไมส่วนใดของกระบวนการนี้จึงไม่ได้รันใน CI

<Aside type="danger" title="ห้ามส่งโทเค็นเป็นอาร์กิวเมนต์โดยเด็ดขาด">
โทเค็นบนบรรทัดคำสั่งจะไปปรากฏในประวัติเชลล์และในรายการโปรเซส ซึ่ง
ผู้ใช้คนอื่นทุกคนบนเครื่องสามารถอ่านได้ `capture-sitecli.sh` ปฏิเสธ
`--token` โดยสิ้นเชิงด้วยเหตุผลนั้น และส่งส่วนหัวให้ `curl` ผ่าน stdin
แทน
</Aside>
