Customer Edge ทุกตัวให้บริการคอนโซลไซต์ของ F5 บน `https://<sli-ip>:65500` ในการติดตั้ง
นี้ โดยทั่วไปแล้วนี่คือเส้นทางที่ควรลองก่อนเป็นอันดับแรก

มันเรียกร้องจากคุณน้อยที่สุด: ไม่ต้องแจกจ่ายคีย์ SSH ไม่ต้องดูแล jump host ไม่ต้องมี public IP บน
โหนด และไม่ต้องเปลี่ยน VM เพื่อเปิดใช้งาน ผู้ที่สามารถเชื่อมต่อได้จะกลายเป็น **การตัดสินใจด้วย Azure
RBAC** และมันไม่จำเป็นต้องให้ไซต์ลงทะเบียนแล้ว: หน้านี้ถูกบันทึกครั้งแรกในขณะที่ทั้งสามไซต์รายงาน
`site_state: FAILED` และได้รับการตรวจสอบซ้ำแล้วว่าไม่เปลี่ยนแปลงกับโหนดเดียวกันเมื่อสถานะเป็น
`ONLINE`

ข้อจำกัดคือคอนโซลไซต์ตอบสนองเฉพาะบนที่อยู่ภายใน (SLI) ของโหนดเท่านั้น
ซึ่งเข้าถึงได้จากภายใน VNet เท่านั้น Azure Bastion ปิดช่องว่างนั้นโดยไม่ต้องวาง
สิ่งอื่นใดเพิ่มเติมบนเครือข่าย

<Aside type="note" title="สิ่งที่ได้รับการตรวจสอบยืนยันที่นี่ และสิ่งที่ไม่ได้ตรวจสอบ">
ทุกคำสั่งและทุกผลลัพธ์บนหน้านี้ถูกรันกับ `f5-xc-ce-vm-01` ในการติดตั้งนี้
และถูกนำมาแสดงตามต้นฉบับทุกประการ รวมถึงกรณีที่ล้มเหลว

**การยืนยันตัวตนได้รับการตรวจสอบแล้ว**: ข้อมูลรับรอง `admin` ของอุปกรณ์คืนค่า `200` ผ่าน
อุโมงค์ สิ่งที่ *ไม่ได้* ทดสอบคือตัวคอนโซลเอง — ไม่มีเนื้อหาด้านล่างที่อธิบายว่าคุณจะ
เห็นหรือทำอะไรได้บ้างเมื่อเข้าไปข้างใน

**Azure RBAC ไม่ได้รับการตรวจสอบยืนยัน** ทุกการรันดำเนินการในฐานะเจ้าของ subscription ดังนั้นข้อกำหนด Reader
ในขั้นตอนที่ 2 จึงเป็นข้อกำหนดที่ Microsoft ระบุไว้ในเอกสาร มิใช่สิ่งที่ถูกวัดผล
ที่นี่
</Aside>

<Aside type="caution" title="Bastion เป็นแบบเลือกเปิดใช้งาน และไม่ได้ถูกติดตั้งโดยค่าเริ่มต้น">
`enable_bastion` มีค่าเริ่มต้นเป็น `false` ดังนั้นเมื่อรัน `terraform apply` แบบค่าเริ่มต้นจะไม่มีโฮสต์ Bastion
และ `terraform output -raw bastion_name` จะเป็น `null` ให้ตั้งค่า `enable_bastion = true` ใน
`terraform/terraform.tfvars` — ในการติดตั้งนี้ค่าดังกล่าวเป็น `true`

เหตุผลที่เป็นแบบเลือกเปิดใช้งานคือค่าใช้จ่าย ไม่ใช่ความเสี่ยง: โฮสต์ SKU แบบ Standard จะคิดค่าบริการรายชั่วโมง
ตั้งแต่วินาทีที่จัดเตรียมเสร็จ ไม่ว่าจะมีใครเปิดอุโมงค์หรือไม่ก็ตาม — USD
0.29/ชั่วโมง ใน `eastus` สำหรับสอง scale unit ที่รวมมาให้ (ราคาขายปลีก, 2026-07) ประมาณ USD 212 ต่อ
เดือน ปิดใช้งานอีกครั้งเมื่อการสาธิตไม่ต้องการการเข้าถึงคอนโซล
</Aside>

## ก่อนเริ่มต้น

<Steps>

1. ลงชื่อเข้าใช้ Azure และเพิ่มส่วนขยาย Bastion การทำอุโมงค์เป็นคุณสมบัติของไคลเอนต์ดั้งเดิม
   และส่วนขยายนี้ไม่ได้ถูกติดตั้งโดยค่าเริ่มต้น

   ```bash
   az login
   az extension add --name bastion
   ```

2. ต้องมีสิทธิ์ **Reader** บนเครื่องเสมือน CE, network interface ของมัน และโฮสต์ Bastion
   นี่คือข้อกำหนดที่ Microsoft ระบุไว้ในเอกสารและ **ไม่ได้รับการตรวจสอบยืนยันที่นี่** — ทุกการรันในการติดตั้ง
   นี้ดำเนินการในฐานะเจ้าของ subscription ดังนั้นจึงไม่มีบทบาทที่ต่ำกว่าใดที่ถูกแสดงว่า
   เพียงพอหรือไม่เพียงพอ

3. ยืนยันว่า Bastion ถูกติดตั้งและมีความสามารถที่จำเป็น SKU แบบ Basic ไม่รองรับทั้งการทำอุโมงค์และ
   การเชื่อมต่อแบบอิงตาม IP ดังนั้น `Standard` และ `True` ที่นี่จึงมีความสำคัญทั้งคู่

   ```bash
   az network bastion list -g rg-mcn-ce-ha-rmordasiewicz \
     --query "[].{name:name, sku:sku.name, tunneling:enableTunneling}" -o table
   ```

   ```text
   Name               Sku       Tunneling
   -----------------  --------  -----------
   ce-ha-lab-bastion  Standard  True
   ```

</Steps>

## เปิดอุโมงค์

นำค่าต่าง ๆ มาจาก `terraform output` แทนที่จะพิมพ์เอง — resource id ไม่ใช่
สิ่งที่ควรประกอบขึ้นด้วยมือ

<Steps>

1. อ่านชื่อของโฮสต์ Bastion, resource group และ resource id ของ VM ของ CE เป้าหมาย

   ```bash
   cd terraform
   BASTION=$(terraform output -raw bastion_name)
   RG=$(terraform output -raw resource_group_name)
   VM_ID=$(terraform output -json ce_vm_ids | jq -r '.eastus01')
   ```

   ```text
   ce-ha-lab-bastion
   rg-mcn-ce-ha-rmordasiewicz
   /subscriptions/…/providers/Microsoft.Compute/virtualMachines/f5-xc-ce-vm-01
   ```

   <Aside type="caution" title="แมปนี้ใช้คีย์ตามไซต์ ไม่ใช่ตามชื่อ VM">
   คีย์ของ `ce_vm_ids` คือ `eastus01`, `eastus02`, `eastus03` — **ไม่ใช่** ชื่อ VM
   ตัวกรองอย่าง `jq -r '."f5-xc-ce-vm-01"'` จะคืนค่า `null` และอุโมงค์จะล้มเหลวเพราะ
   resource id ว่างเปล่า หากไม่แน่ใจให้แสดงรายการออกมา:

   ```bash
   terraform output -json ce_vm_ids | jq -r 'keys | join(", ")'
   ```

   ```text
   eastus01, eastus02, eastus03
   ```

   </Aside>

2. เริ่มอุโมงค์ มันจะเปิดพอร์ตค้างไว้จนกว่าจะหยุด ดังนั้นให้รันเป็นเบื้องหลังหรือใช้
   เทอร์มินัลที่สอง

   ```bash
   az network bastion tunnel \
     --name "$BASTION" \
     --resource-group "$RG" \
     --target-resource-id "$VM_ID" \
     --resource-port 65500 \
     --port 65500 &
   ```

   ```text
   WARNING: Opening tunnel on port: 65500
   WARNING: Tunnel is ready, connect on port 65500
   WARNING: Ctrl + C to close
   ```

   ทั้งสามบรรทัดมีคำนำหน้าว่า `WARNING:` นั่นคือ Azure CLI เขียนความคืบหน้าไปยัง
   stderr ไม่ใช่ปัญหา รอจนกว่าจะเห็น `Tunnel is ready` ก่อนเชื่อมต่อ

3. ยืนยันว่าตัวรับฟังอยู่ในเครื่อง บน loopback:

   ```bash
   lsof -nP -iTCP:65500 -sTCP:LISTEN
   ```

   ```text
   COMMAND   PID  USER  FD  TYPE  DEVICE  SIZE/OFF  NODE  NAME
   Python  41648  you   7u  IPv4  …            0t0   TCP  127.0.0.1:65500 (LISTEN)
   ```

4. เปิดคอนโซล อุโมงค์ทำให้มันเป็นบริการในเครื่อง ดังนั้นที่อยู่คือ `localhost` — ไม่ใช่
   ที่อยู่ของโหนด

   ```bash
   open https://localhost:65500/          # macOS
   xdg-open https://localhost:65500/      # Linux
   ```

5. หยุดอุโมงค์เมื่อเสร็จสิ้น — `Ctrl-C` หรือ `kill %1` หากคุณรันเป็นเบื้องหลัง
   การเปิดค้างไว้จะยึดพอร์ต 65500 ในเครื่องและเซสชัน Bastion เอาไว้

</Steps>

## สิ่งที่คุณจะได้เห็น

**กล่องโต้ตอบขอข้อมูลรับรอง ไม่ใช่หน้าล็อกอิน** คอนโซลใช้การยืนยันตัวตนแบบ HTTP Basic ดังนั้น
เบราว์เซอร์จะแสดงกล่องขอชื่อผู้ใช้และรหัสผ่านของตัวเอง ไม่มีฟอร์มให้ดู:

```bash
curl -skI https://localhost:65500/
```

```text
HTTP/1.1 401 Unauthorized
WWW-Authenticate: Basic realm="Volterra Site Console"
Content-Type: text/html; charset=utf-8
Content-Length: 0
```

การได้ `401` พร้อม realm ดังกล่าวคือคอนโซลกำลังทำงานอย่างถูกต้อง มันคือสิ่งที่คำขอที่ไม่ผ่านการยืนยันตัวตน
ควรได้รับ — และการส่งข้อมูลรับรอง `admin` ไปยัง URL เดียวกันจะได้คำตอบ
`200` ซึ่งเป็นวิธียืนยันข้อมูลรับรองก่อนเปิดเบราว์เซอร์:

```bash
curl -sk -u admin -o /dev/null -w '%{http_code}\n' https://localhost:65500/
```

```text
Enter host password for user 'admin':
200
```

`-u admin` โดยไม่มีเครื่องหมายทวิภาคทำให้ `curl` ถามรหัสผ่านแทนที่จะรับจาก
บรรทัดคำสั่ง ซึ่งรหัสผ่านจะไปตกอยู่ในประวัติของเชลล์และในรายการโปรเซส

**คำเตือนเรื่องใบรับรอง ด้วยสามเหตุผลพร้อมกัน** ตรวจสอบใบรับรองโดยตรง:

```bash
openssl s_client -connect localhost:65500 -servername localhost </dev/null 2>/dev/null \
  | openssl x509 -noout -subject -issuer -dates
```

```text
subject=C=US, ST=California, L=Santa Clara, O=Volterra, OU=Volterra Edge Services, CN=site-local.volterra.io
issuer=C=US, ST=California, L=Santa Clara, O=Volterra, OU=Volterra Edge Services, CN=site-local.volterra.io
notBefore=Oct 25 04:51:31 2024 GMT
notAfter=Oct 25 04:51:31 2025 GMT
```

subject เท่ากับ issuer ดังนั้นจึงเป็นใบรับรองแบบลงนามด้วยตนเอง ชื่อคือ `site-local.volterra.io` ในขณะที่
คุณกำลังเชื่อมต่อไปยัง `localhost` จึงไม่ตรงกัน และบนบิลด์ที่การติดตั้งนี้
ใช้งานอยู่ **ใบรับรองหมดอายุไปแล้วเมื่อวันที่ 25 ตุลาคม 2025** — อุปกรณ์มาพร้อมกับใบรับรองนี้ และไม่มีสิ่งใด
ใน repository นี้ที่ต่ออายุให้

คาดหวังได้ว่าจะเจอคำเตือนตรง ๆ จากเบราว์เซอร์ และจะเจอทุกครั้ง บรรทัด subject ด้านบนคือ
ส่วนที่มีประโยชน์: มันคือวิธียืนยันว่าคุณเข้าถึงตัวอุปกรณ์จริง ไม่ใช่สิ่งอื่นที่
รับฟังอยู่บนพอร์ต 65500 ในเครื่อง

## ข้อมูลรับรองของผู้ดูแลระบบ

ลงชื่อเข้าใช้ในฐานะ `admin` **เอกสารนี้ไม่เผยแพร่รหัสผ่าน และไม่ควรเผยแพร่**

<Aside type="danger" title="ในการติดตั้งนี้ รหัสผ่านดังกล่าวยังคงเป็นค่าเริ่มต้นจากโรงงานของ F5">
นี่คือข้อเท็จจริงที่วัดได้ ไม่ใช่ข้อสงสัย: ข้อมูลรับรองค่าเริ่มต้นจากโรงงานสามารถยืนยันตัวตนได้และ
คืนค่า `200` บน CE ทั้งสามตัวในวันนี้ F5 เผยแพร่ค่าเริ่มต้นนั้นและกำหนดให้ต้อง
เปลี่ยน แต่ยังไม่มีการเปลี่ยน

ผลลัพธ์ในทางปฏิบัติคือ ในการติดตั้งนี้ "มีสิทธิ์ Reader บน Bastion" เทียบเท่ากับ
การเข้าถึงคอนโซลของอุปกรณ์ได้เต็มรูปแบบ สำหรับใครก็ตามที่รู้ค่าที่อยู่ในเอกสาร
สาธารณะของ F5 จงเปลี่ยนมันเสีย และถือว่าการเปลี่ยนเป็นส่วนหนึ่งของการติดตั้งโหนด แทนที่จะ
เป็นการเสริมความแข็งแกร่งในภายหลัง
</Aside>

สองเหตุผลที่การไม่เผยแพร่รหัสผ่านมีความสำคัญที่นี่มากกว่าที่เห็น:

- เอกสารนี้เป็นสาธารณะ การพิมพ์รหัสผ่านคอนโซลปัจจุบันของทั้งฟลีตจะเปลี่ยน
  "มีสิทธิ์ Reader บน Bastion" ให้กลายเป็นการเข้าถึงอุปกรณ์เต็มรูปแบบสำหรับใครก็ตามที่อ่านหน้านี้
- รหัสผ่านที่เผยแพร่ในเอกสารจะผิดทันทีที่มีคนหมุนเปลี่ยนมัน และ
  ผิดในแบบที่ทำให้เข้าใจผิดมากที่สุด — ผู้อ่านจะสรุปว่าการเข้าถึงของตนเสีย แทนที่จะ
  คิดว่าหน้าเอกสารล้าสมัย

เมื่อมีการหมุนเปลี่ยนแล้ว ให้ไปขอรหัสผ่านจากที่ที่ทีมของคุณเก็บความลับด้านปฏิบัติการเอาไว้

<Aside type="caution" title="การตั้งรหัสผ่านจาก Terraform ยังไม่ได้รับการตรวจสอบยืนยัน">
`admin_user_credentials.admin_password` บนอ็อบเจ็กต์ไซต์ดูเหมือนจะเป็นวิธีเชิงประกาศ
สำหรับตั้งค่านี้ แต่ **ยังไม่ได้รับการยืนยัน** ว่ามันมีผลถึงคอนโซลไซต์บนบิลด์นี้ ดังนั้นอย่า
สันนิษฐานว่ามันใช้ได้

อย่าอ่าน[หน้า SSH](../ssh/)เป็นหลักฐานสนับสนุนไม่ว่าทางใด ข้อค้นพบที่ว่า
`admin_password` "ไม่ได้เปลี่ยนอะไรเลย" นั้นถูกวัดกับการยืนยันตัวตนของ SSH ซึ่ง `vpm`
ข้ามไปทั้งหมดสำหรับผู้ใช้ `admin` นั่นไม่ได้บอกอะไรเกี่ยวกับคอนโซล
</Aside>

## ทำไมอุโมงค์จึงต้องชี้ไปยัง resource id

`--target-resource-id` เป็นสิ่งจำเป็น การชี้ไปยังที่อยู่ของโหนดแทนจะถูกปฏิเสธ —
ไม่ว่าคุณจะใช้ที่อยู่ใดก็ตาม จึงจงใจไม่พิมพ์ที่อยู่จริงไว้ที่นี่:

```bash
az network bastion tunnel --name "$BASTION" -g "$RG" \
  --target-ip-address <any-sli-address> --resource-port 65500 --port 65501
```

```text
ERROR: Custom ports are not allowed. Allowed ports for Tunnel with IP connect is 22, 3389.
```

เหตุผล **ไม่ใช่** เพราะการเชื่อมต่อแบบอิงตาม IP ถูกปิดใช้งาน — บน Bastion ตัวนี้
`ip_connect_enabled` เป็น `true` Microsoft ไม่รองรับพอร์ตกำหนดเองผ่านการเชื่อมต่อไคลเอนต์ดั้งเดิม
แบบอิงตาม IP ไม่ว่าการตั้งค่านั้นจะเป็นอย่างไร
([เอกสาร Azure](https://learn.microsoft.com/azure/bastion/connect-ip-address)) และ 65500 เป็น
พอร์ตกำหนดเอง การตรวจสอบการกำหนดค่า Bastion ที่นี่ไม่นำไปสู่อะไรเลย ให้ใช้ resource
id

## เมื่อมันใช้งานไม่ได้

| อาการ | สาเหตุ | วิธีแก้ |
| --- | --- | --- |
| `ERROR: Custom ports are not allowed. Allowed ports for Tunnel with IP connect is 22, 3389.` | ใช้ `--target-ip-address` | ใช้ `--target-resource-id` |
| `ERROR: Defined port is currently unavailable` | มีอุโมงค์อื่นยึดพอร์ตในเครื่องนั้นอยู่แล้ว | หยุดอุโมงค์อีกตัว หรือส่งค่า `--port` อื่น; `--resource-port` ยังคงเป็น 65500 |
| `terraform output -raw bastion_name` เป็น `null` หรือว่างเปล่า | Bastion ยังไม่ได้ถูกติดตั้ง | ตั้งค่า `enable_bastion = true` แล้ว apply |
| อุโมงค์เริ่มทำงานแต่ resource id ว่างเปล่า | ตัวกรอง `jq` ใช้ชื่อ VM แทนคีย์ของไซต์ | ใช้คีย์เป็น `eastus01`/`02`/`03` |
| `401 Unauthorized`, realm `Volterra Site Console` | ไม่ใช่ข้อผิดพลาด — เป็นคำขอที่ไม่ผ่านการยืนยันตัวตน | ให้ข้อมูลรับรอง `admin` |
| เบราว์เซอร์ปฏิเสธใบรับรอง | ลงนามด้วยตนเอง, ชื่อไม่ตรงกัน และหมดอายุตั้งแต่ ต.ค. 2025 | เป็นเรื่องปกติ; ยืนยันว่า subject คือ `CN=site-local.volterra.io` แล้วดำเนินการต่อ |

<Aside type="note" title="ความล้มเหลวด้านการให้สิทธิ์ไม่ได้ถูกจำลองซ้ำ">
สิทธิ์ RBAC ไม่เพียงพอเป็นอีกสาเหตุที่ชัดเจนของความล้มเหลว แต่การจำลองซ้ำหมายถึงต้อง
ถอนการกำหนดบทบาทออกจากการติดตั้งที่ใช้ร่วมกัน จึงไม่ได้บันทึกไว้ที่นี่พร้อม
ข้อความผิดพลาดตามต้นฉบับ หากอุโมงค์ล้มเหลวตั้งแต่เริ่มต้นด้วยข้อผิดพลาดด้านการให้สิทธิ์ ให้ตรวจสอบสิทธิ์ Reader บน
ทั้งสามอย่าง ได้แก่ VM, NIC ของมัน และโฮสต์ Bastion
</Aside>
