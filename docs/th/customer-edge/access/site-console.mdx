บันทึกเมื่อ 2026-07-28 จาก CE หนึ่งเครื่องของการติดตั้งนี้ `sitecli/capture-manifest.json`
บันทึกว่าเป็นโหนดใด และ `scripts/capture-sitecli.sh --check` จะตรวจสอบชุดคำสั่ง
อีกครั้งกับ CE ที่ทำงานอยู่จริง

ทุก Customer Edge ให้บริการคอนโซลไซต์ของ F5 บน `https://<sli-ip>:65500` ในการติดตั้งนี้
มักเป็นเส้นทางที่ควรลองก่อน

มันเรียกร้องจากคุณน้อยที่สุด: ไม่ต้องแจกจ่ายคีย์ SSH ไม่ต้องดูแล jump host ไม่ต้องมี public IP บน
โหนด และไม่ต้องเปลี่ยน VM เพื่อเปิดใช้งาน ใครจะเชื่อมต่อได้กลายเป็น **การตัดสินใจของ Azure
RBAC** และไม่จำเป็นต้องให้ไซต์ลงทะเบียนแล้ว: หน้านี้ถูกบันทึกครั้งแรกขณะที่ทั้งสามไซต์รายงาน
`site_state: FAILED` และตรวจสอบซ้ำแล้วไม่มีการเปลี่ยนแปลงกับโหนดเดียวกันเมื่อไซต์เหล่านั้นอยู่ในสถานะ `ONLINE`

ข้อจำกัดคือคอนโซลไซต์ตอบสนองเฉพาะบนที่อยู่ภายใน (SLI) ของโหนด ซึ่งเข้าถึงได้จากภายใน VNet เท่านั้น
Azure Bastion ปิดช่องว่างนั้นได้โดยไม่ต้องนำสิ่งอื่นใดมาวางไว้บนเครือข่าย

<Aside type="note" title="สิ่งที่ได้รับการตรวจสอบที่นี่ และสิ่งที่ยังไม่ได้ตรวจสอบ">
ทุกคำสั่งและทุกเอาต์พุตในหน้านี้ถูกรันกับ `f5-xc-ce-vm-01` ในการติดตั้งนี้
และแสดงซ้ำแบบคำต่อคำ รวมถึงกรณีที่ล้มเหลว

**การยืนยันตัวตนได้รับการตรวจสอบแล้ว**: ข้อมูลรับรอง `admin` ของอุปกรณ์คืนค่า `200` ผ่าน
ทันเนล สิ่งที่ *ไม่ได้* ทดลองคือคอนโซลเอง — เนื้อหาด้านล่างไม่ได้อธิบายว่าคุณจะ
เห็นหรือทำอะไรได้เมื่อเข้าไปข้างในแล้ว

**Azure RBAC ยังไม่ได้รับการตรวจสอบ** ทุกครั้งที่รันนั้นทำในฐานะเจ้าของ subscription ดังนั้นข้อกำหนด Reader
ในขั้นตอนที่ 2 จึงเป็นข้อกำหนดที่ Microsoft ระบุไว้ในเอกสาร ไม่ใช่สิ่งที่วัดผลได้จากที่นี่
</Aside>

<Aside type="caution" title="Bastion เป็นแบบ opt-in และไม่ได้ติดตั้งโดยค่าเริ่มต้น">
`enable_bastion` มีค่าเริ่มต้นเป็น `false` ดังนั้นเมื่อ `terraform apply` แบบค่าเริ่มต้นจะไม่มีโฮสต์ Bastion
และ `terraform output -raw bastion_name` จะเป็น `null` ตั้งค่า `enable_bastion = true` ใน
`terraform/terraform.tfvars` — ในการติดตั้งนี้ค่าเป็น `true`

เหตุผลที่เป็นแบบ opt-in คือค่าใช้จ่าย ไม่ใช่ความเสี่ยง: โฮสต์ SKU แบบ Standard คิดค่าบริการรายชั่วโมง
ตั้งแต่วินาทีที่จัดเตรียมเสร็จ ไม่ว่าจะมีใครเปิดทันเนลหรือไม่ — USD
0.29/ชั่วโมง ใน `eastus` สำหรับ scale unit สองหน่วยที่รวมมา (ราคาขายปลีก, 2026-07) หรือประมาณ USD 212 ต่อ
เดือน ปิดมันอีกครั้งเมื่อการสาธิตไม่ต้องการการเข้าถึงคอนโซล
</Aside>

## ก่อนเริ่มต้น

<Steps>

1. ลงชื่อเข้าใช้ Azure และเพิ่มส่วนขยาย Bastion การทำทันเนลเป็นคุณสมบัติของไคลเอนต์แบบเนทีฟ
   และส่วนขยายนี้ไม่ได้ติดตั้งมาโดยค่าเริ่มต้น

   ```bash
   az login
   az extension add --name bastion
   ```

2. ต้องมีสิทธิ์ **Reader** บนเครื่องเสมือน CE, เน็ตเวิร์กอินเทอร์เฟซของมัน และโฮสต์ Bastion
   นี่เป็นข้อกำหนดที่ Microsoft ระบุไว้ในเอกสารและ **ยังไม่ได้ตรวจสอบที่นี่** — ทุกครั้งที่รันใน
   การติดตั้งนี้ทำในฐานะเจ้าของ subscription ดังนั้นจึงไม่มีบทบาทที่ต่ำกว่าที่ได้รับการแสดงว่า
   เพียงพอหรือไม่เพียงพอ

3. ยืนยันว่า Bastion ถูกติดตั้งและมีความสามารถที่ต้องการ SKU แบบ Basic ไม่รองรับทั้งการทำทันเนลและ
   การเชื่อมต่อแบบอาศัย IP ดังนั้น `Standard` และ `True` ที่นี่จึงมีความสำคัญทั้งคู่

   ```bash
   az network bastion list -g "$(terraform output -raw resource_group_name)" \
     --query "[].{name:name, sku:sku.name, tunneling:enableTunneling}" -o table
   ```

   ```text
   Name               Sku       Tunneling
   -----------------  --------  -----------
   ce-ha-lab-bastion  Standard  True
   ```

</Steps>

## เปิดทันเนล

นำค่าต่าง ๆ มาจาก `terraform output` แทนที่จะพิมพ์เอง — resource id ไม่ใช่
สิ่งที่ควรประกอบขึ้นด้วยมือ

<Steps>

1. อ่านชื่อของโฮสต์ Bastion, resource group และ resource id ของ VM ของ CE เป้าหมาย

   ```bash
   cd terraform
   BASTION=$(terraform output -raw bastion_name)
   RG=$(terraform output -raw resource_group_name)
   VM_ID=$(terraform output -json ce_vm_ids | jq -r '.eastus01')
   ```

   ```text
   ce-ha-lab-bastion
   rg-mcn-ce-ha-rmordasiewicz
   /subscriptions/…/providers/Microsoft.Compute/virtualMachines/f5-xc-ce-vm-01
   ```

   <Aside type="caution" title="แมปนี้ใช้คีย์ตามไซต์ ไม่ใช่ตามชื่อ VM">
   คีย์ของ `ce_vm_ids` คือ `eastus01`, `eastus02`, `eastus03` — **ไม่ใช่** ชื่อ VM
   ฟิลเตอร์อย่าง `jq -r '."f5-xc-ce-vm-01"'` จะคืนค่า `null` และทันเนลจะล้มเหลวเพราะ
   resource id ว่างเปล่า หากไม่แน่ใจให้แสดงรายการออกมา:

   ```bash
   terraform output -json ce_vm_ids | jq -r 'keys | join(", ")'
   ```

   ```text
   eastus01, eastus02, eastus03
   ```

   </Aside>

2. เริ่มทันเนล มันจะคงพอร์ตเปิดไว้จนกว่าจะถูกหยุด ดังนั้นให้รันเป็นเบื้องหลังหรือใช้
   เทอร์มินัลที่สอง

   ```bash
   az network bastion tunnel \
     --name "$BASTION" \
     --resource-group "$RG" \
     --target-resource-id "$VM_ID" \
     --resource-port 65500 \
     --port 65500 &
   ```

   ```text
   WARNING: Opening tunnel on port: 65500
   WARNING: Tunnel is ready, connect on port 65500
   WARNING: Ctrl + C to close
   ```

   ทั้งสามบรรทัดมีคำนำหน้าว่า `WARNING:` นั่นคือ Azure CLI เขียนความคืบหน้าไปที่
   stderr ไม่ใช่ปัญหา รอให้ขึ้น `Tunnel is ready` ก่อนเชื่อมต่อ

3. ยืนยันว่าตัวรับฟังอยู่ในเครื่อง บน loopback:

   ```bash
   lsof -nP -iTCP:65500 -sTCP:LISTEN
   ```

   ```text
   COMMAND   PID  USER  FD  TYPE  DEVICE  SIZE/OFF  NODE  NAME
   Python  41648  you   7u  IPv4  …            0t0   TCP  127.0.0.1:65500 (LISTEN)
   ```

4. เปิดคอนโซล ทันเนลทำให้มันเป็นแบบโลคัล ดังนั้นที่อยู่คือ `localhost` — ไม่ใช่
   ที่อยู่ของโหนด

   ```bash
   open https://localhost:65500/          # macOS
   xdg-open https://localhost:65500/      # Linux
   ```

5. หยุดทันเนลเมื่อเสร็จสิ้น — `Ctrl-C` หรือ `kill %1` หากคุณรันเป็นเบื้องหลัง
   การปล่อยให้เปิดไว้จะยึดพอร์ตโลคัล 65500 และเซสชัน Bastion ไว้

</Steps>

## สิ่งที่คุณจะเห็น

**กล่องโต้ตอบข้อมูลรับรอง ไม่ใช่หน้าล็อกอิน** คอนโซลใช้การยืนยันตัวตนแบบ HTTP Basic ดังนั้น
เบราว์เซอร์จะแสดงกล่องถามชื่อผู้ใช้และรหัสผ่านของตัวเอง ไม่มีฟอร์มให้ดู:

```bash
curl -skI https://localhost:65500/
```

```text
HTTP/1.1 401 Unauthorized
WWW-Authenticate: Basic realm="Volterra Site Console"
Content-Type: text/html; charset=utf-8
Content-Length: 0
```

`401` พร้อม realm นั้นคือคอนโซลทำงานอย่างถูกต้อง มันคือสิ่งที่คำขอที่ยังไม่ได้ยืนยันตัวตน
ควรได้รับ — และการส่งข้อมูลรับรอง `admin` ไปที่ URL เดียวกันจะตอบ
`200` ซึ่งเป็นวิธียืนยันข้อมูลรับรองก่อนเปิดเบราว์เซอร์:

```bash
curl -sk -u admin -o /dev/null -w '%{http_code}\n' https://localhost:65500/
```

```text
Enter host password for user 'admin':
200
```

`-u admin` โดยไม่มีเครื่องหมายทวิภาคทำให้ `curl` ถามรหัสผ่านแทนที่จะรับจาก
บรรทัดคำสั่ง ซึ่งจะไปปรากฏในประวัติเชลล์และในรายการโปรเซส

**คำเตือนเรื่องใบรับรอง ด้วยสามเหตุผลพร้อมกัน** ตรวจสอบใบรับรองโดยตรง:

```bash
openssl s_client -connect localhost:65500 -servername localhost </dev/null 2>/dev/null \
  | openssl x509 -noout -subject -issuer -dates
```

```text
subject=C=US, ST=California, L=Santa Clara, O=Volterra, OU=Volterra Edge Services, CN=site-local.volterra.io
issuer=C=US, ST=California, L=Santa Clara, O=Volterra, OU=Volterra Edge Services, CN=site-local.volterra.io
notBefore=Oct 25 04:51:31 2024 GMT
notAfter=Oct 25 04:51:31 2025 GMT
```

subject เท่ากับ issuer ดังนั้นมันเป็นใบรับรองแบบ self-signed ชื่อคือ `site-local.volterra.io` ขณะที่
คุณเชื่อมต่อไปยัง `localhost` จึงไม่ตรงกัน และในบิลด์ที่การติดตั้งนี้
ใช้อยู่ **ใบรับรองหมดอายุเมื่อวันที่ 25 ตุลาคม 2025** — อุปกรณ์มาพร้อมกับใบรับรองนี้ และไม่มีอะไร
ในรีโพสิทอรีนี้ที่ต่ออายุให้

คาดหวังคำเตือนตรง ๆ จากเบราว์เซอร์ และคาดหวังว่าจะเจอทุกครั้ง บรรทัด subject ด้านบนคือ
ส่วนที่มีประโยชน์: มันคือวิธียืนยันว่าคุณเข้าถึงอุปกรณ์จริง ไม่ใช่สิ่งอื่นที่
รับฟังอยู่บนพอร์ตโลคัล 65500

## ข้อมูลรับรองของผู้ดูแลระบบ

ลงชื่อเข้าใช้เป็น `admin` **เอกสารนี้ไม่เผยแพร่รหัสผ่าน และไม่ควรเผยแพร่**

<Aside type="danger" title="ในการติดตั้งนี้ รหัสผ่านนั้นยังเป็นค่าเริ่มต้นจากโรงงานของ F5">
นี่เป็นข้อเท็จจริงที่วัดผลได้ ไม่ใช่ข้อสงสัย: ข้อมูลรับรองค่าเริ่มต้นจากโรงงานยืนยันตัวตนได้และ
คืนค่า `200` บน CE ทั้งสามเครื่องในวันนี้ F5 เผยแพร่ค่าเริ่มต้นนั้นและกำหนดให้ต้อง
เปลี่ยน แต่ก็ยังไม่ได้เปลี่ยน

ผลในทางปฏิบัติคือในการติดตั้งนี้ "มีสิทธิ์ Reader บน Bastion" เท่ากับ
การเข้าถึงคอนโซลของอุปกรณ์ได้อย่างสมบูรณ์ สำหรับใครก็ตามที่รู้ค่าที่อยู่ใน
เอกสารสาธารณะของ F5 ให้เปลี่ยนมัน และถือว่าการเปลี่ยนเป็นส่วนหนึ่งของการติดตั้งโหนด แทนที่จะ
เป็นการเพิ่มความแข็งแกร่งภายหลัง
</Aside>

สองเหตุผลที่การไม่เผยแพร่มันสำคัญกว่าที่ดูเผิน ๆ:

- เอกสารนี้เป็นสาธารณะ การพิมพ์รหัสผ่านคอนโซลปัจจุบันของกลุ่มเครื่องจะเปลี่ยน
  "มีสิทธิ์ Reader บน Bastion" ให้กลายเป็นการเข้าถึงอุปกรณ์อย่างสมบูรณ์สำหรับทุกคนที่อ่านหน้านี้
- รหัสผ่านที่เผยแพร่ในเอกสารจะผิดทันทีที่มีใครหมุนเปลี่ยนมัน และ
  ผิดในแบบที่ทำให้เข้าใจผิดมากที่สุด — ผู้อ่านจะสรุปว่าการเข้าถึงของตนเสียหาย แทนที่จะ
  สรุปว่าหน้านี้เก่าเกินไป

เมื่อหมุนเปลี่ยนแล้ว ให้ไปเอามาจากที่ที่ทีมของคุณเก็บความลับด้านปฏิบัติการ

<Aside type="caution" title="การตั้งรหัสผ่านจาก Terraform ยังไม่ได้รับการตรวจสอบ">
`admin_user_credentials.admin_password` บนออบเจ็กต์ไซต์ดูเหมือนเป็นวิธีแบบประกาศ
สำหรับตั้งค่านี้ แต่ **ยังไม่ได้รับการยืนยัน** ว่าจะไปถึงคอนโซลไซต์บนบิลด์นี้ ดังนั้น
อย่าสันนิษฐานว่ามันทำได้

อย่าอ่าน[หน้า SSH](../ssh/)เป็นหลักฐานในทางใดทางหนึ่งเช่นกัน ข้อค้นพบที่ว่า
`admin_password` "ไม่ได้เปลี่ยนอะไร" นั้นวัดผลกับการยืนยันตัวตนของ SSH ซึ่ง `vpm`
ข้ามไปทั้งหมดสำหรับผู้ใช้ `admin` นั่นไม่ได้บอกอะไรเกี่ยวกับคอนโซล
</Aside>

## เหตุใดทันเนลจึงต้องชี้ไปที่ resource id

`--target-resource-id` เป็นสิ่งจำเป็น การชี้ไปที่ที่อยู่ของโหนดแทนจะถูกปฏิเสธ —
ไม่ว่าคุณจะใช้ที่อยู่ใดก็ตาม ดังนั้นจึงตั้งใจไม่พิมพ์ที่อยู่จริงไว้ที่นี่:

```bash
az network bastion tunnel --name "$BASTION" -g "$RG" \
  --target-ip-address <any-sli-address> --resource-port 65500 --port 65501
```

```text
ERROR: Custom ports are not allowed. Allowed ports for Tunnel with IP connect is 22, 3389.
```

เหตุผล **ไม่ใช่** ว่าการเชื่อมต่อแบบอาศัย IP ถูกปิดใช้งาน — บน Bastion นี้
`ip_connect_enabled` เป็น `true` Microsoft ไม่รองรับพอร์ตแบบกำหนดเองผ่านการเชื่อมต่อ
ไคลเอนต์เนทีฟแบบอาศัย IP ไม่ว่าจะตั้งค่านั้นอย่างไร
([เอกสาร Azure](https://learn.microsoft.com/azure/bastion/connect-ip-address)) และ 65500 คือ
พอร์ตแบบกำหนดเอง การตรวจสอบการตั้งค่า Bastion ที่นี่ไม่นำไปสู่อะไร ให้ใช้ resource
id

## เมื่อมันไม่ทำงาน

| อาการ | สาเหตุ | วิธีแก้ |
| --- | --- | --- |
| `ERROR: Custom ports are not allowed. Allowed ports for Tunnel with IP connect is 22, 3389.` | ใช้ `--target-ip-address` | ใช้ `--target-resource-id` |
| `ERROR: Defined port is currently unavailable` | มีทันเนลอื่นยึดพอร์ตโลคัลนั้นไว้อยู่แล้ว | หยุดทันเนลอีกตัว หรือส่งค่า `--port` ที่ต่างออกไป; `--resource-port` ยังคงเป็น 65500 |
| `terraform output -raw bastion_name` เป็น `null` หรือว่างเปล่า | Bastion ยังไม่ได้ติดตั้ง | ตั้งค่า `enable_bastion = true` และ apply |
| ทันเนลเริ่มต้นแต่ resource id ว่างเปล่า | ฟิลเตอร์ `jq` ใช้ชื่อ VM แทนคีย์ของไซต์ | ใช้คีย์ `eastus01`/`02`/`03` |
| `401 Unauthorized` realm `Volterra Site Console` | ไม่ใช่ข้อผิดพลาด — เป็นคำขอที่ยังไม่ยืนยันตัวตน | ส่งข้อมูลรับรอง `admin` |
| เบราว์เซอร์ปฏิเสธใบรับรอง | self-signed, ชื่อไม่ตรงกัน และหมดอายุตั้งแต่ ต.ค. 2025 | เป็นเรื่องที่คาดไว้; ยืนยันว่า subject เป็น `CN=site-local.volterra.io` แล้วดำเนินการต่อ |

<Aside type="note" title="ความล้มเหลวด้านการให้สิทธิ์ไม่ได้ถูกทำซ้ำ">
RBAC ที่ไม่เพียงพอเป็นอีกวิธีที่ชัดเจนที่ทำให้ล้มเหลว แต่การทำซ้ำจะหมายถึงการ
ถอดการกำหนดบทบาทออกจากการติดตั้งที่ใช้ร่วมกัน จึงไม่ได้บันทึกไว้ที่นี่พร้อม
ข้อความข้อผิดพลาดแบบคำต่อคำ หากทันเนลล้มเหลวตอนเริ่มต้นด้วยข้อผิดพลาดด้านการให้สิทธิ์ ให้ตรวจสอบสิทธิ์ Reader บน
ทั้งสามอย่าง คือ VM, NIC ของมัน และโฮสต์ Bastion
</Aside>
