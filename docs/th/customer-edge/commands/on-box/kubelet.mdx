สามคำสั่งจัดการไฟล์พารามิเตอร์ kubelet แบบกำหนดเอง
`/etc/vpm/kubelet-custom-params.txt` ทั้งสามคำสั่งเป็นของ F5 ไม่มีคำสั่งใดอยู่บน
[debug API](../../../access/debug-api/) และทั้งสามคำสั่งต้องดำเนินการภายใต้การแนะนำของฝ่ายสนับสนุน — พารามิเตอร์ kubelet เปลี่ยนแปลงวิธีที่โหนดรัน Kubernetes workloads

<Aside type="danger" title="อย่าใช้คำสั่งเหล่านี้ยกเว้นเมื่อฝ่ายสนับสนุน F5 ขอให้ดำเนินการ">
พารามิเตอร์ kubelet แบบกำหนดเองจะคงอยู่หลังจากรีบูตและใช้กับทุก workload ที่โหนดรัน
ไม่มีการตรวจสอบความถูกต้องที่นี่: พารามิเตอร์ที่ไม่ถูกต้องจะถูกยอมรับและมีผลเมื่อ kubelet เริ่มต้นครั้งถัดไป
</Aside>

## `kubelet-get-params`

อ่านพารามิเตอร์แบบกำหนดเองที่ใช้งานอยู่ในปัจจุบัน

```bash
execcli kubelet-get-params
```

```text file=../../../../_data/sitecli-kubelet-get-params.txt
```

**คำสั่งนี้ไม่ทำงานจาก Site CLI บน build นี้** บัญชี `admin` ไม่สามารถ
อ่านไฟล์พารามิเตอร์ได้ ดังนั้นคำสั่งจะล้มเหลวไม่ว่าจะมีพารามิเตอร์ถูกตั้งค่าไว้หรือไม่:

```text
Error: failed to read all params: failed to read custom param file:
open /etc/vpm/kubelet-custom-params.txt: permission denied
```

**เหตุใดสิ่งนี้จึงสำคัญกว่าที่เห็น** ความล้มเหลวเป็นข้อผิดพลาดด้าน *สิทธิ์การเข้าถึง* ไม่ใช่ผลลัพธ์ที่ว่างเปล่า
และทั้งสองอย่างสับสนกันได้ง่าย — "failed to read all params" อ่านเหมือนว่า "ไม่มีพารามิเตอร์"
แต่ไม่ใช่หลักฐานว่าไม่มีพารามิเตอร์ที่ถูกกำหนดค่าไว้ บน build นี้วิธีเดียวที่จะดูพารามิเตอร์เหล่านั้นจาก Site CLI คือด้วย
[การเข้าถึง root เสริม](../root-access/) ซึ่งต้องดำเนินการภายใต้การแนะนำของฝ่ายสนับสนุนเช่นกัน

<Aside type="note" title="สิ่งที่ได้รับการยืนยัน">
คำสั่งมีอยู่ รัน และส่งคืนข้อผิดพลาดข้างต้นในฐานะ `admin` บน build
`crt-20250613-3382` ว่าคำสั่งจะสำเร็จภายใต้บัญชี root `xuser` หรือไม่นั้น **ไม่ได้ทดสอบ** —
การได้รับบัญชีนั้นจะทำการแก้ไขโหนด
</Aside>

## `kubelet-add-param`

เพิ่มพารามิเตอร์แบบกำหนดเอง

```bash
execcli kubelet-add-param <parameter>
```

เมื่อรันโดยไม่มีอาร์กิวเมนต์จะรายงาน arity ของตัวเอง ซึ่งเป็นวิธีที่ยืนยันข้อกำหนดโดยไม่ได้ตั้งค่าใด ๆ:

```text
Error: at least one parameter is required
```

**ไม่มีผลลัพธ์ที่บันทึกไว้** คำสั่งนี้เขียนไปยังโหนด ได้รับการยืนยันว่ามีอยู่และต้องการอาร์กิวเมนต์ แต่ไม่ได้รันพร้อมอาร์กิวเมนต์

## `kubelet-remove-param`

ลบพารามิเตอร์แบบกำหนดเอง

```bash
execcli kubelet-remove-param <parameter>
```

**ไม่มีผลลัพธ์ที่บันทึกไว้** ด้วยเหตุผลเดียวกัน

<Aside type="caution" title="ไม่มีคำสั่งเขียนใดอยู่ใน allow-list แบบอ่านอย่างเดียว">
`scripts/sitecli_ssh_harvest.py` ปฏิเสธที่จะรัน `kubelet-add-param` และ
`kubelet-remove-param`: เฉพาะชื่อที่อยู่ใน allow-list แบบอ่านอย่างเดียวเท่านั้นที่สามารถรันได้ และ
สิ่งอื่นใดจะถูกระบุและไม่ถูกรันเลย นี่เป็นการตั้งใจ — deny-list ป้องกันได้เฉพาะสิ่งที่มีคนคิดจะระบุไว้เท่านั้น
</Aside>
