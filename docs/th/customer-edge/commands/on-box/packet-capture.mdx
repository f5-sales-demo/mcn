`vifdump` ดักจับแพ็กเก็ตบนอินเทอร์เฟซเสมือนของ Argo data plane มีห้าคำสั่ง ทั้งหมดเป็นของ F5 และไม่มีคำสั่งใดอยู่บน [debug API](../../../access/debug-api/)

<Aside type="danger" title="คำสั่งเหล่านี้เขียนลงในโหนด และไม่มีการรันบนหน้านี้">
`vifdump` และ `vifdump-d` เริ่มต้นการดักจับที่เขียนไฟล์ `.pcap` ลงใน `/tmp` ภายใน
Argo container บน CE ที่มีดิสก์ขนาด 31 GiB การดักจับที่ปล่อยทิ้งไว้จะกลายเป็นปัญหาพื้นที่ดิสก์
ที่มีตัวนับเวลาถอยหลัง

ทุกคำสั่งในที่นี้จัดทำเอกสารจากข้อมูลเมตาของแคตตาล็อกของอุปกรณ์เองและคำอธิบายในเมนูการเติมคำอัตโนมัติ **ไม่มีผลลัพธ์ที่ดักจับปรากฏบนหน้านี้** และ harness สำหรับเก็บข้อมูลปฏิเสธการรันคำสั่งเหล่านี้ทั้งหมด
</Aside>

## เหตุใดหน้านี้จึงไม่มีผลลัพธ์ โดยเฉพาะเจาะจง

จำนวนอาร์กิวเมนต์บน Site CLI สามารถค้นพบได้โดยการรันคำสั่งโดยไม่มีอาร์กิวเมนต์ — ระบบจะตอบกลับว่า `not sufficient args for command <name>` ซึ่งปลอดภัยสำหรับคำสั่งที่อ่านอย่างเดียว เมื่อนำไปใช้กับ `vifdump` ระหว่างการจัดทำเอกสารนี้ คำสั่งดังกล่าวส่งคืน **โดยไม่มีข้อผิดพลาดใดเลย** บนโหนดที่ยังคงลงทะเบียนอยู่ ไม่ทราบว่ามีการเริ่มต้นการดักจับหรือไม่ เนื่องจากโหนดถูกทำลายและสร้างขึ้นใหม่ก่อนที่จะสามารถตรวจสอบได้

นี่คือเหตุผลทั้งหมดสำหรับการออกแบบของ harness: การรันคำสั่งนั้น **ถูกปฏิเสธโดยค่าเริ่มต้น** ไม่ใช่การขึ้นบัญชีดำ `vifdump` ไม่อยู่ในบัญชีดำใดๆ เพราะไม่มีใครนึกถึงมัน เฉพาะรายการที่อนุญาตอย่างชัดเจนเท่านั้นที่จะปฏิเสธคำสั่งที่ไม่มีใครนึกถึง

## `vifdump`

ดักจับแพ็กเก็ตบน vif ที่ระบุ

```bash
execcli vifdump <vif-id> [options]
```

นำ vif id มาจาก [`vif --list`](../../network/dataplane-forwarding/)

## `vifdump-d`

ดักจับแพ็กเก็ตที่**ถูกดรอป** บน vif หนึ่งรายการหรือทั้งหมด

```bash
execcli vifdump-d <vif-id|all>
```

ใช้คู่กับ [`dropstats`](../../network/dataplane-drops/): `dropstats` บอกให้คุณทราบว่ามีการดรอปเกิดขึ้นและตัวนับใดกำลังเพิ่มขึ้น ส่วน `vifdump-d` แสดงแพ็กเก็ตให้คุณเห็น

## `vifdump-stop`

หยุดการดักจับที่การรันก่อนหน้าทิ้งไว้

```bash
execcli vifdump-stop
```

คำอธิบายของอุปกรณ์เองคือ "stop vifdump command if previous run abnormally ended" ซึ่งบอกให้คุณทราบว่าโหมดความล้มเหลวนั้นเป็นที่คาดหมาย: การดักจับอาจมีอายุยืนกว่าเซสชันที่เริ่มต้นมัน หากคุณได้รัน `vifdump` และไม่แน่ใจว่ายังคงทำงานอยู่หรือไม่ ให้รันคำสั่งนี้

## `vifdump-file-cp`

คัดลอกไฟล์ดักจับออกจาก Argo container ไปยังโฮสต์ในตำแหน่ง `/tmp/vifdump/`

```bash
execcli vifdump-file-cp
```

เทียบเท่ากับ `docker cp $(argo):/tmp/. /tmp/vifdump/` จำเป็นต้องใช้เนื่องจากการดักจับถูกเขียน*ภายใน*คอนเทนเนอร์

## `vifdump-file-rm`

ลบไฟล์ `.pcap` ออกจาก Argo container

```bash
execcli vifdump-file-rm
```

**รันคำสั่งนี้เมื่อคุณดำเนินการเสร็จสิ้น** ร่วมกับ `vifdump-stop` คำสั่งทั้งสองเป็นคู่การล้างข้อมูลสำหรับการดักจับใดๆ และทั้งสองนี้คือสิ่งที่คุณควรรันก่อนเป็นอันดับแรกหากคุณรับช่วงต่อโหนดที่อาจมีคนอื่นทิ้งการดักจับไว้ทำงาน
