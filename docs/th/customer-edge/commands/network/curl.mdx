สองคำสั่ง และความแตกต่างระหว่างสองคำสั่งนี้คือคุณค่าทั้งหมดของการใช้งาน

## `curl-host`

ทำงานในเนมสเปซเครือข่ายของโฮสต์ — การเชื่อมต่อของโหนดเอง ก่อนที่ data plane จะเข้ามาเกี่ยวข้อง

```bash
{"command":["curl-host","-v","cloud.f5.com"]}
```

```text file=../../../../_data/sitecli-curl-host.txt
```

## `curl-vega`

ทำงานภายในบริบทคลัสเตอร์ Kubernetes ดังนั้นจึงผ่าน DNS และเส้นทางเครือข่ายของคลัสเตอร์

```bash
{"command":["curl-vega","-v","cloud.f5.com"]}
```

```text file=../../../../_data/sitecli-curl-vega.txt
```

<Aside type="tip" title="คู่คำสั่งนี้คือการแบ่งครึ่งปัญหา">
รันทั้งสองคำสั่ง หาก `curl-host` สำเร็จแต่ `curl-vega` ล้มเหลว แสดงว่าโหนดมีการเชื่อมต่ออยู่
และเครือข่ายของคลัสเตอร์หรือ DNS ของคลัสเตอร์มีปัญหา หากทั้งสองล้มเหลว ปัญหาอยู่ที่ต้นทางก่อนถึงโหนด — เส้นทาง, ไฟร์วอลล์, หรือเส้นทาง egress หากเฉพาะ `curl-host` ล้มเหลว
คุณพบสิ่งผิดปกติและควรตรวจสอบตาราง routing ของโฮสต์ก่อน
</Aside>

ทั้งสองคำสั่งรับอาร์กิวเมนต์ `curl` ปกติเป็นองค์ประกอบอาร์เรย์แยกกัน ควรคงไว้ซึ่ง `-v`
เนื่องจากบรรทัดการเชื่อมต่อและการ TLS handshake มักเป็นจุดที่แสดงความล้มเหลว
