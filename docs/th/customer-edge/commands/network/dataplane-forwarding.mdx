Argo เก็บสถานะการส่งต่อแยกจาก Linux kernel เมื่อ
[`ip`](../ip/) และคำสั่งเหล่านี้ขัดแย้งกัน คำสั่งเหล่านี้คือสิ่งที่ควบคุมการส่งทราฟฟิก

## `rt`

ตารางเส้นทาง vRouter แยกตาม VRF

```bash
{"command":["rt","--dump","2"]}
```

```text file=../../../../_data/sitecli-rt.txt
```

<Aside type="danger" title="VRF id ไม่ใช่ค่าที่ BGP รายงาน">
`show-ip-bgp-summary` แสดง `vrf-id 3` นั่นคือหมายเลขของ FRR และเป็น
namespace ที่แตกต่างจาก vRouter table id การส่งค่านั้นมาที่นี่จะล้มเหลวในลักษณะที่
ดูเหมือนโหนดเสีย:

```
vRouter(Response):  [No such file or directory (2)]
```

คำตอบเดียวกันจะถูกส่งกลับสำหรับ `--dump 0` บน topology นี้ **VRF 2** คือ
ตาราง inet4 ที่มีข้อมูล โดย VRF 1 มีสองเส้นทาง หากไม่ทราบ id
ให้ลองค้นหาขึ้นไปจาก 1 แทนที่จะเชื่อถือผลลัพธ์จาก BGP
</Aside>

## `nh`

ตาราง next-hop ทุกเส้นทางชี้ไปยัง next-hop id และตารางนี้ใช้สำหรับแก้ไขค่าเหล่านั้น

```bash
{"command":["nh","--list"]}
```

```text file=../../../../_data/sitecli-nh.txt
```

แต่ละรายการมี `Type` และ VRF ที่เป็นสมาชิก มีแปดประเภทที่พบในโหนดเหล่านี้
ในสัดส่วนต่อไปนี้ — เหมือนกันทั้งสาม CE เมื่อนับรวม:

```text
Tunnel 558   Encap 27   NAT 22   Vrf 16   Receive 14   Composite 4   Drop 2   Resolve 2
```

เส้นทางที่แก้ไขไปยัง next-hop แบบ `Drop` คือ blackhole และการรวมกันนั้นควรตรวจสอบ
ทุกครั้งที่ prefix ปรากฏใน `rt` แต่ทราฟฟิกยังคงหายไป

<Aside type="caution" title="ข้อมูลที่บันทึกไว้ข้างต้นถูกตัดทอน จึงไม่ครอบคลุมทุกประเภท">
นั่นคือ 60 บรรทัดแรกจากทั้งหมด 3,849 บรรทัด `Tunnel` ซึ่งเป็นประเภทที่พบบ่อยที่สุดอย่างชัดเจน ไม่
ปรากฏใน 60 บรรทัดนั้นเลย — ดังนั้นอย่าอ่านข้อมูลที่บันทึกว่าเป็นรายการประเภทครบถ้วน และอย่า
สรุปว่าประเภทใดไม่มีในโหนดเพียงเพราะไม่ปรากฏในข้อมูลที่ถูกตัดทอน จำนวนนับข้างต้นมาจากการตอบกลับแบบไม่ตัดทอน
</Aside>

## `vif`

ตารางอินเทอร์เฟซเสมือน: สิ่งที่ data plane ผูกไว้ และตัวนับแต่ละอินเทอร์เฟซ

```bash
{"command":["vif","--list"]}
```

```text file=../../../../_data/sitecli-vif.txt
```

คำอธิบายแฟล็กที่ด้านบนควรอ่านครั้งหนึ่ง — `Vp` หมายถึงอินเทอร์เฟซกายภาพ vhost
`Dpdk` หมายถึงอินเทอร์เฟซที่จัดการโดย DPDK ใช้สิ่งนี้เพื่อยืนยันว่า data plane ได้รับอินเทอร์เฟซที่คาดหวัง
และเพื่อดูตัวนับ RX และ TX ที่ Linux ไม่แสดง
เนื่องจากทราฟฟิกไม่เคยถึง kernel

## `mpls`

```bash
execcli mpls --help
```

ตาราง MPLS ของ Argo เข้าถึงได้ **เฉพาะจากเครื่องนั้น** — `mpls` ไม่อยู่ใน debug API ดังนั้น
ต่างจาก `rt`, `nh` และ `vif` ข้างต้น จำเป็นต้องใช้ [SSH](../../../access/ssh/) หรือ
[serial console](../../../access/serial-console/) ผ่าน
[`execcli`](../../on-box/)

ไม่มีผลลัพธ์ที่บันทึกไว้ที่นี่ ในการ deploy นี้ CE ส่งต่อ IPv4 ด้วย BGP และ ECMP และ
ไม่ใช้ MPLS label ดังนั้นข้อมูลที่บันทึกจะแสดงตารางว่างและไม่มีประโยชน์ การมีอยู่ของคำสั่ง
และรูปแบบอาร์กิวเมนต์ `--help` ได้รับการยืนยันจากเมนูการเติมคำของอุปกรณ์เอง แต่ผลลัพธ์เมื่อมีข้อมูลไม่ได้รับการนำเสนอ
