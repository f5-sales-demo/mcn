Argo แยกสถานะการส่งต่อ (forwarding state) ออกจาก Linux kernel เมื่อ
[`ip`](../ip/) และคำสั่งเหล่านี้ให้ผลไม่ตรงกัน คำสั่งเหล่านี้คือสิ่งที่ควบคุมการเคลื่อนที่ของทราฟฟิกจริง

## `rt`

ตารางเส้นทางของ vRouter แยกตาม VRF

```bash
{"command":["rt","--dump","2"]}
```

```text file=../../../../_data/sitecli-rt.txt
```

<Aside type="danger" title="VRF id ไม่ใช่ค่าเดียวกับที่ BGP รายงาน">
`show-ip-bgp-summary` แสดง `vrf-id 3` นั่นคือการนับหมายเลขของ FRR และเป็น
namespace ที่ต่างจาก table id ของ vRouter การส่งค่านั้นเข้ามาที่นี่จะล้มเหลวในลักษณะที่
ดูเหมือนว่าโหนดเสีย:

```
vRouter(Response):  [No such file or directory (2)]
```

คำตอบแบบเดียวกันจะได้จาก `--dump 0` ในโทโพโลยีนี้ **VRF 2** เป็นตาราง inet4 ที่มีข้อมูล
โดย VRF 1 มีเส้นทางอยู่สองเส้นทาง หากคุณไม่ทราบ id
ให้ทดลองไล่ขึ้นไปจาก 1 แทนที่จะเชื่อผลลัพธ์จาก BGP
</Aside>

## `nh`

ตาราง next-hop ทุกเส้นทางจะชี้ไปที่ next-hop id และคำสั่งนี้จะแปลค่าเหล่านั้น

```bash
{"command":["nh","--list"]}
```

```text file=../../../../_data/sitecli-nh.txt
```

แต่ละรายการจะมี `Type` และ VRF ที่รายการนั้นสังกัดอยู่ มีแปดประเภทที่ปรากฏบนโหนดเหล่านี้ ในสัดส่วน
ดังนี้ — เหมือนกันทั้งสาม CE เมื่อทำการนับ:

```text
Tunnel 558   Encap 27   NAT 22   Vrf 16   Receive 14   Composite 4   Drop 2   Resolve 2
```

เส้นทางที่แปลค่าไปเป็น next hop แบบ `Drop` คือ blackhole และการรวมกันนี้ควรตรวจสอบ
ทุกครั้งที่ prefix มีอยู่ใน `rt` แต่ทราฟฟิกยังคงหายไป

<Aside type="caution" title="ผลลัพธ์ที่แสดงด้านบนถูกตัดทอน จึงไม่มีทุกประเภท">
เป็นเพียง 60 บรรทัดแรกจากทั้งหมด 3,849 บรรทัด `Tunnel` ซึ่งเป็นประเภทที่พบมากที่สุดอย่างมาก ไม่
ปรากฏใน 60 บรรทัดนั้นเลย — ดังนั้นอย่าอ่านผลลัพธ์นี้เป็นบัญชีรายการประเภททั้งหมด และอย่า
สรุปว่าประเภทใดไม่มีอยู่บนโหนดเพียงเพราะไม่ปรากฏในผลลัพธ์ที่ถูกตัดทอน ตัวเลขการนับ
ด้านบนมาจากผลลัพธ์ที่ไม่ถูกตัดทอน
</Aside>

## `vif`

ตารางอินเทอร์เฟซเสมือน: สิ่งที่ data plane ผูกอยู่ด้วย และตัวนับ
แยกตามอินเทอร์เฟซ

```bash
{"command":["vif","--list"]}
```

```text file=../../../../_data/sitecli-vif.txt
```

คำอธิบายแฟล็ก (flags legend) ที่ด้านบนควรอ่านหนึ่งครั้ง — `Vp` หมายถึงอินเทอร์เฟซกายภาพแบบ vhost
และ `Dpdk` หมายถึงอินเทอร์เฟซที่จัดการโดย DPDK ใช้สิ่งนี้เพื่อยืนยันว่า data plane ได้ยึดครอง
อินเทอร์เฟซที่คุณคาดหวังไว้ และเพื่อดูตัวนับ RX และ TX ที่ Linux ไม่แสดง
เนื่องจากทราฟฟิกไม่เคยไปถึง kernel
