Argo เก็บสถานะการส่งต่อแยกจากเคอร์เนล Linux เมื่อ
[`ip`](../ip/) และคำสั่งเหล่านี้ไม่ตรงกัน คำสั่งเหล่านี้คือสิ่งที่ควบคุมการส่งทราฟฟิก

## `rt`

ตารางเส้นทาง vRouter แยกตาม VRF

```bash
{"command":["rt","--dump","2"]}
```

```text file=../../../../_data/sitecli-rt.txt
```

<Aside type="danger" title="VRF id ไม่ใช่ตัวเดียวกับที่ BGP รายงาน">
`show-ip-bgp-summary` แสดง `vrf-id 3` ซึ่งเป็นการกำหนดหมายเลขของ FRR และอยู่ใน
namespace ที่แตกต่างจาก vRouter table id การส่งค่านี้มาที่นี่จะล้มเหลวในลักษณะที่
อ่านได้ว่าโหนดเสีย:

```
vRouter(Response):  [No such file or directory (2)]
```

คำตอบเดิมจะกลับมาสำหรับ `--dump 0` ใน topology นี้ **VRF 2** คือตาราง inet4 ที่มีข้อมูล
โดย VRF 1 มีสองเส้นทาง หากคุณไม่ทราบ id ให้ลองค้นหาขึ้นไปจาก 1 แทนที่จะเชื่อ
ผลลัพธ์จาก BGP
</Aside>

## `nh`

ตาราง next-hop ทุกเส้นทางชี้ไปยัง next-hop id และคำสั่งนี้จะแก้ไขค่าเหล่านั้น

```bash
{"command":["nh","--list"]}
```

```text file=../../../../_data/sitecli-nh.txt
```

แต่ละรายการมี `Type` — `Drop`, `Encap`, `Tunnel`, `Composite` — และ VRF ที่รายการนั้นสังกัดอยู่
เส้นทางที่แก้ไขเป็น next hop แบบ `Drop` คือ blackhole และการผสมดังกล่าวควรตรวจสอบ
เมื่อมี prefix อยู่ใน `rt` แต่ทราฟฟิกยังคงหายไป

## `vif`

ตารางอินเทอร์เฟซเสมือน: สิ่งที่ดาต้าเพลนผูกอยู่ด้วย และตัวนับต่ออินเทอร์เฟซ

```bash
{"command":["vif","--list"]}
```

```text file=../../../../_data/sitecli-vif.txt
```

คำอธิบายสัญลักษณ์ flags ที่ด้านบนควรอ่านสักครั้ง — `Vp` หมายถึงอินเทอร์เฟซ vhost ทางกายภาพ
`Dpdk` หมายถึงอินเทอร์เฟซที่จัดการโดย DPDK ใช้คำสั่งนี้เพื่อยืนยันว่าดาต้าเพลนได้อ้างสิทธิ์
อินเทอร์เฟซที่คุณคาดหวัง และเพื่อดูตัวนับ RX และ TX ที่ Linux ไม่แสดง
เนื่องจากทราฟฟิกไม่เคยถึงเคอร์เนล
