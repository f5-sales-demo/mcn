## `dig`

```bash
{"command":["dig","volterra.azurecr.io"]}
```

```text file=../../../../_data/sitecli-dig.txt
```

อ่าน `status:` ในส่วนหัวก่อน — `NOERROR` พร้อมจำนวน `ANSWER` ที่ไม่เป็นศูนย์ หมายความว่าการค้นหาสำเร็จ

`SERVER:` ที่ด้านล่างระบุตัวแก้ไขที่ตอบสนอง ซึ่งเป็นส่วนที่ควรตรวจสอบ: บนโหนด Azure โดยปกติจะเป็นตัวแก้ไขของแพลตฟอร์มที่ `168.63.129.16` และหากเป็นค่าอื่น แสดงว่าโหนดกำลังใช้ตัวแก้ไขที่คุณไม่ได้ตั้งใจ

ความล้มเหลวในการลงทะเบียนมักย้อนกลับไปที่ DNS หากโหนดไม่สามารถแก้ไข `register.ves.volterra.io` หรือ container registry ได้ ทุกอย่างที่อยู่ถัดไปจะไม่ทำงาน และนี่คือวิธีที่รวดเร็วที่สุดในการพิสูจน์

คำสั่งนี้รับอาร์กิวเมนต์ `dig` ปกติ รวมถึง `@resolver` เพื่อสอบถามเซิร์ฟเวอร์เฉพาะ — มีประโยชน์สำหรับการแสดงให้เห็นว่าตัวแก้ไขหนึ่งตอบสนองและอีกตัวหนึ่งไม่ตอบสนอง

:::note
`dig` ไม่ปรากฏในเอกสารอ้างอิง Site CLI ที่เผยแพร่รุ่นเก่าเลย พบโดยการขอแคตตาล็อกคำสั่งของโหนดเอง แทนที่จะอ่านจากเอกสาร ซึ่งเป็นเหตุผลที่ทุกคำสั่งในเว็บไซต์นี้ถูกค้นพบมา ไม่ใช่คัดลอกมา
:::
