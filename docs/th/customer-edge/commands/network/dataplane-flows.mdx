Argo ติดตามทุกการเชื่อมต่อ วิธีที่คุณสืบค้นตารางนั้นสำคัญกว่าสิ่งที่อยู่ในตาราง
เพราะการดัมพ์ทั้งหมดไม่มีขอบเขตจำกัดในเชิงหลักการ และยุ่งยากในเชิงปฏิบัติ

<Aside type="caution" title="629,760 คือความจุของตาราง ไม่ใช่จำนวนโฟลว์">
บรรทัดส่วนหัว `Flow table(size 161218560, entries 629760)` รายงานจำนวนช่องที่ดาต้าเพลน
จัดสรรไว้ และจะเป็นค่าเดียวกันบนทุกโหนดที่นี่โดยไม่ขึ้นกับโหลด จำนวนโฟลว์ที่ใช้งานอยู่จริง
ไม่ได้อยู่ในบรรทัดนั้น `Entries: Created … Added … Deleted …` ที่อยู่ถัดลงมาไม่กี่บรรทัดคือ
ตัวนับตลอดอายุการใช้งาน ส่วนโฟลว์ที่มีข้อมูลอยู่จริงคือระเบียนที่พิมพ์ออกมาหลังคำอธิบายสัญลักษณ์ —
มี 73 รายการในการรันครั้งหนึ่งขณะเขียนเอกสารนี้ ภายในการตอบกลับความยาว 542 บรรทัด
</Aside>

## `flow-l-match`

เกือบทุกครั้งนี่คือคำสั่งที่คุณต้องการ รับค่าเป็นแอดเดรส หรือแอดเดรสพร้อมพอร์ต

```bash
{"command":["flow-l-match","100.127.192.10:53"]}
```

```text file=../../../../_data/sitecli-flow-l-match.txt
```

การกระทำ (action) ในแต่ละโฟลว์คือประเด็นสำคัญ: `F` คือ forward, `D` คือ drop, `N` คือ NAT
โฟลว์ที่ปรากฏพร้อมการกระทำ `D` หมายความว่าดาต้าเพลนได้ตัดสินใจอย่างจงใจ ซึ่งจะชี้นำให้คุณ
ไปตรวจสอบนโยบายมากกว่าการเชื่อมต่อ

## `flow-l`

การดัมพ์ทั้งหมด

```bash
{"command":["flow-l"]}
```

```text file=../../../../_data/sitecli-flow-l.txt
```

<Aside type="caution" title="ถูกตัดทอน และขนาดเปลี่ยนแปลงได้">
ตัวอย่างที่จับมาข้างต้นถูกตัดเหลือเพียง 60 บรรทัดแรกจากการตอบกลับความยาว 1,186 บรรทัด การรันครั้งหนึ่ง
ขณะเขียนเอกสารนี้ส่งคืนมา 542 บรรทัด — ความยาวของการตอบกลับขึ้นอยู่กับจำนวนโฟลว์ที่ใช้งานอยู่ ดังนั้น
ตัวเลขทั้งสองจึงไม่ใช่คุณสมบัติของคำสั่ง ให้ใช้ `flow-l-match` เว้นแต่คุณจำเป็นต้องสำรวจ
ทั้งตารางจริง ๆ
</Aside>
