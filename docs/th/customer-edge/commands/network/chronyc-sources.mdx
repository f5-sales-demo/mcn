## `chronyc-sources`

{"command":["chronyc-sources"]}
```

```

คอลัมน์ `MS` มี **สอง** อักขระ ไม่ใช่หนึ่ง อักขระแรกคือโหมด — `^` หมายถึงเซิร์ฟเวอร์ —
และอักขระ**ที่สอง**คือสถานะ: `*` คือแหล่งที่ถูกเลือกใช้อยู่ในปัจจุบัน `+` คือทางเลือกที่ยอมรับได้
`-` คือแหล่งที่ถูกคัดออกโดยอัลกอริทึมการคัดเลือก และ `?` คือแหล่งที่ติดต่อไม่ได้
ดังนั้น `^*` คือเซิร์ฟเวอร์ที่ถูกเลือก และ `^?` คือเซิร์ฟเวอร์ที่ติดต่อไม่ได้ การอ่านเพียงอักขระแรก
ไม่ได้บอกอะไรเลย เพราะในที่นี้ทุกบรรทัดเป็น `^` ทั้งหมด

การมี `*` เพียงหนึ่งรายการเท่านั้นคือกรณีที่ปกติดี และยังถือว่าปกติแม้ว่าแหล่งอื่นจะแสดง `?` ก็ตาม

`Reach` เป็นรีจิสเตอร์เลขฐานแปดของการสอบถามแปดครั้งล่าสุด ดังนั้น `377` หมายถึงสำเร็จทั้งแปดครั้ง
ค่าที่ต่ำกว่านั้นหมายถึงมีอย่างน้อยหนึ่งครั้งจากแปดครั้งล่าสุดที่ไม่สำเร็จ — แต่นั่นก็รวมถึงแหล่งที่
เพิ่งเริ่มตอบสนองเมื่อไม่นานมานี้ ซึ่งรีจิสเตอร์ยังอยู่ในระหว่างการเติมค่า การรันคำสั่งขณะเขียนเอกสารนี้
แสดงค่า `3` และ `37` อยู่ข้างๆ ค่า `377` บนโหนดที่มีแหล่งหนึ่งถูกเลือกใช้
(`^*`) และแบนเนอร์ล็อกอินรายงานว่า `NTP: Synced` ควรอ่านค่า `Reach` ร่วมกับ `LastRx`
ซึ่งแสดงว่าแหล่งนั้นตอบสนองครั้งล่าสุดเมื่อนานเท่าใดแล้ว แทนที่จะถือว่าค่าใดๆ ที่ต่ำกว่า `377`
เป็นความผิดพลาด

ควรตรวจสอบตั้งแต่เนิ่นๆ เมื่อการยืนยันตัวตนหรือ TLS ล้มเหลวโดยไม่มีสาเหตุที่มองเห็นได้:
โหนดที่นาฬิกาเคลื่อนไปไกลพอจะปฏิเสธใบรับรองที่ถูกต้อง และโทเคนของโหนดนั้นก็จะถูกปฏิเสธ
โดยข้อผิดพลาดที่เกิดขึ้นมักไม่ค่อยกล่าวถึงเรื่องเวลาเลย
