คำสั่งเหล่านี้รายงานมุมมองของเคอร์เนล ส่วน Argo data plane เก็บมุมมองของตัวเองไว้ ซึ่งดูได้ผ่าน
[`vif`](../dataplane-forwarding/) และทั้งสองอย่างอาจไม่ตรงกัน

## `ip`

รับคำสั่งย่อยของ `ip` โดย `addr` เป็นคำสั่งที่ใช้กันทั่วไป ส่วน `route`, `link` และ `neigh` ก็ใช้งานได้เช่นกัน

```bash
{"command":["ip","addr"]}
```

```text file=../../../../_data/sitecli-ip.txt
```

CE มี Azure NIC สามตัวโดยการออกแบบ — management/SLO, external, internal/SLI — แต่
guest ไม่ได้แสดงผลตามลำดับที่ชื่อเหล่านั้นบ่งชี้ และนี่คือจุดที่การอ่านผลลัพธ์ผิดพลาดทำให้เสียเวลา

| ใน guest | รับผิดชอบ |
| --- | --- |
| `a-i-eth0` | **ไม่มีที่อยู่เลย** — นี่คือ eth0 ทางกายภาพที่ถูกเปลี่ยนชื่อ และ Argo data plane เป็นเจ้าของมัน |
| `vhost0` | ที่อยู่ management/SLO ซึ่งเป็นที่อยู่ที่ BGP ใช้ peer และเป็นที่อยู่ที่ site object รายงาน |
| `eth1` และ `eth2` | ที่อยู่ external และ internal/SLI — แต่ **ไม่ได้เรียงตามลำดับที่แน่นอน** |

<Aside type="danger" title="อินเทอร์เฟซใดระหว่าง eth1 และ eth2 ที่เป็นอินเทอร์เฟซภายในนั้นแตกต่างกันในแต่ละโหนด">
อ่านสดจาก CE ทั้งสามตัวในการติดตั้งนี้: บน `f5-xc-ce-vm-01` และ
`f5-xc-ce-vm-03` ที่อยู่ internal/SLI อยู่บน `eth2` และบน `f5-xc-ce-vm-02` อยู่บน
`eth1` ไม่มีสิ่งใดในการกำหนดค่าที่เลือกสิ่งนี้

ดังนั้นอย่าอนุมานซับเน็ตจากชื่ออินเทอร์เฟซ และอย่านำการจับคู่จากโหนดหนึ่งไปใช้กับ
อีกโหนดหนึ่ง ให้จับคู่ด้วยที่อยู่แทน — ซับเน็ตที่ที่อยู่ของ CE สังกัดอยู่นั้นคงที่ แม้ว่า
อินเทอร์เฟซที่ถือที่อยู่นั้นจะไม่คงที่ก็ตาม
</Aside>

การที่ `a-i-eth0` ไม่มีที่อยู่ก็เป็นเหตุผลทั้งหมดที่ทำให้เข้าถึง `sshd` บนที่อยู่
management ไม่ได้: ไม่มี listener อยู่ที่นั่น ไม่ใช่พอร์ตถูกบล็อก ดูที่
[SSH](../../../access/ssh/)

## `ip-link-show`

เฉพาะชั้น link เท่านั้น: สถานะ, MTU, queueing discipline, MAC

```bash
{"command":["ip-link-show"]}
```

```text file=../../../../_data/sitecli-ip-link-show.txt
```

เร็วกว่า `ip addr` เมื่อคำถามคือ "ลิงก์ up อยู่หรือไม่ และ MTU ของมันเป็นเท่าไร"
ความไม่ตรงกันของ MTU เป็นสาเหตุที่เกิดซ้ำ ๆ ของอุโมงค์ที่สร้างขึ้นได้แต่ไม่ส่งผ่านทราฟฟิก

## `ip-link-set` <Badge text="Exec tier — mutating" variant="danger" />

นำอินเทอร์เฟซหรือกลุ่มขึ้น (up) หรือลง (down)

```
ip-link-set (<device>||<group>) (up||down)
```

<Aside type="danger" title="ไม่ได้รันที่นี่ และเข้าถึงไม่ได้ด้วยวิธีปกติ">
นี่เป็นคำสั่งระดับ `Exec` เพียงคำสั่งเดียวในบิลด์นี้ โดยจะไปที่ endpoint `exec`
แทนที่จะเป็น `exec-user` และมันเปลี่ยนแปลงโหนด: การนำ `eth0` ลงบน CE ระยะไกล
จะทำให้เส้นทางที่คุณใช้จัดการมันหายไป รวมถึง debug API เองด้วย

หน้านี้ไม่มีผลลัพธ์ที่ถูกบันทึกไว้โดยเจตนา ชุดเครื่องมือบันทึกผลลัพธ์ปฏิเสธ
คำสั่งระดับ `Exec` ทั้งหมด และอ่านระดับดังกล่าวจากแคตตาล็อกสด ไม่ใช่จาก
รายการที่ฮาร์ดโค้ดไว้ ดังนั้นข้อความนี้จะยังเป็นจริงอยู่หากบิลด์ในอนาคตเลื่อนคำสั่งอื่นเข้ามาในระดับนี้
</Aside>
