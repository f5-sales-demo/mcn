CE สร้างอุโมงค์ IPsec ไปยัง F5 regional edges หากอุโมงค์เหล่านั้นหยุดทำงาน ไซต์จะถูก
แยกออกจากเครือข่ายทั่วโลก ไม่ว่าภายในจะดูมีสุขภาพดีเพียงใดก็ตาม

## `ipsec-status`

```bash
{"command":["ipsec-status"]}
```

```text file=../../../../_data/sitecli-ipsec-status.txt
```

บรรทัดแรกคือคำตอบ: `Security Associations (2 up, 0 connecting)` ค่าใดก็ตามใน
`connecting` คืออุโมงค์ที่พยายามเชื่อมต่อแต่ล้มเหลว

SA แต่ละรายการระบุชื่อ regional edge ที่อุโมงค์นั้นสิ้นสุด — `ny8-nyc`, `dc12-ash` คือ
รหัส F5 POP — ดังนั้นข้อมูลนี้ยังบอกให้ทราบด้วยว่าไซต์เชื่อมต่อกับ edge ใดบ้าง

`ESTABLISHED` พร้อมระยะเวลา ตามด้วย `INSTALLED, TUNNEL` คือคู่ที่มีสุขภาพดี: รายการแรก
คือ IKE session ส่วนรายการที่สองคือ child SA ที่รับส่งทราฟฟิกจริง IKE session ที่สร้างขึ้น
แล้วแต่ไม่มี child SA ที่ติดตั้งอยู่คือความผิดพลาดที่น่าสนใจ

## `ipsec-statusall`

ข้อมูลเดียวกันบวกกับตัวนับไบต์และแพ็กเก็ตต่อ SA, ตัวจับเวลาการต่อกุญแจ และอัลกอริทึม
ที่ตกลงใช้

```bash
{"command":["ipsec-statusall"]}
```

```text file=../../../../_data/sitecli-ipsec-statusall.txt
```

ใช้เพื่อแยกความแตกต่างระหว่าง "อุโมงค์ทำงานอยู่" กับ "อุโมงค์กำลังรับส่งทราฟฟิก"
อุโมงค์ที่สร้างขึ้นมาหลายชั่วโมงแต่มีไบต์ใกล้ศูนย์คืออุโมงค์ที่ทำงานอยู่แต่ไม่ได้ใช้งาน
ซึ่งมักหมายความว่าปัญหาอยู่ที่การกำหนดเส้นทาง ไม่ใช่ที่อุโมงค์
