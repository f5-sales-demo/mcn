บันทึกเมื่อ 2026-07-28 จาก CE หนึ่งเครื่องของการปรับใช้นี้ `sitecli/capture-manifest.json`
บันทึกว่าเป็นโน้ดใด และ `scripts/capture-sitecli.sh --check` ตรวจสอบซ้ำชุดคำสั่ง
เทียบกับ CE ที่ใช้งานจริง

## `diagnosis`

<Aside type="caution" title="ขอบเขต GLOBAL — การขนส่งที่แตกต่างกัน">
เช่นเดียวกับ `health` คือการ `GET` ไปยังพาธ `global` และไม่สามารถเข้าถึงได้ผ่าน `exec-user`

```bash
curl -sS -H "Authorization: APIToken $XCSH_API_TOKEN" \
  "$XCSH_API_URL/api/operate/namespaces/system/sites/<site>/vpm/debug/global/diagnosis"
```

</Aside>

```json file=../../../../_data/sitecli-diagnosis.txt
```

ผลลัพธ์จะถูกรายงานแยกตามโน้ด ดังนั้นบนไซต์แบบหลายโน้ดคุณจะได้รับหนึ่งบล็อกต่อโน้ด
`gateway_connectivity` และ `dns_connectivity` แต่ละรายการมีสรุปผลการ ping — `dest_ip`, `sent`,
`received`, `lost` และเวลา round-trip

<Aside type="danger" title="การตรวจสอบ ping ทั้งสองรายการรายงานการสูญหาย 100% บนโน้ดที่มีสุขภาพสมบูรณ์">
ในโทโพโลยีนี้ **ทั้ง** `gateway_connectivity` (ไปยัง `10.0.1.1`) และ `dns_connectivity` (ไปยัง
`168.63.129.16`) รายงาน `sent: 5, received: 0, lost: 100` ในขณะที่ไซต์อยู่ในสถานะ `ONLINE`
ส่งต่อทราฟฟิกได้ และ `registration_status: OK` — ได้รับการตรวจสอบยืนยันอีกครั้งขณะเขียนเอกสารนี้ บล็อก
`lost: 100` สองรายการในการตอบกลับครั้งเดียวเป็นสิ่งที่ดูน่าตกใจที่สุดในหน้านี้ และ
มันคือสถานะปกติ

`dns_connectivity` เป็นตัวที่ทำให้เข้าใจผิดมากกว่าในสองรายการ เพราะ DNS ทำงานได้อย่างชัดเจน:
`dns_query_result` ในการตอบกลับเดียวกันนั้นมีการค้นหาที่สำเร็จสิบรายการ ซึ่งเป็น `NOERROR` เทียบกับ
รีโซลเวอร์ตัวเดียวกันนั้น การตรวจสอบนี้วัดความสามารถในการเข้าถึงผ่าน ICMP ซึ่งที่อยู่ของแพลตฟอร์ม Azure
ไม่ตอบสนอง มันไม่ได้วัด DNS

ให้ถือว่าฟิลด์ทั้งสองนี้เป็นสัญญาณเฉพาะเมื่อคุณมีหลักฐานอื่นของปัญหาอยู่แล้ว หรือ
เมื่อค่ามีการเปลี่ยนแปลง
</Aside>

ฟิลด์ที่ควรอ่านก่อนอยู่ที่ส่วนอื่นของการตอบกลับ: `registration_status`,
`curl_response` (หนึ่งรายการต่อหนึ่งเอนด์พอยต์ของ F5 ที่โน้ดต้องใช้ แต่ละรายการเป็น `OK` หรือไม่),
`dns_query_result` และ `ntp_sync_status`

`resolv_conf` แสดงรีโซลเวอร์ที่โน้ดจะใช้จริง ซึ่งควรนำไปเปรียบเทียบกับ
สิ่งที่คุณคาดหวังก่อนที่จะเสียเวลาไปกับ [`dig`](../../network/dig/)
