สิบสามจากสามสิบสี่คำสั่ง

| หากคุณต้องการ | ใช้ |
| --- | --- |
| คำตอบเดียวว่าโหนดทำงานปกติหรือไม่ | [health](./health/) |
| การตรวจสอบการเชื่อมต่อและ DNS ที่โหนดดำเนินการเอง | [diagnosis](./diagnosis/) |
| คอนเทนเนอร์ของ Kubernetes workload | [crictl](./crictl/) |
| คอนเทนเนอร์ของแพลตฟอร์ม: vpm, argo, site-console | [docker](./docker/) |
| บันทึกบริการ รวมถึงการลงทะเบียน | [journalctl](./journalctl/) |

## โหนดรันรันไทม์คอนเทนเนอร์สองรายการ

สิ่งนี้มักทำให้ผู้คนแปลกใจ และส่งผลต่อการเลือกคำสั่งที่จะตอบคำถามของคุณ

- **Docker** รันคอนเทนเนอร์ของแพลตฟอร์ม — `vpm`, `argo_watch`, `site-console`
- **CRI-O** รัน Kubernetes workload ซึ่งเข้าถึงได้ผ่าน `crictl`

ทั้งสองทำงานพร้อมกัน ทั้งสองส่งคืนผลลัพธ์จริง และไม่มีรายการใดทดแทนอีกรายการได้ `docker-ps` ที่แสดงคอนเทนเนอร์สามรายการไม่ใช่มุมมองบางส่วนของโหนดที่เสียหาย แต่เป็นรายการทั้งหมดของสิ่งที่ Docker รัน หากคุณกำลังมองหา `vpm` นั่นคือคอนเทนเนอร์ Docker หากคุณกำลังมองหา pod นั่นคือ CRI-O

## คำสั่งสองรายการใช้การขนส่งที่แตกต่างกัน

`health` และ `diagnosis` มีขอบเขต `GLOBAL`: เป็นคำขอ `GET` ไปยังเส้นทาง `global` ส่งคืน JSON แทนที่จะเป็นข้อความจากเทอร์มินัล และ**ไม่สามารถเข้าถึงได้ผ่าน `exec-user`** — การส่งคำสั่งไปที่นั่นจะตอบกลับว่า `command not supported` ซึ่งอ่านดูเหมือนว่าคำสั่งนั้นไม่มีอยู่ ดู [debug API](../../access/debug-api/)
