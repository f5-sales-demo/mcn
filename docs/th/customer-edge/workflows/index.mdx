[เอกสารอ้างอิงคำสั่ง](../commands/) จัดระเบียบตามสิ่งที่แต่ละคำสั่งทำ ส่วนหน้าเหล่านี้
จัดระเบียบตามสิ่งที่เกิดข้อผิดพลาดขึ้น

| อาการ | เวิร์กโฟลว์ |
| --- | --- |
| ไซต์ไม่เคยออนไลน์ หรือหลุดออกจากเทแนนต์ | [การลงทะเบียน](./registration/) |
| เส้นทางไม่ถูกประกาศหรือไม่ถูกเรียนรู้ ไม่สามารถเข้าถึง VIP ได้ | [BGP](./bgp-diagnostics/) |
| ทราฟฟิกไปถึงโหนดแต่ไม่ได้มาถึงปลายทาง | [ดาต้าเพลน](./dataplane-diagnostics/) |

แต่ละขั้นตอนมีลิงก์ไปยังหน้าที่จัดทำเอกสารของคำสั่งนั้น ไม่มีการกล่าวซ้ำในที่นี้
ดังนั้นไวยากรณ์จึงมีที่อยู่เพียงแห่งเดียวและไม่สามารถคลาดเคลื่อนไปจากโหนดได้

## ก่อนเริ่มเวิร์กโฟลว์ใด ๆ

ระบุให้ได้ว่าคุณกำลังใช้เส้นทางการเข้าถึงแบบใด เพราะสิ่งนี้เปลี่ยนสิ่งที่คุณทำได้:

```bash
curl -sS -H "Authorization: APIToken $XCSH_API_TOKEN" \
  "$XCSH_API_URL/api/config/namespaces/system/sites/<site>" | jq -r '.spec.site_state'
```

`ONLINE` หมายความว่า [debug API](../access/debug-api/) จะตอบสนอง หากเป็นค่าอื่นใด หมายความว่า
เวิร์กโฟลว์การลงทะเบียนคือสิ่งที่คุณต้องการ พร้อมกับหนึ่งในเส้นทางที่ไม่ขึ้นอยู่กับ
การลงทะเบียน: [Site Console](../access/site-console/) ขณะที่โหนดยังมีเส้นทางเครือข่ายอยู่
[serial console](../access/serial-console/) เมื่อไม่มีเส้นทางแล้ว

ไซต์ที่ **หายไปทั้งหมด** ยังมีคำอธิบายอีกหนึ่งข้อที่ต้องตัดออกก่อนจะสรุปว่า "ไม่เคย
ลงทะเบียน": นั่นคือคุณกำลังสอบถามผิดเทแนนต์ `cd terraform && terraform output -raw
xc_tenant` จะบอกชื่อเทแนนต์ที่การปรับใช้นี้สังกัดอยู่
