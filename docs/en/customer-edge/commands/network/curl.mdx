Two commands, and the distinction between them is the entire value.

## `curl-host`

Runs in the host network namespace — the node's own connectivity, before the data
plane is involved.

```bash
{"command":["curl-host","-v","cloud.f5.com"]}
```


## `curl-vega`

Runs in the Vega (control plane) context rather than the host's. The observable difference,
and the only one established here, is the environment it inherits: `curl-vega` reports a
`NO_PROXY` list covering the private ranges, `int.ves.io`, `int.volterra.us` and the site's
own `.tenant.local` domain, and `curl-host` reports none. What that implies about the DNS
path is not measured.

```bash
{"command":["curl-vega","-v","cloud.f5.com"]}
```

```text file=../../../../_data/sitecli-curl-vega.txt
```

<Aside type="tip" title="The pair is a bisection">
Run both. If `curl-host` succeeds and `curl-vega` fails, the node has connectivity and
something in the control-plane context does not — its proxy settings or its resolver. If both
fail, the problem is upstream of the node: routing, a firewall, or the egress path. If only
`curl-host` fails, you have found something unusual and should check the host routing table
first.

On a healthy node both succeed and reach the same address, so a clean pair proves nothing
about which context is in use — it is the *divergence* that carries the information.
</Aside>

Both accept normal `curl` arguments as separate array elements. `-v` is worth keeping
because the connection and TLS handshake lines are usually where the failure shows.
