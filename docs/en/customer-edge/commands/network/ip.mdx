## `ip`

Takes an `ip` subcommand. `addr` is the common one; `route`, `link` and `neigh` also
work.

```bash
{"command":["ip","addr"]}
```

```text file=../../../../_data/sitecli-ip.txt
```

The CE has three Azure NICs by design, named `mgmt`, `external` and `internal` after the
subnets they sit in. Those names describe Azure, not the F5 Distributed Cloud interface
roles: the `mgmt` NIC is the **Site Local Outside (SLO)** interface, and no out-of-band
management network is configured on these sites — see
[the interface model](../../../interface-model/). The guest then presents none of the three
the way that ordering suggests, and this is where reading the output wrong costs time.

| In the guest | Carries |
| --- | --- |
| `a-i-eth0` | **no address at all** — this is the renamed physical eth0, and the Argo data plane owns it |
| `vhost0` | the SLO address, the one BGP peers from and the one the site object reports |
| `eth1` and `eth2` | the external and internal/SLI addresses — but **not in a fixed order** |

<Aside type="danger" title="Which of eth1 and eth2 is the internal interface differs between nodes">
Read live from the three CEs in this one deployment: on `f5-xc-ce-vm-01` and
`f5-xc-ce-vm-03` the internal/SLI address is on `eth2`, and on `f5-xc-ce-vm-02` it is on
`eth1`. Nothing in the configuration chooses this.

So never infer a subnet from an interface name, and never carry a mapping from one node to
another. Match on the address instead — the subnet a CE address belongs to is stable even
though the interface holding it is not.
</Aside>

`a-i-eth0` carrying no address is also the whole reason `sshd` cannot be reached on the
SLO address. See [the interface model](../../../interface-model/).

## `ip-link-show`

Link-layer only: state, MTU, queueing discipline, MAC.

```bash
{"command":["ip-link-show"]}
```

```text file=../../../../_data/sitecli-ip-link-show.txt
```

Quicker than `ip addr` when the question is "is the link up and what is its MTU".
MTU mismatches are a recurring cause of tunnels that establish but pass no traffic.

## `ip-link-set` <Badge text="Exec tier — mutating" variant="danger" />

Takes an interface or group up or down.

```text
ip-link-set (<device>||<group>) (up||down)
```

<Aside type="danger" title="Not run here, and not reachable the usual way">
This is the only `Exec`-tier command on this build. It goes to the `exec` endpoint
rather than `exec-user`, and it changes the node: taking `eth0` down on a remote CE
removes the path you are managing it through, including the debug API itself.

There is deliberately no captured output on this page. The capture harness refuses
the entire `Exec` tier, and reads the tier from the live catalog rather than a
hardcoded list, so this stays true if a future build promotes other commands into it.
</Aside>
