The from-zero rebuild selected `crt-20260201-0179`. On 2026-08-03, that build exposed
43 commands through the debug application programming interface (API) and 89 through the
on-box `execcli` menu. The older fleet exposed 34 and 82 respectively.

Nine commands were added to the debug API. Seven of those were also the seven-command
difference in the on-box menu; `systemctl-restart-crio` and
`systemctl-restart-kubelet` already existed on-box and are newly reachable through the
debug API.

<Aside type="caution" title="Catalog presence is not permission to run a command">
The capture harness refuses every command that the live catalog classifies as `Exec`. It
also requires an explicit manifest entry before running a newly discovered `ExecUser`
command. A tier and a harmless-looking name do not prove that a command only reads.
</Aside>

## `iptables-lv`

Runs `iptables -L -v -n` and returns the packet-and-byte-counted filter tables.

Captured 2026-08-03 from one CE of this deployment.

```bash
execcli iptables-lv
```

```text file=../../../../_data/sitecli-iptables-lv.txt
```

The warning about legacy tables is load-bearing:

```text
# Warning: iptables-legacy tables present, use iptables-legacy to see them
```

Rules in the legacy tables are not shown here, and the Site CLI offers no command that reads
them.

## `collect-database-stats` writes to the node

This command begins with file-descriptor, connection, and filesystem statistics, then runs a
15-second `fio` random-write benchmark against the filesystem used by `etcd`:

```text
Running fio disk performance test (15 seconds)...
etcd-test: (g=0): rw=randwrite, bs=(R) 4096B-4096B, (W) 4096B-4096B ...
etcd-test: Laying out IO file (1 file / 250MiB)
```

<Aside type="danger" title="The command writes despite its name">
The captured output includes `rw=randwrite` and lays out a 250 MiB file. Run it only when F5
support requests a disk test and the node can tolerate competing input/output (I/O). The
capture harness records an explicit skip reason and never executes it.
</Aside>

Captured 2026-07-28 on a disposable CE. The current fleet was not used to repeat a write
benchmark whose behavior was already established by its own output.

```bash
execcli collect-database-stats
```

```text file=../../../../_data/sitecli-collect-database-stats.txt
```

<Aside type="note" title="The evidence changed the capture policy">
This command was initially treated as read-only because its name and appliance description
say that it collects statistics. Its captured output revealed the writes. A test now scans
committed evidence for write markers and fails if such a command appears on the read-only
allow-list.
</Aside>

## `systemctl-restart-NetworkManager`

The catalog exposes these four exact command names:

```text
systemctl-restart-NetworkManager
systemctl-restart-crio
systemctl-restart-kubelet
systemctl-start-crio-prune
```

The current on-box catalog describes this as `restart NetworkManager service`. The debug API
classifies it as privileged `Exec`. Restarting it interrupts node networking, so the capture
harness never executes it.

## `systemctl-restart-crio`

The current on-box catalog describes this as `restart crio service`. The debug API classifies
it as privileged `Exec`. Restarting the container runtime interrupts workloads, so the
capture harness never executes it.

## `systemctl-restart-kubelet`

The current on-box catalog describes this as `restart kubelet service`. The debug API
classifies it as privileged `Exec`. Restarting kubelet interrupts workload supervision, so

## `systemctl-start-crio-prune`

The current on-box catalog describes this as `start crio image prune service`. The debug API
classifies it as privileged `Exec`. A prune changes container-image storage, so the capture
harness never executes it.

<Aside type="caution" title="Mutating commands stay off the allow-list">
`scripts/sitecli_ssh_harvest.py` enumerates these commands and refuses to execute them. Tests
assert that restart, prune, write-benchmark, packet-capture, and other mutating commands stay
off the allow-list.
</Aside>

<Aside type="note" title="What was verified">
The debug API catalog and on-box completion menu were both refreshed on 2026-08-03 against
software build `crt-20260201-0179`. The API exposed 43 commands and the on-box menu exposed
89 `execcli` commands. The capture run captured 34, skipped nine, and failed none. The on-box
node reported `PROVISIONED` when its catalog was captured.
</Aside>
