Use Site Console when the node has a working Azure network path but the F5 control-plane
debug API is unavailable. The console runs on the node-local HTTPS service on TCP `65500`.

The default showcase does not expose an inbound public management rule. An optional Azure
Bastion host reaches the service through the CE virtual machine resource ID.

## Before you start

You need Azure access to the CE virtual machine, its network interface, and the Bastion
host. You also need Azure CLI, Terraform, and `jq`.

<Aside type="caution" title="Bastion is opt-in">
`enable_bastion` defaults to `false` because Azure Bastion has a standing cost. Set it to
`true` and follow [Deploy the showcase](../../../showcase/deploy/) before using this procedure.
</Aside>

<Steps>

1. Sign in to Azure.

   ```bash
   az login
   az extension add --name bastion
   ```

2. Confirm that Terraform created a Standard Bastion with tunneling enabled.

   ```bash
   az network bastion list \
     --resource-group "$(terraform -chdir=terraform output -raw resource_group_name)" \
     --query "[].{name:name, sku:sku.name, tunneling:enableTunneling}" \
     --output table
   ```

</Steps>

## Open the tunnel

Use Terraform outputs for every deployment-specific value.

<Steps>

1. Choose an Azure CE key.

   ```bash
   terraform -chdir=terraform output -json ce_vm_ids | jq -r 'keys[]'
   export CE_KEY=eastus01
   ```

2. Read the Bastion, resource group, and CE resource ID.

   ```bash
   export BASTION=$(terraform -chdir=terraform output -raw bastion_name)
   export RESOURCE_GROUP=$(terraform -chdir=terraform output -raw resource_group_name)
   export CE_VM_ID=$(terraform -chdir=terraform output -json ce_vm_ids | jq -r --arg key "$CE_KEY" '.[$key]')
   ```

3. Start the tunnel in a dedicated terminal.

   ```bash
   az network bastion tunnel \
     --name "$BASTION" \
     --resource-group "$RESOURCE_GROUP" \
     --target-resource-id "$CE_VM_ID" \
     --resource-port 65500 \
     --port 65500
   ```

4. Confirm that Site Console challenges for authentication.

   ```bash
   curl --insecure --head https://localhost:65500/
   ```

   A healthy unauthenticated service returns `401 Unauthorized` and the
   `Volterra Site Console` Basic authentication realm.

5. Read the CE site name that corresponds to the selected node.

   ```bash
   export SITE_NAME=$(terraform -chdir=terraform output -json xc_site_names | jq -r --arg key "$CE_KEY" '.[$key]')
   ```

6. Read the site-managed password locally.

   ```bash
   terraform -chdir=terraform output -json site_console_admin_passwords | jq -r --arg site "$SITE_NAME" '.[$site]'
   ```

   Do not paste this value into a ticket, terminal transcript, or documentation.

7. Verify the credential without placing it on the command line.

   ```bash
   curl --insecure --user admin --output /dev/null --write-out '%{http_code}\n' https://localhost:65500/
   ```

   Enter the password when `curl` prompts. A working credential returns `200`.

8. Open `https://localhost:65500/` in a browser and sign in as `admin`.

9. Stop the tunnel with `Ctrl+C` when you finish.

</Steps>

## How Terraform manages the credential

Terraform generates one password for each Secure Mesh v2 site and sets it through the
site's supported `admin_user_credentials.admin_password` field. The API receives the
Base64 value through its `string:///` secret contract over authenticated HTTPS. No cloud
extension or post-boot script modifies the CE operating system.

The sensitive output is redacted from ordinary `terraform output`, but the password still
exists in Terraform state. Protect the Azure backend as a secret store.

## Troubleshoot the tunnel

| Symptom | Cause | Action |
| --- | --- | --- |
| `bastion_name` is `null` | Bastion is disabled | Set `enable_bastion = true`, plan, and apply |
| `Defined port is currently unavailable` | Another process owns local port `65500` | Stop it or choose another local `--port` |
| `Custom ports are not allowed` | The tunnel used a target IP | Use `--target-resource-id`; keep `--resource-port 65500` |
| `401 Unauthorized` | The request has no valid credential | Sign in as `admin` with the password for that site name |
| Browser rejects the certificate | The node-local certificate is not trusted for `localhost` | Inspect the certificate and follow your certificate policy |

Use [serial console](../serial-console/) if the node has no working network path. Use the
[debug API](../debug-api/) for repeatable collection after the site becomes `ONLINE`.
