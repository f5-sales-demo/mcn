Treat each showcase Customer Edge as disposable. Terraform creates its site, issues site-scoped
cloud-init once, and boots the node. Rebuild from configuration instead of preserving changes made
on the appliance.

## Select software at creation

`ce_os_version` and `ce_sw_version` select the Azure and Canadian Customer Edge versions. Empty
values ask F5 Distributed Cloud for its current advertised versions. A concrete value pins a new
node at creation.

The version fields are create-time inputs for this deployment. Don't use an ordinary update to
change an installed node. Rebuild the disposable stack and verify the resulting version and site
state.

## Keep enough disk capacity

The Azure CE module provisions a 64 GB operating-system disk and rejects values below 40 GB. This
avoids the marketplace image's smaller default, which was insufficient for the advertised software
pair during validation. The KVM CE uses an 80 GB overlay as required by the KVM showcase contract.

<Aside type="caution" title="Don't reduce the disk to a measured floor">
Payload sizes change between software builds. Keep capacity headroom and validate a new version on
a disposable node before using it in a presentation.
</Aside>

## Rebuild safely

<Steps>

1. **Save and review the plan.**

   Confirm that the CE node and its `xcsh_site_cloud_init` issuance are replaced together. A node
   must never boot with a token already consumed by an earlier instance.

2. **Remove the node from service.**

   Verify that the remaining BGP or ILB paths continue serving traffic before replacement.

3. **Apply the reviewed replacement.**

   Terraform removes the dependent node state before issuing new cloud-init for its site.

4. **Wait for the site to report `ONLINE`.**

   Confirm the installed operating-system and software versions from the site status or node health
   output.

5. **Verify routing and application traffic.**

   Restore the path only after the route and service evidence matches the
   [verification procedure](../workflows/).

6. **Run a clean plan.**

   A clean plan proves the issued cloud-init remained in state and was not refreshed into another
   one-time credential.

</Steps>

<Aside type="danger" title="Replacing a CE discards node-local state">
A replacement loses anything changed only on the appliance. Keep supported configuration in
Terraform and use the on-box configuration commands only when F5 support directs you.
</Aside>
