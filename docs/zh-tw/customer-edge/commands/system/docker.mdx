Docker 負責執行平台服務。Kubernetes 工作負載則由
[CRI-O](../crictl/) 管理。

## `docker-ps`

```bash
{"command":["docker-ps"]}
```

```text file=../../../../_data/sitecli-docker-ps.txt
```

<Aside type="tip" title="三個容器是完整清單，而非節點異常">
`vpm`、`argo_watch` 與 `site-console`。由於節點大部分服務執行於 CRI-O 之下，若您預期在此看到 Kubernetes 工作負載，簡短的 `docker-ps` 輸出看起來可能像是故障。實際上並非如此——這是健康 CE 上 Docker 容器的完整集合，`vpm` 存在且狀態為 `Up` 是此頁面最重要的一行資訊。
</Aside>

## `docker-images`

```bash
{"command":["docker-images"]}
```

```text file=../../../../_data/sitecli-docker-images.txt
```

映像標籤可識別節點實際執行的平台版本，建議與 [`health`](../health/) 所回報的軟體建置版本相互比對。

## `docker-inspect`

```bash
{"command":["docker-inspect","<container-id-or-name"]}
```

```text file=../../../../_data/sitecli-docker-inspect.txt
```

可接受名稱或 ID，因此 `docker-inspect vpm` 可正常運作，且在重啟後仍保持穩定。完整 JSON 內容包含：掛載點、環境變數、重啟策略及退出狀態。

## `docker-logs`

```bash
{"command":["docker-logs","<container-id-or-name>"]}
```

```text file=../../../../_data/sitecli-docker-logs.txt
```

`docker-logs vpm` 是查看註冊錯誤最快速的途徑。若需取得包含時間戳記且跨重啟的相同資訊，請改用 [`journalctl`](../journalctl/)。
