於 2026-07-28 從此部署的一個 CE 擷取。這些為節點上的指令，因此透過 Site CLI 而非 debug API 執行；`sitecli/exec-catalog.json` 記錄介面，`sitecli/capture-manifest.json` 記錄節點資訊。

Envoy 在 Customer Edge 上終止並代理應用程式流量。以下四個指令查詢其管理介面，且均不在
[debug API](../../../access/debug-api/) 之列。

<Aside type="note" title="每一個都以 curl 進度計開頭">
這些是對 Envoy 管理端點的 `curl` 包裝器，呼叫時未加 `-s`，因此以下每個擷取內容的前兩三行均為 curl 將傳輸進度寫入 stderr 的輸出：

```text
  % Total    % Received % Xferd  Average Speed   Time    Time     Time  Current
                                 Dload  Upload   Total   Spent    Left  Speed
  0     0    0     0 …
```

這不是 Envoy 的輸出，也不是錯誤訊息。它同時具有實用價值：`% Received` 的位元組計數可讓您判斷 Envoy 是否有任何回應，從而區分「未設定監聽器」與「管理介面未回應」兩種情況。
</Aside>

## `envoy-listeners`

Envoy 已安裝的每個監聽器，格式為 `name:address:port`。

```bash
execcli envoy-listeners
```

```text file=../../../../_data/sitecli-envoy-listeners.txt
```

**應注意的事項。** 在此部署中，監聽器包含 `10.250.0.10:80`——即 CE 向 BGP 公告的 VIP。這單一行將三個層次串聯在一起：若 [`show-ip-bgp-summary`](../../network/bgp/) 顯示前綴正在被公告，但此監聽器不存在，則路由正被吸引至一個不會提供服務的節點，這是 ECMP 集合中最嚴重的故障模式，因為流量會被負載分散至黑洞。

尾端的 `[fe80:…]:80` 是監聽器所綁定介面的鏈路本地位址。

**它無法告訴您的事項。** 與上游健康狀態無關——無論其後方是否可達，監聽器均會存在。如需相關資訊，請使用 `envoy-clusters`。

## `envoy-clusters`

每個叢集及其每優先級的連線與請求限制。

```bash
execcli envoy-clusters
```

```text file=../../../../_data/sitecli-envoy-clusters.txt
```

**應注意的事項。** 各行格式為 `cluster::scope::key::value`。`observability_name` 項目可識別每個叢集，而 `default_priority::max_connections`、`max_pending_requests` 及 `max_requests` 這三項則顯示請求限制——若某叢集持續達到其 `max_pending_requests`，表示其正受到設定的節流，而非上游的限制。

## `envoy-config-dump`

Envoy 的完整設定，以 JSON 格式呈現。檔案較大：在閒置的示範節點上為 126 KB。

```bash
execcli envoy-config-dump
```

```text file=../../../../_data/sitecli-envoy-config-dump.txt
```

**應注意的事項。** 頂層的 `configs` 陣列中，每種設定類型各有一個物件——包括 bootstrap、叢集、監聽器、路由及密鑰。當監聽器或叢集存在但行為異常時，可查閱此項目，建議以搜尋方式使用而非逐行閱讀。

## `envoy-hc-config-dump`

專門針對健康檢查的設定。

```bash
execcli envoy-hc-config-dump
```

```text file=../../../../_data/sitecli-envoy-hc-config-dump.txt
```

**應注意的事項。** 在此部署中，它回傳**單一位元組**——在 `curl` 進度計中顯示為 `100 1`——表示未安裝任何健康檢查設定。對於未設定健康檢查來源池的 CE 而言，這是預期狀態，值得特別留意：此處的空白結果並非查詢失敗。
