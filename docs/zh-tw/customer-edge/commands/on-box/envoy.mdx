擷取自 2026-07-28，來源為此部署中的一個 CE。這些是節點上的本機命令，因此透過 Site CLI 而非 debug API 取得；`sitecli/exec-catalog.json` 記錄了介面範圍，而 `sitecli/capture-manifest.json` 記錄了取自哪一個節點。

Envoy 在 Customer Edge 上終結並代理應用程式流量。以下四個命令會查詢它的管理介面，且沒有任何一個屬於 [debug API](../../../access/debug-api/)。

<Aside type="note" title="每一個命令都以 curl 進度表開頭">
它們都是針對 Envoy 管理端點的 `curl` 包裝，呼叫時未加上 `-s`，因此下方每份擷取結果的前兩三行都是 curl 寫入 stderr 的傳輸進度：

```text
  % Total    % Received % Xferd  Average Speed   Time    Time     Time  Current
                                 Dload  Upload   Total   Spent    Left  Speed
  0     0    0     0 …
```

那不是 Envoy 的輸出，也不是錯誤。它同時也很有用：`% Received` 的位元組計數會告訴你 Envoy 是否有回傳任何內容，這能區分「沒有設定任何 listener」與「管理介面沒有回應」。
</Aside>

## `envoy-listeners`

Envoy 已安裝的每一個 listener，格式為 `name:address:port`。

```bash
execcli envoy-listeners
```

```text file=../../../../_data/sitecli-envoy-listeners.txt
```

**要注意什麼。** 在此部署中，listener 帶有 `10.250.0.10:80` — 也就是 CE 向 BGP 宣告的 VIP。這一行把三個層次連結起來：如果 [`show-ip-bgp-summary`](../../network/bgp/) 顯示該前綴正在被宣告，但這個 listener 卻不存在，代表路由被吸引到一個不會提供服務的節點，這在 ECMP 集合中是最糟的故障模式，因為流量會被分攤進黑洞。

結尾的 `[fe80:…]:80` 是該 listener 所綁定介面的 link-local 位址。

**它不會告訴你什麼。** 完全不會提供上游健康狀態的資訊 — 不論後端是否可達，listener 都會存在。這部分請使用 `envoy-clusters`。

## `envoy-clusters`

每一個 cluster，以及其各優先權層級的連線與請求限制。

```bash
execcli envoy-clusters
```

```text file=../../../../_data/sitecli-envoy-clusters.txt
```

**要注意什麼。** 每一行的格式為 `cluster::scope::key::value`。`observability_name` 項目用於識別各個 cluster，而 `default_priority::max_connections`、`max_pending_requests` 與 `max_requests` 這三個值則是請求限制出現的位置 — 若某個 cluster 卡在其 `max_pending_requests` 上限，表示它是被組態設定節流，而不是被上游節流。

## `envoy-config-dump`

Envoy 的完整組態，以 JSON 呈現。檔案很大：在一個原本閒置的示範節點上為 126 KB。

```bash
execcli envoy-config-dump
```

```text file=../../../../_data/sitecli-envoy-config-dump.txt
```

**要注意什麼。** 最上層的 `configs` 陣列中，每種組態類型各有一個物件 — bootstrap、clusters、listeners、routes、secrets。當某個 listener 或 cluster 存在但行為不如預期時，就該取用這份輸出，而且應該用搜尋而非逐行閱讀的方式處理它。

## `envoy-hc-config-dump`

專門針對健康檢查的組態。

```bash
execcli envoy-hc-config-dump
```

```text file=../../../../_data/sitecli-envoy-hc-config-dump.txt
```

**要注意什麼。** 在此部署中它只回傳**單一位元組** — 在 curl 進度表中顯示為 `100 1` — 表示沒有安裝任何健康檢查組態。對於沒有健康檢查來源池（origin pool）的 CE 而言，這是預期的狀態，值得認清這一點：這裡的空結果並不代表查詢失敗。
