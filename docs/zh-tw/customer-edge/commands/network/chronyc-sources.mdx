`MS` 欄位是**兩個**字元，而非一個。第一個字元代表模式 —— `^` 表示伺服器 ——
而**第二個**字元代表狀態：`*` 是目前選定的來源，`+` 是可接受的
替代來源，`-` 是被選擇演算法排除的來源，`?` 則是無法連線的來源。
因此 `^*` 是選定的伺服器，而 `^?` 是無法連線的伺服器；只讀第一個
字元完全無法提供任何資訊，因為這裡每一行的第一個字元都是 `^`。

恰好有一個 `*` 就是健康的狀態，即使其他來源顯示 `?` 也依然成立。

`Reach` 是最近八次輪詢的八進位暫存器，因此 `377` 代表八次全部成功。
任何較低的數值都表示最近八次中至少有一次未成功 —— 但這也包含了某個
最近才開始回應的來源，其暫存器仍在填充中。撰寫本文時執行的一次輸出
在某個節點上同時顯示了 `3`、`37` 與 `377`，該節點已選定一個來源
（`^*`），且其登入橫幅顯示 `NTP: Synced`。請將 `Reach` 與 `LastRx`
一併判讀，後者顯示該來源上次回應距今多久，而不要把任何低於 `377`
的數值都視為故障。

當認證或 TLS 在沒有明顯原因的情況下失敗時，值得及早檢查此項：
時鐘漂移過大的節點會拒絕有效的憑證，其權杖也會被拒絕，
而由此產生的錯誤訊息很少會提及時間問題。
