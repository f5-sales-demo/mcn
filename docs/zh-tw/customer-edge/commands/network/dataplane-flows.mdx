Argo 會追蹤每一條連線。查詢此表格的方式比表格本身的內容更為重要，
因為完整傾印在原理上是無界限的，實際操作上也相當不便。

<Aside type="caution" title="629,760 是表格的容量，而非流量數目">
標頭行 `Flow table(size 161218560, entries 629760)` 回報的是資料
平面配置了多少插槽，且在此處的每個節點上都相同，與負載無關。即時的流量
數目並不在該行中。下方數行的 `Entries: Created … Added … Deleted …` 是
生命週期計數器，而實際已填入的流量則是圖例之後印出的那些記錄 ——
在撰寫本文時執行的一次結果中共有 73 筆，回應總共 542 行。
</Aside>

## `flow-l-match`

幾乎總是你所需要的指令。接受一個位址，或是一個位址加通訊埠。

```bash
{"command":["flow-l-match","100.127.192.10:53"]}
```

```text file=../../../../_data/sitecli-flow-l-match.txt
```

每條流量上的動作才是重點：`F` 轉送、`D` 丟棄、`N` NAT。若某條流量存在
且動作為 `D`，表示資料平面做出了刻意的決定，這會將你的排查方向導向
政策，而非連線能力。

## `flow-l`

完整傾印。

```bash
{"command":["flow-l"]}
```

<Aside type="caution" title="已裁剪，且大小會變動">
上方的擷取內容是從 1,186 行的回應中裁剪出的前 60 行。撰寫本文時執行的
一次結果回傳了 542 行 —— 回應長度取決於有多少流量處於作用中，因此
這兩個數字都不是該指令的固有屬性。除非你真的需要檢視整張表格，否則請使用
`flow-l-match`。
</Aside>
