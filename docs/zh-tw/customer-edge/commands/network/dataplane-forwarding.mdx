Argo 將轉發狀態與 Linux 核心分開維護。當
[`ip`](../ip/) 與這些命令顯示的結果不一致時，以這些命令的結果為準進行流量轉發。

## `rt`

vRouter 路由表，依 VRF 區分。

```bash
{"command":["rt","--dump","2"]}
```

```text file=../../../../_data/sitecli-rt.txt
```

<Aside type="danger" title="VRF id 並非 BGP 所回報的那個">
`show-ip-bgp-summary` 顯示的是 `vrf-id 3`。那是 FRR 的編號，與 vRouter 的表格 id 屬於不同的命名空間。將其傳入此處會以一種讀起來像節點損壞的方式失敗：

```
vRouter(Response):  [No such file or directory (2)]
```

傳入 `--dump 0` 也會得到相同的回應。在此拓撲中，**VRF 2** 是已填入資料的 inet4 表，VRF 1 則持有兩條路由。若您不確定 id，請從 1 開始向上探測，而非信任 BGP 的輸出。
</Aside>

## `nh`

下一跳表。每條路由都指向一個下一跳 id，此表負責解析它們。

```bash
{"command":["nh","--list"]}
```

```text file=../../../../_data/sitecli-nh.txt
```

每個條目包含一個 `Type` 及其所屬的 VRF。這些節點上共出現八種類型，
計數後在所有三個 CE 上的比例完全相同：

```text
Tunnel 558   Encap 27   NAT 22   Vrf 16   Receive 14   Composite 4   Drop 2   Resolve 2
```

解析至 `Drop` 下一跳的路由為黑洞路由，當某個前綴出現在 `rt` 中但流量仍然消失時，這種組合值得重點檢查。

<Aside type="caution" title="上方的擷取內容已被截斷，因此並未包含所有類型">
這只是 3,849 行中的前 60 行。`Tunnel` 是目前為止最常見的類型，在這 60 行中完全未出現——因此請勿將此擷取內容視為完整的類型清單，也請勿因某類型未出現在截斷的擷取內容中，就斷定該節點上不存在該類型。以上計數來自未截斷的完整回應。
</Aside>

## `vif`

虛擬介面表：資料平面所綁定的介面，以及各介面的計數器。

```bash
{"command":["vif","--list"]}
```

```text file=../../../../_data/sitecli-vif.txt
```

頂部的旗標說明值得閱讀一次——`Vp` 標記 vhost 實體介面，`Dpdk` 標記由 DPDK 管理的介面。使用此表可確認資料平面已接管您預期的介面，並查看 Linux 不會顯示的 RX 與 TX 計數器（因為流量從未到達核心）。

## `mpls`

```bash
execcli mpls --help
```

Argo MPLS 表。**僅可從機器本端存取**——`mpls` 不在除錯 API 上，因此與上述 `rt`、`nh` 及 `vif` 不同，需要透過 [SSH](../../../access/ssh/) 或
[序列主控台](../../../access/serial-console/)，並使用
[`execcli`](../../on-box/) 執行。

此處未提供擷取輸出。在此部署中，CE 使用 BGP 與 ECMP 轉發 IPv4，不使用 MPLS 標籤，因此擷取結果只會顯示空表，無法提供任何參考價值。其存在性及 `--help` 參數形式已從設備自身的補全選單中驗證；其填入後的輸出內容在此不予重現。
