Azure 序列主控台透過 Azure 平台連接至節點的模擬序列埠。它不經過 F5 Distributed Cloud 控制平面、節點的資料平面，或任何由節點控制的網路路徑 — 這正是它在其他方式均失效時仍能運作的原因。

當 CE **從未成功啟動**時，請使用此方式：註冊失敗、站台未出現在租戶中，或節點已啟動但無對外路由。在上述所有情況下，[debug API](../debug-api/) 沒有可用的隧道進行轉送，且節點出廠時 SSH 為關閉狀態。

## 先決條件：開機診斷

Azure 要求 VM 必須啟用開機診斷，才能連接序列主控台。此設定由 `terraform/modules/ce-node` 啟用：

```hcl
boot_diagnostics {}
```

空的區塊會選取 Azure 受管儲存體，因此無需自行管理診斷儲存體帳戶、生命週期原則或存取金鑰。在節點上確認此設定：

```bash
az vm show -g <resource-group> -n <vm-name> --query diagnosticsProfile
```

```json
{ "bootDiagnostics": { "enabled": true } }
```

<Aside type="caution" title="啟用並不具溯及效力">
開機診斷在**開機時**擷取序列日誌。對已在執行中的 VM 啟用此功能，並不會為已發生的開機程序產生日誌，因此 `az vm boot-diagnostics get-boot-log` 會回應：

```
<Error><Code>BlobNotFound</Code><Message>The specified blob does not exist.
```

這是預期行為，並非故障。節點下次重新開機後才會產生開機日誌。然而，即時主控台連接可立即運作 — 它不依賴日誌。
</Aside>

## 在無終端機情況下檢查可用性

連接需要互動式工作階段，但判斷是否*能夠*連接只需兩個 API 呼叫。兩者均可用於健康狀態檢查。

服務必須對訂閱啟用 — 管理員可於整個租戶範圍內停用：

```bash
az rest --method get --url \
  "https://management.azure.com/subscriptions/<sub>/providers/Microsoft.SerialConsole/consoleServices/default?api-version=2018-05-01"
```

```json
{ "properties": { "disabled": false } }
```

接著，對特定節點的序列埠發出連線請求：

```bash
az rest --method post \
  --headers "Content-Type=application/json" --body '{}' --url \
  "https://management.azure.com/subscriptions/<sub>/resourceGroups/<rg>/providers/Microsoft.Compute/virtualMachines/<vm>/providers/Microsoft.SerialConsole/serialPorts/0/connect?api-version=2018-05-01"
```

以 `wss://` 開頭的 `connectionString` — 在此部署中為 `eastus.gateway.serialconsole.azure.com` — 表示主控台目前可供連接。在啟用開機診斷之前，此呼叫沒有任何目標可供連接。

<Aside type="danger" title="該連線字串是一個憑證">
它是嵌入 URL 中的短效持有人權杖。請勿將其記錄至日誌、貼入工單，或提交至版本控制。當您示範呼叫成功時，僅顯示主機名稱即可。
</Aside>

## 連接步驟

<Steps>

1. 安裝擴充功能（僅需一次）：

   ```bash
   az extension add --name serial-console
   ```

2. 連接：

   ```bash
   az serial-console connect -g <resource-group> -n <vm-name>
   ```

3. 您將進入節點本身的登入提示，而非直接進入 shell。此為 Site CLI，需要節點上設定的憑證 — 佈建時的管理員密碼，或透過 change-password 端點設定的密碼。序列主控台證明了*通道*可用；它並不繞過驗證機制。

</Steps>

<Aside type="caution" title="需要真實終端機">
`az serial-console connect` 會將終端機設為原始模式，因此無法在腳本、管線，或任何不具備 TTY 的情境中執行。它會在聯繫 Azure 之前於用戶端側失敗：

```
ERROR: (19, 'Operation not supported by device')
  File ".../azext_serialconsole/custom.py", line 633, in connect_serialconsole
    GV.serial_console_instance.launch_console()
```

此錯誤追蹤涉及終端機處理，而非序列主控台中斷 — 上述兩個 API 呼叫仍會回報主控台為可用狀態。若需要可自動化的信號，請改用那些 API 呼叫，而非嘗試將連接操作腳本化。
</Aside>

## 此處可觀察到而 API 無法顯示的資訊

- **cloud-init** 執行中、失敗，或從未啟動 — 這是節點從未完成註冊的常見原因。
- **針對 `register.ves.volterra.io` 的註冊嘗試**，包括設定錯誤或租戶拒絕的權杖。
- **核心與開機訊息**，來自任何代理程式執行之前的階段。
- 節點處於**無可用網路路徑**的狀態，此情況會使所有其他存取路由失效。

對於狀態為 `ONLINE` 的節點，建議優先使用 debug API：它可腳本化、能產生可重複執行的證據，且不會佔用唯一的序列埠。
