存取路徑共有兩條，採用哪一條取決於節點的狀態，而非個人偏好。

| 節點狀態 | 路徑 | 可腳本化 | 涵蓋範圍 |
| --- | --- | --- | --- |
| `ONLINE` | [除錯 API](./debug-api/) | 是 | 34 個指令，包含唯讀與特權操作 |
| 未註冊或無法連線 | [序列主控台](./serial-console/) | 否 — 需要終端機 | 節點上的完整 Site CLI |

## 為何此分流不是偏好問題

除錯 API 由 F5 Distributed Cloud 控制平面提供服務，該平面透過 `vpm` 在註冊期間建立的隧道將請求轉發至節點。未完成註冊即表示沒有隧道，也就意味著 API 無從轉發。

其失敗方式並不直觀，而非明顯可辨，因此從未成功上線的節點看起來會像是 API 問題。

序列主控台則走完全不同的路徑——透過 Azure 平台連接至節點的模擬序列埠。它不在乎節點是否已完成註冊、是否具備網路可達性，或資料平面是否正常運作。這種獨立性正是其核心價值所在，也是為何 CE 虛擬機器必須保持開機診斷功能啟用的原因。

<Aside type="note" title="應優先選擇的方式">
若您正在撰寫自動化腳本，或收集日後需要重新執行的證據，請使用除錯 API。若註冊本身就是出問題的環節，序列主控台並非備用選項——而是唯一的選擇。
</Aside>

## 憑證

兩條路徑使用不同的憑證，且均不應出現在指令列中。

- **除錯 API** — F5 Distributed Cloud API 權杖，以 `XCSH_API_TOKEN` 表示，搭配 `XCSH_API_URL` 作為租戶 URL。`xcsh` 情境設定檔位於 `~/.config/xcsh/contexts/<tenant>.json`，兩者均儲存於此，這也是 `scripts/capture-sitecli.sh` 在環境變數未提供時的讀取來源。
- **序列主控台** — 您的互動式 Azure 登入。此處不使用服務主體：F5 企業 Entra 租戶不允許佈建服務主體，這也是為何本流程的任何環節均無法在 CI 中執行。

<Aside type="danger" title="切勿將權杖作為引數傳遞">
出現在指令列上的權杖會留存於 Shell 歷史記錄及程序清單中，機器上的其他所有使用者均可讀取。`capture-sitecli.sh` 基於此原因明確拒絕 `--token` 參數，改為透過標準輸入將標頭傳遞給 `curl`。
</Aside>
