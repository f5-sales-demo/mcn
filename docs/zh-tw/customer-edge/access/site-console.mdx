擷取自 2026-07-28，取自此部署的其中一個 CE。`sitecli/capture-manifest.json`
記錄了是哪個節點，而 `scripts/capture-sitecli.sh --check` 會針對線上 CE
重新驗證指令介面。

每個 Customer Edge 都在 `https://<sli-ip>:65500` 上提供 F5 的站點主控台。在此
部署上，這通常是應該優先嘗試的途徑。

它對您的要求最少：不需要散發 SSH 金鑰、不需要維護跳板主機、節點上不需要公用 IP，
也不需要更換 VM 才能啟用。誰可以連線變成一項 **Azure RBAC 決策**。而且它不需要站點
已註冊：本頁面最初擷取時，三個站點全都回報 `site_state: FAILED`，而當它們變為
`ONLINE` 後針對相同節點重新驗證，結果完全相同。

問題在於站點主控台僅在節點的內部 (SLI) 位址上回應，而該位址只能從 VNet 內部存取。
Azure Bastion 彌補了這個落差，且不會在網路上增加其他任何東西。

<Aside type="note" title="這裡驗證了什麼，又沒有驗證什麼">
本頁面上的每一個指令與每一項輸出都是針對此部署中的 `f5-xc-ce-vm-01` 執行的，
並逐字重現，包括失敗的情況。

**驗證已通過驗證**：設備的 `admin` 憑證透過通道回傳 `200`。*未*進行實測的是主控台本身 —
以下內容不會描述您進入之後可以看到或執行什麼。

**Azure RBAC 未經驗證。**每次執行都是以訂用帳戶擁有者的身分進行，因此步驟 2 中的 Reader
需求是 Microsoft 的文件化要求，而非此處實測所得。
</Aside>

<Aside type="caution" title="Bastion 是選擇性啟用，預設不會部署">
`enable_bastion` 預設為 `false`，因此在預設的 `terraform apply` 下不會有 Bastion
主機，且 `terraform output -raw bastion_name` 為 `null`。請在
`terraform/terraform.tfvars` 中設定 `enable_bastion = true` — 在此部署上它是 `true`。

它之所以是選擇性啟用是基於成本，而非風險：Standard SKU 主機從佈建那一刻起就會按小時
計費，無論是否有人開啟通道 — 在 `eastus` 以隨附的兩個擴充單位計算為每小時 USD
0.29（零售價，2026-07），約每月 USD 212。當示範不需要主控台存取時，請再將它關閉。
</Aside>

## 開始之前

<Steps>

1. 登入 Azure 並新增 Bastion 擴充功能。通道功能是原生用戶端功能，
   而該擴充功能預設不會安裝。

   ```bash
   az login
   az extension add --name bastion
   ```

2. 對 CE 虛擬機器、其網路介面與 Bastion 主機持有 **Reader** 權限。
   這是 Microsoft 的文件化要求，且**在此處未經驗證** — 此部署中的每次執行
   都是以訂用帳戶擁有者身分進行，因此沒有任何較低權限角色被證實為
   足夠或不足夠。

3. 確認 Bastion 已部署且具備所需能力。Basic SKU 既不支援通道也不支援
   以 IP 為基礎的連線，因此這裡的 `Standard` 與 `True` 兩者都至關重要。

   ```bash
   az network bastion list -g "$(terraform output -raw resource_group_name)" \
     --query "[].{name:name, sku:sku.name, tunneling:enableTunneling}" -o table
   ```

   ```text
   Name               Sku       Tunneling
   -----------------  --------  -----------
   ce-ha-lab-bastion  Standard  True
   ```

</Steps>

## 開啟通道

請從 `terraform output` 取得數值，而不要手動輸入 — 資源 ID 不是應該手動組合的東西。

<Steps>

1. 讀取 Bastion 主機名稱、資源群組，以及目標 CE 的 VM 資源 ID。

   ```bash
   cd terraform
   BASTION=$(terraform output -raw bastion_name)
   RG=$(terraform output -raw resource_group_name)
   VM_ID=$(terraform output -json ce_vm_ids | jq -r '.eastus01')
   ```

   ```text
   ce-ha-lab-bastion
   rg-mcn-ce-ha-rmordasiewicz
   /subscriptions/…/providers/Microsoft.Compute/virtualMachines/f5-xc-ce-vm-01
   ```

   <Aside type="caution" title="此對應表以站點為鍵，而非以 VM 名稱">
   `ce_vm_ids` 的鍵是 `eastus01`、`eastus02`、`eastus03` — **不是** VM 名稱。像
   `jq -r '."f5-xc-ce-vm-01"'` 這樣的篩選器會回傳 `null`，接著通道就會因為
   資源 ID 為空而失敗。若不確定，請列出它們：

   ```bash
   terraform output -json ce_vm_ids | jq -r 'keys | join(", ")'
   ```

   ```text
   eastus01, eastus02, eastus03
   ```

   </Aside>

2. 啟動通道。它會保持連接埠開啟直到停止，因此請將它放到背景執行或使用
   第二個終端機。

   ```bash
   az network bastion tunnel \
     --name "$BASTION" \
     --resource-group "$RG" \
     --target-resource-id "$VM_ID" \
     --resource-port 65500 \
     --port 65500 &
   ```

   ```text
   WARNING: Opening tunnel on port: 65500
   WARNING: Tunnel is ready, connect on port 65500
   WARNING: Ctrl + C to close
   ```

   三行全都以 `WARNING:` 為前綴。那是 Azure CLI 將進度寫入
   stderr，並非問題。請等待 `Tunnel is ready` 後再連線。

3. 確認接聽程式在本機的 loopback 上：

   ```bash
   lsof -nP -iTCP:65500 -sTCP:LISTEN
   ```

   ```text
   COMMAND   PID  USER  FD  TYPE  DEVICE  SIZE/OFF  NODE  NAME
   Python  41648  you   7u  IPv4  …            0t0   TCP  127.0.0.1:65500 (LISTEN)
   ```

4. 開啟主控台。通道使它成為本機服務，因此位址是 `localhost` — 而不是
   節點的位址。

   ```bash
   open https://localhost:65500/          # macOS
   xdg-open https://localhost:65500/      # Linux
   ```

5. 完成後請停止通道 — 按 `Ctrl-C`，若您放到背景執行則使用 `kill %1`。
   讓它保持開啟會佔用本機連接埠 65500 與 Bastion 工作階段。

</Steps>

## 您將會看到什麼

**一個憑證對話框，而不是登入頁面。**主控台使用 HTTP 基本驗證，因此
瀏覽器會跳出自己的使用者名稱與密碼提示。沒有表單可看：

```bash
curl -skI https://localhost:65500/
```

```text
HTTP/1.1 401 Unauthorized
WWW-Authenticate: Basic realm="Volterra Site Console"
Content-Type: text/html; charset=utf-8
Content-Length: 0
```

帶有該 realm 的 `401` 表示主控台運作正常。這正是未經驗證的
請求應該得到的結果 — 而對同一 URL 提供 `admin` 憑證會回應
`200`，這就是您在開啟瀏覽器前確認憑證的方式：

```bash
curl -sk -u admin -o /dev/null -w '%{http_code}\n' https://localhost:65500/
```

```text
Enter host password for user 'admin':
200
```

`-u admin` 不加冒號會讓 `curl` 提示輸入密碼，而不是從命令列取得，
否則密碼會出現在 shell 歷史記錄與行程清單中。

**憑證警告，同時有三個原因。**直接檢查憑證：

```bash
openssl s_client -connect localhost:65500 -servername localhost </dev/null 2>/dev/null \
  | openssl x509 -noout -subject -issuer -dates
```

```text
subject=C=US, ST=California, L=Santa Clara, O=Volterra, OU=Volterra Edge Services, CN=site-local.volterra.io
issuer=C=US, ST=California, L=Santa Clara, O=Volterra, OU=Volterra Edge Services, CN=site-local.volterra.io
notBefore=Oct 25 04:51:31 2024 GMT
notAfter=Oct 25 04:51:31 2025 GMT
```

subject 與 issuer 相同，因此它是自我簽署的。名稱是 `site-local.volterra.io`，
而您連線的是 `localhost`，所以不會相符。而且在此部署所執行的組建上，
**該憑證已於 2025 年 10 月 25 日到期** — 設備隨附此憑證，而本存放庫中
沒有任何機制會更新它。

請預期會出現直白的瀏覽器警告，而且每次都會出現。上面的 subject 這一行才是
有用的部分：那是您確認自己連到的是設備，而非其他在本機連接埠 65500 上
接聽之物的方式。

## 管理員憑證

以 `admin` 身分登入。**本文件不會公布密碼，也不應該公布。**

<Aside type="danger" title="在此部署上，該密碼仍是 F5 的原廠預設值">
這是實測事實，不是猜測：原廠預設憑證今天在全部三個 CE 上都能通過驗證並
回傳 `200`。F5 公開了該預設值並要求必須變更它，而它並未被變更。

實際後果是，在此部署上「對 Bastion 持有 Reader 權限」等同於完整的設備主控台
存取權，只要對方知道一個記載於 F5 公開文件中的值。請變更它，並將變更它視為
部署節點的一部分，而非事後的強化措施。
</Aside>

不公布它在這裡比看起來更重要，有兩個原因：

- 本文件是公開的。印出整個機群目前的主控台密碼，會讓
  「對 Bastion 持有 Reader 權限」對任何閱讀此頁的人變成完整的設備存取權。
- 文件中公布的密碼在有人輪替它的那一刻就是錯的，而且錯得最具誤導性 —
  讀者會下結論認為自己的存取權出了問題，而不是這個頁面過時了。

一旦密碼經過輪替，請從您團隊存放營運機密的地方取得它。

<Aside type="caution" title="從 Terraform 設定密碼未經驗證">
站點物件上的 `admin_user_credentials.admin_password` 看起來是設定此項目的宣告式
方式。但**尚未**確認它在此組建上能夠影響站點主控台，因此請勿
假設它可以。

也不要把 [SSH 頁面](../ssh/)當作任一方向的證據。它關於
`admin_password`「毫無變化」的發現是針對 SSH 驗證所測得，而 `vpm`
對 `admin` 使用者完全略過 SSH 驗證。那對主控台沒有任何說明力。
</Aside>

## 為何通道必須指向資源 ID

`--target-resource-id` 是必要的。改為指向節點的位址會被拒絕 —
無論您使用哪個位址，因此這裡刻意不列出任何真實位址：

```bash
az network bastion tunnel --name "$BASTION" -g "$RG" \
  --target-ip-address <any-sli-address> --resource-port 65500 --port 65501
```

```text
ERROR: Custom ports are not allowed. Allowed ports for Tunnel with IP connect is 22, 3389.
```

原因**不是**以 IP 為基礎的連線被停用 — 在此 Bastion 上
`ip_connect_enabled` 是 `true`。無論該設定為何，Microsoft 都不支援在以 IP 為基礎的
原生用戶端連線上使用自訂連接埠
（[Azure 文件](https://learn.microsoft.com/azure/bastion/connect-ip-address)），而 65500 是
自訂連接埠。在這裡檢查 Bastion 組態毫無幫助；請使用資源
ID。

## 當它無法運作時

| 症狀 | 原因 | 修正方式 |
| --- | --- | --- |
| `ERROR: Custom ports are not allowed. Allowed ports for Tunnel with IP connect is 22, 3389.` | 使用了 `--target-ip-address` | 改用 `--target-resource-id` |
| `ERROR: Defined port is currently unavailable` | 另一條通道已佔用該本機連接埠 | 停止另一條通道，或傳入不同的 `--port`；`--resource-port` 維持 65500 |
| `terraform output -raw bastion_name` 為 `null` 或空值 | Bastion 未部署 | 設定 `enable_bastion = true` 並套用 |
| 通道啟動但資源 ID 為空 | `jq` 篩選器使用了 VM 名稱而非站點鍵 | 以 `eastus01`/`02`/`03` 為鍵 |
| `401 Unauthorized`，realm 為 `Volterra Site Console` | 並非故障 — 未經驗證的請求 | 提供 `admin` 憑證 |
| 瀏覽器拒絕該憑證 | 自我簽署、名稱不符，且自 2025 年 10 月起已到期 | 屬預期情況；確認 subject 為 `CN=site-local.volterra.io` 後繼續 |

<Aside type="note" title="未重現授權失敗情況">
RBAC 權限不足是另一個明顯的失敗方式，但要重現它就必須從
共用部署中移除角色指派，因此此處不以逐字錯誤訊息記錄。
若通道在啟動時因授權錯誤而失敗，請檢查 VM、其 NIC 與 Bastion 主機
三者上的 Reader 權限。
</Aside>
