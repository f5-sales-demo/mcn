每個 Customer Edge 均在 `https://<sli-ip>:65500` 提供 F5 的站台控制台。在本部署中，這通常是首先嘗試的路徑。

它對您的要求最少：無需散發 SSH 金鑰、無需維護跳板機、節點上不需公開 IP，也不需要替換 VM 才能啟用。誰可以連線成為 **Azure RBAC 的決定**。且不需要站台已完成註冊 — 以下的操作記錄是在三個站台均回報 `site_state: FAILED` 時擷取的。

需注意的是，站台控制台僅在節點的內部（SLI）位址上回應，只能從 VNet 內部存取。Azure Bastion 在不將其他任何東西放上網路的情況下，填補了這個缺口。

<Aside type="note" title="此處已驗證與未驗證的內容">
本頁面上的每個命令及每份輸出，均在本部署中的 `f5-xc-ce-vm-01` 上執行，並逐字重現，包括失敗情況。

唯一未執行的一件事是**登入**。步驟在憑證提示處停止，因此以下內容均未描述登入後的控制台樣貌。
</Aside>

## 開始之前

<Steps>

1. 登入 Azure 並新增 Bastion 擴充功能。通道功能是原生用戶端功能，預設不會安裝此擴充功能。

   ```bash
   az login
   az extension add --name bastion
   ```

2. 持有 CE 虛擬機器、其網路介面及 Bastion 主機的 **Reader** 角色。

3. 確認 Bastion 已部署且具備所需能力。基本 SKU 不支援通道功能或基於 IP 的連線，因此此處的 `Standard` 與 `True` 均至關重要。

   ```bash
   az network bastion list -g rg-mcn-ce-ha-rmordasiewicz \
     --query "[].{name:name, sku:sku.name, tunneling:enableTunneling}" -o table
   ```

   ```text
   Name               Sku       Tunneling
   -----------------  --------  -----------
   ce-ha-lab-bastion  Standard  True
   ```

</Steps>

## 開啟通道

請從 `terraform output` 取得值，而非手動輸入 — 資源 ID 不適合手動組合。

<Steps>

1. 讀取 Bastion 主機名稱、資源群組，以及目標 CE 的 VM 資源 ID。

   ```bash
   cd terraform
   BASTION=$(terraform output -raw bastion_name)
   RG=$(terraform output -raw resource_group_name)
   VM_ID=$(terraform output -json ce_vm_ids | jq -r '.eastus01')
   ```

   ```text
   ce-ha-lab-bastion
   rg-mcn-ce-ha-rmordasiewicz
   /subscriptions/…/providers/Microsoft.Compute/virtualMachines/f5-xc-ce-vm-01
   ```

   <Aside type="caution" title="映射以站台為索引鍵，而非 VM 名稱">
   `ce_vm_ids` 的索引鍵為 `eastus01`、`eastus02`、`eastus03` — **而非** VM 名稱。使用 `jq -r '."f5-xc-ce-vm-01"'` 之類的篩選器會回傳 `null`，通道接著因資源 ID 為空而失敗。若不確定，請列出所有索引鍵：

   ```bash
   terraform output -json ce_vm_ids | jq -r 'keys | join(", ")'
   ```

   ```text
   eastus01, eastus02, eastus03
   ```
   </Aside>

2. 啟動通道。它會持續開放連接埠直到停止，因此請將其放到背景執行或使用第二個終端機。

   ```bash
   az network bastion tunnel \
     --name "$BASTION" \
     --resource-group "$RG" \
     --target-resource-id "$VM_ID" \
     --resource-port 65500 \
     --port 65500 &
   ```

   ```text
   WARNING: Opening tunnel on port: 65500
   WARNING: Tunnel is ready, connect on port 65500
   WARNING: Ctrl + C to close
   ```

   三行均以 `WARNING:` 為前綴。這是 Azure CLI 將進度寫入 stderr，並非問題。連線前請等待 `Tunnel is ready` 出現。

3. 確認監聽器在本機的回送位址上：

   ```bash
   lsof -nP -iTCP:65500 -sTCP:LISTEN
   ```

   ```text
   COMMAND   PID  USER  FD  TYPE  DEVICE  SIZE/OFF  NODE  NAME
   Python  41648  you   7u  IPv4  …            0t0   TCP  127.0.0.1:65500 (LISTEN)
   ```

4. 開啟控制台。通道使其成為本機存取，因此位址為 `localhost` — 而非節點的位址。

   ```bash
   open https://localhost:65500/          # macOS
   xdg-open https://localhost:65500/      # Linux
   ```

5. 完成後停止通道 — 使用 `Ctrl-C`，或若已放到背景執行則使用 `kill %1`。保持開啟會佔用本機連接埠 65500 及 Bastion 工作階段。

</Steps>

## 您將看到的內容

**憑證對話框，而非登入頁面。** 控制台使用 HTTP Basic 驗證，因此瀏覽器會彈出其自有的使用者名稱和密碼提示。沒有表單可供查看：

```bash
curl -skI https://localhost:65500/
```

```text
HTTP/1.1 401 Unauthorized
WWW-Authenticate: Basic realm="Volterra Site Console"
Content-Length: 0
```

具有該 realm 的 `401` 表示控制台運作正常。這是未驗證的請求應該收到的回應。

**憑證警告，同時因三個原因觸發。** 直接檢查憑證：

```bash
openssl s_client -connect localhost:65500 -servername localhost </dev/null 2>/dev/null \
  | openssl x509 -noout -subject -issuer -dates
```

```text
subject=C=US, ST=California, L=Santa Clara, O=Volterra, OU=Volterra Edge Services, CN=site-local.volterra.io
issuer=C=US, ST=California, L=Santa Clara, O=Volterra, OU=Volterra Edge Services, CN=site-local.volterra.io
notBefore=Oct 25 04:51:31 2024 GMT
notAfter=Oct 25 04:51:31 2025 GMT
```

主體等於簽發者，因此是自簽憑證。名稱為 `site-local.volterra.io`，而您連線至 `localhost`，因此名稱不符。且在本部署所執行的版本上，**憑證於 2025 年 10 月 25 日過期** — 設備隨附此憑證，本儲存庫中沒有任何機制會更新它。

預期會看到直接的瀏覽器警告，且每次都會出現。上方的主體行是有用的部分：這是您確認已到達設備而非其他在本機連接埠 65500 監聽的服務的方式。

## 管理員憑證

以 `admin` 身份登入。**本文件不會公布密碼，也不應該公布。**

全新出廠的 Customer Edge 隨附 F5 已公開的預設值，且 F5 要求必須更改。應將更改密碼視為部署節點的一部分，而非後續強化步驟。以下兩個原因說明此事在這裡比看起來更為重要：

- 本文件是公開的。在文件中印出整個機群目前的控制台密碼，會讓「持有 Bastion 的 Reader 角色」變成任何閱讀此頁面的人均可獲得完整設備存取權。
- 在文件中公布的密碼，一旦有人更換就立即失效，且以最具誤導性的方式失效 — 讀者會認為是自己的存取出了問題，而非頁面已過時。

請從您的團隊存放操作機密的地方取得密碼。若答案是「仍為出廠預設值」，請在執行任何其他操作前先更改它。

<Aside type="caution" title="從 Terraform 設定密碼尚未驗證">
站台物件上的 `admin_user_credentials.admin_password` 看起來像是設定此項目的宣告式方式。尚**未**確認它是否在此版本上對站台控制台生效，因此請勿假設它有效。

也不要將 [SSH 頁面](../ssh/) 視為任何一方向的佐證。其發現 `admin_password`「沒有任何改變」是針對 SSH 驗證測量的，而 `vpm` 完全跳過了 `admin` 使用者的 SSH 驗證。這對控制台的情況毫無說明。
</Aside>

## 為何通道必須指向資源 ID

`--target-resource-id` 是必要的。改以節點的位址為目標會被拒絕：

```bash
az network bastion tunnel --name "$BASTION" -g "$RG" \
  --target-ip-address 10.0.3.5 --resource-port 65500 --port 65501
```

```text
ERROR: Custom ports are not allowed. Allowed ports for Tunnel with IP connect is 22, 3389.
```

原因**並非** IP 型連線已停用 — 在此 Bastion 上 `ip_connect_enabled` 為 `true`。無論該設定為何，Microsoft 不支援透過基於 IP 的原生用戶端連線使用自訂連接埠（[Azure 文件](https://learn.microsoft.com/azure/bastion/connect-ip-address)），而 65500 是自訂連接埠。檢查此處的 Bastion 設定毫無幫助；請使用資源 ID。

## 當它無法運作時

| 症狀 | 原因 | 修正方式 |
| --- | --- | --- |
| `ERROR: Custom ports are not allowed. Allowed ports for Tunnel with IP connect is 22, 3389.` | 使用了 `--target-ip-address` | 改用 `--target-resource-id` |
| `ERROR: Defined port is currently unavailable` | 另一個通道已佔用該本機連接埠 | 停止另一個通道，或傳入不同的 `--port`；`--resource-port` 保持為 65500 |
| 通道已啟動但資源 ID 為空 | `jq` 篩選器使用了 VM 名稱而非站台索引鍵 | 改用 `eastus01`/`02`/`03` 作為索引鍵 |
| `401 Unauthorized`，realm 為 `Volterra Site Console` | 這不是錯誤 — 是未驗證的請求 | 提供 `admin` 憑證 |
| 瀏覽器拒絕憑證 | 自簽憑證、名稱不符，且自 2025 年 10 月起已過期 | 預期行為；確認主體為 `CN=site-local.volterra.io` 後繼續 |

<Aside type="note" title="授權失敗未重現">
RBAC 權限不足是另一個明顯的失敗方式，但重現它需要從共用部署中移除角色指派，因此此處未以逐字錯誤記錄。若通道在啟動時因授權錯誤而失敗，請檢查 VM、其 NIC 及 Bastion 主機三者上的 Reader 角色。
</Aside>
