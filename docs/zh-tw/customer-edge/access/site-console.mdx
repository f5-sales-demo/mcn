每個 Customer Edge 都會在 `https://<sli-ip>:65500` 上提供 F5 的站點主控台。在此
部署中，這通常是應該最先嘗試的途徑。

它對你的要求最少：不需要散發 SSH 金鑰、不需要維護跳板主機、節點上不需要公開 IP，
也不需要替換 VM 才能啟用。誰可以連線變成一項 **Azure RBAC 決策**。而且它不需要
站點已註冊：本頁最初是在三個站點全都回報 `site_state: FAILED` 時擷取的，之後在同一批
節點變為 `ONLINE` 後重新驗證，內容並未改變。

問題在於站點主控台只會在節點的內部（SLI）位址上回應，而該位址只能從 VNet 內部連線。
Azure Bastion 可以彌補這個落差，而不需要在網路上放置任何其他東西。

<Aside type="note" title="此處已驗證與未驗證的內容">
本頁上的每一個命令與每一段輸出都是針對此部署中的 `f5-xc-ce-vm-01` 執行，並且逐字重現，
包含失敗的情形。

**驗證已通過**：設備的 `admin` 憑證透過通道會回傳 `200`。**未**經實測的是主控台本身——
以下內容都沒有描述你進入之後能看到或做什麼。

**Azure RBAC 未經驗證。** 每一次執行都是以訂閱擁有者身分進行，因此步驟 2 中的 Reader
需求是 Microsoft 文件所記載的要求，而非此處實際量測所得。
</Aside>

<Aside type="caution" title="Bastion 需自行啟用，預設不會部署">
`enable_bastion` 預設為 `false`，因此在預設的 `terraform apply` 下不會有 Bastion
主機，且 `terraform output -raw bastion_name` 會是 `null`。請在
`terraform/terraform.tfvars` 中設定 `enable_bastion = true`——在此部署中它是 `true`。

它之所以需自行啟用是因為成本，而不是風險：Standard SKU 主機從佈建那一刻起就會按小時
計費，不論是否有人開啟通道——在 `eastus` 為每小時 0.29 美元，包含兩個內建擴充單位
（零售價，2026-07），約每月 212 美元。當示範不需要主控台存取時，請再把它關掉。
</Aside>

## 開始之前

<Steps>

1. 登入 Azure 並新增 Bastion 擴充功能。通道是原生用戶端功能，該擴充功能預設不會安裝。

   ```bash
   az login
   az extension add --name bastion
   ```

2. 對 CE 虛擬機器、其網路介面以及 Bastion 主機持有 **Reader** 權限。
   這是 Microsoft 文件記載的要求，且**在此未經驗證**——此部署中的每一次執行都是以
   訂閱擁有者身分進行，因此並未證明任何較低的角色足夠或不足。

3. 確認 Bastion 已部署且具備所需能力。Basic SKU 既不支援通道也不支援基於 IP 的連線，
   因此此處的 `Standard` 與 `True` 兩者都不可或缺。

   ```bash
   az network bastion list -g rg-mcn-ce-ha-rmordasiewicz \
     --query "[].{name:name, sku:sku.name, tunneling:enableTunneling}" -o table
   ```

   ```text
   Name               Sku       Tunneling
   -----------------  --------  -----------
   ce-ha-lab-bastion  Standard  True
   ```

</Steps>

## 開啟通道

請從 `terraform output` 取得數值，而不要手動輸入——資源 id 不是應該手工組出來的東西。

<Steps>

1. 讀取 Bastion 主機名稱、資源群組，以及目標 CE 的 VM 資源 id。

   ```bash
   cd terraform
   BASTION=$(terraform output -raw bastion_name)
   RG=$(terraform output -raw resource_group_name)
   VM_ID=$(terraform output -json ce_vm_ids | jq -r '.eastus01')
   ```

   ```text
   ce-ha-lab-bastion
   rg-mcn-ce-ha-rmordasiewicz
   /subscriptions/…/providers/Microsoft.Compute/virtualMachines/f5-xc-ce-vm-01
   ```

   <Aside type="caution" title="此對應表以站點為索引鍵，而非 VM 名稱">
   `ce_vm_ids` 的索引鍵是 `eastus01`、`eastus02`、`eastus03`——**不是** VM 名稱。像
   `jq -r '."f5-xc-ce-vm-01"'` 這樣的篩選器會回傳 `null`，通道接著會因為資源 id 為空而
   失敗。若不確定，請列出它們：

   ```bash
   terraform output -json ce_vm_ids | jq -r 'keys | join(", ")'
   ```

   ```text
   eastus01, eastus02, eastus03
   ```

   </Aside>

2. 啟動通道。它會維持連接埠開啟直到被停止，因此請把它放到背景執行或使用第二個終端機。

   ```bash
   az network bastion tunnel \
     --name "$BASTION" \
     --resource-group "$RG" \
     --target-resource-id "$VM_ID" \
     --resource-port 65500 \
     --port 65500 &
   ```

   ```text
   WARNING: Opening tunnel on port: 65500
   WARNING: Tunnel is ready, connect on port 65500
   WARNING: Ctrl + C to close
   ```

   三行都以 `WARNING:` 為前綴。那是 Azure CLI 將進度寫到 stderr，不是問題。
   請等到出現 `Tunnel is ready` 之後再連線。

3. 確認接聽器在本機的 loopback 上：

   ```bash
   lsof -nP -iTCP:65500 -sTCP:LISTEN
   ```

   ```text
   COMMAND   PID  USER  FD  TYPE  DEVICE  SIZE/OFF  NODE  NAME
   Python  41648  you   7u  IPv4  …            0t0   TCP  127.0.0.1:65500 (LISTEN)
   ```

4. 開啟主控台。通道讓它變成本機服務，因此位址是 `localhost`——而不是節點的位址。

   ```bash
   open https://localhost:65500/          # macOS
   xdg-open https://localhost:65500/      # Linux
   ```

5. 完成後停止通道——按 `Ctrl-C`，或若你把它放到背景則使用 `kill %1`。
   讓它保持開啟會佔用本機連接埠 65500 以及 Bastion 工作階段。

</Steps>

## 你會看到什麼

**一個憑證對話框，而不是登入頁面。** 主控台使用 HTTP Basic 驗證，因此
瀏覽器會顯示自己的使用者名稱與密碼提示。沒有表單可看：

```bash
curl -skI https://localhost:65500/
```

```text
HTTP/1.1 401 Unauthorized
WWW-Authenticate: Basic realm="Volterra Site Console"
Content-Type: text/html; charset=utf-8
Content-Length: 0
```

帶有該 realm 的 `401` 表示主控台運作正常。這正是未經驗證的請求應該得到的結果——
而對同一個 URL 提供 `admin` 憑證會回應
`200`，這就是你在開啟瀏覽器之前確認憑證的方式：

```bash
curl -sk -u admin -o /dev/null -w '%{http_code}\n' https://localhost:65500/
```

```text
Enter host password for user 'admin':
200
```

`-u admin` 不加冒號會讓 `curl` 提示輸入密碼，而不是從命令列取得——後者會讓密碼留在
shell 歷史紀錄與行程清單中。

**憑證警告，同時有三個原因。** 直接檢查憑證：

```bash
openssl s_client -connect localhost:65500 -servername localhost </dev/null 2>/dev/null \
  | openssl x509 -noout -subject -issuer -dates
```

```text
subject=C=US, ST=California, L=Santa Clara, O=Volterra, OU=Volterra Edge Services, CN=site-local.volterra.io
issuer=C=US, ST=California, L=Santa Clara, O=Volterra, OU=Volterra Edge Services, CN=site-local.volterra.io
notBefore=Oct 25 04:51:31 2024 GMT
notAfter=Oct 25 04:51:31 2025 GMT
```

subject 與 issuer 相同，因此它是自我簽署的。名稱是 `site-local.volterra.io`，而
你連線的是 `localhost`，因此不會相符。而在此部署所執行的版本上，
**該憑證已於 2025 年 10 月 25 日過期**——設備隨附了它，而此儲存庫中沒有任何機制會更新它。

請預期瀏覽器會給出直接的警告，而且每次都會出現。上面的 subject 那一行才是有用的部分：
它是你確認自己連到設備、而不是連到其他在本機連接埠 65500 上接聽的東西的方式。

## 管理員憑證

以 `admin` 登入。**本文件不會公布密碼，也不應該公布。**

<Aside type="danger" title="在此部署上該密碼仍是 F5 的原廠預設值">
這是實測結果，不是猜測：原廠預設憑證今天在全部三台 CE 上都能通過驗證並回傳
`200`。F5 公開了該預設值並要求必須變更，而它並未被變更。

實際後果是，在此部署上「對 Bastion 持有 Reader」等同於完整的設備主控台存取權，
只要對方知道一個記載於 F5 公開文件中的值即可。請變更它，並把變更它視為部署節點的一部分，
而不是事後才做的強化工作。
</Aside>

不公布它在此處比看起來更重要，有兩個理由：

- 本文件是公開的。印出整個機群目前的主控台密碼，會讓任何讀到本頁的人把
  「對 Bastion 持有 Reader」變成完整的設備存取權。
- 公布在文件裡的密碼，在有人輪換它的那一刻就是錯的，而且錯得最容易誤導人——
  讀者會認為自己的存取權壞了，而不是認為這一頁過時了。

一旦它被輪換過，請從你的團隊存放營運機密的地方取得。

<Aside type="caution" title="從 Terraform 設定密碼未經驗證">
站點物件上的 `admin_user_credentials.admin_password` 看起來是設定此項的宣告式方式。
但**尚未**確認它在此版本上能作用到站點主控台，因此請勿假設它可以。

也不要把 [SSH 頁面](../ssh/) 讀作任何一方的證據。該頁得出的
`admin_password`「什麼都沒改變」的結論，是針對 SSH 驗證量測的，而 `vpm` 對 `admin`
使用者完全跳過 SSH 驗證。那與主控台無關。
</Aside>

## 為何通道必須指向資源 id

`--target-resource-id` 是必要的。改為指向節點的位址會被拒絕——
不論你用哪個位址，因此此處刻意不列出任何真實位址：

```bash
az network bastion tunnel --name "$BASTION" -g "$RG" \
  --target-ip-address <any-sli-address> --resource-port 65500 --port 65501
```

```text
ERROR: Custom ports are not allowed. Allowed ports for Tunnel with IP connect is 22, 3389.
```

原因**不是**基於 IP 的連線被停用——在此 Bastion 上
`ip_connect_enabled` 為 `true`。不論該設定為何，Microsoft 都不支援在基於 IP 的
原生用戶端連線上使用自訂連接埠
（[Azure 文件](https://learn.microsoft.com/azure/bastion/connect-ip-address)），而 65500 是
自訂連接埠。在此檢查 Bastion 設定不會有任何幫助；請使用資源 id。

## 當它無法運作時

| 症狀 | 原因 | 解法 |
| --- | --- | --- |
| `ERROR: Custom ports are not allowed. Allowed ports for Tunnel with IP connect is 22, 3389.` | 使用了 `--target-ip-address` | 改用 `--target-resource-id` |
| `ERROR: Defined port is currently unavailable` | 另一個通道已佔用該本機連接埠 | 停止另一個通道，或傳入不同的 `--port`；`--resource-port` 維持 65500 |
| `terraform output -raw bastion_name` 為 `null` 或空值 | Bastion 未部署 | 設定 `enable_bastion = true` 並套用 |
| 通道啟動了但資源 id 為空 | `jq` 篩選器使用了 VM 名稱而非站點索引鍵 | 以 `eastus01`/`02`/`03` 為索引鍵 |
| `401 Unauthorized`，realm 為 `Volterra Site Console` | 不是故障——這是未經驗證的請求 | 提供 `admin` 憑證 |
| 瀏覽器拒絕該憑證 | 自我簽署、名稱不符，且自 2025 年 10 月起已過期 | 屬預期情形；確認 subject 為 `CN=site-local.volterra.io` 後繼續 |

<Aside type="note" title="授權失敗未經重現">
RBAC 權限不足是另一個明顯會導致失敗的原因，但要重現它就得從共用部署中移除角色指派，
因此此處未附上逐字的錯誤訊息。若通道在啟動時因授權錯誤而失敗，請檢查 VM、其 NIC
以及 Bastion 主機這三者上的 Reader 權限。
</Aside>
