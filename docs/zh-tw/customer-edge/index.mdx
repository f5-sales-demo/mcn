Customer Edge (CE) 是本儲存庫佈建至 Azure 的 F5 Distributed Cloud 節點 —— `terraform/modules/ce-node`，以
`volterraedgeservices/volterra-node` marketplace 映像檔建置。

它執行資料平面 (Argo)、控制平面 (Vega)、一個 Envoy proxy、一套 Kubernetes
堆疊，以及 `vpm`——負責註冊節點並管理節點上其他一切的代理程式。

當 CE 出現異常時，Site CLI 就是診斷工具。第一個決定是判斷適用哪一條存取路徑，選錯會浪費時間，而且症狀看起來像是節點壞了。

## 兩條存取路徑，且兩者不可互換

<CardGrid>
  <LinkCard
    title="Debug API"
    description="For a node that is <code>ONLINE</code>. Scriptable, read-only, and covers 34 commands."
    href="./access/debug-api/"
  />
  <LinkCard
    title="Serial console"
    description="For a node that never registered. The only route when the API cannot answer."
    href="./access/serial-console/"
  />
</CardGrid>

debug API **透過 F5 Distributed Cloud 控制平面**連線至節點。
這正是為何這個區分如此重要：只有在節點已完成註冊並回報 `ONLINE` 之後，API 才能作出回應。

註冊失敗的節點——錯誤的 cloud-init、過期的權杖、無法路由至
`register.ves.volterra.io`——恰恰是你需要診斷的情況，也恰恰是 API 無法服務的情況。

SSH 不是第三個選項。`sshd` 在節點上執行，並在其內部 (SLI)
位址上回應，但 `admin` 帳號無法通過驗證：`vpm` 會略過該使用者，因此你在 site 物件上設定的
`ssh_key` 永遠不會被套用。沒有任何安全群組規則能改變這一點。相關證據列於 [SSH](./access/ssh/) 頁面，該頁面之所以存在，是因為那裡的每個症狀看起來都像是防火牆或憑證故障。

所以：如果 site 為 `ONLINE`，就使用 debug API。如果不是，serial console 是唯一的進入方式。

<Aside type="caution" title="先檢查 site 狀態">
一個請求就能告訴你目前處於哪條路徑：

```bash
curl -sS -H "Authorization: APIToken $XCSH_API_TOKEN" \
  "$XCSH_API_URL/api/config/namespaces/system/sites/<site>" \
  | jq -r '.spec.site_state'
```

`ONLINE` 表示 debug API 可以運作。其他任何狀態——或是不存在的 site——都意味著要使用 serial console。
</Aside>

## 安全規則

以下規則適用於下列各頁面中的每一個命令。

- **除非你有十足把握，否則僅執行唯讀操作。** 命令介面分為兩個
  權限層級，而 `Exec` 層級的命令會變更節點狀態，或讀取某個狀態
  標記。這些頁面上沒有任何內容會執行 `Exec` 命令，擷取工具鏈亦然。
- **絕不要從命令名稱推測它是安全的。** `ip-link-set` 讀起來像是
  查詢，實際上會將介面關閉。`systemctl-restart-crio` 會在資料平面正在運作的情況下重新啟動
  容器執行環境。
- **優先使用能回答問題的最小範圍命令。** `health` 與
  `diagnosis` 能以低成本摘要節點狀態；`flow-l` 則會傾印一份 629,760 筆項目的流量
  表。
- **CE 承載實際流量。** 這些是共用的示範環境。請假設有人
  正在使用你正在除錯的那個 site 進行演示。

## 本文件涵蓋的內容

在此租戶所執行的軟體版本上，所有可透過 debug API 存取的命令，
每一項的輸出都是從實際運作中的節點擷取，而非從別處轉抄而來。

[命令參考](./commands/)列出所有命令及其類別、權限
層級與傳輸方式；[工作流程](./workflows/)則將它們串接成你在出問題時實際會使用的操作序列。

Site CLI 中僅能在節點上執行的部分——`configure`、`configure-network`、
`factory-reset`、`upgrade` 以及大約六十個其他 `ExecCLI` 命令——不在
涵蓋範圍內。

這些命令只能透過 serial console 工作階段存取，因此關於它們的任何內容都無法以程式方式
驗證，而未經驗證的命令語法正是本文件存在所要避免重複發生的缺陷。
