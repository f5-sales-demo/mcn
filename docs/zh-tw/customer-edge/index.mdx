Customer Edge（CE）是本儲存庫佈建至 Azure 的 F5 Distributed Cloud 節點——`terraform/modules/ce-node`，
由 `volterraedgeservices/volterra-node` Marketplace 映像檔建置而成。

它運行資料平面（Argo）、控制平面（Vega）、Envoy Proxy、Kubernetes
堆疊，以及 `vpm`——負責註冊節點並管理其上所有元件的代理程式。

當 CE 出現異常時，Site CLI 是主要的診斷工具。首要決策是判斷適用哪種存取路徑，選錯路徑將浪費時間，且表現形式如同節點損壞。

## 兩種存取路徑，且不可互換

<CardGrid>
  <LinkCard
    title="Debug API"
    description="For a node that is <code>ONLINE</code>. Scriptable, read-only, and covers 34 commands."
    href="./access/debug-api/"
  />
  <LinkCard
    title="Serial console"
    description="For a node that never registered. The only route when the API cannot answer."
    href="./access/serial-console/"
  />
</CardGrid>

Debug API 透過 **F5 Distributed Cloud 控制平面**連接節點。
這正是兩者區別的關鍵所在：API 只有在節點完成註冊並回報 `ONLINE` 狀態後才能回應。

若節點因 cloud-init 設定錯誤、Token 過期或無法路由至
`register.ves.volterra.io` 而未能完成註冊——這類情況恰恰是您最需要診斷資訊的時候，卻也正是 API 無法提供服務的情況。

[SSH](./access/ssh/) 是第三種選項，也是唯一能存取設備完整命令介面的方式——Debug API 僅提供 34 個命令，而節點本身提供更多。
然而有兩項限制：`sshd` 僅監聽節點的內部（SLI）位址，因此需要 VNet 內部的主機才能連線；
且金鑰由 cloud-init 於首次開機時寫入，因為 Site 物件上的 `ssh_key` 欄位實際上無效——`vpm` 會略過 `admin` 使用者，從不套用該欄位。
因此，若要在運行中的節點上啟用 SSH，必須重新佈建這些節點。

總結：若 Site 狀態為 `ONLINE` 且 34 個命令已足夠，請使用 Debug API。若需要完整命令介面且能夠連接 VNet，請使用 SSH。若問題出在節點無法完成註冊，序列主控台是唯一的進入途徑。

<Aside type="caution" title="請先確認 Site 狀態">
一個請求即可判斷您所處的路徑：

```bash
curl -sS -H "Authorization: APIToken $XCSH_API_TOKEN" \
  "$XCSH_API_URL/api/config/namespaces/system/sites/<site>" \
  | jq -r '.spec.site_state'
```

`ONLINE` 表示 Debug API 可正常使用。其他任何狀態——或 Site 不存在——則表示需使用序列主控台。
</Aside>

## 安全規則

以下規則適用於以下各頁面的所有命令。

- **除非確定，否則僅執行唯讀操作。** 命令介面分為兩個權限層級，`Exec` 層級的命令會修改節點狀態或讀取狀態標記。本文各頁面均不執行 `Exec` 命令，擷取工具亦同。
- **切勿從命令名稱推測其安全性。** `ip-link-set` 看似查詢命令，實際上會使網路介面下線。`systemctl-restart-crio` 會在活躍資料平面下重啟容器執行環境。
- **優先使用能回答問題的最精簡命令。** `health` 與 `diagnosis` 能以低成本彙總節點狀態；`flow-l` 則會傾印包含 629,760 筆記錄的流量表。
- **CE 承載著線上流量。** 這些是共用的示範環境。請假設您正在除錯的 Site 上，有人正在進行展示。

## 本文涵蓋範圍

所有可透過 Debug API 存取的命令（基於本租用戶運行的軟體版本），每個命令均附有從線上節點實際擷取的輸出，而非轉錄自其他來源。

[命令參考](./commands/)列出所有命令及其類別、權限層級與傳輸方式；[工作流程](./workflows/)則將這些命令串聯成您在實際排查問題時所使用的操作序列。

節點本機專屬的 Site CLI 部分——`configure`、`configure-network`、
`factory-reset`、`upgrade`，以及約六十個額外的 `ExecCLI` 命令——不在本文涵蓋範圍內。

這些命令僅能透過序列主控台工作階段存取，因此無法以程式化方式驗證，而本文件的存在正是為了避免重蹈未經驗證之命令語法所帶來的缺陷。
