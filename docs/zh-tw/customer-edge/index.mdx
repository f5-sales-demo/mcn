Customer Edge（CE）是本儲存庫佈建至 Azure 的 F5 Distributed Cloud 節點——`terraform/modules/ce-node`，
由 `volterraedgeservices/volterra-node` Marketplace 映像檔建置而成。

它執行資料平面（Argo）、控制平面（Vega）、Envoy Proxy、Kubernetes 堆疊，以及 `vpm`——負責節點註冊並管理其上所有元件的代理程式。

當 CE 發生異常時，Site CLI 是主要的診斷工具。首要決策是判斷適用哪條存取路徑，選錯路徑將浪費時間，且表現形式與節點故障無異。

## 兩條存取路徑，且無法互換

  />
  <LinkCard
    title="Serial console"

</CardGrid>

Debug API 透過 **F5 Distributed Cloud 控制平面**連線至節點。
這正是區分兩條路徑的根本原因：API 僅能在節點完成註冊並回報 `ONLINE` 狀態後才能回應。

若節點因 cloud-init 錯誤、Token 過期、或無法路由至 `register.ves.volterra.io` 而未能完成註冊，正是最需要診斷資訊的情境，卻也正是 API 無法服務的情境。

此外，節點出廠即關閉 SSH。Port 22 在 CE 本身即為關閉狀態，並非由網路安全群組所封鎖：

```console
$ ssh -o ConnectTimeout=10 admin@<ce-public-ip>
ssh: connect to host <ce-public-ip> port 22: Connection refused
```

已在 VNet 內部、從同一子網路的跳板主機驗證，開放安全群組規則無法改變此行為。

因此：若 Site 狀態為 `ONLINE`，請使用 Debug API；若否，序列主控台是唯一的連入方式。

<Aside type="caution" title="請先確認 Site 狀態">
一個請求即可判斷您所在的路徑：

```bash
curl -sS -H "Authorization: APIToken $XCSH_API_TOKEN" \
  "$XCSH_API_URL/api/config/namespaces/system/sites/<site>" \
  | jq -r '.spec.site_state'
```

`ONLINE` 表示 Debug API 可正常使用。其他任何狀態——或 Site 不存在——均表示需使用序列主控台。
</Aside>

## 安全規則

以下規則適用於後續所有頁面的每一條指令。

- **非必要不執行寫入操作。** 指令介面分為兩個權限層級，`Exec` 層級的指令會變更節點狀態或讀取狀態標記。本文件所有頁面均不執行 `Exec` 指令，擷取工具組亦然。
- **切勿僅憑名稱假設指令安全性。** `ip-link-set` 看似查詢指令，實際上會關閉網路介面；`systemctl-restart-crio` 會在即時資料平面運行期間重啟容器執行環境。
- **優先使用最精確、範圍最小的指令來回答問題。** `health` 與 `diagnosis` 以低成本方式彙整節點狀態；`flow-l` 則會傾印多達 629,760 筆的流量表。
- **CE 承載即時流量。** 這些是共用示範環境，請假設當前正在除錯的 Site 有人正在進行展示。

## 本文件涵蓋範圍

本文件涵蓋此租戶所執行軟體版本上，可透過 Debug API 存取的所有指令，每條指令均附有從即時節點擷取的輸出，而非轉錄自其他來源。

[指令參考](./commands/)列出所有指令及其類別、權限層級與傳輸方式；[工作流程](./workflows/)則將其串連為實際排查問題時使用的操作序列。

Site CLI 中僅限節點本機存取的部分——`configure`、`configure-network`、`factory-reset`、`upgrade` 以及約六十條 `ExecCLI` 指令——不在本文件涵蓋範圍內。

這些指令僅能透過序列主控台連線存取，因此無法以程式方式驗證，而本文件存在的目的正是為了避免重蹈未經驗證的指令語法所帶來的缺失。
