[指令參考](../commands/) 是依照各指令的功能來組織的。而以下內容
則是依照發生了什麼問題來組織。

| 症狀 | 工作流程 |
| --- | --- |
| 站點從未上線，或已從租戶中脫離 | [註冊](./registration/) |
| 路由未被公告或學習到；VIP 無法連線 | [BGP](./bgp-diagnostics/) |
| 流量抵達節點但未真正送達 | [資料平面](./dataplane-diagnostics/) |

每個步驟都會連結到記錄該指令的頁面。此處不重複敘述任何內容，
因此語法只存在唯一一處，也不會與節點的實際行為產生落差。

## 在開始任何工作流程之前

先確認你所處的存取路徑，因為它會決定哪些操作是可行的：

```bash
curl -sS -H "Authorization: APIToken $XCSH_API_TOKEN" \
  "$XCSH_API_URL/api/config/namespaces/system/sites/<site>" | jq -r '.spec.site_state'
```

`ONLINE` 表示 [debug API](../access/debug-api/) 會有回應。其他任何狀態都表示
你需要的是註冊工作流程，以及其中一條不依賴註冊的路徑：當節點仍有網路路徑時使用
[站點主控台](../access/site-console/)，若沒有網路路徑則使用
[序列主控台](../access/serial-console/)。

一個**完全找不到**的站點，在斷定「它從未註冊」之前還有一個可能需要排除：
你查詢的是錯誤的租戶。`cd terraform && terraform output -raw
xc_tenant` 會顯示此部署所屬的租戶名稱。
