Docker प्लेटफ़ॉर्म सेवाएं चलाता है। Kubernetes वर्कलोड
[CRI-O](../crictl/) के अंतर्गत हैं।

## `docker-ps`

```bash
{"command":["docker-ps"]}
```

```text file=../../../../_data/sitecli-docker-ps.txt
```

<Aside type="tip" title="तीन कंटेनर पूरी सूची है, कोई टूटा हुआ नोड नहीं">
`vpm`, `argo_watch` और `site-console`। चूँकि अधिकांश नोड CRI-O के अंतर्गत चलता है, इसलिए एक
छोटा `docker-ps` विफलता जैसा दिख सकता है यदि आप यहाँ Kubernetes वर्कलोड की उम्मीद कर रहे हैं।
ऐसा नहीं है — यह एक स्वस्थ CE पर Docker कंटेनरों का पूरा सेट है, और
`vpm` का मौजूद होना और `Up` स्थिति में होना पृष्ठ पर सबसे महत्वपूर्ण पंक्ति है।
</Aside>

## `docker-inspect`

```bash
{"command":["docker-inspect","<container-id-or-name"]}
```

```text file=../../../../_data/sitecli-docker-inspect.txt
```

नाम के साथ-साथ ID भी स्वीकार करता है, इसलिए `docker-inspect vpm` काम करता है और
पुनः आरंभ के बाद भी स्थिर रहता है। पूर्ण JSON: माउंट, वातावरण, पुनः आरंभ नीति और निकास स्थिति।

## `docker-logs`

```bash
{"command":["docker-logs","<container-id-or-name>"]}
```

```text file=../../../../_data/sitecli-docker-logs.txt
```

`docker-logs vpm` पंजीकरण त्रुटियों तक पहुँचने का सबसे तेज़ मार्ग है। टाइमस्टैम्प के साथ
और पुनः आरंभ के बाद भी समान जानकारी के लिए, इसके बजाय
[`journalctl`](../journalctl/) का उपयोग करें।
