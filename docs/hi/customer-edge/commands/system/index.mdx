चौंतीस में से तेरह कमांड।

| यदि आप चाहते हैं | उपयोग करें |
| --- | --- |
| नोड स्वस्थ है या नहीं, इसका एक उत्तर | [health](./health/) |
| नोड द्वारा स्वयं चलाए गए कनेक्टिविटी और DNS प्रोब | [diagnosis](./diagnosis/) |
| Kubernetes वर्कलोड कंटेनर | [crictl](./crictl/) |
| प्लेटफ़ॉर्म कंटेनर: vpm, argo, site-console | [docker](./docker/) |
| सेवा लॉग, पंजीकरण सहित | [journalctl](./journalctl/) |

## नोड दो कंटेनर रनटाइम चलाता है

यह लोगों को आश्चर्यचकित करता है, और यह बदलता है कि कौन सा कमांड आपके प्रश्न का उत्तर देता है।

- **Docker** प्लेटफ़ॉर्म कंटेनर चलाता है — `vpm`, `argo_watch`, `site-console`।
- **CRI-O** Kubernetes वर्कलोड चलाता है, जिसे `crictl` के माध्यम से एक्सेस किया जाता है।

दोनों एक साथ सक्रिय हैं, दोनों वास्तविक आउटपुट देते हैं, और न तो एक दूसरे का विकल्प है। `docker-ps` का तीन कंटेनर दिखाना एक टूटे हुए नोड का आंशिक दृश्य नहीं है; यह उस चीज़ की पूरी सूची है जो Docker चलाता है। यदि आप `vpm` खोज रहे हैं, तो यह एक Docker कंटेनर है। यदि आप एक पॉड खोज रहे हैं, तो वह CRI-O में है।

## दो कमांड एक अलग ट्रांसपोर्ट का उपयोग करते हैं

`health` और `diagnosis` `GLOBAL` स्कोप के हैं: ये एक `global` पाथ पर `GET` अनुरोध हैं, टर्मिनल टेक्स्ट के बजाय JSON लौटाते हैं, और **`exec-user` के माध्यम से पहुँचे नहीं जा सकते** — उन्हें वहाँ भेजने पर `command not supported` का उत्तर मिलता है, जो ऐसा लगता है जैसे कमांड मौजूद ही नहीं है। [debug API](../../access/debug-api/) देखें।
