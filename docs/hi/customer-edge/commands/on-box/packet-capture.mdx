`vifdump` Argo डेटा प्लेन के वर्चुअल इंटरफ़ेस पर पैकेट कैप्चर करता है। पाँच कमांड, सभी
F5 के, कोई भी [debug API](../../../access/debug-api/) पर नहीं।

<Aside type="danger" title="ये नोड पर लिखते हैं, और इनमें से कोई भी इस पृष्ठ पर नहीं चलाया गया है">
`vifdump` और `vifdump-d` एक ऐसा कैप्चर शुरू करते हैं जो Argo कंटेनर के अंदर `/tmp` में
`.pcap` फ़ाइलें लिखता है। 31 GiB डिस्क वाले CE पर, चलता हुआ छोड़ा गया कैप्चर एक निर्धारित
समय के साथ डिस्क-स्पेस की समस्या है।

यहाँ प्रत्येक कमांड को अप्लायंस के अपने कैटलॉग मेटाडेटा और उसके
कम्पलीशन-मेनू विवरण से प्रलेखित किया गया है। **इस पृष्ठ पर कोई कैप्चर किया गया आउटपुट नहीं है**, और हार्वेस्ट
हार्नेस उनमें से किसी को भी निष्पादित करने से मना करता है।
</Aside>

## विशेष रूप से इस पृष्ठ पर कोई आउटपुट क्यों नहीं है

Site CLI पर तर्क संख्या (argument arity) एक कमांड को बिना तर्क के चलाकर खोजी जा सकती है — यह
`not sufficient args for command <name>` का उत्तर देती है। यह एक रीड-ओनली कमांड के लिए सुरक्षित है।
इस दस्तावेज़ीकरण कार्य के दौरान `vifdump` पर लागू किया गया, तो यह एक ऐसे नोड पर **बिल्कुल कोई त्रुटि नहीं** लौटाया जो अभी भी रजिस्टर हो रहा था। क्या कोई कैप्चर शुरू हुआ, यह अज्ञात है, क्योंकि नोड को जाँचे जाने से पहले नष्ट करके फिर से बनाया गया था।

यही हार्नेस के डिज़ाइन का पूरा तर्क है: निष्पादन **डिफ़ॉल्ट-अस्वीकृत** है, न कि
deny-listed। `vifdump` किसी deny-list पर नहीं था, क्योंकि किसी ने इसके बारे में सोचा नहीं था। केवल एक
स्पष्ट allow-list उस कमांड को अस्वीकार करती है जिसके बारे में किसी ने नहीं सोचा।

## `vifdump`

एक निर्दिष्ट vif पर पैकेट कैप्चर करें।

```bash
execcli vifdump <vif-id> [options]
```

vif id [`vif --list`](../../network/dataplane-forwarding/) से लें।

## `vifdump-d`

एक vif या उन सभी पर **छोड़े गए (dropped)** पैकेट कैप्चर करें।

```bash
execcli vifdump-d <vif-id|all>
```

[`dropstats`](../../network/dataplane-drops/) के साथ जोड़ता है: `dropstats` आपको बताता है कि ड्रॉप हो रहे हैं
और कौन सा काउंटर बढ़ रहा है, `vifdump-d` आपको पैकेट दिखाता है।

## `vifdump-stop`

एक ऐसे कैप्चर को रोकता है जिसे पिछले रन ने पीछे छोड़ दिया था।

```bash
execcli vifdump-stop
```

अप्लायंस का अपना विवरण है "stop vifdump command if previous run abnormally ended",
जो आपको विफलता मोड बताता है जो अपेक्षित है: एक कैप्चर उस सत्र से अधिक समय तक जी सकता है जिसने इसे शुरू किया।
यदि आपने `vifdump` चलाया है और अनिश्चित हैं कि यह अभी भी चल रहा है, तो इसे चलाएँ।

## `vifdump-file-cp`

कैप्चर फ़ाइलों को Argo कंटेनर से होस्ट पर `/tmp/vifdump/` में कॉपी करता है।

```bash
execcli vifdump-file-cp
```

`docker cp $(argo):/tmp/. /tmp/vifdump/` के समतुल्य। आवश्यक है क्योंकि कैप्चर
कंटेनर *के अंदर* लिखा जाता है।

## `vifdump-file-rm`

Argo कंटेनर से `.pcap` फ़ाइलें हटाता है।

```bash
execcli vifdump-file-rm
```

**जब आप समाप्त कर लें तो इसे चलाएँ।** `vifdump-stop` के साथ मिलकर यह किसी भी कैप्चर कार्य के लिए क्लीनअप जोड़ी है, और ये दोनों वही हैं जो आप पहले चलाते हैं यदि आप किसी ऐसे नोड को संभालते हैं जहाँ किसी और ने कैप्चर चलता छोड़ा हो।
