**34 कमांड** उजागर करता है। नीचे दिया गया प्रत्येक पृष्ठ लिखित उदाहरणों के बजाय उस नोड का वास्तविक आउटपुट दिखाता है।

## केवल नए बिल्ड पर उपलब्ध

एक वर्तमान बिल्ड (`crt-20260201-0179`) **43** कमांड उजागर करता है — एक सख्त सुपरसेट,
बिना किसी हटाव और बिना किसी बदले हुए मेटाडेटा के। वे नौ जो इस टेनेंट के पास नहीं हैं:

| कमांड | श्रेणी | स्तर |
| --- | --- | --- |
| `collect-database-stats` | System | `ExecUser` |
| `iptables-lv` | Network | `ExecUser` |
| `marker-exists-NetworkManager` | System | `Exec` |
| `marker-exists-crio` | System | `Exec` |
| `marker-exists-kubelet` | System | `Exec` |
| `systemctl-restart-NetworkManager` | System | `Exec` |
| `systemctl-restart-crio` | System | `Exec` |
| `systemctl-restart-kubelet` | System | `Exec` |
| `systemctl-start-crio-prune` | System | `Exec` |

इन्हें केवल नाम और स्तर से सूचीबद्ध किया गया है, उस बिल्ड पर एक नोड के विरुद्ध कैटलॉग खोज से। यहाँ इनके लिए कोई कैप्चर किया हुआ आउटपुट नहीं है, क्योंकि यह टेनेंट इन्हें चला नहीं सकता। ध्यान दें कि नौ में से चार एक लाइव डेटा प्लेन के अंतर्गत सेवाएँ पुनरारंभ करती हैं।

<Aside type="note" title="सतह का बदलाव पहचानना">
क्योंकि सतह सॉफ़्टवेयर बिल्ड के साथ बढ़ती है, कैटलॉग उस बिल्ड को रिकॉर्ड करता है जिससे वह आया था, और `scripts/capture-sitecli.sh --check` एक बिल्ड परिवर्तन को जोड़े गए या हटाए गए कमांड से अलग रिपोर्ट करता है। जब इन नोड्स को अपग्रेड किया जाता है, तो वह जाँच ही आपको बताती है कि ये नौ आ गए हैं।
</Aside>
