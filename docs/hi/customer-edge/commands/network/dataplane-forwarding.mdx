Argo फ़ॉरवर्डिंग स्टेट को Linux कर्नेल से अलग रखता है। जब
[`ip`](../ip/) और ये कमांड असहमत होते हैं, तो ये कमांड ही ट्रैफ़िक को आगे बढ़ाते हैं।

## `rt`

vRouter रूट टेबल, प्रति VRF।

```bash
{"command":["rt","--dump","2"]}
```

```text file=../../../../_data/sitecli-rt.txt
```

<Aside type="danger" title="VRF id वह नहीं है जो BGP रिपोर्ट करता है">
`show-ip-bgp-summary` `vrf-id 3` प्रिंट करता है। यह FRR की क्रमांकन व्यवस्था है और यह
vRouter टेबल id से एक भिन्न नेमस्पेस है। इसे यहाँ पास करने पर विफलता इस तरह दिखती है
कि नोड ख़राब लगने लगता है:

```
vRouter(Response):  [No such file or directory (2)]
```

`--dump 0` के लिए भी वही उत्तर आता है। इस टोपोलॉजी पर **VRF 2** ही आबाद inet4 टेबल है,
जबकि VRF 1 में दो रूट हैं। यदि आपको id पता नहीं है, तो BGP आउटपुट पर भरोसा करने के बजाय
1 से ऊपर की ओर जाँच करें।
</Aside>

## `nh`

नेक्स्ट-हॉप टेबल। प्रत्येक रूट एक नेक्स्ट-हॉप id की ओर संकेत करता है, और यह उन्हें हल करता है।

```bash
{"command":["nh","--list"]}
```

```text file=../../../../_data/sitecli-nh.txt
```

प्रत्येक प्रविष्टि में एक `Type` और वह VRF होता है जिससे वह संबंधित है। इन नोड्स पर आठ प्रकार
इन अनुपातों में मिलते हैं — गिने जाने पर तीनों CE में एक समान:

```text
Tunnel 558   Encap 27   NAT 22   Vrf 16   Receive 14   Composite 4   Drop 2   Resolve 2
```

`Drop` नेक्स्ट हॉप पर हल होने वाला रूट एक ब्लैकहोल है, और जब भी कोई प्रीफ़िक्स `rt` में मौजूद हो
फिर भी ट्रैफ़िक गायब हो जाए, तो यह संयोजन जाँचने योग्य है।

<Aside type="caution" title="ऊपर का कैप्चर छँटा हुआ है, इसलिए इसमें हर प्रकार नहीं है">
यह 3,849 में से पहली 60 पंक्तियाँ हैं। `Tunnel`, जो कहीं बड़े अंतर से सबसे सामान्य प्रकार है, उन 60
पंक्तियों में बिल्कुल भी नहीं दिखता — इसलिए इस कैप्चर को पूर्ण प्रकार-सूची न समझें, और किसी नोड पर
कोई प्रकार अनुपस्थित है यह निष्कर्ष केवल इसलिए न निकालें कि वह एक छँटे हुए कैप्चर में अनुपस्थित है।
ऊपर दी गई गणनाएँ बिना छँटे उत्तर से आई हैं।
</Aside>

## `vif`

वर्चुअल इंटरफ़ेस टेबल: डेटा प्लेन किससे बाइंड होता है, और प्रति-इंटरफ़ेस
काउंटर।

```bash
{"command":["vif","--list"]}
```

```text file=../../../../_data/sitecli-vif.txt
```

शीर्ष पर दी गई फ़्लैग सूची एक बार पढ़ने योग्य है — `Vp` vhost भौतिक
इंटरफ़ेस को चिह्नित करता है, `Dpdk` एक DPDK-प्रबंधित इंटरफ़ेस को। इसका उपयोग यह पुष्टि करने के लिए करें
कि डेटा प्लेन ने वह इंटरफ़ेस अपने अधिकार में ले लिया है जिसकी आप अपेक्षा करते हैं, और उन RX तथा TX काउंटरों को
देखने के लिए जो Linux नहीं दिखाता क्योंकि ट्रैफ़िक कभी कर्नेल तक पहुँचता ही नहीं।
