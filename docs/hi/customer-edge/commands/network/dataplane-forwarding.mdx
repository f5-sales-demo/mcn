Argo फ़ॉरवर्डिंग स्थिति को Linux कर्नेल से अलग रखता है। जब
[`ip`](../ip/) और ये कमांड असहमत हों, तो ट्रैफ़िक इन्हीं कमांड के अनुसार चलता है।

## `rt`

vRouter रूट टेबल, प्रति VRF।

```bash
{"command":["rt","--dump","2"]}
```

```text file=../../../../_data/sitecli-rt.txt
```

<Aside type="danger" title="VRF id वह नहीं है जो BGP रिपोर्ट करता है">
`show-ip-bgp-summary` `vrf-id 3` प्रिंट करता है। यह FRR की नंबरिंग है और यह
vRouter टेबल id से एक अलग नेमस्पेस है। इसे यहाँ पास करने पर इस तरह विफलता आती है
जो एक टूटे हुए नोड जैसी दिखती है:

```
vRouter(Response):  [No such file or directory (2)]
```

`--dump 0` के लिए भी यही उत्तर आता है। इस टोपोलॉजी में **VRF 2** populated inet4 टेबल है,
जबकि VRF 1 में दो रूट हैं। यदि आपको id नहीं पता, तो BGP आउटपुट पर भरोसा करने के
बजाय 1 से ऊपर की ओर जाँच करें।
</Aside>

## `nh`

नेक्स्ट-हॉप टेबल। हर रूट एक नेक्स्ट-हॉप id की ओर संकेत करता है, और यह उन्हें resolve करता है।

```bash
{"command":["nh","--list"]}
```

```text file=../../../../_data/sitecli-nh.txt
```

प्रत्येक एंट्री में एक `Type` होता है — `Drop`, `Encap`, `Tunnel`, `Composite` — और वह VRF
जिससे वह संबंधित है। `Drop` नेक्स्ट हॉप पर resolve होने वाला रूट एक blackhole है, और
यह संयोजन तब जाँचने योग्य है जब कोई prefix `rt` में मौजूद हो फिर भी ट्रैफ़िक गायब हो जाए।

## `vif`

वर्चुअल इंटरफेस टेबल: डेटा प्लेन किससे बाइंड होता है, और प्रति-इंटरफेस काउंटर।

```bash
{"command":["vif","--list"]}
```

```text file=../../../../_data/sitecli-vif.txt
```

शीर्ष पर दिया गया flags legend एक बार पढ़ने योग्य है — `Vp` vhost physical
इंटरफेस को चिह्नित करता है, `Dpdk` एक DPDK-प्रबंधित को। इसका उपयोग यह पुष्टि करने के लिए करें
कि डेटा प्लेन ने आपके अपेक्षित इंटरफेस को claim किया है, और उन RX और TX काउंटर देखने के लिए
जो Linux नहीं दिखाता क्योंकि ट्रैफ़िक कर्नेल तक कभी पहुँचता ही नहीं।
