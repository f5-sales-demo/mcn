Argo फॉरवर्डिंग स्टेट को Linux कर्नेल से अलग रखता है। जब
[`ip`](../ip/) और ये कमांड्स असहमत हों, तो ये कमांड्स ही ट्रैफ़िक को मूव करती हैं।

## `rt`

vRouter रूट टेबल, प्रति VRF।

```bash
{"command":["rt","--dump","2"]}
```

```text file=../../../../_data/sitecli-rt.txt
```

<Aside type="danger" title="VRF id वह नहीं है जो BGP रिपोर्ट करता है">
`show-ip-bgp-summary` `vrf-id 3` प्रिंट करता है। यह FRR की नंबरिंग है और यह
vRouter टेबल id से एक अलग नेमस्पेस है। इसे यहाँ पास करने पर एक टूटे हुए नोड की तरह दिखने वाली विफलता आती है:

```
vRouter(Response):  [No such file or directory (2)]
```

`--dump 0` के लिए भी यही उत्तर मिलता है। इस टोपोलॉजी पर **VRF 2** पॉप्युलेटेड inet4 टेबल है, जिसमें VRF 1 दो रूट्स रखता है। यदि आप id नहीं जानते, तो BGP आउटपुट पर भरोसा करने की बजाय 1 से ऊपर की ओर प्रोब करें।
</Aside>

## `nh`

नेक्स्ट-हॉप टेबल। हर रूट एक नेक्स्ट-हॉप id की ओर इंगित करता है, और यह उन्हें रिज़ॉल्व करता है।

```bash
{"command":["nh","--list"]}
```

```text file=../../../../_data/sitecli-nh.txt
```

प्रत्येक एंट्री में एक `Type` और जिस VRF से वह संबंधित है, वह होता है। इन नोड्स पर आठ प्रकार आते हैं, इन अनुपातों में — तीनों CE में गिनने पर समान:

```text
Tunnel 558   Encap 27   NAT 22   Vrf 16   Receive 14   Composite 4   Drop 2   Resolve 2
```

एक `Drop` नेक्स्ट हॉप को रिज़ॉल्व करने वाला रूट एक ब्लैकहोल है, और यह संयोजन जाँचने योग्य है जब कोई प्रीफिक्स `rt` में मौजूद हो फिर भी ट्रैफ़िक गायब हो जाए।

<Aside type="caution" title="ऊपर का कैप्चर ट्रिम किया हुआ है, इसलिए इसमें हर प्रकार नहीं है">
यह 3,849 में से पहली 60 लाइनें हैं। `Tunnel`, जो अब तक का सबसे सामान्य प्रकार है, उन 60 में बिल्कुल नहीं आता — इसलिए कैप्चर को पूर्ण प्रकार इन्वेंटरी के रूप में न पढ़ें, और यह न मान लें कि कोई प्रकार किसी नोड से अनुपस्थित है क्योंकि वह ट्रिम किए गए कैप्चर से अनुपस्थित है। ऊपर की गिनती अनट्रिम किए गए रिस्पॉन्स से ली गई थी।
</Aside>

## `vif`

वर्चुअल इंटरफेस टेबल: डेटा प्लेन किससे बाइंड होता है, और प्रति-इंटरफेस काउंटर्स।

```bash
{"command":["vif","--list"]}
```

```text file=../../../../_data/sitecli-vif.txt
```

शीर्ष पर फ्लैग्स लेजेंड एक बार पढ़ने योग्य है — `Vp` vhost फिजिकल इंटरफेस को चिह्नित करता है, `Dpdk` एक DPDK-प्रबंधित इंटरफेस को। इसका उपयोग यह पुष्टि करने के लिए करें कि डेटा प्लेन ने वह इंटरफेस क्लेम किया है जिसकी आप अपेक्षा करते हैं, और RX और TX काउंटर्स देखने के लिए जो Linux नहीं दिखाता क्योंकि ट्रैफ़िक कभी कर्नेल तक पहुँचता ही नहीं।

## `mpls`

```bash
execcli mpls --help
```

Argo MPLS टेबल। **केवल बॉक्स से** पहुँचने योग्य — `mpls` डिबग API पर नहीं है, इसलिए
`rt`, `nh` और `vif` के विपरीत इसके लिए [`execcli`](../../on-box/) के माध्यम से
[SSH](../../../access/ssh/) या
[सीरियल कंसोल](../../../access/serial-console/) की आवश्यकता है।

यहाँ कोई कैप्चर आउटपुट नहीं है। इस डिप्लॉयमेंट पर CE BGP और ECMP के साथ IPv4 फॉरवर्ड करता है और MPLS लेबल का उपयोग नहीं करता, इसलिए एक कैप्चर एक खाली टेबल दिखाएगा और कुछ नहीं सिखाएगा। इसका अस्तित्व और इसका `--help` आर्गुमेंट फॉर्म अप्लायंस के अपने कम्पलीशन मेनू से सत्यापित है; इसका पॉप्युलेटेड आउटपुट यहाँ पुनः प्रस्तुत नहीं किया गया है।
