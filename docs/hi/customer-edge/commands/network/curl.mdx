दो कमांड, और उनके बीच का अंतर ही पूरा मूल्य है।

## `curl-host`

होस्ट नेटवर्क नेमस्पेस में चलता है — नोड की अपनी कनेक्टिविटी, डेटा प्लेन
के शामिल होने से पहले।

```bash
{"command":["curl-host","-v","cloud.f5.com"]}
```

```text file=../../../../_data/sitecli-curl-host.txt
```

## `curl-vega`

Kubernetes क्लस्टर संदर्भ के अंदर चलता है, इसलिए यह क्लस्टर के DNS और
नेटवर्क पथ से गुज़रता है।

```bash
{"command":["curl-vega","-v","cloud.f5.com"]}
```

```text file=../../../../_data/sitecli-curl-vega.txt
```

<Aside type="tip" title="यह जोड़ी एक द्विभाजन है">
दोनों चलाएँ। यदि `curl-host` सफल होता है और `curl-vega` विफल होता है, तो नोड में कनेक्टिविटी है
और क्लस्टर नेटवर्क या उसका DNS टूटा हुआ है। यदि दोनों विफल होते हैं, तो समस्या नोड के
ऊपरी स्तर पर है — रूटिंग, फ़ायरवॉल, या एग्रेस पथ। यदि केवल `curl-host` विफल होता है, तो
आपने कुछ असामान्य पाया है और पहले होस्ट रूटिंग तालिका की जाँच करनी चाहिए।
</Aside>

दोनों सामान्य `curl` तर्कों को अलग-अलग array तत्वों के रूप में स्वीकार करते हैं। `-v` रखना
उचित है क्योंकि कनेक्शन और TLS हैंडशेक लाइनें आमतौर पर वहीं होती हैं जहाँ विफलता दिखती है।
