प्रत्येक Customer Edge F5 के साइट कंसोल को `https://<sli-ip>:65500` पर सर्व करता है। इस
डिप्लॉयमेंट पर यह आमतौर पर पहले आज़माने का मार्ग है।

यह आपसे सबसे कम माँगता है: कोई SSH कुंजी वितरित करने की नहीं, कोई जंप होस्ट बनाए रखने की नहीं, नोड पर कोई सार्वजनिक IP नहीं, और इसे सक्षम करने के लिए कोई VM प्रतिस्थापन नहीं। कौन कनेक्ट कर सकता है यह एक **Azure RBAC निर्णय** बन जाता है। और इसे साइट के पंजीकृत होने की आवश्यकता नहीं है — नीचे दिया गया ट्रांसक्रिप्ट तब कैप्चर किया गया था जब तीनों साइटें `site_state: FAILED` रिपोर्ट कर रही थीं।

पकड़ यह है कि साइट कंसोल केवल नोड के आंतरिक (SLI) पते पर उत्तर देता है,
जो केवल VNet के अंदर से पहुँचा जा सकता है। Azure Bastion नेटवर्क पर कुछ और डाले बिना
उस अंतर को बंद करता है।

<Aside type="note" title="यहाँ क्या सत्यापित है, और क्या नहीं">
इस पृष्ठ पर प्रत्येक कमांड और प्रत्येक आउटपुट इस डिप्लॉयमेंट में `f5-xc-ce-vm-01` के
विरुद्ध चलाया गया था और विफलताओं सहित, शब्दशः पुनः प्रस्तुत किया गया है।

एक चीज़ जो अभ्यास में नहीं आई वह है **साइन इन करना**। चरण क्रेडेंशियल प्रॉम्प्ट पर रुकते
हैं, इसलिए नीचे कुछ भी वर्णित नहीं करता कि एक बार अंदर जाने पर कंसोल कैसा दिखता है।
</Aside>

## शुरू करने से पहले

<Steps>

1. Azure में साइन इन करें और Bastion एक्सटेंशन जोड़ें। टनलिंग एक नेटिव-क्लाइंट सुविधा है
   और एक्सटेंशन डिफ़ॉल्ट रूप से स्थापित नहीं होता।

   ```bash
   az login
   az extension add --name bastion
   ```

2. CE वर्चुअल मशीन, उसके नेटवर्क इंटरफ़ेस, और Bastion होस्ट पर **Reader** रखें।

3. पुष्टि करें कि Bastion तैनात और सक्षम है। Basic SKU न तो टनलिंग और न ही
   IP-आधारित कनेक्शन का समर्थन करता है, इसलिए यहाँ `Standard` और `True` दोनों महत्वपूर्ण हैं।

   ```bash
   az network bastion list -g rg-mcn-ce-ha-rmordasiewicz \
     --query "[].{name:name, sku:sku.name, tunneling:enableTunneling}" -o table
   ```

   ```text
   Name               Sku       Tunneling
   -----------------  --------  -----------
   ce-ha-lab-bastion  Standard  True
   ```

</Steps>

## टनल खोलें

`terraform output` से मान लें बजाय उन्हें टाइप करने के — संसाधन id को हाथ से असेम्बल करने
की चीज़ नहीं है।

<Steps>

1. Bastion होस्ट नाम, संसाधन समूह, और लक्ष्य CE की VM संसाधन id पढ़ें।

   ```bash
   cd terraform
   BASTION=$(terraform output -raw bastion_name)
   RG=$(terraform output -raw resource_group_name)
   VM_ID=$(terraform output -json ce_vm_ids | jq -r '.eastus01')
   ```

   ```text
   ce-ha-lab-bastion
   rg-mcn-ce-ha-rmordasiewicz
   /subscriptions/…/providers/Microsoft.Compute/virtualMachines/f5-xc-ce-vm-01
   ```

   <Aside type="caution" title="मैप साइट द्वारा कुंजीबद्ध है, VM नाम से नहीं">
   `ce_vm_ids` कुंजियाँ `eastus01`, `eastus02`, `eastus03` हैं — **VM नाम नहीं**। एक
   फ़िल्टर जैसे `jq -r '."f5-xc-ce-vm-01"'` `null` लौटाता है, और टनल फिर एक
   खाली संसाधन id पर विफल हो जाता है। यदि अनिश्चित हों तो उन्हें सूचीबद्ध करें:

   ```bash
   terraform output -json ce_vm_ids | jq -r 'keys | join(", ")'
   ```

   ```text
   eastus01, eastus02, eastus03
   ```
   </Aside>

2. टनल शुरू करें। यह पोर्ट को रोके रखता है जब तक रोका न जाए, इसलिए इसे बैकग्राउंड करें
   या दूसरा टर्मिनल उपयोग करें।

   ```bash
   az network bastion tunnel \
     --name "$BASTION" \
     --resource-group "$RG" \
     --target-resource-id "$VM_ID" \
     --resource-port 65500 \
     --port 65500 &
   ```

   ```text
   WARNING: Opening tunnel on port: 65500
   WARNING: Tunnel is ready, connect on port 65500
   WARNING: Ctrl + C to close
   ```

   तीनों पंक्तियाँ `WARNING:` से प्रीफ़िक्स हैं। यह Azure CLI stderr पर प्रगति लिख
   रहा है, कोई समस्या नहीं। कनेक्ट करने से पहले `Tunnel is ready` की प्रतीक्षा करें।

3. पुष्टि करें कि लिसनर लोकल, लूपबैक पर है:

   ```bash
   lsof -nP -iTCP:65500 -sTCP:LISTEN
   ```

   ```text
   COMMAND   PID  USER  FD  TYPE  DEVICE  SIZE/OFF  NODE  NAME
   Python  41648  you   7u  IPv4  …            0t0   TCP  127.0.0.1:65500 (LISTEN)
   ```

4. कंसोल खोलें। टनल इसे लोकल बना देता है, इसलिए पता `localhost` है — नोड का पता नहीं।

   ```bash
   open https://localhost:65500/          # macOS
   xdg-open https://localhost:65500/      # Linux
   ```

5. जब आप समाप्त कर लें तो टनल बंद करें — `Ctrl-C`, या `kill %1` यदि आपने इसे
   बैकग्राउंड किया था। इसे खुला छोड़ने से लोकल पोर्ट 65500 और Bastion सत्र होल्ड होता है।

</Steps>

## आप क्या देखेंगे

**एक क्रेडेंशियल डायलॉग, लॉगिन पृष्ठ नहीं।** कंसोल HTTP Basic प्रमाणीकरण का उपयोग करता है,
इसलिए ब्राउज़र अपना स्वयं का उपयोगकर्ता नाम और पासवर्ड प्रॉम्प्ट उठाता है। देखने के लिए
कोई फ़ॉर्म नहीं है:

```bash
curl -skI https://localhost:65500/
```

```text
HTTP/1.1 401 Unauthorized
WWW-Authenticate: Basic realm="Volterra Site Console"
Content-Length: 0
```

उस realm के साथ `401` कंसोल का सही ढंग से काम करना है। यही वह है जो एक
अप्रमाणीकृत अनुरोध को मिलना चाहिए।

**एक साथ तीन कारणों से प्रमाणपत्र चेतावनी।** प्रमाणपत्र की सीधे जाँच करना:

```bash
openssl s_client -connect localhost:65500 -servername localhost </dev/null 2>/dev/null \
  | openssl x509 -noout -subject -issuer -dates
```

```text
subject=C=US, ST=California, L=Santa Clara, O=Volterra, OU=Volterra Edge Services, CN=site-local.volterra.io
issuer=C=US, ST=California, L=Santa Clara, O=Volterra, OU=Volterra Edge Services, CN=site-local.volterra.io
notBefore=Oct 25 04:51:31 2024 GMT
notAfter=Oct 25 04:51:31 2025 GMT
```

Subject issuer के बराबर है, इसलिए यह स्व-हस्ताक्षरित है। नाम `site-local.volterra.io` है
जबकि आप `localhost` से कनेक्ट कर रहे हैं, इसलिए यह मेल नहीं खाएगा। और इस डिप्लॉयमेंट
के बिल्ड पर, **प्रमाणपत्र 25 अक्टूबर 2025 को समाप्त हो गया** — उपकरण इसे भेजता है, और
इस रिपॉजिटरी में कुछ भी इसे नवीनीकृत नहीं करता।

एक कड़े ब्राउज़र चेतावनी की अपेक्षा करें, और हर बार इसकी अपेक्षा करें। ऊपर की subject
पंक्ति उपयोगी भाग है: यह वह है जिससे आप पुष्टि करते हैं कि आप उपकरण तक पहुँचे न कि
लोकल पोर्ट 65500 पर सुन रही किसी अन्य चीज़ तक।

## admin क्रेडेंशियल

`admin` के रूप में साइन इन करें। **यह दस्तावेज़ीकरण पासवर्ड प्रकाशित नहीं करता, और करना भी नहीं चाहिए।**

एक फ़ैक्टरी-ताज़ा Customer Edge F5 के प्रकाशित डिफ़ॉल्ट के साथ आता है, और F5 आवश्यकता
करता है कि इसे बदला जाए। इसे बदलना नोड तैनात करने के हिस्से के रूप में मानें न कि बाद
की हार्डनिंग के रूप में। दो कारण जो इसे यहाँ अधिक महत्वपूर्ण बनाते हैं जितना दिख सकता है:

- यह दस्तावेज़ीकरण सार्वजनिक है। फ्लीट का वर्तमान कंसोल पासवर्ड प्रिंट करना
  "Bastion पर Reader रखता है" को उस पृष्ठ को पढ़ने वाले किसी के लिए भी पूर्ण उपकरण
  पहुँच में बदल देगा।
- दस्तावेज़ीकरण में प्रकाशित पासवर्ड उस क्षण गलत होता है जब कोई इसे बदलता है, और
  सबसे भ्रामक तरीके से गलत — पाठक यह निष्कर्ष निकालता है कि उनकी पहुँच टूटी हुई है
  बजाय इसके कि पृष्ठ पुराना हो गया है।

पासवर्ड वहाँ से लें जहाँ आपकी टीम ऑपरेशनल सीक्रेट रखती है। यदि उत्तर है
"यह अभी भी फ़ैक्टरी डिफ़ॉल्ट है", तो कुछ और करने से पहले इसे बदलें।

<Aside type="caution" title="Terraform से पासवर्ड सेट करना सत्यापित नहीं है">
साइट ऑब्जेक्ट पर `admin_user_credentials.admin_password` इसे सेट करने का घोषणात्मक
तरीका लगता है। यह इस बिल्ड पर साइट कंसोल तक पहुँचने की **पुष्टि नहीं हुई है**, इसलिए
यह न मानें कि यह करता है।

[SSH पृष्ठ](../ssh/) को भी किसी भी दिशा में साक्ष्य के रूप में न पढ़ें। इसकी खोज कि
`admin_password` ने "कुछ नहीं बदला" SSH प्रमाणीकरण के विरुद्ध मापी गई थी, जिसे `vpm`
`admin` उपयोगकर्ता के लिए पूरी तरह से छोड़ देता है। यह कंसोल के बारे में कुछ नहीं कहता।
</Aside>

## टनल को संसाधन id को क्यों लक्षित करना चाहिए

`--target-resource-id` आवश्यक है। नोड के पते को लक्षित करना अस्वीकार किया जाता है:

```bash
az network bastion tunnel --name "$BASTION" -g "$RG" \
  --target-ip-address 10.0.3.5 --resource-port 65500 --port 65501
```

```text
ERROR: Custom ports are not allowed. Allowed ports for Tunnel with IP connect is 22, 3389.
```

कारण यह **नहीं** है कि IP-आधारित कनेक्शन अक्षम है — इस Bastion पर
`ip_connect_enabled` `true` है। Microsoft उस सेटिंग की परवाह किए बिना IP-आधारित
नेटिव-क्लाइंट कनेक्शन पर कस्टम पोर्ट का समर्थन नहीं करता
([Azure docs](https://learn.microsoft.com/azure/bastion/connect-ip-address)), और 65500 एक
कस्टम पोर्ट है। यहाँ Bastion कॉन्फ़िगरेशन का निरीक्षण करने से कहीं नहीं पहुँचते;
संसाधन id का उपयोग करें।

## जब यह काम नहीं करता

| लक्षण | कारण | समाधान |
| --- | --- | --- |
| `ERROR: Custom ports are not allowed. Allowed ports for Tunnel with IP connect is 22, 3389.` | `--target-ip-address` का उपयोग किया | `--target-resource-id` का उपयोग करें |
| `ERROR: Defined port is currently unavailable` | एक और टनल पहले से उस लोकल पोर्ट को होल्ड कर रहा है | दूसरा टनल बंद करें, या एक अलग `--port` पास करें; `--resource-port` 65500 रहता है |
| टनल शुरू होता है लेकिन संसाधन id खाली है | `jq` फ़िल्टर ने साइट कुंजी के बजाय VM नाम का उपयोग किया | `eastus01`/`02`/`03` पर कुंजीबद्ध करें |
| `401 Unauthorized`, realm `Volterra Site Console` | कोई दोष नहीं — अप्रमाणीकृत अनुरोध | `admin` क्रेडेंशियल प्रदान करें |
| ब्राउज़र प्रमाणपत्र अस्वीकार करता है | स्व-हस्ताक्षरित, नाम बेमेल, और अक्टूबर 2025 से समाप्त | अपेक्षित; पुष्टि करें कि subject `CN=site-local.volterra.io` है और आगे बढ़ें |

<Aside type="note" title="प्राधिकरण विफलताओं को पुनः उत्पन्न नहीं किया गया">
अपर्याप्त RBAC इसके विफल होने का एक और स्पष्ट तरीका है, लेकिन इसे पुनः उत्पन्न करने का
अर्थ होगा साझा डिप्लॉयमेंट से रोल असाइनमेंट हटाना, इसलिए इसे यहाँ शब्दशः त्रुटि के साथ
दस्तावेज़ीकृत नहीं किया गया है। यदि टनल एक प्राधिकरण त्रुटि के साथ शुरुआत में विफल हो
जाता है, तो VM, उसके NIC, और Bastion होस्ट तीनों पर Reader जाँचें।
</Aside>
