दो मार्ग मौजूद हैं, और कौन-सा लागू होता है यह वरीयता के बजाय नोड की स्थिति से तय होता है।

| नोड की स्थिति | मार्ग | स्क्रिप्टयोग्य | कवर करता है |
| --- | --- | --- | --- |
| `ONLINE` | [Debug API](./debug-api/) | हाँ | 34 कमांड, रीड-ओनली और विशेषाधिकार प्राप्त |
| अपंजीकृत, या अनुपलब्ध | [Serial console](./serial-console/) | नहीं — टर्मिनल की आवश्यकता है | पूर्ण ऑन-बॉक्स Site CLI |

## विभाजन वरीयता क्यों नहीं है

Debug API, F5 Distributed Cloud कंट्रोल प्लेन द्वारा परोसी जाती है, जो पंजीकरण के दौरान `vpm` द्वारा स्थापित टनल `vpm` के माध्यम से नोड तक रिले करती है। पंजीकरण नहीं होने का अर्थ है कोई टनल नहीं, जिसका अर्थ है API के पास रिले करने के लिए कुछ नहीं है।

यह किसी स्पष्ट तरीके के बजाय एक अनुपयोगी तरीके से विफल होती है, इसलिए एक नोड जो कभी चालू नहीं हुआ वह API समस्या जैसा दिखता है।

Serial console पूरी तरह दूसरे रास्ते से जाती है — Azure प्लेटफ़ॉर्म के माध्यम से नोड के एमुलेटेड सीरियल पोर्ट तक। इसे इस बात की कोई परवाह नहीं है कि नोड ने पंजीकरण किया है, नेटवर्क रीचेबिलिटी है, या कार्यशील डेटा प्लेन है। यही स्वतंत्रता इसका पूरा उद्देश्य है, और इसीलिए CE VMs पर बूट डायग्नोस्टिक्स सक्षम रहना आवश्यक है।

<Aside type="note" title="किसे चुनें">
यदि आप स्वचालन लिख रहे हैं, या ऐसे साक्ष्य एकत्र कर रहे हैं जिन्हें आप बाद में पुनः चलाना चाहते हैं, तो Debug API का उपयोग करें। यदि पंजीकरण ही वह चीज़ है जो टूटी हुई है, तो serial console कोई फ़ॉलबैक नहीं है — यह एकमात्र विकल्प है।
</Aside>

## क्रेडेंशियल

दोनों मार्ग अलग-अलग क्रेडेंशियल का उपयोग करते हैं, और दोनों में से कोई भी कमांड लाइन पर नहीं होना चाहिए।

- **Debug API** — एक F5 Distributed Cloud API टोकन, `XCSH_API_TOKEN` के रूप में, और टेनेंट URL `XCSH_API_URL` के रूप में। `~/.config/xcsh/contexts/<tenant>.json` पर स्थित `xcsh` कॉन्टेक्स्ट फ़ाइल दोनों को रखती है, जिसे `scripts/capture-sitecli.sh` तब पढ़ता है जब एनवायरनमेंट उन्हें उपलब्ध नहीं कराता।
- **Serial console** — आपका इंटरेक्टिव Azure लॉगिन। इसके लिए कोई सर्विस प्रिंसिपल नहीं है: F5 कॉर्पोरेट Entra टेनेंट एक को प्रोविज़न करने की अनुमति नहीं देता, और यही कारण है कि इसका कोई भाग CI में नहीं चलता।

<Aside type="danger" title="टोकन को कभी भी आर्गुमेंट के रूप में न पास करें">
कमांड लाइन पर एक टोकन शेल हिस्ट्री और प्रोसेस लिस्ट में दर्ज हो जाता है, जहाँ मशीन पर हर दूसरा उपयोगकर्ता इसे पढ़ सकता है। इसी कारण `capture-sitecli.sh` `--token` को पूरी तरह अस्वीकार करता है और इसके बजाय stdin पर `curl` को हेडर प्रदान करता है।
</Aside>
