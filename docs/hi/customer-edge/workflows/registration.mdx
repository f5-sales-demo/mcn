<Aside type="danger" title="API इसे डीबग नहीं कर सकता">
डीबग API नोड तक F5 Distributed Cloud कंट्रोल प्लेन के माध्यम से पहुँचता है, उस
टनल के ज़रिए जिसे रजिस्ट्रेशन स्थापित करती है। यदि रजिस्ट्रेशन विफल हो गई तो कोई टनल नहीं है,
इसलिए इस साइट पर हर कमांड इस विशेष विफलता के लिए अनुपलब्ध है। कार्य
[serial console](../../access/serial-console/) से करें।
</Aside>

<Steps>

1. **पुष्टि करें कि टेनेंट क्या सोचता है।** साइट सूची से अनुपस्थित होना
   `ONLINE` न होने से भिन्न समस्या है।

   ```bash
   curl -sS -H "Authorization: APIToken $XCSH_API_TOKEN" \
     "$XCSH_API_URL/api/config/namespaces/system/sites" | jq -r '.items[].name'
   ```

   यदि साइट मौजूद है और `ONLINE` रिपोर्ट करती है, तो रजिस्ट्रेशन सफल रही और आप
   गलत वर्कफ़्लो में हैं।

2. **एक लंबित रजिस्ट्रेशन की जाँच करें।** एक नोड रजिस्टर हो सकता है और फिर
   स्वीकृति का इंतज़ार कर सकता है, जो बाहर से विफलता जैसा ही दिखता है।

   ```bash
   curl -sS -H "Authorization: APIToken $XCSH_API_TOKEN" \
     "$XCSH_API_URL/api/register/namespaces/system/listregistrationsbystate"
   ```

3. **पुष्टि करें कि VM वास्तव में चल रहा है**, सॉफ़्टवेयर दोष मानने से पहले।

   ```bash
   az vm list -d -g <resource-group> --query "[].{name:name,power:powerState}" -o table
   ```

4. **सीरियल कंसोल से जुड़ें।** इसके लिए एक टर्मिनल की आवश्यकता है — इसे स्क्रिप्ट नहीं किया जा सकता।

   ```bash
   az serial-console connect -g <resource-group> -n <vm-name>
   ```

   यदि यह अस्वीकार करे, तो यह निष्कर्ष निकालने से पहले कि नोड अनुपलब्ध है, VM पर
   बूट डायग्नोस्टिक्स सक्षम है या नहीं यह जाँचें; वह पूर्वापेक्षा और उसके विफलता मोड
   [serial console](../../access/serial-console/) पृष्ठ पर कवर किए गए हैं।

5. **कंसोल जो दिखाता है उसे इस क्रम में पढ़ें।** पहले cloud-init — एक नोड जिसका
   cloud-init कभी पूरा नहीं हुआ उसके पास रजिस्टर करने के लिए कोई कॉन्फ़िगरेशन नहीं है।
   फिर रजिस्ट्रेशन के प्रयास स्वयं, फिर DNS: यदि नोड
   `register.ves.volterra.io` को रिज़ॉल्व नहीं कर सकता, तो कुछ भी डाउनस्ट्रीम काम नहीं कर सकता।

6. **एक बार नोड `ONLINE` हो जाए**, [`health`](../../commands/system/health/) से
   सत्यापन करें और `state: PROVISIONED` की अपेक्षा करें।

</Steps>

## सामान्य कारण

- cloud-init पूरा नहीं हुआ, इसलिए `/etc/vpm/config.yaml` अनुपस्थित है या गलत है।
- रजिस्ट्रेशन टोकन समाप्त हो गया है, पहले ही उपयोग किया जा चुका है, या किसी अन्य टेनेंट का है।
- `register.ves.volterra.io` तक कोई एग्रेस रूट नहीं है।
- क्लॉक स्क्यू इतना बड़ा है कि सर्टिफिकेट अमान्य हो जाएं — बाद में
  [`chronyc-sources`](../../commands/network/chronyc-sources/) से जल्दी खारिज किया जा सकता है, लेकिन नोड ऑनलाइन होने तक पहुँचा नहीं जा सकता।
