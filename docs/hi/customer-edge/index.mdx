एक कस्टमर एज (CE) वह F5 Distributed Cloud नोड है जिसे यह रिपॉज़िटरी Azure में
प्रोविज़न करती है — `terraform/modules/ce-node`, जो
`volterraedgeservices/volterra-node` मार्केटप्लेस इमेज से बनाया गया है।

यह डेटा प्लेन (Argo), कंट्रोल प्लेन (Vega), एक Envoy प्रॉक्सी, एक Kubernetes
स्टैक, और `vpm` चलाता है — वह एजेंट जो नोड को रजिस्टर करता है और उस पर बाकी सब कुछ
प्रबंधित करता है।

जब कोई CE ठीक से काम नहीं करता, तो Site CLI ही वह उपकरण है। पहला निर्णय यह है कि कौन-सा
एक्सेस पथ लागू होता है, और इसे गलत चुनना समय इस तरह बर्बाद करता है कि वह एक
खराब नोड जैसा दिखता है।

डिबग API नोड तक **F5 Distributed Cloud कंट्रोल प्लेन के माध्यम से** पहुँचता है।
यही पूरी वजह है कि यह विभाजन मायने रखता है: API तभी उत्तर दे सकता है जब नोड
रजिस्टर हो चुका हो और `ONLINE` रिपोर्ट कर रहा हो।

वह नोड जो रजिस्टर होने में विफल रहा — खराब cloud-init, समाप्त हो चुका टोकन,
`register.ves.volterra.io` तक कोई रूट नहीं — ठीक वही स्थिति है जहाँ आपको डायग्नोस्टिक्स
चाहिए, और ठीक वही स्थिति है जिसे API सेवा नहीं दे सकता।

[SSH](./access/ssh/) तीसरा विकल्प है, और एकमात्र ऐसा जो उपकरण की पूरी कमांड सतह तक
पहुँचता है — डिबग API 34 कमांड उजागर करता है जबकि नोड स्वयं कहीं अधिक प्रदान करता है।
दो चीज़ें इसे सीमित करती हैं। `sshd` केवल नोड के आंतरिक (SLI) पते पर उत्तर देता है,
इसलिए इसे VNet के भीतर एक होस्ट चाहिए; और कुंजी पहले बूट पर cloud-init द्वारा लिखी जाती है,
क्योंकि साइट ऑब्जेक्ट पर `ssh_key` फ़ील्ड निष्क्रिय है — `vpm` `admin` उपयोगकर्ता को छोड़ देता है
और उसे कभी लागू नहीं करता। इसलिए चल रहे नोड्स पर इसे सक्षम करने का अर्थ है उन्हें बदलना।

तो: यदि साइट `ONLINE` है और 34 कमांड पर्याप्त हैं, तो डिबग API का उपयोग करें। यदि आपको
शेष सतह चाहिए और आप VNet तक पहुँच सकते हैं, तो SSH का उपयोग करें। यदि रजिस्ट्रेशन ही
टूटा हुआ है, तो सीरियल कंसोल ही एकमात्र रास्ता है।

<Aside type="caution" title="पहले साइट की स्थिति जाँचें">
एक अनुरोध आपको बता देता है कि आप किस पथ पर हैं:

```bash
curl -sS -H "Authorization: APIToken $XCSH_API_TOKEN" \
  "$XCSH_API_URL/api/config/namespaces/system/sites/<site>" \
  | jq -r '.spec.site_state'
```

`ONLINE` का अर्थ है कि डिबग API काम करेगा। इसके अलावा कुछ भी — या ऐसी साइट जो मौजूद
ही नहीं है — का अर्थ है सीरियल कंसोल।
</Aside>

## सुरक्षा नियम

ये नीचे दिए गए हर पृष्ठ की हर कमांड पर लागू होते हैं।

- **तब तक केवल-पठन, जब तक आप निश्चित न हों।** कमांड सतह दो विशेषाधिकार स्तरों में
  बँटी है, और `Exec` स्तर या तो नोड को बदलता है या किसी स्थिति मार्कर को पढ़ता है।
  इन पृष्ठों पर कुछ भी `Exec` कमांड नहीं चलाता, और न ही कैप्चर हार्नेस चलाता है।
- **कभी यह न मानें कि कोई कमांड अपने नाम से सुरक्षित है।** `ip-link-set` एक
  क्वेरी जैसा पढ़ा जाता है और एक इंटरफ़ेस को डाउन कर देता है। `systemctl-restart-crio`
  एक जीवंत डेटा प्लेन के नीचे कंटेनर रनटाइम को पुनः आरंभ करता है।
- **उस सबसे संकीर्ण कमांड को प्राथमिकता दें जो प्रश्न का उत्तर देती है।** `health` और
  `diagnosis` नोड का सारांश सस्ते में देते हैं; `flow-l` 629,760-प्रविष्टियों वाली फ़्लो
  तालिका डंप करता है।
- **एक CE जीवंत ट्रैफ़िक सेवा देता है।** ये साझा डेमो वातावरण हैं। यह मान लें कि कोई
  उसी साइट से प्रस्तुति दे रहा है जिसे आप डिबग कर रहे हैं।

## यहाँ क्या दस्तावेज़ित है

इस टेनेंट पर चल रहे सॉफ़्टवेयर बिल्ड पर डिबग API के माध्यम से पहुँच योग्य हर कमांड,
जिनमें से प्रत्येक का आउटपुट कहीं और से नकल किए जाने के बजाय एक जीवंत नोड से कैप्चर किया गया है।

[कमांड संदर्भ](./commands/) उन सभी को उनकी श्रेणी, विशेषाधिकार स्तर और ट्रांसपोर्ट के
साथ सूचीबद्ध करता है; [वर्कफ़्लो](./workflows/) उन्हें उन अनुक्रमों में जोड़ते हैं जिन्हें आप
वास्तव में तब उपयोग करते हैं जब कुछ गलत होता है।

Site CLI के केवल-ऑन-बॉक्स हिस्से — `configure`, `configure-network`,
`factory-reset`, `upgrade` और लगभग साठ और `ExecCLI` कमांड — शामिल नहीं हैं,
क्योंकि उनका आउटपुट किसी जीवंत नोड से उस तरह कैप्चर नहीं किया गया है जिस तरह नीचे दिए गए
हर पृष्ठ का किया गया है।

फिर भी, वे अब पहुँच से बाहर नहीं हैं। `scripts/sitecli_ssh_harvest.py` उपकरण के अपने
कम्प्लीशन मेनू को [SSH](./access/ssh/) पर चलाता है और प्रत्येक कमांड के लिए उपकरण द्वारा
दिया गया विवरण रिकॉर्ड करता है, ताकि सतह का अनुमान लगाने के बजाय उसे मापा जा सके।
इसका निष्पादन डिफ़ॉल्ट रूप से अस्वीकृत है — यह सब कुछ गणना करता है और केवल एक अनुमति-सूची चलाता है —
क्योंकि असत्यापित कमांड सिंटैक्स, और असत्यापित कमांड *प्रभाव*, वही दोष हैं जिन्हें दोहराए जाने
से बचाने के लिए यह दस्तावेज़ीकरण मौजूद है।
