[명령어 참조](../commands/)는 각 명령어가 무엇을 하는지에 따라 구성되어 있습니다. 이
문서들은 무엇이 잘못되었는지에 따라 구성되어 있습니다.

| 증상 | 워크플로 |
| --- | --- |
| 사이트가 한 번도 온라인이 되지 않았거나, 테넌트에서 이탈함 | [등록](./registration/) |
| 경로가 광고되거나 학습되지 않음; VIP에 접근할 수 없음 | [BGP](./bgp-diagnostics/) |
| 트래픽이 노드에 도달하지만 전달되지 않음 | [데이터 플레인](./dataplane-diagnostics/) |

각 단계는 해당 명령어를 문서화한 페이지로 연결됩니다. 여기에서는 아무것도 다시 설명하지 않으므로,
구문은 정확히 한 곳에만 존재하며 노드와 어긋날 수 없습니다.

## 시작하기 전에

어떤 접근 경로를 사용하고 있는지 확인하십시오. 이에 따라 가능한 작업이 달라집니다:

```bash
curl -sS -H "Authorization: APIToken $XCSH_API_TOKEN" \
  "$XCSH_API_URL/api/config/namespaces/system/sites/<site>" | jq -r '.spec.site_state'
```

`ONLINE`이면 [디버그 API](../access/debug-api/)가 응답합니다. 그 외의 값이라면 등록
워크플로가 필요하며, 등록에 의존하지 않는 경로 중 하나를 사용해야 합니다: 노드에 아직 네트워크
경로가 있다면 [사이트 콘솔](../access/site-console/), 없다면
[시리얼 콘솔](../access/serial-console/)입니다.

**완전히 누락된** 사이트의 경우 "등록되지 않았다"라고 결론짓기 전에 배제해야 할 설명이 하나 더
있습니다: 잘못된 테넌트를 조회하고 있을 가능성입니다. `cd terraform && terraform output -raw
xc_tenant`를 실행하면 이 배포가 속한 테넌트를 확인할 수 있습니다.
