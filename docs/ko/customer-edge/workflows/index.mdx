[명령어 참조](../commands/)는 각 명령어가 수행하는 작업을 기준으로 정리되어 있습니다. 여기서는
문제가 발생한 상황을 기준으로 정리되어 있습니다.

| 증상 | 워크플로우 |
| --- | --- |
| 사이트가 온라인 상태가 되지 않거나 테넌트에서 제외된 경우 | [등록](./registration/) |
| 라우트가 광고되거나 학습되지 않음; VIP에 연결할 수 없는 경우 | [BGP](./bgp-diagnostics/) |
| 트래픽이 노드에 도달하지만 수신되지 않는 경우 | [데이터 플레인](./dataplane-diagnostics/) |

각 단계는 해당 명령어를 문서화한 페이지로 연결됩니다. 여기에는 내용이 중복 기술되지 않으므로,
구문은 정확히 하나의 위치에만 존재하며 노드와 불일치가 발생하지 않습니다.

## 시작하기 전에

현재 사용 중인 액세스 경로를 확인하세요. 액세스 경로에 따라 가능한 작업이 달라집니다:

```bash
curl -sS -H "Authorization: APIToken $XCSH_API_TOKEN" \
  "$XCSH_API_URL/api/config/namespaces/system/sites/<site>" | jq -r '.spec.site_state'
```

`ONLINE` 상태이면 [디버그 API](../access/debug-api/)가 응답합니다. 그 외의 상태이면
[시리얼 콘솔](../access/serial-console/)을 사용해야 하며, 이 경우 등록 워크플로우를 진행해야 합니다.
