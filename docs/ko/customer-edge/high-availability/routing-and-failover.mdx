라우팅 수준 고가용성 디자인에서, 각 Customer Edge (CE) 사이트는 Border Gateway Protocol (BGP)을 통해 동일한 서비스 프리픽스를 발신합니다. 노스바운드 라우터는 사용 가능한 광고를 Equal-Cost Multi-Path (ECMP) 넥스트 홉으로 설치하고 트래픽을 분산하고 장애 경로를 제거하는 지점이 됩니다.

```text
서비스 VIP /32
       |
업스트림 라우터: 이퀄 코스트 넥스트 홉
       |              |              |
    CE 사이트 1    CE 사이트 2    CE 사이트 3
```

## 서비스 주소를 경로로 광고

서비스가 IPv4인 경우 개별 가상 IP 주소(VIP)를 `/32` 호스트 경로로 광고하십시오. 이러한 서비스 주소용으로 라우팅 전용 프리픽스를 예약하고, 해당 프리픽스를 Virtual Private Cloud (VPC), Virtual Network (VNet), VLAN 또는 로컬 서브넷에 연결하지 마십시오. 네트워크는 연결된 세그먼트의 Address Resolution Protocol (ARP)이 아닌 라우팅 광고로부터 서비스 주소를 학습해야 합니다.

서비스 프리픽스를 분리하여 유지하면 연결된 경로와 BGP 경로 간의 모호성을 방지할 수 있습니다. 또한 경로 정책, 필터링 및 용량 계획이 명확해집니다. 조직의 주소 관리 프로세스에 따라 프리픽스를 할당하십시오. 실습용 프리픽스를 다른 네트워크에 복사하지 마십시오.

## 라우팅이 장애 경로를 제거하도록 허용

수립된 BGP 세션은 업스트림 라우터에 활성 신호를 제공합니다. 세션이 닫히거나 홀드 타이머가 만료되면 피어는 해당 세션을 통해 학습한 경로를 철회합니다. 양쪽 피어가 모두 지원하고 활성화한 경우 Bidirectional Forwarding Detection (BFD)을 통해 더 빠른 장애 감지가 가능합니다. 따라서 수렴 시간은 구성된 프로토콜 및 타이머에 따라 달라지며 즉각적이지 않습니다.

정적 경로에는 동등한 세션 상태가 없습니다. 정적 ECMP 경로는 고객 라우터 또는 Software-Defined Wide Area Network (SD-WAN) 컨트롤러가 지원되는 헬스 메커니즘으로 넥스트 홉을 추적하고 경로를 제거하지 않는 한 CE 장애 후에도 적격한 상태로 유지됩니다. 이 메커니즘이 없으면 라우터는 계속해서 장애가 발생한 CE를 선택하여 일부 플로우를 블랙홀로 만들 수 있습니다.

<Aside type="danger" title="도달 가능한 넥스트 홉이 애플리케이션의 정상을 의미하지는 않습니다">
BGP는 라우팅 피어가 사용 가능함을 증명합니다. 이것이 해당 피어 뒤의 모든 애플리케이션이 정상임을 반드시 증명하는 것은 아닙니다. 라우팅 세션 상태로 충분한지 아니면 서비스 헬스에 별도의 지원되는 신호가 필요한지 결정하십시오.
</Aside>

## CE 플리트 전에 라우터 크기 산정

라우터는 설치할 이퀄 코스트 경로 수를 결정합니다. 라우터의 최대 ECMP 경로 수와 각 VIP에 대해 예상되는 CE 광고 수를 비교하십시오. 광고 수가 설치된 경로 제한보다 큰 경우, 추가적인 정상 CE 사이트가 해당 프리픽스에 대해 사용되지 않은 채로 남아 있을 수 있습니다.

BGP 수신 경로 뷰에만 의존하기보다는 설치된 포워딩 테이블을 확인하십시오. 제어 평면은 데이터 평면이 설치하는 것보다 더 많은 후보를 유지할 수 있습니다.

## 우선순위와 ECMP를 서로 다른 정책으로 취급

경로는 경로 선택 속성 및 메트릭이 동일하게 만드는 동안에만 이퀄 코스트가 됩니다. 로컬 기본 설정, Multi-Exit Discriminator (MED), 관리 거리 또는 정적 경로 메트릭을 변경하면 특정 VIP에 대해 하나의 CE가 선호되도록 만들 수 있습니다. 이는 유효한 조향 정책이지만 균등 분산이 아닌 활성/선호(active/preferred) 동작입니다.

이러한 비대칭이 의도적인 경우에만 프리픽스당 우선순위를 적용하십시오. 선호 경로가 철회될 때 덜 선호되는 경로가 사용 가능해지는지 확인하고, CE보다 오래 유지되는 추적되지 않는 정적 선호 경로를 남겨두지 마십시오.

## 제어 평면 레이블과 트래픽 증거 분리

여러 터널 또는 경로가 있는 디자인에서 `ACTIVE` 레이블은 제어 평면 동기화를 위해 선택된 경로를 식별할 수 있지만 다른 ECMP 경로가 데이터를 전달하지 않는다는 것을 증명하지는 않습니다. 이 레이블만으로 포워딩 상태를 유유하지 마십시오. 경로 또는 터널 테이블을 확인하고 예상되는 모든 경로에서 트래픽 카운터를 관찰하십시오.

## 전체 경로 검증

각 서비스 프리픽스에 대해 다음을 모두 검증하십시오.

- 의도한 모든 CE가 프리픽스를 광고하는지 여부
- 업스트림 BGP 테이블이 예상 경로를 수락하는지 여부
- 포워딩 테이블이 플랫폼이 지원하는 것보다 많지도 적지도 않은 경로를 설치하는지 여부
- 하나의 광고를 철회하면 구성된 감지 및 수렴 간격 후에 해당 넥스트 홉이 제거되는지 여부
- 남은 경로를 통해 애플리케이션 검사가 성공하는지 여부

CE 광고 문제와 업스트림 포워딩 문제를 구별하려면 리포지토리의 [BGP 진단 워크플로](../../workflows/bgp-diagnostics/)를 사용하십시오.

## 표준 참조

- [RFC 4271](https://www.rfc-editor.org/rfc/rfc4271.html)은 BGP 경로 철회 및 홀드 타이머 동작을 정의합니다.
- [RFC 5880](https://www.rfc-editor.org/rfc/rfc5880.html)은 BFD 장애 감지를 정의합니다.
