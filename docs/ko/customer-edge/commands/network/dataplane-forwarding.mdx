Argo는 포워딩 상태를 Linux 커널과 별도로 유지합니다.
[`ip`](../ip/)와 이 명령들이 서로 다른 결과를 보일 때, 실제로 트래픽을 움직이는 것은 이 명령들입니다.

## `rt`

VRF별 vRouter 라우트 테이블입니다.

```bash
{"command":["rt","--dump","2"]}
```

```text file=../../../../_data/sitecli-rt.txt
```

<Aside type="danger" title="VRF id는 BGP가 보고하는 값이 아닙니다">
`show-ip-bgp-summary`는 `vrf-id 3`을 출력합니다. 그것은 FRR의 번호 체계이며 vRouter 테이블 id와는
다른 네임스페이스입니다. 이 값을 여기에 전달하면 노드가 고장난 것처럼 보이는 방식으로 실패합니다:

```
vRouter(Response):  [No such file or directory (2)]
```

`--dump 0`에 대해서도 동일한 응답이 돌아옵니다. 이 토폴로지에서는 **VRF 2**가 채워진
inet4 테이블이며, VRF 1은 두 개의 라우트를 보유하고 있습니다. id를 모른다면
BGP 출력을 신뢰하지 말고 1부터 위로 올려가며 확인하십시오.
</Aside>

## `nh`

넥스트 홉 테이블입니다. 모든 라우트는 넥스트 홉 id를 가리키며, 이 명령이 그것을 해석해 줍니다.

```bash
{"command":["nh","--list"]}
```

```text file=../../../../_data/sitecli-nh.txt
```

각 항목은 `Type`과 소속 VRF를 담고 있습니다. 이 노드들에서는 여덟 가지 타입이
다음 비율로 나타나며, 세 개의 CE 모두에서 집계했을 때 동일합니다:

```text
Tunnel 558   Encap 27   NAT 22   Vrf 16   Receive 14   Composite 4   Drop 2   Resolve 2
```

`Drop` 넥스트 홉으로 해석되는 라우트는 블랙홀이며, 프리픽스가 `rt`에 존재하는데도 트래픽이
사라지는 경우에는 이 조합을 반드시 확인해 볼 만합니다.

<Aside type="caution" title="위 캡처는 잘려 있어 모든 타입을 포함하지 않습니다">
이는 3,849행 중 처음 60행입니다. 압도적으로 가장 흔한 타입인 `Tunnel`은 그 60행 안에
전혀 나타나지 않습니다. 따라서 이 캡처를 전체 타입 목록으로 읽지 마시고, 잘린 캡처에
없다는 이유로 어떤 타입이 노드에 존재하지 않는다고 결론짓지 마십시오. 위의 집계는
잘리지 않은 응답에서 얻은 것입니다.
</Aside>

## `vif`

가상 인터페이스 테이블: 데이터 플레인이 바인딩하는 대상과 인터페이스별
카운터입니다.

```bash
{"command":["vif","--list"]}
```

```text file=../../../../_data/sitecli-vif.txt
```

상단의 플래그 범례는 한 번 읽어 볼 만합니다 — `Vp`는 vhost 물리
인터페이스를, `Dpdk`는 DPDK가 관리하는 인터페이스를 나타냅니다. 이를 사용해 데이터 플레인이
예상한 인터페이스를 점유했는지 확인하고, 트래픽이 커널에 도달하지 않기 때문에 Linux가
보여주지 않는 RX 및 TX 카운터를 확인하십시오.
