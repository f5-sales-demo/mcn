Argo는 모든 연결을 추적합니다. 전체 덤프는 원칙적으로 제한이 없고 실제로 다루기 불편하기 때문에,
테이블에 무엇이 담겨 있는지보다 테이블을 어떻게 조회하는지가 더 중요합니다.

<Aside type="caution" title="629,760은 테이블의 용량이며, 플로우 수가 아닙니다">
헤더 줄 `Flow table(size 161218560, entries 629760)`은 데이터 플레인이 할당한 슬롯 수를
보고하며, 부하와 무관하게 여기의 모든 노드에서 동일합니다. 실제 활성 플로우 수는 그 줄에 없습니다.
몇 줄 아래의 `Entries: Created … Added … Deleted …`는 누적 카운터이며, 실제로 채워진 플로우는
범례 뒤에 출력되는 레코드입니다 — 이 문서를 작성하는 동안 수행한 실행에서는 542줄 응답 중 73개였습니다.
</Aside>

## `flow-l-match`

거의 항상 원하는 것이 이 명령입니다. 주소 하나, 또는 주소와 포트를 받습니다.

```bash
{"command":["flow-l-match","100.127.192.10:53"]}
```

```text file=../../../../_data/sitecli-flow-l-match.txt
```

각 플로우의 action이 핵심입니다: `F` 전달, `D` 드롭, `N` NAT. action이 `D`인 플로우가
존재한다는 것은 데이터 플레인이 의도적인 결정을 내렸다는 의미이며, 이는 연결성 문제가 아니라
정책을 살펴보도록 안내합니다.

## `flow-l`

전체 덤프입니다.

```bash
{"command":["flow-l"]}
```

```text file=../../../../_data/sitecli-flow-l.txt
```

<Aside type="caution" title="잘려 있으며, 크기는 변동합니다">
위 캡처는 1,186줄 응답에서 처음 60줄만 잘라낸 것입니다. 이 문서를 작성하는 동안의 실행은
542줄을 반환했습니다 — 응답 길이는 활성 플로우 수에 따라 달라지므로, 두 숫자 모두 명령 자체의
속성은 아닙니다. 테이블 전체를 살펴봐야 할 진짜 필요가 없다면 `flow-l-match`를 사용하십시오.
</Aside>
