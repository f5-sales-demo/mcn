CE는 BGP에 FRR을 사용합니다. 이 토폴로지에서는 두 개의 Azure Route Server
인스턴스와 피어링하고, VIP를 광고하며, VNet 프리픽스를 학습합니다.

## `show-ip-bgp-summary`

여기서 시작하세요. 한 화면에서 피어링이 활성화되어 있는지, 얼마나 오래
안정적으로 유지되었는지 확인할 수 있습니다.

```bash
{"command":["show-ip-bgp-summary"]}
```

```text file=../../../../_data/sitecli-show-ip-bgp-summary.txt
```

`State/PfxRcd`를 먼저 확인하세요. 숫자는 수신된 프리픽스의 수를 나타내며 세션이
확립되었음을 의미합니다. 그 외의 값 — `Active`, `Connect`, `Idle` — 은 세션이
활성화되지 않은 상태입니다. `Up/Down`은 현재 상태가 지속된 시간을 보여주므로,
계속 재설정되는 세션은 의심스럽게 작은 값을 나타냅니다.

<Aside type="caution" title="여기서의 vrf id는 rt가 원하는 것이 아닙니다">
이 출력은 `vrf-id 3`을 보고합니다. 이는 FRR의 번호 체계입니다. Argo 데이터 플레인은
별도의 테이블 id를 사용하며, FRR의 번호를
[`rt --dump`](../dataplane-forwarding/)에 전달하면 `No such file or directory`가
반환됩니다. 이는 잘못된 인수가 아니라 노드가 손상된 것처럼 보일 수 있습니다.
</Aside>

## `show-ip-bgp`

최적 경로 선택이 표시된 전체 테이블입니다.

```bash
{"command":["show-ip-bgp"]}
```

```text file=../../../../_data/sitecli-show-ip-bgp.txt
```

`*`는 유효한 경로, `>`는 선택된 최적 경로, `=`는 멀티패스 멤버를 나타냅니다. 하나의
프리픽스에 대해 두 항목이 모두 `*=`로 표시되면 ECMP가 적용 중임을 의미하며, 이것이
이 토폴로지에서 의도된 상태입니다.

## `show-ip-bgp-neighbors`

이웃별 세부 정보: 협상된 기능, 타이머, 메시지 카운터 및 마지막 재설정 이유.

```bash
{"command":["show-ip-bgp-neighbors"]}
```

요약에서 세션이 플래핑되고 있고 그 원인을 알아야 할 때 사용하세요.
`Last reset`과 그 이유가 유용한 항목입니다.

<Aside type="note" title="이 페이지에 캡처된 출력이 아직 없습니다">
이 캡처는 `f5-sales-demo/docs-control#795`가 반영될 때까지 커밋할 수 없습니다. FRR이
Graceful Restart 줄에서 단어를 잘못 철자하며, `codespell`이 해당 파일을 거부합니다.

캡처된 텍스트를 수정하면 실제로 발생하지 않은 출력을 설명하는 문서가 되므로,
대신 업스트림에서 수정 중입니다. 그 동안은 자신의 노드에서 직접 명령어를 실행하세요.
</Aside>

## `show-ip-bgp-neighbors-advertised-route`

이 노드가 피어에게 알리는 내용으로, 노드가 알고 있는 내용과 구별됩니다.

```bash
{"command":["show-ip-bgp-neighbors-advertised-route"]}
```

```text file=../../../../_data/sitecli-show-ip-bgp-neighbors-advertised-route.txt
```

이 명령어는 "VIP가 VNet에서 도달할 수 없다"는 문제에 사용합니다. VIP가
여기에 없으면 문제는 이 노드에 있으며, 피어를 아무리 살펴봐도 도움이 되지 않습니다.
