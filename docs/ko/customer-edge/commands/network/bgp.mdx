CE는 BGP를 위해 FRR을 실행합니다. 이 토폴로지에서는 두 개의 Azure Route Server
인스턴스와 피어링하고, VIP를 광고하며, VNet 프리픽스를 학습합니다.

## `show-ip-bgp-summary`

여기서 시작하십시오. 한 화면으로 피어링이 정상 동작 중인지, 얼마나 오래 안정적으로
유지되었는지 알 수 있습니다.

```bash
{"command":["show-ip-bgp-summary"]}
```

```text file=../../../../_data/sitecli-show-ip-bgp-summary.txt
```

먼저 `State/PfxRcd`를 확인하십시오. 숫자는 수신한 프리픽스의 개수이며 세션이
확립되었음을 의미합니다. 그 외의 값 — `Active`, `Connect`, `Idle` — 은 세션이
정상 동작하지 않는 상태입니다. `Up/Down`은 현재 상태가 얼마나 지속되었는지를 보여주므로,
계속 재설정되는 세션은 의심스러울 정도로 작은 값을 나타냅니다.

<Aside type="caution" title="여기의 vrf id는 rt가 요구하는 값이 아닙니다">
이 출력은 `vrf-id 3`을 보고합니다. 이는 FRR의 번호 체계입니다. Argo 데이터 플레인은
별도의 테이블 id를 사용하며, FRR의 번호를
[`rt --dump`](../dataplane-forwarding/)에 전달하면 `No such file or directory`가 반환되는데,
이는 잘못된 인수 문제라기보다 노드가 고장난 것처럼 보입니다.
</Aside>

## `show-ip-bgp`

베스트 패스 선택이 표시된 전체 테이블입니다.

```bash
{"command":["show-ip-bgp"]}
```

```text file=../../../../_data/sitecli-show-ip-bgp.txt
```

`*`는 유효한 경로, `>`는 선택된 베스트 패스, `=`는 멀티패스 멤버를 의미합니다. 위 캡처에서
학습된 VNet 프리픽스 `10.0.0.0/16`은 두 개의 경로 — 각 Route Server 인스턴스를 경유하는
경로 — 를 가지며 `*=`와 `*>`로 표시됩니다. 즉, 베스트 패스와 멀티패스 멤버가 함께 있으므로
노드는 반환 트래픽을 두 인스턴스에 부하 분산합니다. VIP `10.250.0.10/32`는 이 노드가
직접 생성하기 때문에 단일 `*>` 경로를 가집니다.

<Aside type="caution" title="이 데모의 3방향 ECMP는 이 출력에서 보이지 않습니다">
`show-ip-bgp`는 한 노드의 테이블입니다. 이 배포가 시연하는 ECMP는 세 개의 *서로 다른*
CE가 동일한 `/32`를 광고하는 것이며, Azure 측에서 프로그래밍됩니다. 따라서 단일 CE의
BGP 테이블로는 이를 확인할 수 없으며, 여기서 VIP에 멀티패스 표시가 없는 것은 결함이 아닙니다.
대신 Route Server 피어링이나 클라이언트의 유효 경로 테이블에서 이를 증명하십시오.
둘 다 [as-built 페이지](../../../../as-built/)에 있습니다.
</Aside>

## `show-ip-bgp-neighbors`

네이버별 상세 정보: 협상된 기능, 타이머, 메시지 카운터, 그리고 마지막 재설정 사유입니다.

```bash
{"command":["show-ip-bgp-neighbors"]}
```

요약에서 세션이 플래핑하는 것으로 나타나고 그 이유를 알아야 할 때 사용하십시오.
`Last reset`과 그 사유가 유용한 항목입니다.

<Aside type="note" title="이 페이지에는 아직 캡처된 출력이 없습니다">
이 캡처는 `f5-sales-demo/docs-control#795`가 반영될 때까지 커밋할 수 없습니다. FRR이
Graceful Restart 항목에서 단어를 잘못 표기하여 `codespell`이 해당 파일을 거부합니다.

캡처된 텍스트를 수정하면 이 문서가 실제로 발생하지 않은 출력을 설명하게 되므로,
대신 업스트림에서 수정 중입니다. 그동안에는 직접 자신의 노드에서 명령을 실행하십시오.
</Aside>

## `show-ip-bgp-neighbors-advertised-route`

이 노드가 알고 있는 내용이 아니라, 피어에게 알리고 있는 내용입니다.

```bash
{"command":["show-ip-bgp-neighbors-advertised-route"]}
```

```text file=../../../../_data/sitecli-show-ip-bgp-neighbors-advertised-route.txt
```

"VNet에서 VIP에 도달할 수 없다"는 상황에 사용하는 명령입니다. 여기에 VIP가 없다면
문제는 이 노드에 있으며, 피어를 아무리 살펴봐도 도움이 되지 않습니다.

출력은 **피어별로** `bgp neighbor:` 블록을 하나씩 반복하므로, 이 토폴로지에서는 동일한
두 프리픽스가 두 번 — 각 Route Server 인스턴스마다 한 번씩 — 나타납니다. 이는 중복
렌더링이 아니라, 노드가 두 피어 모두에 광고하고 있음을 확인해 주는 것입니다. 한 피어에는
블록이 있고 다른 피어에는 없거나 짧은 경우가 주목해야 할 상황입니다.
