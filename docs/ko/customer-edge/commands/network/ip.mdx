이 배포의 CE 한 대에서 2026-07-28에 캡처되었습니다. `sitecli/capture-manifest.json`에
어떤 노드였는지 기록되어 있으며, `scripts/capture-sitecli.sh --check`는 실제 CE를 대상으로
명령 표면을 다시 검증합니다.

이 명령들은 커널의 관점을 보고합니다. Argo 데이터 플레인은
[`vif`](../dataplane-forwarding/)를 통해 볼 수 있는 자체적인 관점을 유지하며, 둘은 서로
일치하지 않을 수 있습니다.

## `ip`

`ip` 하위 명령을 받습니다. `addr`가 일반적으로 사용되며, `route`, `link`, `neigh`도
동작합니다.

```bash
{"command":["ip","addr"]}
```

```text file=../../../../_data/sitecli-ip.txt
```

CE는 설계상 세 개의 Azure NIC — 관리/SLO, 외부, 내부/SLI — 를 갖지만, 게스트는 그 순서가
암시하는 방식으로 이들을 제공하지 않으며, 바로 이 지점에서 출력을 잘못 읽으면 시간을
낭비하게 됩니다.

| 게스트에서 | 담당하는 것 |
| --- | --- |
| `a-i-eth0` | **주소가 전혀 없음** — 이름이 변경된 물리 eth0이며, Argo 데이터 플레인이 소유합니다 |
| `vhost0` | 관리/SLO 주소로, BGP가 피어링하는 주소이자 사이트 객체가 보고하는 주소입니다 |
| `eth1` 및 `eth2` | 외부 및 내부/SLI 주소 — 다만 **순서가 고정되어 있지 않습니다** |

<Aside type="danger" title="eth1과 eth2 중 어느 것이 내부 인터페이스인지는 노드마다 다릅니다">
이 단일 배포의 세 CE에서 실시간으로 읽은 결과: `f5-xc-ce-vm-01`과 `f5-xc-ce-vm-03`에서는
내부/SLI 주소가 `eth2`에 있고, `f5-xc-ce-vm-02`에서는 `eth1`에 있습니다. 구성에서 이를
선택하는 요소는 없습니다.

따라서 인터페이스 이름으로 서브넷을 추론하지 말고, 한 노드의 매핑을 다른 노드로 옮기지
마십시오. 대신 주소로 매칭하십시오 — CE 주소가 속한 서브넷은 그것을 보유한 인터페이스가
그렇지 않더라도 안정적입니다.
</Aside>

`a-i-eth0`가 주소를 갖지 않는다는 점은 관리 주소에서 `sshd`에 도달할 수 없는 이유
그 자체이기도 합니다: 포트가 차단된 것이 아니라 거기에 리스너가 없습니다.
[SSH](../../../access/ssh/)를 참조하십시오.

## `ip-link-show`

링크 계층만: 상태, MTU, 큐잉 규율, MAC.

```bash
{"command":["ip-link-show"]}
```

```text file=../../../../_data/sitecli-ip-link-show.txt
```

"링크가 올라와 있는가, MTU는 무엇인가"가 질문일 때는 `ip addr`보다 빠릅니다.
MTU 불일치는 터널이 수립되지만 트래픽이 전달되지 않는 원인으로 반복적으로 나타납니다.

## `ip-link-set` <Badge text="Exec tier — mutating" variant="danger" />

인터페이스 또는 그룹을 up 또는 down 상태로 만듭니다.

```text
ip-link-set (<device>||<group>) (up||down)
```

<Aside type="danger" title="여기서 실행되지 않으며, 일반적인 방식으로 접근할 수도 없습니다">
이 빌드에서 유일한 `Exec` 계층 명령입니다. `exec-user`가 아닌 `exec` 엔드포인트로
전달되며, 노드를 변경합니다: 원격 CE에서 `eth0`을 down 상태로 만들면 디버그 API 자체를
포함해 해당 CE를 관리하는 경로가 사라집니다.

이 페이지에는 의도적으로 캡처된 출력이 없습니다. 캡처 하니스는 `Exec` 계층 전체를
거부하며, 하드코딩된 목록이 아니라 실시간 카탈로그에서 계층을 읽으므로, 향후 빌드가
다른 명령을 이 계층으로 승격해도 이 원칙은 유지됩니다.
</Aside>
