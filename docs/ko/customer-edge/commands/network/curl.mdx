두 개의 명령이 있으며, 그 차이점이 바로 전체 가치입니다.

## `curl-host`

호스트 네트워크 네임스페이스에서 실행되며 — 데이터 플레인이 관여하기 이전의 노드 자체 연결입니다.

```bash
{"command":["curl-host","-v","cloud.f5.com"]}
```

```text file=../../../../_data/sitecli-curl-host.txt
```

## `curl-vega`

Kubernetes 클러스터 컨텍스트 내부에서 실행되므로, 클러스터의 DNS 및 네트워크 경로를 통과합니다.

```bash
{"command":["curl-vega","-v","cloud.f5.com"]}
```

```text file=../../../../_data/sitecli-curl-vega.txt
```

<Aside type="tip" title="두 명령은 이분법적 쌍입니다">
두 명령을 모두 실행하세요. `curl-host`는 성공하고 `curl-vega`가 실패하면, 노드는 연결성을 가지고 있으며 클러스터 네트워크 또는 DNS에 문제가 있는 것입니다. 둘 다 실패하면, 문제는 노드 상위에 있습니다 — 라우팅, 방화벽, 또는 이그레스 경로를 확인하세요. `curl-host`만 실패하는 경우, 비정상적인 상황이므로 먼저 호스트 라우팅 테이블을 확인해야 합니다.
</Aside>

두 명령 모두 일반 `curl` 인수를 별도의 배열 요소로 허용합니다. `-v`는 유지하는 것이 좋은데, 연결 및 TLS 핸드셰이크 라인이 보통 실패가 나타나는 지점이기 때문입니다.
