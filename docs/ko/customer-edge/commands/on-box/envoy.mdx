이 배포의 CE 한 대에서 2026-07-28에 캡처했습니다. 온박스(on-box) 명령이므로 디버그 API가 아닌
Site CLI를 통해 전달됩니다. `sitecli/exec-catalog.json`은 해당 서피스를 기록하고,
`sitecli/capture-manifest.json`은 어느 노드였는지를 기록합니다.

Envoy는 Customer Edge에서 애플리케이션 트래픽을 종료하고 프록시합니다. 아래 네 가지 명령은
Envoy의 admin 인터페이스를 조회하며, 어느 것도
[디버그 API](../../../access/debug-api/)에는 없습니다.

<Aside type="note" title="이 명령들은 모두 curl 진행률 표시로 시작합니다">
이 명령들은 Envoy의 admin 엔드포인트를 감싸는 `curl` 래퍼이며 `-s` 없이 호출되므로, 아래 모든
캡처의 처음 두세 줄은 stderr로 출력되는 curl의 전송 진행 상황입니다:

```text
  % Total    % Received % Xferd  Average Speed   Time    Time     Time  Current
                                 Dload  Upload   Total   Spent    Left  Speed
  0     0    0     0 …
```

이는 Envoy의 출력이 아니며 오류도 아닙니다. 그리고 유용하기도 합니다: `% Received` 바이트 수는
Envoy가 무언가를 반환하기는 했는지를 알려주며, 이를 통해 "구성된 listener가 없음"과
"admin 인터페이스가 응답하지 않음"을 구분할 수 있습니다.
</Aside>

## `envoy-listeners`

Envoy에 설치된 모든 listener를 `name:address:port` 형식으로 표시합니다.

```bash
execcli envoy-listeners
```

```text file=../../../../_data/sitecli-envoy-listeners.txt
```

**확인할 점.** 이 배포에서 listener는 `10.250.0.10:80`을 가지고 있으며, 이는 CE가 BGP로
광고하는 VIP입니다. 이 한 줄이 세 개의 계층을 하나로 묶어 줍니다. 만약
[`show-ip-bgp-summary`](../../network/bgp/)에서는 프리픽스가 광고되고 있는데 이 listener가
없다면, 해당 경로는 서비스를 제공하지 못할 노드로 트래픽을 끌어당기고 있는 것이며, 이는 ECMP
집합에서 최악의 장애 유형입니다. 트래픽이 블랙홀로 분산되기 때문입니다.

뒤에 붙는 `[fe80:…]:80`은 listener가 바인딩된 인터페이스의 링크 로컬 주소입니다.

**알려주지 않는 것.** 업스트림 상태에 대해서는 아무것도 알려주지 않습니다 — 뒤에 있는 무언가에
도달할 수 있든 없든 listener는 존재합니다. 그 부분은 `envoy-clusters`를 사용하십시오.

## `envoy-clusters`

각 우선순위별 연결 및 요청 제한을 포함한 모든 cluster를 표시합니다.

```bash
execcli envoy-clusters
```

```text file=../../../../_data/sitecli-envoy-clusters.txt
```

**확인할 점.** 각 줄은 `cluster::scope::key::value` 형식입니다. `observability_name` 항목이
각 cluster를 식별하며, `default_priority::max_connections`, `max_pending_requests`,
`max_requests` 세 가지 항목에서 요청 제한을 확인할 수 있습니다 — `max_pending_requests`에
고정되어 있는 cluster는 업스트림이 아니라 구성에 의해 제한(throttle)되고 있는 것입니다.

## `envoy-config-dump`

Envoy의 전체 구성을 JSON으로 출력합니다. 용량이 큽니다: 유휴 상태인 데모 노드에서도 126 KB입니다.

```bash
execcli envoy-config-dump
```

```text file=../../../../_data/sitecli-envoy-config-dump.txt
```

**확인할 점.** 최상위 `configs` 배열에는 구성 유형별로 하나의 객체가 들어 있습니다 —
bootstrap, clusters, listeners, routes, secrets. listener나 cluster가 존재하는데 예상과 다르게
동작할 때 이 명령을 사용하고, 전체를 읽기보다는 검색하십시오.

## `envoy-hc-config-dump`

헬스 체크 구성만 별도로 출력합니다.

```bash
execcli envoy-hc-config-dump
```

```text file=../../../../_data/sitecli-envoy-hc-config-dump.txt
```

**확인할 점.** 이 배포에서는 **단 1바이트**를 반환합니다 — curl 진행률 표시에서 `100 1`로
나타납니다 — 이는 설치된 헬스 체크 구성이 없다는 의미입니다. 헬스 체크 대상 오리진 풀이 없는
CE에서는 예상되는 상태이며, 이를 인지해 둘 가치가 있습니다: 여기서 결과가 비어 있는 것은
쿼리 실패가 아닙니다.
