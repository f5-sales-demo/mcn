이 배포의 CE 중 하나에서 2026-07-28에 캡처되었습니다. 이것들은 온박스 명령이므로 디버그 API가 아닌 Site CLI를 통해 제공됩니다. `sitecli/exec-catalog.json`은 표면을 기록하고 `sitecli/capture-manifest.json`은 노드를 기록합니다.

Envoy는 Customer Edge에서 애플리케이션 트래픽을 종료하고 프록시합니다. 이 네 가지 명령은 Envoy의 관리 인터페이스를 쿼리하며, 그 중 어느 것도
[디버그 API](../../../access/debug-api/)에는 없습니다.

<Aside type="note" title="이 중 모든 항목은 curl 진행 미터로 시작합니다">
이것들은 `-s` 없이 호출된 Envoy의 관리 엔드포인트를 감싸는 `curl` 래퍼이므로, 아래 모든 캡처의 처음 두세 줄은 stderr에 기록된 curl의 전송 진행 내용입니다:

```text
  % Total    % Received % Xferd  Average Speed   Time    Time     Time  Current
                                 Dload  Upload   Total   Spent    Left  Speed
  0     0    0     0 …
```

이것은 Envoy 출력이 아니며 오류도 아닙니다. 또한 유용합니다: `% Received` 바이트 수를 통해 Envoy가 무언가를 반환했는지 여부를 알 수 있으며, 이를 통해 "리스너가 구성되지 않음"과 "관리 인터페이스가 응답하지 않음"을 구분할 수 있습니다.
</Aside>

## `envoy-listeners`

Envoy가 설치한 모든 리스너를 `name:address:port` 형식으로 표시합니다.

```bash
execcli envoy-listeners
```

```text file=../../../../_data/sitecli-envoy-listeners.txt
```

**확인할 사항.** 이 배포에서 리스너는 `10.250.0.10:80` — CE가 BGP에 광고하는 VIP를 포함합니다. 해당 한 줄은 세 가지 계층을 연결합니다: [`show-ip-bgp-summary`](../../network/bgp/)에서 프리픽스가 광고되고 있지만 이 리스너가 없다면, 경로는 이를 서비스하지 않을 노드로 끌어당겨지는 것이며, 이는 ECMP 세트에서 최악의 장애 모드입니다. 트래픽이 블랙홀로 부하 분산되기 때문입니다.

뒤에 오는 `[fe80:…]:80`은 리스너가 바인딩된 인터페이스의 링크 로컬 주소입니다.

**알려주지 않는 사항.** 업스트림 상태에 대해서는 아무것도 알려주지 않습니다 — 리스너는 그 뒤에 있는 것에 접근할 수 있는지 여부와 관계없이 존재합니다. 그에 대해서는 `envoy-clusters`를 사용하십시오.

## `envoy-clusters`

모든 클러스터와 우선순위별 연결 및 요청 제한을 표시합니다.

```bash
execcli envoy-clusters
```

```text file=../../../../_data/sitecli-envoy-clusters.txt
```

**확인할 사항.** 줄은 `cluster::scope::key::value` 형식입니다. `observability_name` 항목은 각 클러스터를 식별하고, `default_priority::max_connections`, `max_pending_requests` 및 `max_requests` 삼중 항목은 요청 제한이 나타나는 곳입니다 — `max_pending_requests`에 고정된 클러스터는 업스트림이 아닌 구성에 의해 스로틀링되고 있는 것입니다.

## `envoy-config-dump`

JSON 형식의 Envoy 전체 구성. 유휴 상태의 데모 노드에서 126 KB로 큽니다.

```bash
execcli envoy-config-dump
```

```text file=../../../../_data/sitecli-envoy-config-dump.txt
```

**확인할 사항.** 최상위 `configs` 배열은 구성 유형별로 하나의 객체를 포함합니다 — 부트스트랩, 클러스터, 리스너, 라우트, 시크릿. 리스너나 클러스터가 존재하지만 예기치 않게 동작할 때 이것을 활용하되, 전체를 읽기보다는 검색하십시오.

## `envoy-hc-config-dump`

특별히 상태 확인 구성을 표시합니다.

```bash
execcli envoy-hc-config-dump
```

```text file=../../../../_data/sitecli-envoy-hc-config-dump.txt
```

**확인할 사항.** 이 배포에서는 **단일 바이트**를 반환합니다 — `curl` 미터에서 `100 1`로 표시됩니다 — 즉, 상태 확인 구성이 설치되어 있지 않음을 의미합니다. 이는 상태 확인된 오리진 풀이 없는 CE의 예상 상태이며, 인식할 가치가 있습니다: 여기서 빈 결과는 쿼리 실패가 아닙니다.
