Envoy는 Customer Edge에서 애플리케이션 트래픽을 종료하고 프록시합니다. 다음 네 가지 명령은
Envoy의 관리 인터페이스를 쿼리하며, 이 중 어느 것도
[디버그 API](../../../access/debug-api/)에 포함되어 있지 않습니다.

<Aside type="note" title="이 명령들은 모두 curl 진행 미터로 시작합니다">
이 명령들은 Envoy의 관리 엔드포인트를 감싸는 `curl` 래퍼로, `-s` 옵션 없이 호출되므로 아래 각 캡처의 처음 두세 줄은 stderr에 출력된 curl의 전송 진행 정보입니다:

```text
  % Total    % Received % Xferd  Average Speed   Time    Time     Time  Current
                                 Dload  Upload   Total   Spent    Left  Speed
  0     0    0     0 …
```

이는 Envoy 출력이 아니며 오류도 아닙니다. 이 정보는 유용하기도 합니다: `% Received` 바이트 수를 통해 Envoy가 실제로 응답을 반환했는지 여부를 확인할 수 있으며, "리스너가 구성되지 않음"과 "관리 인터페이스가 응답하지 않음"을 구별할 수 있습니다.
</Aside>

## `envoy-listeners`

Envoy에 설치된 모든 리스너를 `name:address:port` 형식으로 표시합니다.

```bash
execcli envoy-listeners
```

```text file=../../../../_data/sitecli-envoy-listeners.txt
```

**확인할 사항.** 이 배포에서 리스너는 `10.250.0.10:80`을 포함하며, 이는 CE가 BGP에 광고하는 VIP입니다. 이 단일 줄은 세 가지 레이어를 연결합니다: [`show-ip-bgp-summary`](../../network/bgp/)에서 프리픽스가 광고되고 있지만 이 리스너가 없는 경우, 라우트가 해당 트래픽을 처리하지 못하는 노드로 유인되는 것입니다. 이는 ECMP 세트에서 트래픽이 블랙홀로 부하 분산되기 때문에 가장 심각한 장애 유형입니다.

뒤따르는 `[fe80:…]:80`은 리스너가 바인딩된 인터페이스의 링크-로컬 주소입니다.

**알 수 없는 사항.** 업스트림 상태에 대한 정보는 제공하지 않습니다 — 리스너는 그 뒤에 있는 항목의 도달 가능 여부와 무관하게 존재합니다. 업스트림 상태 확인을 위해서는 `envoy-clusters`를 사용하십시오.

## `envoy-clusters`

모든 클러스터를 우선순위별 연결 및 요청 한도와 함께 표시합니다.

```bash
execcli envoy-clusters
```

```text file=../../../../_data/sitecli-envoy-clusters.txt
```

**확인할 사항.** 각 줄은 `cluster::scope::key::value` 형식입니다. `observability_name` 항목이 각 클러스터를 식별하며, `default_priority::max_connections`, `max_pending_requests`, `max_requests` 세 가지 항목에서 요청 한도를 확인할 수 있습니다 — `max_pending_requests`에 고정된 클러스터는 업스트림이 아닌 구성에 의해 스로틀링되고 있는 것입니다.

## `envoy-config-dump`

Envoy의 전체 구성을 JSON 형식으로 표시합니다. 유휴 상태의 데모 노드에서도 126 KB에 달하는 대용량 데이터입니다.

```bash
execcli envoy-config-dump
```

```text file=../../../../_data/sitecli-envoy-config-dump.txt
```

**확인할 사항.** 최상위 `configs` 배열은 구성 유형별(부트스트랩, 클러스터, 리스너, 라우트, 시크릿) 객체를 하나씩 포함합니다. 리스너 또는 클러스터가 존재하지만 예상과 다르게 동작할 때 이 명령을 사용하되, 전체를 읽기보다는 검색하여 활용하십시오.

## `envoy-hc-config-dump`

상태 확인(health-check) 구성을 구체적으로 표시합니다.

```bash
execcli envoy-hc-config-dump
```

```text file=../../../../_data/sitecli-envoy-hc-config-dump.txt
```

**확인할 사항.** 이 배포에서는 **단일 바이트**를 반환하며, curl 미터에서 `100 1`로 표시됩니다. 이는 상태 확인 구성이 설치되어 있지 않음을 의미합니다. 이는 상태 확인 오리진 풀이 없는 CE의 정상적인 상태이며, 이 점을 인식하는 것이 중요합니다: 여기서 빈 결과는 쿼리 실패가 아닙니다.
