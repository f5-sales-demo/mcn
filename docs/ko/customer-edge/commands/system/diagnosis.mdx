## `diagnosis`

<Aside type="caution" title="GLOBAL 범위 — 다른 전송 방식">
`health`와 마찬가지로, `global` 경로에 대한 `GET` 요청이며 `exec-user`를 통해 접근할 수 없습니다.

```bash
curl -sS -H "Authorization: APIToken $XCSH_API_TOKEN" \
  "$XCSH_API_URL/api/operate/namespaces/system/sites/<site>/vpm/debug/global/diagnosis"
```

</Aside>

```json file=../../../../_data/sitecli-diagnosis.txt
```

노드는 자체 게이트웨이를 프로브하고 노드별로 결과를 보고하므로, 멀티 노드 사이트에서는 각 노드당 하나의 블록이 반환됩니다. `gateway_connectivity`에는 핑 요약 정보인 `sent`, `received`, `lost` 및 왕복 시간이 포함되어 있습니다.

<Aside type="note" title="게이트웨이에 대한 100% 손실이 반드시 장애를 의미하지는 않습니다">
이 토폴로지에서 게이트웨이는 ICMP에 응답하지 않으므로, 사이트가 `ONLINE` 상태에서 트래픽을 포워딩하는 동안 `lost: 100`이 정상 상태입니다. 이 필드는 이미 다른 문제의 증거가 있거나 값이 변경될 때만 신호로 간주하십시오.
</Aside>

`resolv_conf`는 보다 일관되게 유용한 필드로, 노드가 실제로 사용할 리졸버를 보여줍니다. [`dig`](../../network/dig/)에서 시간을 들이기 전에 예상값과 비교해 보는 것이 좋습니다.
