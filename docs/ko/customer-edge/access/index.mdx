네 가지 경로가 작동하며, 어떤 경로를 적용할지는 선호도가 아니라 노드의 상태, 연결 위치, 그리고 접근해야 하는 대상에 따라 결정됩니다.

| 경로 | 노드 `ONLINE` 필요 | 네트워크 도달 가능성 필요 | 제한 사항 | 대상 범위 |
| --- | --- | --- | --- | --- |
| [디버그 API](./debug-api/) | **예** | 예 | 새 사이트에서 약 25~30분의 워밍업 | 34개 명령 |
| [Site 콘솔](./site-console/) | 아니요 | Azure Bastion을 통해 점프 호스트 불필요 | Bastion은 터널링이 지원되는 Standard SKU여야 함 | F5의 노드 문제 해결 UI |
| [SSH](./ssh/) | 아니요 | VNet 내부에서 내부 주소로만 | 키는 첫 번째 부팅 시 존재해야 함 | 온박스 Site CLI 전체 |
| [직렬 콘솔](./serial-console/) | 아니요 | 아니요 | VM당 하나의 세션, 2,048자 붙여넣기 제한 | 온박스 Site CLI 전체 |

직렬 콘솔은 최후의 수단이며, 작동하는 네트워크 경로가 없는 노드에서도 사용할 수 있는 유일한 경로입니다.

[Site 콘솔](./site-console/)은 일반적으로 가장 먼저 시도해 볼 경로입니다. 접근이 자격 증명 배포 문제 대신 Azure RBAC 결정이 되므로, SSH 키를 배포할 필요가 없고 점프 호스트도 없으며 노드에 공개 IP도 불필요하고 VM 교체도 필요하지 않습니다. 명령 인터페이스가 아닌 F5 자체의 문제 해결 UI를 제공하므로, 특정 명령을 실행하거나 무언가를 스크립팅해야 할 때는 이를 넘어서는 경로를 선택하십시오.

SSH는 디버그 API가 충분하지 않을 때 선택하는 경로입니다. 어플라이언스가 API를 통해 노출하는 34개보다 훨씬 많은 명령을 제공하기 때문입니다. 두 가지 비용이 있습니다. 키는 cloud-init에 의해 기록되므로 **첫 번째 부팅** 시 반드시 존재해야 합니다. 즉, 실행 중인 노드에서 이를 활성화하면 해당 노드를 교체해야 하며, 현재 이로 인해 등록이 막힐 수 있습니다 ([이슈 674](https://github.com/f5-sales-demo/mcn/issues/674)). 또한 `sshd`는 노드의 내부 주소에서만 응답하므로 VNet 내부의 호스트가 필요합니다. 알고 있는 노드 주소를 탐색하면 항상 닫힌 것으로 보고됩니다.

## 분리가 선호도 문제가 아닌 이유

디버그 API는 F5 Distributed Cloud 컨트롤 플레인에서 제공되며, 이는 등록 중에 `vpm`이 설정하는 터널을 통해 노드로 중계됩니다. 등록이 없으면 터널이 없고, 터널이 없으면 API가 중계할 대상이 없습니다.

명확한 오류 대신 도움이 되지 않는 방식으로 실패하므로, 부팅되지 않은 노드는 API 문제처럼 보일 수 있습니다.

직렬 콘솔은 완전히 반대 방향으로 작동합니다. Azure 플랫폼을 통해 노드의 에뮬레이트된 직렬 포트로 연결됩니다. 노드가 등록되어 있는지, 네트워크 도달 가능성이 있는지, 작동하는 데이터 플레인이 있는지 여부에 관계없이 동작합니다. 이러한 독립성이 핵심이며, 바로 이 때문에 CE VM에서 부팅 진단을 활성화된 상태로 유지해야 합니다.

<Aside type="note" title="선택 기준">
자동화를 작성하거나 나중에 다시 실행할 증거를 수집하는 경우, 디버그 API를 사용하십시오. 등록이 문제인 경우, 직렬 콘솔은 대안이 아닙니다. 유일한 옵션입니다.
</Aside>

## 자격 증명

각 경로는 서로 다른 자격 증명을 사용하며, 그 어느 것도 명령줄에 입력해서는 안 됩니다.

- **디버그 API** — `XCSH_API_TOKEN`으로 설정된 F5 Distributed Cloud API 토큰과 `XCSH_API_URL`로 설정된 테넌트 URL. `~/.config/xcsh/contexts/<tenant>.json`에 있는 `xcsh` 컨텍스트 파일에 두 값이 모두 포함되어 있으며, 환경에서 제공하지 않을 경우 `scripts/capture-sitecli.sh`가 이 파일을 읽습니다.
- **SSH** — 배포 시 첫 번째 부팅에서 `/var/home/admin/.ssh/authorized_keys`에 기록된 공개 키의 개인 키 절반과, 내부 주소에 도달하기 위한 VNet 내부의 호스트. `azureuser`가 아닌 `admin`으로 연결하십시오.
- **직렬 콘솔** — 대화형 Azure 로그인. 이를 위한 서비스 주체는 없습니다. F5 기업 Entra 테넌트가 서비스 주체 프로비저닝을 허용하지 않으며, 이 때문에 CI에서는 어떤 부분도 실행되지 않습니다.

<Aside type="danger" title="토큰을 인수로 전달하지 마십시오">
명령줄에 입력된 토큰은 셸 기록과 프로세스 목록에 남아, 해당 머신의 다른 모든 사용자가 읽을 수 있습니다. `capture-sitecli.sh`가 바로 이 이유로 `--token`을 완전히 거부하며, 대신 `curl`에 stdin을 통해 헤더를 제공합니다.
</Aside>
