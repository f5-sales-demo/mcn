تتصل وحدة التحكم التسلسلية Azure Serial Console بالمنفذ التسلسلي المُحاكى للعقدة عبر منصة Azure. لا تمر عبر مستوى تحكم F5 Distributed Cloud، ولا عبر مستوى بيانات العقدة، ولا عبر أي مسار شبكي تتحكم فيه العقدة — وهذا هو السبب الدقيق في عملها عندما لا يعمل أي شيء آخر.

الجأ إليها عندما لا **تعمل CE قط**: فشل التسجيل، أو الموقع غائب عن المستأجر، أو أن العقدة تعمل لكن ليس لديها مسار للخروج. في جميع تلك الحالات، لا تملك [debug API](../debug-api/) أي نفق للترحيل عبره، كما أن SSH مُغلق على العقدة كما تم تسليمها.

## المتطلب الأساسي: تشخيصات التمهيد

تشترط Azure تفعيل تشخيصات التمهيد على الجهاز الافتراضي قبل إرفاق وحدة تحكم تسلسلية. يُمكِّن ذلك `terraform/modules/ce-node`:

```hcl
boot_diagnostics {}
```

يختار الكتلة الفارغة تخزين Azure المُدار، لذا لا يوجد حساب تخزين للتشخيصات، ولا سياسة دورة حياة، ولا مفتاح وصول يلزم إدارته. تحقق من ذلك على عقدة:

```bash
az vm show -g <resource-group> -n <vm-name> --query diagnosticsProfile
```

```json
{ "bootDiagnostics": { "enabled": true } }
```

<Aside type="caution" title="تفعيله ليس بأثر رجعي">
تلتقط تشخيصات التمهيد سجل التسلسل **عند التمهيد**. لا يؤدي تشغيلها لجهاز افتراضي يعمل بالفعل إلى إنشاء سجل للتمهيد الذي حدث، لذا يُجيب `az vm boot-diagnostics get-boot-log` بـ:

```
<Error><Code>BlobNotFound</Code><Message>The specified blob does not exist.
```

هذا متوقع وليس خطأً. يوجد سجل تمهيد بعد إعادة تشغيل العقدة في المرة التالية. أما الإرفاق المباشر بوحدة التحكم فيعمل فوراً — ولا يعتمد على السجل.
</Aside>

## التحقق من التوافر دون طرفية

يستلزم الإرفاق جلسة تفاعلية، غير أن معرفة ما إذا كان *سيتم* الإرفاق يتطلب استدعاءين فقط لـ API. كلاهما مفيد في فحص صحة النظام.

يجب تفعيل الخدمة للاشتراك — يستطيع المسؤول تعطيلها على مستوى المستأجر بأكمله:

```bash
az rest --method get --url \
  "https://management.azure.com/subscriptions/<sub>/providers/Microsoft.SerialConsole/consoleServices/default?api-version=2018-05-01"
```

```json
{ "properties": { "disabled": false } }
```

ثم اطلب اتصالاً بالمنفذ التسلسلي لعقدة محددة:

```bash
az rest --method post \
  --headers "Content-Type=application/json" --body '{}' --url \
  "https://management.azure.com/subscriptions/<sub>/resourceGroups/<rg>/providers/Microsoft.Compute/virtualMachines/<vm>/providers/Microsoft.SerialConsole/serialPorts/0/connect?api-version=2018-05-01"
```

`connectionString` يبدأ بـ `wss://` — في هذا النشر
`eastus.gateway.serialconsole.azure.com` — يعني أن وحدة التحكم قابلة للإرفاق الآن. قبل تفعيل تشخيصات التمهيد، لم يكن لهذا الاستدعاء ما يرتبط به.

<Aside type="danger" title="سلسلة الاتصال تلك هي بيانات اعتماد">
إنها رمز حامل قصير العمر مضمّن في URL. لا تُسجِّلها، ولا تلصقها في تذكرة، ولا تُدرجها في الكود. اطبع اسم المضيف فقط عند إثبات نجاح الاستدعاء.
</Aside>

## الإرفاق

<Steps>

1. ثبّت الامتداد مرة واحدة:

   ```bash
   az extension add --name serial-console
   ```

2. أرفق:

   ```bash
   az serial-console connect -g <resource-group> -n <vm-name>
   ```

3. تصل إلى موجه تسجيل دخول العقدة الخاص بها، وليس إلى shell. هذه هي Site CLI، وتحتاج إلى بيانات اعتماد مُعيَّنة على العقدة — كلمة مرور المسؤول من التوفير، أو كلمة مرور مُعيَّنة عبر نقطة نهاية تغيير كلمة المرور. تُثبت وحدة التحكم التسلسلية أن *القناة* تعمل؛ فهي لا تتجاوز المصادقة.

</Steps>

<Aside type="caution" title="تحتاج إلى طرفية حقيقية">
يضع `az serial-console connect` الطرفية في الوضع الخام، لذا لا يمكن تشغيله من سكريبت، أو خط أنابيب، أو أي سياق دون TTY. يفشل على جانب العميل قبل الاتصال بـ Azure:

```
ERROR: (19, 'Operation not supported by device')
  File ".../azext_serialconsole/custom.py", line 633, in connect_serialconsole
    GV.serial_console_instance.launch_console()
```

هذا التتبع يتعلق بمعالجة الطرفية، وليس بانقطاع في وحدة التحكم التسلسلية — لا يزال استدعاءا API أعلاه يُفيدان بأن وحدة التحكم متاحة. إذا كنت بحاجة إلى إشارة قابلة للأتمتة، استخدم تلك الاستدعاءات بدلاً من محاولة أتمتة الإرفاق.
</Aside>

## ما يمكنك رؤيته هنا مما لا تستطيع API إظهاره

- **cloud-init** يعمل، أو يفشل، أو لا يبدأ قط — السبب المعتاد لعقدة لا تُسجَّل أبداً.
- **محاولات التسجيل** ضد `register.ves.volterra.io`، بما فيها خطأ في التكوين أو رمز رفضه المستأجر.
- **رسائل النواة والتمهيد** من قبل تشغيل أي عميل.
- العقدة عندما **لا يوجد لديها مسار شبكي يعمل**، مما يُبطل كل مسار آخر.

بالنسبة للعقدة التي تكون `ONLINE`، فضّل debug API: فهي قابلة للأتمتة، وتُنتج أدلة يمكن إعادة تشغيلها، ولا تشغل المنفذ التسلسلي الوحيد.
