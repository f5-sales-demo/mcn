تم التوثيق في 2026-07-28 من إحدى عُقد CE في هذا النشر. يسجّل `sitecli/capture-manifest.json`
أي عقدة كانت، ويعيد `scripts/capture-sitecli.sh --check` التحقق من مجموعة الأوامر
مقابل عقدة CE حيّة.

يقدّم كل Customer Edge وحدة تحكم الموقع من F5 على `https://<sli-ip>:65500`. في هذا
النشر تكون عادةً المسار الأول الذي يُجدر تجربته.

وهي أقل المسارات مطالبةً منك: لا مفتاح SSH لتوزيعه، ولا مضيف وسيط لصيانته، ولا عنوان IP عام على
العقدة، ولا استبدال للجهاز الافتراضي لتمكينها. ويصبح تحديد من يُسمح له بالاتصال **قرار Azure RBAC**.
كما أنها لا تحتاج إلى أن يكون الموقع مسجّلاً: فقد تم توثيق هذه الصفحة أول مرة
بينما كانت المواقع الثلاثة جميعها تُبلّغ عن `site_state: FAILED`، وأُعيد التحقق منها دون تغيير مقابل
العُقد نفسها بعد أن أصبحت `ONLINE`.

المشكلة أن وحدة تحكم الموقع تستجيب فقط على العنوان الداخلي (SLI) للعقدة،
والذي لا يمكن الوصول إليه إلا من داخل شبكة VNet. ويعالج Azure Bastion هذه الفجوة دون إضافة
أي شيء آخر إلى الشبكة.

<Aside type="note" title="ما تم التحقق منه هنا، وما لم يتم">
كل أمر وكل مخرَج في هذه الصفحة تم تشغيله مقابل `f5-xc-ce-vm-01` في هذا
النشر ويُعاد إنتاجه حرفياً، بما في ذلك حالات الفشل.

**تم التحقق من المصادقة**: تُعيد بيانات اعتماد `admin` الخاصة بالجهاز الرمز `200` عبر
النفق. أما ما *لم* يُختبر فهو وحدة التحكم نفسها — لا شيء فيما يلي يوضّح ما يمكنك
رؤيته أو فعله بعد الدخول.

**لم يتم التحقق من Azure RBAC.** جرى كل تشغيل بصفة مالك الاشتراك، لذا فإن شرط Reader
في الخطوة 2 هو شرط موثّق من Microsoft بدلاً من كونه شيئاً تم قياسه
هنا.
</Aside>

<Aside type="caution" title="Bastion اختياري، ولا يُنشر افتراضياً">
تكون القيمة الافتراضية لـ `enable_bastion` هي `false`، لذا في تنفيذ `terraform apply` الافتراضي لا يوجد مضيف Bastion
وتكون قيمة `terraform output -raw bastion_name` هي `null`. عيّن `enable_bastion = true` في
`terraform/terraform.tfvars` — وهي `true` في هذا النشر.

سبب كونها اختيارية هو التكلفة، لا المخاطرة: يفرض مضيف من فئة Standard-SKU رسماً ثابتاً بالساعة
من لحظة توفيره، سواء فتح أحدهم نفقاً أم لا — 0.29 دولار أمريكي
للساعة في `eastus` لوحدتَي القياس المضمّنتين (السعر بالتجزئة، 2026-07)، أي نحو 212 دولاراً أمريكياً في
الشهر. أوقفه من جديد عندما لا يحتاج العرض التوضيحي إلى الوصول إلى وحدة التحكم.
</Aside>

## قبل أن تبدأ

<Steps>

1. سجّل الدخول إلى Azure وأضف إضافة Bastion. فالتنفيق ميزة خاصة بالعميل الأصلي
   والإضافة غير مثبتة افتراضياً.

   ```bash
   az login
   az extension add --name bastion
   ```

2. يجب أن تملك دور **Reader** على الجهاز الافتراضي لعقدة CE، وواجهة الشبكة الخاصة به، ومضيف Bastion.
   هذا شرط موثّق من Microsoft وهو **غير مُتحقَّق منه هنا** — فكل تشغيل في هذا
   النشر جرى بصفة مالك الاشتراك، لذا لم يُثبت أن أي دور أدنى كافٍ
   أو غير كافٍ.

3. تأكّد من أن Bastion منشور وقادر. فئة Basic SKU لا تدعم التنفيق ولا
   الاتصال المعتمد على IP، لذا فإن `Standard` و`True` هنا كلتاهما أساسيتان.

   ```bash
   az network bastion list -g "$(terraform output -raw resource_group_name)" \
     --query "[].{name:name, sku:sku.name, tunneling:enableTunneling}" -o table
   ```

   ```text
   Name               Sku       Tunneling
   -----------------  --------  -----------
   ce-ha-lab-bastion  Standard  True
   ```

</Steps>

## فتح النفق

خُذ القيم من `terraform output` بدلاً من كتابتها — فمعرّف المورد ليس
شيئاً يُجمَّع يدوياً.

<Steps>

1. اقرأ اسم مضيف Bastion، ومجموعة الموارد، ومعرّف مورد الجهاز الافتراضي لعقدة CE المستهدفة.

   ```bash
   cd terraform
   BASTION=$(terraform output -raw bastion_name)
   RG=$(terraform output -raw resource_group_name)
   VM_ID=$(terraform output -json ce_vm_ids | jq -r '.eastus01')
   ```

   ```text
   ce-ha-lab-bastion
   rg-mcn-ce-ha-rmordasiewicz
   /subscriptions/…/providers/Microsoft.Compute/virtualMachines/f5-xc-ce-vm-01
   ```

   <Aside type="caution" title="الخريطة مفتاحها الموقع، لا اسم الجهاز الافتراضي">
   مفاتيح `ce_vm_ids` هي `eastus01` و`eastus02` و`eastus03` — **وليست** أسماء الأجهزة الافتراضية. فمرشّح
   مثل `jq -r '."f5-xc-ce-vm-01"'` يُعيد `null`، ثم يفشل النفق بسبب
   معرّف مورد فارغ. اسردها إن لم تكن متأكداً:

   ```bash
   terraform output -json ce_vm_ids | jq -r 'keys | join(", ")'
   ```

   ```text
   eastus01, eastus02, eastus03
   ```

   </Aside>

2. ابدأ النفق. فهو يُبقي المنفذ مفتوحاً حتى يتم إيقافه، لذا شغّله في الخلفية أو استخدم
   طرفية ثانية.

   ```bash
   az network bastion tunnel \
     --name "$BASTION" \
     --resource-group "$RG" \
     --target-resource-id "$VM_ID" \
     --resource-port 65500 \
     --port 65500 &
   ```

   ```text
   WARNING: Opening tunnel on port: 65500
   WARNING: Tunnel is ready, connect on port 65500
   WARNING: Ctrl + C to close
   ```

   الأسطر الثلاثة كلها مسبوقة بـ `WARNING:`. هذا مجرد كتابة Azure CLI للتقدّم إلى
   stderr، وليس مشكلة. انتظر ظهور `Tunnel is ready` قبل الاتصال.

3. تأكّد من أن المستمع محلي، على loopback:

   ```bash
   lsof -nP -iTCP:65500 -sTCP:LISTEN
   ```

   ```text
   COMMAND   PID  USER  FD  TYPE  DEVICE  SIZE/OFF  NODE  NAME
   Python  41648  you   7u  IPv4  …            0t0   TCP  127.0.0.1:65500 (LISTEN)
   ```

4. افتح وحدة التحكم. النفق يجعلها محلية، لذا فإن العنوان هو `localhost` — وليس
   عنوان العقدة.

   ```bash
   open https://localhost:65500/          # macOS
   xdg-open https://localhost:65500/      # Linux
   ```

5. أوقف النفق عند الانتهاء — بواسطة `Ctrl-C`، أو `kill %1` إن كنت قد شغّلته في الخلفية.
   فترْكه مفتوحاً يحتفظ بالمنفذ المحلي 65500 وبجلسة Bastion.

</Steps>

## ما ستراه

**مربع حوار لبيانات الاعتماد، وليس صفحة تسجيل دخول.** تستخدم وحدة التحكم مصادقة HTTP Basic، لذا
يُظهر المتصفح مطالبته الخاصة باسم المستخدم وكلمة المرور. لا يوجد نموذج للنظر إليه:

```bash
curl -skI https://localhost:65500/
```

```text
HTTP/1.1 401 Unauthorized
WWW-Authenticate: Basic realm="Volterra Site Console"
Content-Type: text/html; charset=utf-8
Content-Length: 0
```

الرمز `401` مع ذلك المجال (realm) يعني أن وحدة التحكم تعمل بشكل صحيح. فهذا ما يُفترض أن يحصل عليه
الطلب غير المُصادق — وتقديم بيانات اعتماد `admin` إلى العنوان نفسه يُعيد
`200`، وهي الطريقة التي تتأكد بها من بيانات الاعتماد قبل فتح متصفح:

```bash
curl -sk -u admin -o /dev/null -w '%{http_code}\n' https://localhost:65500/
```

```text
Enter host password for user 'admin':
200
```

استخدام `-u admin` دون نقطتين يجعل `curl` يطلب كلمة المرور بدلاً من أخذها من
سطر الأوامر، حيث ستنتهي في سجل الأوامر (shell history) وفي قائمة العمليات.

**تحذير بشأن الشهادة، لثلاثة أسباب في الوقت نفسه.** بالتحقق من الشهادة مباشرة:

```bash
openssl s_client -connect localhost:65500 -servername localhost </dev/null 2>/dev/null \
  | openssl x509 -noout -subject -issuer -dates
```

```text
subject=C=US, ST=California, L=Santa Clara, O=Volterra, OU=Volterra Edge Services, CN=site-local.volterra.io
issuer=C=US, ST=California, L=Santa Clara, O=Volterra, OU=Volterra Edge Services, CN=site-local.volterra.io
notBefore=Oct 25 04:51:31 2024 GMT
notAfter=Oct 25 04:51:31 2025 GMT
```

الموضوع (subject) يساوي المُصدر (issuer)، أي أنها موقّعة ذاتياً. والاسم هو `site-local.volterra.io` في حين
أنك تتصل بـ `localhost`، لذا لن يتطابق. وعلى الإصدار الذي يعمل عليه هذا
النشر، **انتهت صلاحية الشهادة في 25 أكتوبر 2025** — فالجهاز يأتي بها، ولا شيء
في هذا المستودع يجدّدها.

توقّع تحذيراً صريحاً من المتصفح، وتوقّعه في كل مرة. سطر الموضوع أعلاه هو
الجزء المفيد: فهو الطريقة التي تتأكد بها من أنك وصلت إلى الجهاز وليس إلى شيء آخر
يستمع على المنفذ المحلي 65500.

## بيانات اعتماد المسؤول

سجّل الدخول باسم `admin`. **لا تنشر هذه الوثائق كلمة المرور، ولا ينبغي لها ذلك.**

<Aside type="danger" title="في هذا النشر لا تزال كلمة المرور تلك هي القيمة الافتراضية من مصنع F5">
هذه حقيقة مقيسة، وليست ظناً: بيانات الاعتماد الافتراضية من المصنع تُصادَق وتُعيد
`200` على عُقد CE الثلاثة جميعها اليوم. تنشر F5 هذا الافتراضي وتشترط تغييره،
وهو لم يُغيَّر.

النتيجة العملية أنه في هذا النشر يكون "امتلاك دور Reader على Bastion" مكافئاً
لوصول كامل إلى وحدة تحكم الجهاز، لأي شخص يعرف قيمة موجودة في وثائق F5
العامة. غيّرها، واعتبر تغييرها جزءاً من نشر العقدة بدلاً
من تصليب لاحق.
</Aside>

سببان يجعلان عدم نشرها أهم هنا مما قد يبدو:

- هذه الوثائق عامة. طبع كلمة مرور وحدة التحكم الحالية للأسطول سيحوّل
  "امتلاك دور Reader على Bastion" إلى وصول كامل للجهاز لأي شخص يقرأ الصفحة.
- كلمة المرور المنشورة في الوثائق تصبح خاطئة لحظة قيام أحدهم بتدويرها، وخاطئة
  بأكثر الطرق تضليلاً — إذ يستنتج القارئ أن وصوله معطّل بدلاً
  من أن الصفحة قديمة.

بعد تدويرها، احصل عليها من أي مكان يحفظ فيه فريقك الأسرار التشغيلية.

<Aside type="caution" title="تعيين كلمة المرور من Terraform غير متحقَّق منه">
تبدو `admin_user_credentials.admin_password` في كائن الموقع الطريقة التعريفية
لتعيين هذا. لكن **لم** يُتأكد من أنها تصل إلى وحدة تحكم الموقع في هذا الإصدار، لذا
لا تفترض أنها تفعل.

ولا تقرأ [صفحة SSH](../ssh/) كدليل في أي من الاتجاهين. فاستنتاجها بأن
`admin_password` "لم تغيّر شيئاً" قيس مقابل مصادقة SSH، التي يتجاوزها `vpm`
تماماً للمستخدم `admin`. وهذا لا يقول شيئاً عن وحدة التحكم.
</Aside>

## لماذا يجب أن يستهدف النفق معرّف المورد

`--target-resource-id` مطلوب. واستهداف عنوان العقدة بدلاً منه مرفوض —
أياً كان العنوان الذي تستخدمه، لذا لم يُطبع هنا أي عنوان حقيقي عن قصد:

```bash
az network bastion tunnel --name "$BASTION" -g "$RG" \
  --target-ip-address <any-sli-address> --resource-port 65500 --port 65501
```

```text
ERROR: Custom ports are not allowed. Allowed ports for Tunnel with IP connect is 22, 3389.
```

السبب **ليس** أن الاتصال المعتمد على IP معطّل — فعلى Bastion هذا تكون
`ip_connect_enabled` بقيمة `true`. لا تدعم Microsoft المنافذ المخصّصة عبر اتصالات
العميل الأصلي المعتمدة على IP بغض النظر عن هذا الإعداد
([وثائق Azure](https://learn.microsoft.com/azure/bastion/connect-ip-address))، والمنفذ 65500 هو
منفذ مخصّص. تفقّد تكوين Bastion هنا لا يوصل إلى شيء؛ استخدم معرّف
المورد.

## عندما لا يعمل

| العَرَض | السبب | الحل |
| --- | --- | --- |
| `ERROR: Custom ports are not allowed. Allowed ports for Tunnel with IP connect is 22, 3389.` | استخدام `--target-ip-address` | استخدم `--target-resource-id` |
| `ERROR: Defined port is currently unavailable` | نفق آخر يحتفظ بذلك المنفذ المحلي بالفعل | أوقف النفق الآخر، أو مرّر قيمة `--port` مختلفة؛ ويبقى `--resource-port` على 65500 |
| قيمة `terraform output -raw bastion_name` هي `null` أو فارغة | Bastion غير منشور | عيّن `enable_bastion = true` ثم نفّذ apply |
| يبدأ النفق لكن معرّف المورد فارغ | مرشّح `jq` استخدم اسم الجهاز الافتراضي بدلاً من مفتاح الموقع | استخدم المفاتيح `eastus01`/`02`/`03` |
| `401 Unauthorized`، بالمجال `Volterra Site Console` | ليس خطأً — طلب غير مُصادق | قدّم بيانات اعتماد `admin` |
| المتصفح يرفض الشهادة | موقّعة ذاتياً، وعدم تطابق الاسم، ومنتهية الصلاحية منذ أكتوبر 2025 | متوقّع؛ تأكّد من أن الموضوع هو `CN=site-local.volterra.io` وتابع |

<Aside type="note" title="لم يُعَد إنتاج حالات فشل التخويل">
نقص RBAC هو الطريقة الأخرى البديهية لفشل هذا، لكن إعادة إنتاجه يعني
إزالة تعيينات الأدوار من نشر مشترك، لذا فهو غير موثّق هنا بخطأ
حرفي. إذا فشل النفق عند البدء بخطأ تخويل، فتحقّق من دور Reader على
الثلاثة جميعاً: الجهاز الافتراضي، وواجهة الشبكة الخاصة به، ومضيف Bastion.
</Aside>
