كل Customer Edge يخدم وحدة تحكم الموقع من F5 على `https://<sli-ip>:65500`. في هذا
النشر، تكون عادةً أول مسار يُجرَّب.

تتطلب أقل قدر ممكن منك: لا مفتاح SSH للتوزيع، ولا خادم وسيط للصيانة، ولا عنوان IP عام
على العقدة، ولا استبدال للجهاز الافتراضي لتمكينها. تصبح صلاحية الاتصال **قراراً خاضعاً لـ Azure RBAC**.
ولا تحتاج إلى تسجيل الموقع — تمّ تسجيل النسخة أدناه بينما كانت المواقع الثلاثة تُبلّغ عن `site_state: FAILED`.

التحفظ الوحيد هو أن وحدة تحكم الموقع تستجيب فقط على العنوان الداخلي للعقدة (SLI)،
والذي لا يمكن الوصول إليه إلا من داخل الشبكة الافتراضية. يسدّ Azure Bastion هذه الفجوة دون وضع
أي شيء آخر على الشبكة.

<Aside type="note" title="ما تم التحقق منه وما لم يُتحقق منه">
كل أمر وكل مخرج في هذه الصفحة نُفِّذ على `f5-xc-ce-vm-01` في هذا
النشر وتم نسخه حرفياً، بما في ذلك حالات الفشل.

الشيء الوحيد غير المختبر هو **تسجيل الدخول**. تتوقف الخطوات عند موجه بيانات الاعتماد،
لذا لا يصف أي شيء أدناه شكل وحدة التحكم بعد الدخول إليها.
</Aside>

## قبل البدء

<Steps>

1. سجّل الدخول إلى Azure وأضف إضافة Bastion. النفق ميزة خاصة بالعميل الأصلي
   والإضافة لا تُثبَّت افتراضياً.

   ```bash
   az login
   az extension add --name bastion
   ```

2. احرص على امتلاك صلاحية **Reader** على الجهاز الافتراضي لـ CE وواجهة الشبكة الخاصة به ومضيف Bastion.

3. تأكد من نشر Bastion وقدرته. SKU الأساسي لا يدعم النفق ولا الاتصال القائم على IP،
   لذا فإن `Standard` و`True` هنا كلاهما ضروري.

   ```bash
   az network bastion list -g rg-mcn-ce-ha-rmordasiewicz \
     --query "[].{name:name, sku:sku.name, tunneling:enableTunneling}" -o table
   ```

   ```text
   Name               Sku       Tunneling
   -----------------  --------  -----------
   ce-ha-lab-bastion  Standard  True
   ```

</Steps>

## فتح النفق

خذ القيم من `terraform output` بدلاً من كتابتها يدوياً — معرف المورد ليس شيئاً يُجمَّع يدوياً.

<Steps>

1. اقرأ اسم مضيف Bastion ومجموعة الموارد ومعرف مورد الجهاز الافتراضي للـ CE المستهدف.

   ```bash
   cd terraform
   BASTION=$(terraform output -raw bastion_name)
   RG=$(terraform output -raw resource_group_name)
   VM_ID=$(terraform output -json ce_vm_ids | jq -r '.eastus01')
   ```

   ```text
   ce-ha-lab-bastion
   rg-mcn-ce-ha-rmordasiewicz
   /subscriptions/…/providers/Microsoft.Compute/virtualMachines/f5-xc-ce-vm-01
   ```

   <Aside type="caution" title="المصفوفة مفهرسة بالموقع وليس باسم الجهاز الافتراضي">
   مفاتيح `ce_vm_ids` هي `eastus01` و`eastus02` و`eastus03` — **وليست** أسماء الأجهزة الافتراضية. فلتر
   مثل `jq -r '."f5-xc-ce-vm-01"'` يُرجع `null`، وبالتالي يفشل النفق بسبب معرف مورد فارغ. أدرجها إذا لم تكن متأكداً:

   ```bash
   terraform output -json ce_vm_ids | jq -r 'keys | join(", ")'
   ```

   ```text
   eastus01, eastus02, eastus03
   ```
   </Aside>

2. شغّل النفق. يبقي المنفذ مفتوحاً حتى يُوقَف، لذا شغّله في الخلفية أو استخدم
   نافذة طرفية ثانية.

   ```bash
   az network bastion tunnel \
     --name "$BASTION" \
     --resource-group "$RG" \
     --target-resource-id "$VM_ID" \
     --resource-port 65500 \
     --port 65500 &
   ```

   ```text
   WARNING: Opening tunnel on port: 65500
   WARNING: Tunnel is ready, connect on port 65500
   WARNING: Ctrl + C to close
   ```

   الأسطر الثلاثة مسبوقة بـ `WARNING:`. هذا هو Azure CLI يكتب التقدم إلى
   stderr، وليس مشكلة. انتظر `Tunnel is ready` قبل الاتصال.

3. تأكد من أن المستمع محلي على loopback:

   ```bash
   lsof -nP -iTCP:65500 -sTCP:LISTEN
   ```

   ```text
   COMMAND   PID  USER  FD  TYPE  DEVICE  SIZE/OFF  NODE  NAME
   Python  41648  you   7u  IPv4  …            0t0   TCP  127.0.0.1:65500 (LISTEN)
   ```

4. افتح وحدة التحكم. النفق يجعلها محلية، لذا العنوان هو `localhost` — وليس
   عنوان العقدة.

   ```bash
   open https://localhost:65500/          # macOS
   xdg-open https://localhost:65500/      # Linux
   ```

5. أوقف النفق عند الانتهاء — `Ctrl-C`، أو `kill %1` إذا شغّلته في الخلفية.
   تركه مفتوحاً يحجز المنفذ المحلي 65500 وجلسة Bastion.

</Steps>

## ما ستراه

**مربع حوار بيانات اعتماد، وليس صفحة تسجيل دخول.** تستخدم وحدة التحكم مصادقة HTTP Basic، لذا
يعرض المتصفح موجه اسم المستخدم وكلمة المرور الخاص به. لا توجد نموذج للنظر إليه:

```bash
curl -skI https://localhost:65500/
```

```text
HTTP/1.1 401 Unauthorized
WWW-Authenticate: Basic realm="Volterra Site Console"
Content-Length: 0
```

الاستجابة `401` مع هذا الـ realm تعني أن وحدة التحكم تعمل بشكل صحيح. هذا ما يجب أن تحصل عليه
الطلبات غير المصادق عليها.

**تحذير شهادة، لثلاثة أسباب في آن واحد.** التحقق من الشهادة مباشرةً:

```bash
openssl s_client -connect localhost:65500 -servername localhost </dev/null 2>/dev/null \
  | openssl x509 -noout -subject -issuer -dates
```

```text
subject=C=US, ST=California, L=Santa Clara, O=Volterra, OU=Volterra Edge Services, CN=site-local.volterra.io
issuer=C=US, ST=California, L=Santa Clara, O=Volterra, OU=Volterra Edge Services, CN=site-local.volterra.io
notBefore=Oct 25 04:51:31 2024 GMT
notAfter=Oct 25 04:51:31 2025 GMT
```

الموضوع يساوي المُصدِر، إذن هي شهادة موقَّعة ذاتياً. الاسم هو `site-local.volterra.io` بينما
تتصل بـ `localhost`، لذا لن تتطابق. وفي الإصدار الذي يعمل عليه هذا النشر، **انتهت صلاحية الشهادة في 25 أكتوبر 2025** — الجهاز يُرسلها، ولا شيء في هذا المستودع يجدّدها.

توقع تحذيراً صريحاً من المتصفح، وتوقعه في كل مرة. السطر الخاص بالموضوع أعلاه هو
الجزء المفيد: هذه هي الطريقة التي تؤكد بها وصولك إلى الجهاز وليس إلى شيء آخر
يستمع على المنفذ المحلي 65500.

## بيانات اعتماد المسؤول

سجّل الدخول بـ `admin`. **لا تنشر هذه الوثائق كلمة المرور، ولا ينبغي لها ذلك.**

يأتي Customer Edge الجديد من المصنع بالإعداد الافتراضي المنشور من F5، وتشترط F5 تغييره.
اعتبر تغييره جزءاً من نشر العقدة وليس تحسيناً أمنياً لاحقاً.
سببان يجعلان ذلك أكثر أهمية هنا مما يبدو:

- هذه الوثائق عامة. نشر كلمة مرور وحدة التحكم الحالية للأسطول يحوّل
  "امتلاك Reader على Bastion" إلى وصول كامل للجهاز لأي شخص يقرأ الصفحة.
- كلمة مرور منشورة في الوثائق تصبح خاطئة في اللحظة التي يغيّرها أحد، وخاطئة بأكثر الطرق
  إضلالاً — يستنتج القارئ أن صلاحيات وصوله معطوبة بدلاً من إدراك أن الصفحة قديمة.

احصل على كلمة المرور من حيث يحفظ فريقك أسرار التشغيل. إذا كانت الإجابة هي
"لا تزال الإعداد الافتراضي من المصنع"، غيّرها قبل فعل أي شيء آخر.

<Aside type="caution" title="لم يُتحقق من ضبط كلمة المرور عبر Terraform">
يبدو أن `admin_user_credentials.admin_password` على كائن الموقع هو الطريقة التصريحية
لضبط هذا. **لم يُؤكَّد** وصوله إلى وحدة تحكم الموقع في هذا الإصدار، لذا لا تفترض ذلك.

لا تقرأ [صفحة SSH](../ssh/) كدليل في أي اتجاه. استنتاجها بأن
`admin_password` "لم يغيّر شيئاً" قِيس مقابل مصادقة SSH، التي تتجاوزها `vpm`
للمستخدم `admin` كلياً. هذا لا يقول شيئاً عن وحدة التحكم.
</Aside>

## لماذا يجب أن يستهدف النفق معرف المورد

`--target-resource-id` إلزامي. استهداف عنوان العقدة بدلاً من ذلك مرفوض:

```bash
az network bastion tunnel --name "$BASTION" -g "$RG" \
  --target-ip-address 10.0.3.5 --resource-port 65500 --port 65501
```

```text
ERROR: Custom ports are not allowed. Allowed ports for Tunnel with IP connect is 22, 3389.
```

السبب **ليس** أن الاتصال القائم على IP معطّل — في هذا الـ Bastion
`ip_connect_enabled` هو `true`. لا تدعم Microsoft المنافذ المخصصة عبر الاتصالات
بالعميل الأصلي القائم على IP بصرف النظر عن هذا الإعداد
([وثائق Azure](https://learn.microsoft.com/azure/bastion/connect-ip-address))، و65500 منفذ مخصص. فحص تكوين Bastion هنا لا يفيد؛ استخدم معرف المورد.

## عندما لا يعمل

| الأعراض | السبب | الحل |
| --- | --- | --- |
| `ERROR: Custom ports are not allowed. Allowed ports for Tunnel with IP connect is 22, 3389.` | استُخدم `--target-ip-address` | استخدم `--target-resource-id` |
| `ERROR: Defined port is currently unavailable` | نفق آخر يحجز المنفذ المحلي | أوقف النفق الآخر، أو مرّر `--port` مختلفاً؛ `--resource-port` يبقى 65500 |
| النفق يبدأ لكن معرف المورد فارغ | فلتر `jq` استخدم اسم الجهاز الافتراضي بدلاً من مفتاح الموقع | استخدم المفاتيح `eastus01`/`02`/`03` |
| `401 Unauthorized`، الـ realm هو `Volterra Site Console` | ليس خطأ — طلب غير مصادق عليه | أمدَّ ببيانات اعتماد `admin` |
| المتصفح يرفض الشهادة | موقَّعة ذاتياً، عدم تطابق الاسم، وانتهت صلاحيتها منذ أكتوبر 2025 | متوقع؛ تأكد أن الموضوع هو `CN=site-local.volterra.io` وتابع |

<Aside type="note" title="لم تُعاد إنتاج حالات فشل التفويض">
الـ RBAC غير الكافي هو الطريقة الواضحة الأخرى لفشل هذا، لكن إعادة إنتاجه تعني
إزالة تعيينات الأدوار من نشر مشترك، لذا لم يُوثَّق هنا بخطأ حرفي. إذا فشل النفق
عند البدء بخطأ تفويض، تحقق من صلاحية Reader على الثلاثة: الجهاز الافتراضي وواجهة شبكته ومضيف Bastion.
</Aside>
