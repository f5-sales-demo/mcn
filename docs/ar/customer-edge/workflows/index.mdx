[مرجع الأوامر](../commands/) منظَّم حسب ما يفعله كل أمر. أما هذه الصفحات فهي
منظَّمة حسب ما حدث من خطأ.

| العَرَض | سير العمل |
| --- | --- |
| الموقع لم يصبح متصلاً أبداً، أو انسحب من المستأجر | [التسجيل](./registration/) |
| المسارات غير مُعلَنة أو غير مُتعلَّمة؛ الـ VIP غير قابل للوصول | [BGP](./bgp-diagnostics/) |
| حركة المرور تصل إلى العقدة لكنها لا تُسلَّم | [مستوى البيانات](./dataplane-diagnostics/) |

كل خطوة تربط بالصفحة التي توثّق الأمر. لا شيء يُعاد ذكره هنا،
بحيث يكون للصياغة موطن واحد فقط ولا يمكن أن تختلف عمّا هو موجود على العقدة.

## قبل أي منها

حدِّد مسار الوصول الذي تستخدمه، لأنه يُغيّر ما هو ممكن:

```bash
curl -sS -H "Authorization: APIToken $XCSH_API_TOKEN" \
  "$XCSH_API_URL/api/config/namespaces/system/sites/<site>" | jq -r '.spec.site_state'
```

`ONLINE` تعني أن [واجهة API للتصحيح](../access/debug-api/) ستستجيب. أي شيء آخر يعني أن
سير عمل التسجيل هو ما تحتاجه، وأحد المسارات التي لا تعتمد على
التسجيل: [وحدة تحكم الموقع](../access/site-console/) عندما لا يزال للعقدة مسار شبكي،
و[وحدة التحكم التسلسلية](../access/serial-console/) عندما لا يوجد.

الموقع الذي يكون **مفقوداً تماماً** لديه تفسير إضافي يجب استبعاده قبل القول إنه "لم يُسجَّل
أبداً": وهو أنك تستعلم من المستأجر الخطأ. الأمر `cd terraform && terraform output -raw
xc_tenant` يذكر اسم المستأجر الذي ينتمي إليه هذا النشر.
