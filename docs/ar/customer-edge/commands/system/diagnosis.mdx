## `diagnosis`

<Aside type="caution" title="النطاق العالمي (GLOBAL) — وسيلة نقل مختلفة">
مثل `health`، يُرسَل طلب `GET` إلى مسار `global` ولا يمكن الوصول إليه عبر `exec-user`.

```bash
curl -sS -H "Authorization: APIToken $XCSH_API_TOKEN" \
  "$XCSH_API_URL/api/operate/namespaces/system/sites/<site>/vpm/debug/global/diagnosis"
```

</Aside>

```json file=../../../../_data/sitecli-diagnosis.txt
```

تقوم العقدة بفحص بوابتها الخاصة وتُبلّغ عن النتيجة لكل عقدة على حدة، لذا في الموقع متعدد العقد ستحصل على كتلة واحدة لكل عقدة. يحمل `gateway_connectivity` ملخصاً لنتائج الـ ping — `sent` و`received` و`lost` وأوقات الذهاب والإياب.

<Aside type="note" title="فقدان 100% للبوابة ليس بالضرورة عطلاً">
في هذا التوبولوجيا، لا تستجيب البوابة لـ ICMP، لذا فإن `lost: 100` هو الحال الطبيعي المستقر بينما يكون الموقع في وضع `ONLINE` ويُمرّر حركة المرور. تعامل مع هذا الحقل كإشارة فقط عندما يكون لديك بالفعل دليل آخر على وجود مشكلة، أو عندما تتغير قيمته.
</Aside>

`resolv_conf` هو الحقل الأكثر فائدة بشكل متسق: فهو يُظهر المحلّل (resolver) الذي ستستخدمه العقدة فعلياً، وهو أمر يستحق المقارنة مع ما تتوقعه قبل أن تقضي وقتاً في [`dig`](../../network/dig/).
