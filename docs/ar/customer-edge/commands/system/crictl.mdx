تشغّل CRI-O أحمال عمل Kubernetes. خدمات المنصة — `vpm` و`argo_watch` و`site-console` — هي حاويات [Docker](../docker/) ولن تظهر هنا.

## `crictl-ps`

```bash
{"command":["crictl-ps"]}
```

```text file=../../../../_data/sitecli-crictl-ps.txt
```

الحاويات قيد التشغيل مع الـ pod والصورة وعدد إعادة التشغيل. `ATTEMPT` هو العمود الأهم للقراءة: فارتفاع عدد إعادة التشغيل يدل على حلقة تعطل (crash loop)، ومعرّف الحاوية من هذا المخرج يُغذّي الأمرين التاليين.

## `crictl-ps-a`

```bash
{"command":["crictl-ps-a"]}
```

```text file=../../../../_data/sitecli-crictl-ps-a.txt
```

يشمل الحاويات المنتهية. استخدمه عندما كان شيء ما *يعمل* وتوقّف الآن — إدخال الحاوية المنتهية ومعرّفها هما ما يتيحان لك قراءة سجلات التشغيل الذي فشل.

```bash
{"command":["crictl-images"]}
```

## `crictl-inspect`

```bash
{"command":["crictl-inspect","<container-id>"]}
```

```text file=../../../../_data/sitecli-crictl-inspect.txt
```

JSON كامل: نقاط التوصيل، والبيئة، وحدود الموارد، وسطر الأوامر، وحالة الخروج. طويل، لذا استعلم عنه بدلاً من قراءته بالكامل.


```text file=../../../../_data/sitecli-crictl-logs.txt
```

<Aside type="note" title="معرّفات الحاويات خاصة بكل تشغيل">
المعرّفات في هذه اللقطات مأخوذة من تشغيل عيّنة واحد ولن تكون موجودة على عقدتك. خذ معرّفاً حالياً من `crictl-ps` أولاً. تفعل أداة التقاط اللقطات ذلك تماماً — يحلّ مانيفستها أول معرّف حاوية عند وقت الالتقاط بدلاً من تضمينه بشكل ثابت.
</Aside>
