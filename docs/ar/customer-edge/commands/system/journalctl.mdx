## `journalctl`

```bash
{"command":["journalctl","-u","vpm","-n","200"]}
```

وسيطات `journalctl` القياسية، كل منها عنصر منفصل في المصفوفة. `-u vpm` هو الخيار الذي ستحتاجه في معظم الأوقات: `vpm` هو العميل الذي يسجّل العقدة ويدير كل شيء عليها، لذا فإن سجله هو المكان الذي تظهر فيه أخطاء التسجيل مع الطوابع الزمنية وعبر عمليات إعادة التشغيل.

متغيرات مفيدة:

| الوسيطات | الإجابات |
| --- | --- |
| `-u vpm -n 200` | ما الذي كان يفعله vpm مؤخراً |
| `-u vpm --since "10 min ago"` | ما الذي حدث أثناء إعادة إنتاج المشكلة |
| `-p err -n 100` | الأخطاء من كل الوحدات |
| `-u kubelet -n 200` | لماذا حزمة Kubernetes غير سليمة |

يُفضَّل استخدام هذا الأمر بدلاً من [`docker-logs vpm`](../docker/) عندما تحتاج إلى طوابع زمنية، أو تريد تغطية فترة إعادة تشغيل، أو تريد ربط vpm بوحدة أخرى.
