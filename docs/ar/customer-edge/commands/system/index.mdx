ثلاثة عشر من أصل أربعة وثلاثين أمراً.

| إذا أردت | استخدم |
| --- | --- |
| إجابة واحدة حول ما إذا كانت العقدة سليمة | [health](./health/) |
| فحوصات الاتصال و DNS التي تجريها العقدة بنفسها | [diagnosis](./diagnosis/) |
| حاويات أعباء عمل Kubernetes | [crictl](./crictl/) |
| حاويات المنصة: vpm وargo وsite-console | [docker](./docker/) |
| سجلات الخدمة، بما في ذلك التسجيل | [journalctl](./journalctl/) |

## تشغّل العقدة وقتَي تشغيل حاوية مختلفين

يُفاجئ ذلك كثيرين، وهو يغيّر الأمر الذي يجيب على سؤالك.

- **Docker** يشغّل حاويات المنصة — `vpm` و`argo_watch` و`site-console`.
- **CRI-O** يشغّل أعباء عمل Kubernetes، ويُوصل إليه عبر `crictl`.

كلاهما نشطان في الوقت ذاته، وكلاهما يُعيد مخرجات حقيقية، ولا يُغني أحدهما عن الآخر. إن أظهر `docker-ps` ثلاث حاويات فهذه ليست رؤية جزئية لعقدة معطوبة؛ بل هي القائمة الكاملة لما يشغّله Docker. إن كنت تبحث عن `vpm` فهو حاوية Docker. وإن كنت تبحث عن pod فهو في CRI-O.

## يستخدم أمران وسيلة نقل مختلفة

`health` و`diagnosis` من نطاق `GLOBAL`: فهما طلبات `GET` إلى مسار `global`، وتُعيدان JSON بدلاً من نص طرفي، و**لا يمكن الوصول إليهما عبر `exec-user`** — إذ يُجيب إرسالهما إلى هناك بـ`command not supported`، مما يوحي بأن الأمر غير موجود أصلاً. انظر [واجهة API للتشخيص](../../access/debug-api/).
