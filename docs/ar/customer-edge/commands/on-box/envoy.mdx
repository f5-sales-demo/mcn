يُنهي Envoy حركة مرور التطبيقات ويُوكّلها على Customer Edge. تستعلم هذه الأوامر الأربعة
من واجهة المسؤول الخاصة به، ولا يوجد أيٌّ منها في
[debug API](../../../access/debug-api/).

<Aside type="note" title="كل واحد من هذه الأوامر يبدأ بشريط تقدم curl">
هذه الأوامر عبارة عن أغلفة `curl` حول نقطة نهاية المسؤول في Envoy، ويتم استدعاؤها دون `-s`، لذا فإن السطرين أو الثلاثة الأولى من كل تسجيل أدناه هي تقدم النقل الخاص بـ curl المكتوب إلى stderr:

```text
  % Total    % Received % Xferd  Average Speed   Time    Time     Time  Current
                                 Dload  Upload   Total   Spent    Left  Speed
  0     0    0     0 …
```

هذا ليس إخراجاً لـ Envoy وليس خطأً. وهو مفيد أيضاً: عدد البايتات في `% Received`
يخبرك بما إذا كان Envoy قد أرجع أي شيء على الإطلاق، وهو ما يُميّز حالة "لا توجد مستمعون مُهيَّئون"
عن حالة "لم تستجب واجهة المسؤول".
</Aside>

## `envoy-listeners`

كل مستمع قام Envoy بتثبيته، بصيغة `name:address:port`.

```bash
execcli envoy-listeners
```

```text file=../../../../_data/sitecli-envoy-listeners.txt
```

**ما الذي تبحث عنه.** في هذا النشر يحمل المستمع `10.250.0.10:80` — وهو VIP الذي يُعلن عنه
CE في BGP. يربط هذا السطر الواحد ثلاث طبقات معاً: إذا أظهر
[`show-ip-bgp-summary`](../../network/bgp/) أن البادئة يجري الإعلان عنها لكن هذا
المستمع غائب، فإن المسار يُجذَب إلى عقدة لن تُخدّمه، وهو أسوأ أنماط الفشل في مجموعة ECMP
لأن حركة المرور يتم توزيعها بالتساوي نحو ثقب أسود.

`[fe80:…]:80` اللاحقة هي عنوان link-local للواجهة التي يرتبط بها المستمع.

**ما لا يخبرك به.** لا شيء عن صحة الخادم الأعلى — يوجد المستمع سواء أكان كل ما خلفه
قابلاً للوصول أم لا. استخدم `envoy-clusters` لذلك.

## `envoy-clusters`

كل مجموعة، مع حدود الاتصال والطلبات لكل أولوية.

```bash
execcli envoy-clusters
```

```text file=../../../../_data/sitecli-envoy-clusters.txt
```

**ما الذي تبحث عنه.** الأسطر بصيغة `cluster::scope::key::value`. تُعرّف إدخالات `observability_name`
كل مجموعة، وثلاثية `default_priority::max_connections` و`max_pending_requests`
و`max_requests` هي المكان الذي تظهر فيه حدود الطلبات — مجموعة ثابتة عند `max_pending_requests`
يجري تقييدها بالإعداد لا بالخادم الأعلى.

## `envoy-config-dump`

الإعداد الكامل لـ Envoy بصيغة JSON. حجمه كبير: 126 كيلوبايت على عقدة عرض توضيحي خاملة.

```bash
execcli envoy-config-dump
```

```text file=../../../../_data/sitecli-envoy-config-dump.txt
```

**ما الذي تبحث عنه.** تحتوي مصفوفة `configs` ذات المستوى الأعلى على كائن واحد لكل نوع
إعداد — bootstrap والمجموعات والمستمعون والمسارات والأسرار. الجأ إلى هذا عندما يوجد
مستمع أو مجموعة لكن يتصرف بشكل غير متوقع، وابحث فيه بدلاً من قراءته.

## `envoy-hc-config-dump`

إعدادات الفحص الصحي تحديداً.

```bash
execcli envoy-hc-config-dump
```

```text file=../../../../_data/sitecli-envoy-hc-config-dump.txt
```

**ما الذي تبحث عنه.** في هذا النشر يُرجع **بايتاً واحداً** — يظهر على هيئة `100 1`
في شريط curl — مما يعني أنه لا يوجد إعداد فحص صحي مُثبَّت. هذه هي الحالة المتوقعة
لـ CE بلا مجموعات خوادم مصدر تخضع للفحص الصحي، ويستحق التعرف عليها: النتيجة الفارغة هنا ليست استعلاماً فاشلاً.
