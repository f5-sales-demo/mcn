تم الالتقاط بتاريخ 2026-07-28 من إحدى نقاط CE لهذا النشر. هذه أوامر تُنفَّذ على الصندوق مباشرةً، لذا تأتي
عبر Site CLI بدلاً من debug API؛ يسجّل `sitecli/exec-catalog.json` السطح
و`sitecli/capture-manifest.json` يسجّل العقدة.

يُنهي Envoy حركة المرور الخاصة بالتطبيقات ويُوكّلها على Customer Edge. تستعلم هذه الأوامر الأربعة
واجهة الإدارة الخاصة به، ولا تنتمي أيٌّ منها إلى
[debug API](../../../access/debug-api/).

<Aside type="note" title="كل واحد من هذه الأوامر يبدأ بمقياس تقدم curl">
هي أغلفة `curl` حول نقطة نهاية الإدارة في Envoy، تُستدعى بدون `-s`، لذا فإن أول
سطرين أو ثلاثة في كل التقاط أدناه هي مقياس تقدم النقل الخاص بـ curl المكتوب إلى stderr:

```text
  % Total    % Received % Xferd  Average Speed   Time    Time     Time  Current
                                 Dload  Upload   Total   Spent    Left  Speed
  0     0    0     0 …
```

هذا ليس إخراجاً من Envoy وليس خطأً. وهو مفيد أيضاً: يخبرك عدد البايتات في `% Received`
بما إذا كان Envoy قد أعاد أي شيء على الإطلاق، مما يميّز بين "لا توجد مستمعون مُهيَّئون"
و"واجهة الإدارة لم تستجب".
</Aside>

## `envoy-listeners`

كل مستمع مثبَّت في Envoy، على هيئة `name:address:port`.

```bash
execcli envoy-listeners
```

```text file=../../../../_data/sitecli-envoy-listeners.txt
```

**ما يجب البحث عنه.** في هذا النشر يحمل المستمع `10.250.0.10:80` — وهو VIP الذي يُعلن عنه
CE في BGP. يربط هذا السطر الواحد ثلاث طبقات معاً: إذا أظهر
[`show-ip-bgp-summary`](../../network/bgp/) أن البادئة مُعلَن عنها لكن هذا المستمع
غائب، فإن المسار يُجذَب نحو عقدة لن تقدّم الخدمة، وهو أسوأ أنماط الفشل في مجموعة ECMP
لأن حركة المرور تُوزَّع بالتحميل المشترك نحو ثقب أسود.

الجزء الختامي `[fe80:…]:80` هو عنوان الرابط المحلي للواجهة التي يرتبط بها المستمع.

**ما لا يخبرك به.** لا شيء عن سلامة الخادم الأعلى — يظل المستمع موجوداً سواء كان ما خلفه
قابلاً للوصول أم لا. استخدم `envoy-clusters` لذلك.

## `envoy-clusters`

كل عنقود، مع حدود الاتصال والطلبات لكل أولوية.

```bash
execcli envoy-clusters
```

```text file=../../../../_data/sitecli-envoy-clusters.txt
```

**ما يجب البحث عنه.** الأسطر على هيئة `cluster::scope::key::value`. يُعرَّف كل عنقود
بمدخل `observability_name`، وثلاثية `default_priority::max_connections`
و`max_pending_requests` و`max_requests` هي التي تظهر فيها حدود الطلبات — فعنقود
محصور عند `max_pending_requests` يتعرض للتقييد بسبب الإعداد لا بسبب الخادم الأعلى.

## `envoy-config-dump`

الإعداد الكامل لـ Envoy بتنسيق JSON. حجمه كبير: 126 كيلوبايت على عقدة عرض توضيحي خاملة.

```bash
execcli envoy-config-dump
```

```text file=../../../../_data/sitecli-envoy-config-dump.txt
```

**ما يجب البحث عنه.** تحتوي مصفوفة `configs` على المستوى الأعلى على كائن واحد لكل نوع
إعداد — bootstrap والعناقيد والمستمعون والمسارات والأسرار. الجأ إلى هذا عندما يكون مستمع
أو عنقود موجوداً لكنه يتصرف بشكل غير متوقع، وابحث فيه بدلاً من قراءته بالكامل.

## `envoy-hc-config-dump`

إعداد الفحص الصحي تحديداً.

```bash
execcli envoy-hc-config-dump
```

```text file=../../../../_data/sitecli-envoy-hc-config-dump.txt
```

**ما يجب البحث عنه.** في هذا النشر يُعيد **بايتاً واحداً** — مرئياً على هيئة `100 1`
في مقياس `curl` — مما يعني أنه لم يُثبَّت أي إعداد للفحص الصحي. هذه هي الحالة المتوقعة
لنقطة CE بدون مجمّعات أصل خاضعة للفحص الصحي، ومن المهم التعرف على ذلك: النتيجة الفارغة
هنا ليست استعلاماً فاشلاً.
