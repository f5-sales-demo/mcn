أمران، والتمييز بينهما هو القيمة الكاملة لهما.

## `curl-host`

يعمل في فضاء اسم شبكة المضيف — اتصال العقدة الخاص، قبل أن يُشغَّل مستوى البيانات.

```bash
{"command":["curl-host","-v","cloud.f5.com"]}
```

```text file=../../../../_data/sitecli-curl-host.txt
```

## `curl-vega`

يعمل داخل سياق مجموعة Kubernetes، لذا فإنه يجتاز نظام DNS الخاص بالمجموعة ومسار الشبكة.

```bash
{"command":["curl-vega","-v","cloud.f5.com"]}
```

```text file=../../../../_data/sitecli-curl-vega.txt
```

<Aside type="tip" title="الزوج أداة تقسيم ثنائي">
شغّل كليهما. إذا نجح `curl-host` وأخفق `curl-vega`، فإن العقدة تمتلك اتصالاً وشبكة المجموعة أو نظام DNS الخاص بها معطوب. أما إذا أخفق كلاهما، فالمشكلة في مرحلة تسبق العقدة — التوجيه، أو جدار حماية، أو مسار الخروج. وإذا أخفق `curl-host` وحده، فقد اكتشفت أمراً غير معتاد وعليك التحقق من جدول التوجيه للمضيف أولاً.
</Aside>

يقبل كلاهما وسيطات `curl` العادية كعناصر مصفوفة منفصلة. يستحق الاحتفاظ بـ `-v` لأن أسطر الاتصال ومصافحة TLS هي عادةً المكان الذي يظهر فيه الإخفاق.
