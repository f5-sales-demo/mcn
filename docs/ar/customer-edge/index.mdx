Customer Edge (CE) هو عقدة F5 Distributed Cloud التي يوفرها هذا المستودع داخل
Azure — `terraform/modules/ce-node`، والمبنية من صورة السوق
`volterraedgeservices/volterra-node`.

تُشغّل هذه العقدة مستوى البيانات (Argo)، ومستوى التحكم (Vega)، ووكيل Envoy، وحزمة
Kubernetes، و`vpm`، وهو العميل الذي يسجّل العقدة ويدير كل شيء آخر عليها.

عندما يسيء CE التصرف، يكون Site CLI هو الأداة. القرار الأول هو أي مسار وصول
ينطبق، والخطأ فيه يهدر الوقت بطريقة تبدو وكأنها عقدة معطّلة.

يصل debug API إلى العقدة **عبر مستوى التحكم في F5 Distributed Cloud**.
وهذا هو السبب الكامل لأهمية هذا الفصل: لا يمكن لواجهة API الاستجابة إلا بعد أن تكون
العقدة قد سُجّلت وأبلغت عن الحالة `ONLINE`.

العقدة التي فشلت في التسجيل — cloud-init معطوب، أو رمز منتهي الصلاحية، أو عدم وجود
مسار إلى `register.ves.volterra.io` — هي بالضبط الحالة التي تحتاج فيها إلى
التشخيصات، وبالضبط الحالة التي لا يمكن لواجهة API خدمتها.

SSH ليس خيارًا ثالثًا. يعمل `sshd` على العقدة ويستجيب على عنوانها الداخلي (SLI)،
لكن حساب `admin` لا يمكنه المصادقة: إذ يتخطى `vpm` ذلك المستخدم، لذا لا يُطبَّق أبدًا
`ssh_key` الذي تضبطه على كائن الموقع. ولا توجد قاعدة مجموعة أمان تغيّر ذلك. الدليل
موجود في صفحة [SSH](./access/ssh/)، التي وُجدت لأن كل عَرَض هناك يبدو وكأنه خلل في
جدار الحماية أو في بيانات الاعتماد.

إذن: إذا كان الموقع `ONLINE`، استخدم debug API. وإذا لم يكن كذلك، فإن وحدة التحكم
التسلسلية هي السبيل الوحيد للدخول.

<Aside type="caution" title="تحقق من حالة الموقع أولًا">
طلب واحد يخبرك بالمسار الذي أنت عليه:

```bash
curl -sS -H "Authorization: APIToken $XCSH_API_TOKEN" \
  "$XCSH_API_URL/api/config/namespaces/system/sites/<site>" \
  | jq -r '.spec.site_state'
```

`ONLINE` تعني أن debug API سيعمل. وأي شيء آخر — أو موقع غير موجود — يعني وحدة
التحكم التسلسلية.
</Aside>

## قواعد السلامة

هذه القواعد سارية على كل أمر في كل صفحة أدناه.

- **للقراءة فقط ما لم تكن متأكدًا.** سطح الأوامر مقسّم إلى مستويَي امتياز، ومستوى
  `Exec` إما أن يُعدّل العقدة أو يقرأ مؤشر حالة. لا يُشغّل أي شيء في هذه الصفحات أمر
  `Exec`، ولا يفعل ذلك أيضًا إطار الالتقاط.
- **لا تفترض أبدًا أن أمرًا ما آمن استنادًا إلى اسمه.** يبدو `ip-link-set` وكأنه
  استعلام لكنه يُعطّل واجهة. و`systemctl-restart-crio` يعيد تشغيل بيئة تشغيل
  الحاويات تحت مستوى بيانات نشط.
- **فضّل الأمر الأضيق الذي يجيب على السؤال.** يلخّص `health` و`diagnosis` حالة
  العقدة بتكلفة منخفضة؛ بينما يُفرغ `flow-l` جدول تدفق يحتوي 629,760 مدخلًا.
- **يخدم CE حركة مرور حية.** هذه بيئات عرض توضيحي مشتركة. افترض أن شخصًا ما يقدّم
  عرضًا من الموقع الذي تقوم بتصحيحه.

## ما هو موثّق هنا

كل أمر يمكن الوصول إليه عبر debug API على إصدار البرنامج الذي يشغّله هذا المستأجر،
مع مخرجات مُلتقطة من عقدة حية بدلًا من نسخها من مكان آخر.

يسرد [مرجع الأوامر](./commands/) جميعها مع فئتها ومستوى امتيازها ووسيلة نقلها؛
بينما تربطها [سير العمل](./workflows/) في التسلسلات التي تستخدمها فعليًا عندما يكون
هناك خلل.

أما أجزاء Site CLI المتاحة على الجهاز فقط — `configure` و`configure-network`
و`factory-reset` و`upgrade` وما يقارب ستين أمر `ExecCLI` إضافيًا — فهي غير مشمولة.

فهي متاحة فقط من جلسة وحدة تحكم تسلسلية، لذا لا يمكن التحقق من أي شيء يخصها
برمجيًا، وصيغة الأوامر غير المتحقق منها هي العيب الذي وُجدت هذه الوثائق لتجنّب
تكراره.
