Argo conserve l'état de transfert séparé du noyau Linux. Lorsque
[`ip`](../ip/) et ces commandes ne concordent pas, ce sont ces commandes qui acheminent le trafic.

## `rt`

La table de routage vRouter, par VRF.

```bash
{"command":["rt","--dump","2"]}
```

```text file=../../../../_data/sitecli-rt.txt
```

<Aside type="danger" title="L'identifiant VRF n'est pas celui que BGP rapporte">
`show-ip-bgp-summary` affiche `vrf-id 3`. Il s'agit de la numérotation FRR et il s'agit d'un
espace de nommage différent de l'identifiant de table vRouter. Le passer ici échoue d'une manière qui
se présente comme un nœud défaillant :

```text
vRouter(Response):  [No such file or directory (2)]
```

La même réponse est renvoyée pour `--dump 0`. Sur cette topologie, **VRF 2** est la
table inet4 remplie, avec VRF 1 contenant deux routes. Si vous ne connaissez pas l'identifiant,
sondez vers le haut à partir de 1 plutôt que de vous fier à la sortie BGP.
</Aside>

## `nh`

La table des sauts suivants. Chaque route pointe vers un identifiant de saut suivant, et ceci les résout.

```bash
{"command":["nh","--list"]}
```

```text file=../../../../_data/sitecli-nh.txt
```

Chaque entrée comporte un `Type` et le VRF auquel elle appartient. Huit types apparaissent sur ces nœuds,
dans ces proportions — identiques sur les trois CE lorsqu'ils sont comptés :

```text
Tunnel 558   Encap 27   NAT 22   Vrf 16   Receive 14   Composite 4   Drop 2   Resolve 2
```

Une route se résolvant vers un saut suivant `Drop` est un trou noir, et cette combinaison vaut la peine d'être vérifiée
chaque fois qu'un préfixe est présent dans `rt` alors que le trafic disparaît quand même.

<Aside type="caution" title="La capture ci-dessus est tronquée et ne contient donc pas tous les types">
Il s'agit des 60 premières lignes sur 3 849. `Tunnel`, le type de loin le plus courant, n'apparaît
pas du tout dans ces 60 lignes — ne lisez donc pas la capture comme l'inventaire complet des types, et ne
concluez pas qu'un type est absent d'un nœud parce qu'il est absent d'une capture tronquée. Les comptages
ci-dessus proviennent de la réponse non tronquée.
</Aside>

## `vif`

La table des interfaces virtuelles : ce à quoi le plan de données se lie, ainsi que les
compteurs par interface.

```bash
{"command":["vif","--list"]}
```

```text file=../../../../_data/sitecli-vif.txt
```

La légende des indicateurs en haut mérite d'être lue une fois — `Vp` marque l'interface
physique vhost, `Dpdk` une interface gérée par DPDK. Utilisez ceci pour confirmer que le plan de données a réclamé
l'interface attendue, et pour consulter les compteurs RX et TX que Linux n'affiche pas
car le trafic n'atteint jamais le noyau.

## `mpls`

```bash
execcli mpls --help
```

La table MPLS Argo. Accessible **uniquement depuis la machine** — `mpls` n'est pas sur l'API de débogage, donc
contrairement à `rt`, `nh` et `vif` ci-dessus, il nécessite [SSH](../../../access/ssh/) ou la
[console série](../../../access/serial-console/), via
[`execcli`](../../on-box/).

Aucune sortie capturée ici. Sur ce déploiement, le CE transfère IPv4 avec BGP et ECMP et n'utilise
pas d'étiquettes MPLS, donc une capture montrerait une table vide sans rien enseigner. Son existence
et la forme de son argument `--help` sont vérifiées depuis le menu de complétion propre à l'appliance ; sa
sortie remplie n'est pas reproduite.
