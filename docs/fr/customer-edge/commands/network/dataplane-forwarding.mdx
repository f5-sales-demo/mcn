Argo conserve l'état de transfert séparément du noyau Linux. Lorsque
[`ip`](../ip/) et ces commandes divergent, ce sont ces commandes qui déterminent le trafic.

## `rt`

La table de routage du vRouter, par VRF.

```bash
{"command":["rt","--dump","2"]}
```

```text file=../../../../_data/sitecli-rt.txt
```

<Aside type="danger" title="L'identifiant de VRF n'est pas celui que rapporte BGP">
`show-ip-bgp-summary` affiche `vrf-id 3`. Il s'agit de la numérotation de FRR, qui relève d'un
espace de noms différent de celui de l'identifiant de table du vRouter. Le transmettre ici échoue d'une manière
qui laisse penser à un nœud défaillant :

```
vRouter(Response):  [No such file or directory (2)]
```

La même réponse est renvoyée pour `--dump 0`. Sur cette topologie, **VRF 2** est la
table inet4 renseignée, VRF 1 contenant deux routes. Si vous ne connaissez pas l'identifiant,
sondez à partir de 1 en montant plutôt que de vous fier à la sortie BGP.
</Aside>

## `nh`

La table des sauts suivants. Chaque route pointe vers un identifiant de saut suivant, et cette commande les résout.

```bash
{"command":["nh","--list"]}
```

```text file=../../../../_data/sitecli-nh.txt
```

Chaque entrée porte un `Type` et la VRF à laquelle elle appartient. Huit types apparaissent sur ces nœuds, dans
ces proportions — identiques sur les trois CE lorsqu'on les dénombre :

```text
Tunnel 558   Encap 27   NAT 22   Vrf 16   Receive 14   Composite 4   Drop 2   Resolve 2
```

Une route qui se résout vers un saut suivant `Drop` est un trou noir, et cette combinaison mérite d'être vérifiée
dès qu'un préfixe est présent dans `rt` alors que le trafic disparaît malgré tout.

<Aside type="caution" title="La capture ci-dessus est tronquée, elle ne contient donc pas tous les types">
Il s'agit des 60 premières lignes sur 3 849. `Tunnel`, de loin le type le plus courant, n'apparaît
pas du tout dans ces 60 lignes — ne considérez donc pas la capture comme l'inventaire complet des types, et n'en
concluez pas qu'un type est absent d'un nœud parce qu'il est absent d'une capture tronquée. Les décomptes
ci-dessus proviennent de la réponse non tronquée.
</Aside>

## `vif`

La table des interfaces virtuelles : ce à quoi le plan de données se rattache, ainsi que les
compteurs par interface.

```bash
{"command":["vif","--list"]}
```

```text file=../../../../_data/sitecli-vif.txt
```

La légende des indicateurs en haut mérite d'être lue une fois — `Vp` désigne l'interface physique
vhost, `Dpdk` une interface gérée par DPDK. Utilisez-la pour confirmer que le plan de données a bien pris
en charge l'interface attendue, et pour consulter les compteurs RX et TX que Linux n'affiche pas
parce que le trafic n'atteint jamais le noyau.
