Capturé le 28/07/2026 depuis un CE de ce déploiement. Il s'agit de commandes exécutées directement sur le nœud, elles transitent donc par la CLI du site plutôt que par l'API de débogage ; `sitecli/exec-catalog.json` enregistre la surface et `sitecli/capture-manifest.json` enregistre le nœud concerné.

Envoy termine et achemine le trafic applicatif sur le Customer Edge. Ces quatre commandes interrogent son interface d'administration, et aucune d'entre elles ne fait partie de l'[API de débogage](../../../access/debug-api/).

<Aside type="note" title="Chacune de ces commandes commence par un indicateur de progression curl">
Ce sont des encapsuleurs `curl` autour de l'endpoint d'administration d'Envoy, invoqués sans `-s`, de sorte que les deux ou trois premières lignes de chaque capture ci-dessous correspondent à la progression du transfert curl écrite sur stderr :

```text
  % Total    % Received % Xferd  Average Speed   Time    Time     Time  Current
                                 Dload  Upload   Total   Spent    Left  Speed
  0     0    0     0 …
```

Il ne s'agit pas d'une sortie Envoy ni d'une erreur. C'est également utile : le compteur d'octets `% Received` vous indique si Envoy a renvoyé quoi que ce soit, ce qui permet de distinguer « aucun listener configuré » de « l'interface d'administration n'a pas répondu ».
</Aside>

## `envoy-listeners`

Chaque listener installé par Envoy, au format `nom:adresse:port`.

```bash
execcli envoy-listeners
```

```text file=../../../../_data/sitecli-envoy-listeners.txt
```

**Ce qu'il faut rechercher.** Dans ce déploiement, le listener porte `10.250.0.10:80` — le VIP que le CE annonce dans BGP. Cette ligne unique relie trois couches entre elles : si [`show-ip-bgp-summary`](../../network/bgp/) indique que le préfixe est annoncé mais que ce listener est absent, la route est attirée vers un nœud qui ne pourra pas la servir, ce qui constitue le pire mode de défaillance dans un ensemble ECMP, car le trafic est réparti en charge vers un trou noir.

Le `[fe80:…]:80` en fin de ligne correspond à l'adresse link-local de l'interface à laquelle le listener est lié.

**Ce que cela ne vous indique pas.** Rien sur l'état de santé des serveurs en amont — un listener existe qu'il y ait ou non quelque chose d'accessible derrière lui. Utilisez `envoy-clusters` pour cela.

## `envoy-clusters`

Chaque cluster, avec ses limites de connexion et de requêtes par priorité.

```bash
execcli envoy-clusters
```

```text file=../../../../_data/sitecli-envoy-clusters.txt
```

**Ce qu'il faut rechercher.** Les lignes sont au format `cluster::scope::clé::valeur`. L'entrée `observability_name` identifie chaque cluster, et le triplet `default_priority::max_connections`, `max_pending_requests` et `max_requests` est l'endroit où apparaissent les limites de requêtes — un cluster bloqué à sa valeur `max_pending_requests` est en cours de limitation par la configuration plutôt que par l'amont.

## `envoy-config-dump`

La configuration complète d'Envoy au format JSON. Volumineuse : 126 Ko sur un nœud de démonstration par ailleurs inactif.

```bash
execcli envoy-config-dump
```

```text file=../../../../_data/sitecli-envoy-config-dump.txt
```

**Ce qu'il faut rechercher.** Le tableau `configs` de premier niveau contient un objet par type de configuration — bootstrap, clusters, listeners, routes, secrets. Recourez à cette commande lorsqu'un listener ou un cluster existe mais se comporte de manière inattendue, et effectuez une recherche plutôt que de lire l'intégralité du fichier.

## `envoy-hc-config-dump`

La configuration des health checks spécifiquement.

```bash
execcli envoy-hc-config-dump
```

```text file=../../../../_data/sitecli-envoy-hc-config-dump.txt
```

**Ce qu'il faut rechercher.** Dans ce déploiement, il renvoie un **seul octet** — visible sous la forme `100 1` dans le compteur `curl` — ce qui signifie qu'aucune configuration de health check n'est installée. C'est l'état attendu pour un CE sans pools d'origine soumis à des health checks, et il est utile de le reconnaître : un résultat vide ici n'indique pas une requête échouée.
