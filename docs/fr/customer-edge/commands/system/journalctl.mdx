## `journalctl`

```bash
{"command":["journalctl","-u","vpm","-n","200"]}
```

Arguments `journalctl` standard, chacun étant un élément de tableau distinct. `-u vpm` est celui
dont vous aurez le plus souvent besoin : `vpm` est l'agent qui enregistre le nœud et gère
tout le reste sur celui-ci, ainsi son journal est l'endroit où les échecs d'enregistrement apparaissent avec
des horodatages et entre les redémarrages.

Variantes utiles :

| Arguments | Réponses |
| --- | --- |
| `-u vpm -n 200` | Ce que vpm a fait récemment |
| `-u vpm --since "10 min ago"` | Ce qui s'est passé pendant la reproduction du problème |
| `-p err -n 100` | Erreurs de toutes les unités |
| `-u kubelet -n 200` | Pourquoi la pile Kubernetes est défaillante |

Préférez cette commande à [`docker-logs vpm`](../docker/) lorsque vous avez besoin d'horodatages, souhaitez
couvrir un redémarrage, ou souhaitez corréler vpm avec une autre unité.
