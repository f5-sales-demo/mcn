La [référence des commandes](../commands/) est organisée selon ce que fait chaque commande. Ceux-ci
sont organisés selon ce qui s'est mal passé.

| Symptôme | Workflow |
| --- | --- |
| Le site n'est jamais passé en ligne ou a été retiré du tenant | [Enregistrement](./registration/) |
| Les routes ne sont pas annoncées ou apprises ; la VIP est inaccessible | [BGP](./bgp-diagnostics/) |
| Le trafic atteint le nœud mais n'arrive pas à destination | [Plan de données](./dataplane-diagnostics/) |

Chaque étape renvoie à la page qui documente la commande. Rien n'est reformulé ici,
de sorte que la syntaxe n'a qu'un seul emplacement et ne peut pas se désynchroniser avec le nœud.

## Avant tout

Déterminez le chemin d'accès que vous utilisez, car cela change ce qui est possible :

```bash
curl -sS -H "Authorization: APIToken $XCSH_API_TOKEN" \
  "$XCSH_API_URL/api/config/namespaces/system/sites/<site>" | jq -r '.spec.site_state'
```

`ONLINE` signifie que l'[API de débogage](../access/debug-api/) répondra. Tout autre état signifie
qu'il faut utiliser la [console série](../access/serial-console/), et cela signifie également que le
workflow d'enregistrement est celui dont vous avez besoin.
