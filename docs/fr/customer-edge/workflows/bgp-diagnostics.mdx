Pour un site dont l'état est `ONLINE` — s'il ne l'est pas, commencez par
[l'enregistrement](../registration/).

<Steps>

1. **Le peering est-il établi ?**
   [`show-ip-bgp-summary`](../../commands/network/bgp/). Lisez `State/PfxRcd` : un
   nombre signifie que la session est établie, et `Up/Down` indique si elle a été stable. Une valeur faible
   sur un site actif depuis plusieurs jours signifie que la session est instable.

2. **Si la session est inactive**, la cause se situe généralement en dessous de BGP. Vérifiez que l'interface
   portant le peering est active avec
   [`ip-link-show`](../../commands/network/ip/), puis confirmez l'accessibilité à
   l'adresse du pair. Sur cette topologie, les pairs sont les instances Azure Route Server.

3. **Si la session est active mais que le VIP est inaccessible**, vérifiez ce que le nœud
   annonce réellement avec
   [`show-ip-bgp-neighbors-advertised-route`](../../commands/network/bgp/). Si le
   VIP est absent, le problème se situe sur ce nœud et l'examen du pair ne sera pas utile.

4. **Si le nœud annonce correctement mais que le trafic n'arrive toujours pas**, le
   plan de contrôle et le plan de données sont en désaccord. Vérifiez la table de transfert utilisée
   par le plan de données avec [`rt`](../../commands/network/dataplane-forwarding/),
   en gardant à l'esprit que son identifiant VRF n'est pas celui rapporté par BGP.

   Résolvez ensuite le saut suivant avec `nh`. Un préfixe présent dans `rt` dont le saut suivant est
   `Drop` est un trou noir.

5. **Si la session est instable**, [`show-ip-bgp-neighbors`](../../commands/network/bgp/)
   contient la dernière raison de réinitialisation et les minuteries négociées.

</Steps>

<Aside type="caution" title="Deux schémas de numérotation VRF distincts">
`show-ip-bgp-summary` rapporte le `vrf-id` de FRR. Le plan de données Argo numérote ses tables
séparément, et passer le numéro de FRR à `rt --dump` retourne `No such file or
directory` — ce qui ressemble à un nœud défaillant plutôt qu'à un argument incorrect. Sur cette
topologie, le VRF 2 est la table inet4 renseignée.
</Aside>
